# 작업 로드맵

이 문서는 전체 한글화를 완성하기 위한 작업 순서와 단계별 통과 조건을 관리한다. 지금 확인된 상태는 [현재 상태](status.md), 지금까지의 판단 흐름은 [의사결정 기록](decisions.md), 원본과 구조에 관한 근거는 [초기 조사](initial-survey.md), 재현 가능한 빌드 규칙은 [빌드 파이프라인](build-pipeline.md)이 맡는다.

## 목표와 불변 조건

- 지원 원본은 프로젝트가 식별한 일본판 한 리비전이다.
- 일본어만 한국어로 번역한다. 원본의 영어, 숫자, 로마자 약어는 번역하거나 글꼴 슬롯을 덮지 않는다.
- “전체 한글 지원”은 현대 한글 11,172자를 화면에 상주시킨다는 뜻이 아니다. 전체 번역 코퍼스의 모든 필요한 글리프를 저장할 수 있고, 각 화면의 활성 글리프 집합을 안전하게 표시할 수 있다는 뜻이다.
- 원본 ROM과 패치된 ROM은 저장소와 배포물에 포함하지 않는다.
- 앞 단계의 통과 조건을 만족하지 못하면 번역 분량을 확대하지 않는다.
- 미할당 문자, 활성 슬롯 초과, 보호 문자 침범, 예상하지 않은 ROM 변경은 빌드 실패로 처리한다.

## 전체 경로

| 관문 | 결과 | 상태 |
| --- | --- | --- |
| G0. 기준선 PoC | 일본어 설정 3개가 한글로 표시되고 기존 영어 약어가 유지됨 | 완료 |
| G1. 문자·렌더 경로 조사 | 보호 문자, 글꼴 소비자, CHR 상태와 활성 슬롯 예산 확정 | 진행 중 |
| G2. 매퍼 변환 동등성 | 한글 변경 없이 원본 그래픽·진행·저장 동작 보존 | 완료 |
| G3. 동적 한글 글꼴 | 서로 다른 화면별 작업 집합을 교체하며 한글과 기존 영어를 함께 표시 | 완료 |
| G4. 전체 텍스트 모집단 | 일본어 텍스트·참조·토큰을 전수 열거하고 무수정 왕복 | 완료 |
| G5. 전역 최악 수명 | 전체 소비처 중 최대 동시 글리프·조판·전환 조건을 수용하는 구조 확정 | 진행 중 |
| G6. 전체 번역 적용 | 모든 대상 일본어를 검토된 한국어로 교체 | 대기 |
| G7. 전체 회귀 검증 | 전체 플레이와 모든 렌더 경로에서 치명 결함 0건 | 대기 |
| G8. 배포 | 지원 원본에서 재현 가능한 패치와 사용자 문서 제공 | 대기 |

개별 화면의 통과 수는 전체 진척의 분모로 쓰지 않는다. G4에서 모든 도달 가능한 일본어 소비처를 고정하고, G5에서 그중 가장 큰 동시 작업 집합과 가장 까다로운 조판·전환 조건을 먼저 통과시킨 뒤 같은 구조로 G6 전체 설치를 진행한다.

현재 화면 분모는 45개 중 일본어 대상 36개를 22개 번역 도메인에 전부 연결해 누락 0건이며 모든 도메인이 원천과 번역 입력에 결속됐다. 따라서 G4는 완료했다. 전투의 숨은 상태표까지 포함한 7개 상태군·179엔트리·160개 고유 처리기와 큐 게시자 17/17곳을 소스에서 닫았고, 비일본어 활성 코드의 전역 합집합은 39개다. 전역 고정표는 안전 코드가 171개뿐이라 불가능해 전투별 동적 배정과 최대 8쌍의 재배치 표를 구현했다. 가능한 전투 튜플의 정확 최대 `170/210`은 전투 단계 출력과 콜드 자연 전투에서 닫았다. 주 대사의 최대 175자 레코드는 7장 성 좌표 `(27,10)`의 `C0:18` 생산 경로에 결속했다. 11장의 같은 엔트리 번호 18은 별도 선택자 `30:18`로 흘러 제외한다. 레코드 전체 상주 수요 `275/210` 대신 최대 페이지 `135/210`을 기준으로 15페이지를 세 글꼴 묶음에 설치했고, 초기 선택기·완료 페이지 재적재·90개 완료 상태 표본·점멸 위상·최종 이탈을 현재 출력에 결속했다. 자동 병종 소개의 exact-output 설치 묶음 최대 `161+12=173/210`도 전역 비교에 넣었다. 유닛 UI 3개 화면은 전체 합집합 229자와 요약·상태 공유군 218자의 단일 페이지 불가, 화면별 상한 36/30/30의 수용 가능을 함께 결속했다. 부대 목록은 전체 아군명·머리말 73자와 보존 코드 15개, 합계 `88/210`으로 수용한다. 무기점 공용 페이지는 한글 60자와 보존 코드 90개, 합계 `150/210`으로 아홉 화면 역할의 설치 용량을 결속했다. 소지품의 목록·행동 메뉴·장비·양도·폐기는 전체 번역 입력의 독립 최대 조합으로 각각 24/33/29/35/28칸임을 결속했다. 승급은 초기 사용문 뒤 기존 `battle_animation` 수명으로 전환되고 완료된 중첩 전투 대사에서만 `A`를 요구한다. 대지의 오브는 32단계 효과와 결과 `33`까지 `item_use_result`의 같은 글꼴 수명을 유지한다. 가능한 18개 사용 대사 경로를 상호 배타적으로 비교한 사용 결과 최대는 `43/210`이다. 시작 메뉴 `27/210`, 설정 화면 `90/210`, 맵 메뉴 `203/210`을 결속했다. 저장 질문·전원 종료·중단은 각각 `209/210`이고, 저장 완료 선택지는 전역 상한 실패를 기존 소비자 상태의 8개 불규칙 프레임으로 좁혀 `78/210`으로 닫았다. 엔딩 장 기록은 전체 한글 91자와 보존 활성 코드 0개로 `91/210`에 수용된다. 25개 장의 정확한 장 제목과 완전한 도입 대사 사슬은 전체 상주 대신 네 줄 완료 페이지마다 재적재하며 최대 `43+100=143/210`이다. 현재 출력에 25개 장 전체를 설치·실행한 증거와는 분리한다. 현재 36개 일본어 대상 화면 중 35개 수명을 계수했다. 다음 G5 용량 관문은 원본 에셋 기반 제목 그래픽 하나다.

제목은 일반 텍스트 글꼴 수명과 분리한다. 원본 제목 그래픽을 편집 기준으로 만든 ImageGen 시안에서 칼 흔적을 제거하고, 실제로 두 셀을 쓰는 원본 `TM`까지 보존하도록 마지막 행만 한 셀 좁혔다. 현재 자산은 일본어 로고 전용 코드 `117/121`개를 쓰고 134셀만 교체한다. 누적 출력의 초기·완성 점멸, 칼, `TM`, 저작권 줄과 자동 병종 소개 이탈을 무입력 불규칙 표본으로 결속했다. 다음 단계는 이 그래픽 수요를 36번째 화면 수명으로 등록하고 G5 전역 비교를 닫는 것이다.

## G1. 문자와 렌더 경로 조사

### 작업

1. 원본 글꼴 페이지의 코드별 글리프와 모든 참조자를 목록화한다.
2. 기존 영어·숫자·로마자 약어·아이콘·제어용 타일을 보호 집합으로 확정한다.
3. 대사, 맵 메뉴, 상태, 아이템, 전투, 설정 등 일본어가 표시되는 경로가 어떤 디코더와 글꼴 공급자를 쓰는지 구분한다.
4. 화면 진입·전환·이탈·재진입 시 CHR 뱅크 선택과 타일 수명을 관측한다.
5. 각 경로에서 고정해야 하는 타일 수와 한글에 줄 수 있는 활성 슬롯 수를 계산한다.

화면 역할 레지스트리는 이 작업을 상위에서 관리한다. 먼저 화면마다 진입·이탈과 분기, 일본어·보호 영어, FD/FE 배경, 초상화·창·스프라이트, 점멸·자동 출력, 입력 부작용, 페이지 수명의 집중 요소를 정한다. 그다음 국소 실행 추적은 그 빈칸만 닫는다. 여러 실제 화면을 잇는 경로나 아직 가시 수명이 나뉘지 않은 정적 상태기는 화면 수에 섞지 않고 별도 관측 관문·미분할 화면군으로 묶는다. 사운드 테스트의 `START`와 `SELECT`는 각각 6단계 전투 테스트와 30단계 엔딩 상태기에 결속했지만, 실행 결과 단계 수는 화면 수가 아니었다. `START`는 공용 전투의 유닛 정보·예측·공격·피해·결과 수명을 자동 반복했고, `SELECT`는 원본 영어 도입·캐스트와 스태프, 일본어 장 기록과 인물 후일담, 정적 종단 화면으로 나뉘었다. 공용 전투 엔진의 이름·병종·아이템·별도 대사 원천과 28개 대사 레코드, 엔딩 장 기록·인물 후일담 표까지 소스 결속을 마쳤고, 일본어·보존 원문·레이아웃 코드 집합도 미해결 없이 분할했다. 전투의 시간 글리프·초상화·스프라이트 변형 관문은 공용 전투 11개, 현재 진행도 엔딩 18개, 턴 경계 게임 오버 12개, 적 선공 정규 전투 11개, 플레이어 선공 정규 전투 10개, 합계 62개의 frozen-frame 표본으로 닫았다. 인물 후일담도 자연·직접·라우팅 112개 보이는 엔트리의 560개 불규칙 표본과 선택자 이벤트로 닫았다. 종단 서명은 점멸이 아니라 단계 `1D`에서 12,000프레임 동안 정적이었다. 한 화면의 대표 변형이 닫혀도 다른 장·초상화·CHR 변형은 별도 상태로 유지한다. 부대 목록은 한글 FD 페이지와 원본 `LV/HP`·숫자·일본어 유닛명·초상화의 동시 표시를 닫았다. 맵 유닛 UI는 선택 직후 `unit_summary`, 행동 목록 `unit_command_menu`, 상세 능력치 `unit_status`로 나뉜다. 합성 상태 `04/05/07/0F`의 요약 상단·명령 목록·아이템 목록·상세 능력치 writer를 결속했고, 명령 목록은 유닛·지형·시설 조건에서 고정 라벨 15개를 선택한다. 무기점은 입력 효과와 화면 조합이 다른 아홉 역할로 나눴고 모든 하류를 닫았다. 소지품 흐름은 `item_inventory_list`, `item_action_menu`, `item_transfer_target_selection`, `item_equip_result`, `item_use_result`, `item_transfer_result`, `item_discard_result` 일곱 역할로 나눴다. 장비·양도·폐기의 변경과 결과 대기 화면, 양도 취소와 점멸 대상 선택을 실행으로 닫았다. 사용 가능 아이템 26개는 정적으로 여덟 효과 계열과 직접 결과 대사 `1D..27/2F..33/50`에 결속했고, 아이템 `40`의 회복 성공·최대 HP 무효·마지막 사용 소진을 한 계열의 실행 변형으로 확인했다. 성공 승급은 공용 전투 수명으로 전환되며 완료문에서만 `A`를 한 번 요구한다. 대지의 오브는 32단계 지도 변위 동안 초기 사용문과 CHR을 유지한 뒤 결과 `33`을 같은 수명에 표시한다. 두 경로를 닫아 `item_use_result`는 가능한 18개 경로의 최대 `43/210`으로 수용된다. 원본 `NO ITEM`, `LV`, `HIT`와 내구도 숫자는 보존한다. 장 전환은 기본 여섯 수명과 저장 완료 “아니오”의 종료 안내·사운드 테스트를 분리했고 25개 장 문맥과 장 제목을 정적으로 결속했다. 11장에서는 실제 이동·턴 종료·전투와 `しろ` 선택으로 12장 도입까지 연속 관측했으며, 두 “아니오” 분기와 원본 영어 사운드 테스트 진입도 별도 결속했다. 좌표·행동 상태·승리 단계는 직접 쓰지 않았지만 MOV·HP 진행 가속을 선언했으므로 기준 난이도 증거로 일반화하지 않는다. 나머지 장별 종료 대사·초상화·CHR·제목 바 변형은 실행 회귀 관문으로 잇는다. 병종·아이템·아군명·적군명은 235포인터·234고유 문자열·일본어 원문 코드 100개로 산정했고, 전투 대사의 원본 `!`를 추가 보호한 전역 한글 슬롯 상한은 210칸이다. 검토 상태별 한글 합집합 분석에서 의미 있는 일본어 2,541줄은 모두 초벌 `needs_human_review`이고 `complete`는 0줄이므로 승인된 최종 작업 집합은 아직 미정이다. 화면별 구현을 넓히는 동안 번역 검토를 병행해 승인 집합을 확정한다. 소지품이 바뀌는 요약·상세와 별도 페이지를 여는 명령 메뉴를 같은 고정 유닛 페이지로 단순화하지 않는다. 원본 능력치 약어 여덟 개와 일본어 설명문이 공존하는 자동 `class_profile`은 별도 화면으로 관리한다.

최신 번역 작업 기준선은 직접 진입 구조 뷰 2,732줄과 실제 `E4/E6` 전이 소비 뷰 2,812줄을 분리한다. 번역 뷰의 의미 있는 일본어 2,541줄은 모두 검토 대기 초벌이고 승인 완료는 0줄이다. 일본어 판정이 남은 1줄은 완결 문장이 아닌 미사용 특수 레코드 잔편 후보이므로 임의 번역하지 않는다.

### 통과 조건

- 보호 집합의 각 코드에 원본 바이트, 용도, 소비 경로가 연결돼 있다.
- 전체 레퍼토리 저장 예산과 화면별 활성 작업 집합 예산이 별도 수치로 보고된다.
- 글꼴 구조를 뒤집을 수 있는 미확정 렌더 경로가 남아 있지 않다.
- 조사 도구가 같은 지원 원본에서 같은 목록을 재현하며 예상 리비전이 아니면 실패한다.

## G2. 매퍼 변환 동등성

원본 MMC4의 고정 CHR-ROM만으로 전체 한글을 공급하는 안은 사용하지 않는다. CHR-RAM 또는 확장 CHR-ROM과 확장 PRG를 제공할 수 있는 매퍼 후보를 비교하고 하나를 선택한다.

### 작업

1. PRG 뱅크 전환, CHR 래치 전환, 초기화, 인터럽트와 SRAM 의존성을 목록화한다.
2. 후보 매퍼의 PRG·CHR 용량, CHR-RAM·확장 CHR-ROM 지원, 에뮬레이터와 플래시 카트 호환 범위를 선언한다.
3. 한글 자산을 넣지 않은 변환 ROM을 불변 원본에서 빌드한다.
4. 부팅, 제목, 맵, 설정, 상태, 전투와 저장·불러오기에서 원본 동작을 비교한다.
5. 진행용 유리한 치트를 끈 기준선과 필요한 불리한 개입을 분리해 패배·영구 이탈·자원 부족 경로도 비교한다.

### 통과 조건

- 변환된 ROM이 선언한 실행 환경에서 안정적으로 부팅하고 진행한다.
- 대표 그래픽 상태에서 타일, 애니메이션, 팔레트와 화면 전환이 원본과 의미상 같다.
- SRAM, 리셋, 인터럽트와 뱅크 전환에 새 결함이 없다.
- 모든 실행 코드 변경은 검산 가능한 어셈블 경로와 Expected Write로 생성된다.

동등성을 만들지 못하면 다른 매퍼 후보로 한 번 돌아간다. 어느 후보도 통과하지 못하면 전체 한글 구조를 진행하지 않고 원인을 다시 판정한다.

## G3. 동적 한글 글꼴

### 설계 원칙

- 기존 영어·숫자·약어·아이콘은 고정 슬롯과 원본 코드 의미를 유지한다.
- 한국어는 제어 토큰 및 보존 코드와 충돌하지 않는 명시 인코딩을 사용한다.
- 전체 글리프 자산은 확장 ROM에 저장하고, 화면별로 필요한 글리프만 활성 슬롯에 적재한다.
- 글리프 매핑, 슬롯 할당, 타일 생성과 인코딩 검증은 같은 선언 데이터를 사용한다.

### 필수 실증

1. 페이지 A를 표시한다.
2. 페이지 A와 글리프 합집합을 만들면 활성 슬롯 예산을 넘지만 자체적으로는 예산 안에 드는 페이지 B로 전환한다.
3. 다시 페이지 A로 돌아온다.
4. 세 상태 모두에서 한글, 기존 영어와 주변 그래픽이 정확히 표시되는지 확인한다.

### 통과 조건

- 각 페이지는 자신의 활성 슬롯 예산 안에 있고 A와 B의 합집합은 그 예산을 초과해 실제 교체가 발생한다.
- A → B → A에서 누락, 잔상, 잘못된 재사용, 화면 깨짐과 입력 이상이 없다.
- 같은 화면에서 기존 영어와 한글을 함께 표시하고 영어 타일·코드가 보호된다.
- 미할당 문자와 페이지별 슬롯 초과가 런타임이 아니라 빌드에서 실패한다.
- 화면 진입·이탈·재진입과 연속 페이지 진행에서 적재 시점과 타일 수명이 검증된다.

이 관문이 통과해야 전체 번역 작업을 시작한다. CHR-RAM 업로드와 확장 CHR-ROM 페이지 선택 가운데 어느 쪽을 쓸지는 실제 화면별 소비·전환 증거와 실행 환경 호환성을 비교한 뒤 정한다.

첫 공급 방식은 확장 CHR-ROM 페이지 선택으로 확정했다. 설정 페이지 A와 B는 공유 12자와 페이지별 100자를 합쳐 각각 112자, 합집합 212자로 정적 슬롯 관문과 콜드 `A → B → A`, 화면 이탈 복구를 통과했다. 부대 목록도 인공 A/B 작업 집합으로 같은 공급 관문을 닫았고, 현재 누적 빌드는 그 페이지를 실제 아군명 52개의 생산 페이지로 교체했다. 한 의미 번역 자산에서 부대 목록과 맵 유닛 UI용 물리 코드북을 따로 만들어 한글 이름과 원본 `LV/HP/S`·숫자를 함께 유지한다. 따라서 한 페이지 상한을 넘는 작업 집합 교체와 같은 화면의 한글·기존 영어 공존을 함께 닫아 G3를 완료한다.

## G4. 전체 텍스트 모집단

### 작업

1. 포인터, 인라인 문자열, 공유 문자열과 그래픽 텍스트 후보를 소비자별로 열거한다.
2. 각 항목에 번역 뒤에도 유지되는 ID, 원본 좌표, raw 바이트, 일본어 원문과 제어 토큰을 보존한다.
3. 일본어, 보존할 기존 영어, 비텍스트와 미확정을 구분한다. 혼합 문자열은 일본어 부분만 번역할 수 있도록 보호 경계를 기록한다.
4. 토큰의 인자 폭, 종료 조건과 이동·보존·재계산 정책을 확정한다.
5. 무수정 추출·재삽입의 바이트 또는 선언된 의미 동등성을 검증한다.

### 통과 조건

- 선언한 모집단의 모든 항목이 해결·근거 있는 제외·미확정으로 계수되고 미확정이 0건이다.
- 공유 참조와 문자열 내부 진입을 포함한 원본 관계가 왕복 뒤 보존된다.
- 기존 영어 항목과 혼합 문자열의 영어 구간이 기계적으로 보호된다.
- 전체 엔트리 수, 일본어 코드 수, raw 크기와 렌더 경로별 분량이 재현 가능한 보고서로 나온다.

## G5. 전역 최악 수명

전체 한글화의 구조는 가장 쉬운 화면이 아니라 가장 어려운 화면을 감당해야 한다. G4의 전체 일본어 모집단을 소비자와 글꼴 수명으로 묶고, 실제 번역문을 기준으로 최대 동시 글리프 집합, 가장 긴 조판, 가장 큰 저장 구간, 가장 복잡한 진입·이탈·재진입을 먼저 식별한다.

### 통과 조건

- 모든 도달 가능한 일본어 항목이 정확히 하나 이상의 실제 소비자와 하나의 글꼴 수명에 배정되고 미분류가 0건이다.
- 수명별 보호 코드와 번역 글리프 합집합을 계산하며, 최대 집합도 선택한 페이지 공급 또는 런타임 합성 구조에 들어간다.
- 최장 이름·대사·동적 삽입과 최대 저장 구간이 조판·포인터·저장 공간 예산을 통과한다.
- 최악의 자동 전이와 입력 분기가 화면 진입·이탈·재진입 뒤 원래 그래픽과 글꼴 상태를 복구한다.
- 이 구조가 특정 장이나 한 표본의 우연한 조건에 의존하지 않는다는 반례 검사를 통과한다.

1장 연속 플레이는 이 구조를 검증하는 중요한 회귀 표본이지만 전체 수용 구조의 대리 지표는 아니다. 같은 원인의 결함은 개별 문장 예외가 아니라 인코더, 조판기, 공급기 또는 소비자 경계에서 고친다.

## G6. 전체 번역 적용

- 공용 UI와 장별 텍스트를 소비 경로 단위로 나누어 적용한다.
- 일본어 원문, 제어 토큰과 보호 영어는 번역 자산에서 편집값과 분리한다.
- 자유 문장과 용어·고유명사·말투는 사람이 번역하고 검토한다.
- 각 적용 묶음은 전체 빌드에 통합한 뒤 정적 검사와 대표 실행 회귀를 통과한다.
- 매핑 누락, 슬롯 초과, 레이아웃 초과와 예상하지 않은 일본어 잔존은 항목 목록과 함께 실패한다.

### 통과 조건

- 대상 일본어 항목이 모두 검토된 한국어 또는 승인된 예외로 판정돼 있다.
- 전체 코퍼스의 모든 글리프가 저장 레퍼토리에 있고 모든 화면의 활성 작업 집합이 예산 안에 있다.
- 최종 누적 산출물의 도달 가능한 텍스트·그래픽 소비처에서 대상 일본어 잔존이 0건이다.
- 보호 대상 영어의 변경이 0건이다.
- 전체 빌드가 불변 원본과 승인된 입력만으로 재생성된다.

## G7. 전체 회귀 검증

- 처음부터 엔딩까지 실제 플레이 경로를 검증한다.
- 진행 가속 치트는 화면 도달에만 사용하고, 정상 성공·패배·게임 오버·영구 이탈·자원 부족 경로는 [플레이와 런타임 검증](playtesting.md)의 기준선 또는 불리한 경계 실행으로 별도 확인한다.
- 제목, 설정, 모든 메뉴와 상태창, 아이템, 전투, 장 전환, 저장·불러오기와 엔딩을 렌더 경로별로 확인한다.
- 최악 길이의 이름·수치·변수 삽입과 페이지 전환에서 조판과 글리프 캐시를 확인한다.
- 새 게임, 저장 재개, 화면 이탈·재진입과 장시간 플레이에서 상태 누수를 확인한다.
- 선언한 에뮬레이터와 플래시 카트 또는 실기 호환 범위에서 최종 후보를 검증한다.

알려진 진행 불가, 크래시, 글자 깨짐, 잘못된 진행 정보와 보호 영어 손상이 0건이어야 통과한다.

## G8. 배포

- 지원 일본판 원본의 해시와 패치 적용 방법을 명시한다.
- 불변 원본에서 최종 ROM과 배포 패치를 다시 만들고 적용 결과가 목표 ROM과 일치하는지 확인한다.
- ROM은 포함하지 않고 패치, 사용 설명, 라이선스와 사용한 글꼴 고지를 제공한다.
- 배포 후보의 전체 빌드·정적 검사·실행 증거가 같은 ROM 해시에 귀속돼야 한다.

## 즉시 실행할 작업

1. 완료: 22개 원천 도메인 전부에 한국어 입력을 결속했다.
2. 완료: 전투 입력 일반형 구조에서 사운드 테스트 여섯 조합·일반 전투 두 건·엔딩 비개입과 정확 최대 131글리프의 합성·수명·정리를 실행으로 닫았다. `173/210`은 임의 선택 안전 상한, `170/210`은 가능한 모델의 정확 최대다.
3. 완료: 페이지 0 매퍼 선택 회귀 수정을 콜드 부팅의 자연 일반 전투 두 건과 지도 복귀까지 재확인해 전투 표시 관문을 닫았다.
4. 완료: 조사 교정 뒤 전투 ROM의 자연 전투 두 건에서 합성·표시·조사·정리를 재검증했다.
5. 완료: 전투 로더를 누적 ROM에 합치고 시작·도입·부대 목록과 자연 전투 두 건을 같은 콜드 산출물에서 재검증했다.
6. 완료: 주 대사의 175자 최대 레코드를 구조로 식별했다.
7. 완료: 11장 장 종료 표본이 선택자 `C0:1C`의 다른 사슬임을 확인해 잘못된 최대 수명 결속을 폐기했다.
8. 완료: 7장 성 이벤트가 `C0:18`을 생산하고 11장의 같은 엔트리 번호는 `30:18`이라는 소스 경로를 결속했다.
9. 완료: 7장 `C0:18`의 15페이지·90표본을 관측해 전체 상주 불가·페이지 단위 수용 가능을 확정했다.
10. 완료: 15페이지를 세 글꼴 묶음으로 설치하고 초기 선택기·완료 페이지 재적재·점멸 위상·`NEXT STORY` 이탈을 정확한 출력 해시에 결속했다.
11. 현재: 미계수 화면 5개를 같은 방식으로 비교해 전역 최악 조건을 확정한다. 시작 메뉴 `27/210`, 설정 `90/210`, 아이템 사용 `43/210`, 맵 메뉴 `203/210`, 저장 계열 최대 `209/210`은 닫혔으므로 같은 경로를 반복 관측하지 않는다.
12. 22개 도메인의 번역을 누적 설치하고, 일본어 잔존 0건을 빌드 조건으로 만든 뒤 성공·실패·패배·저장·엔딩 경로를 동일한 최종 ROM 계보에서 검증한다.

기존 수직 슬라이스는 소비자와 실행 계약을 발견한 근거로 유지한다. 앞으로의 진척 판정은 전체 일본어 분모, 최악 수명 수용 여부, 최종 누적 산출물의 일본어 잔존 수로 한다.
