# 초기 조사

기준일: 2026-08-06

## 지원 원본

| 항목 | 값 |
| --- | --- |
| 형식 | iNES 1.0, 트레이너 없음 |
| 매퍼 | 10 (MMC4), 수평 미러링, 배터리 SRAM |
| 파일 크기 | 393,232 bytes |
| 파일 SHA-1 | `0179c550d424e0397496078789e7b116601d120c` |
| PRG | 262,144 bytes, SHA-1 `a74c0760f32f5131d4feb67694123fda6b7da24f` |
| CHR | 131,072 bytes, SHA-1 `98ee1568073c6c41425e4a381cf588433ac9fc97` |

로컬 MAME 소프트웨어 목록의 `firemb`/`HVC-FKROM` PRG·CHR 해시와 일치한다.

## 번역 경계

번역 원문은 일본판 ROM의 일본어다. 같은 ROM에 존재하는 `AT FIRST...`, `STR`, `SKI` 같은 영어·로마자 약어와 숫자는 보존 대상이다. 영문 패치는 번역문을 가져오는 자료가 아니며 제품 빌드가 영문 패치에 의존해서도 안 된다.

## 첫 설정 문자열 경로

파일 오프셋 `0x2CADE`의 24-byte 표는 다음 세 일본어 항목을 `ED`로 구분하고 `EF`로 끝낸다.

| ID | 일본어 | 원본 바이트 |
| --- | --- | --- |
| `sound` | `サウンド` | `3A 32 5F 44 0F` |
| `animation` | `アニメーション` | `30 46 53 3F 3B 8B 5F` |
| `wait_timer` | `ウエイトタイマー` | `32 33 31 44 40 31 50 3F` |

바로 앞의 6502 코드 `BD CE 8A 9D 51 04 E8 C9 EF D0 F5 4C 39 8F`는 CPU 주소 `$8ACE,X`에서 읽어 `$0451,X`로 복사하고 `EF`까지 반복한다. 따라서 문자열 경계와 소비 경로를 함께 정적으로 확인했다.

## 그래픽 구조

CHR은 ROM에 있고 MMC4가 4 KiB 단위로 래치 전환한다. 설정 문자열에 쓰이는 일본어 타일 가운데 12개만 Dalmoori 8x8 한글 타일로 교체해 첫 표시 가능성을 검증한다. 기존 영어 타일은 이 쓰기 집합에 포함하지 않는다.

이 방식은 선택한 가나 코드의 모든 사용처에 영향을 주므로 정식 글꼴 전략이 아니다. 전체 일본어 말뭉치, 화면별 CHR 뱅크와 동시 글자 수를 조사한 뒤 전용 한글 글꼴 적재 또는 조합 방식을 결정해야 한다.

## 한글 글리프 용량 판정

NES의 8x8 2bpp 타일은 글리프 하나에 16 bytes를 사용한다. 지원 원본의 128 KiB CHR에는 8,192타일이 있으며, 전수 검사 결과 7,849타일이 비어 있지 않고 343타일만 전부 0이다. 0인 타일에는 MMC4 래치와 예약 코드가 포함될 수 있으므로 343개는 사용 가능한 공간이 아니라 후보 상한이다. 현재 글꼴이 있는 첫 4 KiB 페이지에서 전부 0인 타일 코드는 `95`, `FF`뿐이다.

| 레퍼토리 | 필요한 타일 | 필요한 저장 공간 | 원본 CHR 상주 판정 |
| --- | ---: | ---: | --- |
| KS X 1001 완성형 | 2,350 | 37,600 bytes | 기존 그래픽과 함께 수용 불가 |
| 현대 한글 완성형 전체 | 11,172 | 178,752 bytes | 한글만으로도 CHR 전체 초과 |

원본 실행에서는 제목과 설정 화면이 같은 글꼴 페이지를 사용하고 서로 다른 그래픽 페이지를 짝으로 선택한다. 현재 MMC4 글꼴 페이지에 완성형 한글을 고정 배치하는 방식으로는 전체 게임을 한글화할 수 없다.

따라서 전체 게임 지원 여부는 전체 한글 레퍼토리를 한 번에 상주시키는지가 아니라, 다음 두 예산을 따로 만족하는지로 판정한다.

- 전체 번역 코퍼스의 글리프를 ROM에 저장하고 코드로 표현할 수 있는가
- 한 화면이나 페이지에서 동시에 필요한 글리프를 활성 타일 슬롯에 올리고 수명 동안 유지할 수 있는가

현재의 우선 후보는 기존 영어·숫자·약어·아이콘을 고정 슬롯으로 보호하고, 확장된 ROM에서 화면별 한글 작업 집합을 CHR-RAM으로 적재하는 구조다. 매퍼 변환과 원본 그래픽 동작 보존이 먼저 입증되기 전에는 정식 구조로 채택하지 않는다.

재현 가능한 글꼴 공급 조사에서 첫 페이지의 256개 코드 가운데 42개를 현재 보호 대상으로 확정했다. 숫자 10개, 대문자 26개, 상태 표의 `:`·`.` 2개, 텍스트 제어 코드 `ED`·`EF`, MMC4 래치 코드 `FD`·`FE`다. 나머지 214개는 사용 가능이 아니라 `unresolved`이며, 전부 0인 `95`와 `FF`도 여기에 포함한다. 이 수치는 확인된 설정·상태 표와 하드웨어 역할만 반영하며 전체 참조자 목록이나 활성 한글 슬롯 예산을 뜻하지 않는다.
