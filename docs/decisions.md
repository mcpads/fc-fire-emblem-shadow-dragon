# 채택한 설계 판단

이 문서는 시행착오를 날짜순으로 쌓는 작업일지가 아니다. 제품 구조를 바꾸는 판단과 그 이유만 남긴다. 현재 산출물과 다음 행동은 [현재 상태](status.md), 코드 소유권은 [한글 표시 경로 소유권](refactoring.md), 전체 통과 조건은 [작업 로드맵](roadmap.md)을 따른다. 폐기된 구현은 Git 이력에만 남기고, 유효한 화면 관측은 비공개 exact-ROM 실행 manifest에 결속한다.

## 번역 범위와 원천

- 지원 일본판의 일본어만 한국어로 바꾼다. 원본 영어·숫자·로마자 약어와 게임 그래픽은 보존한다.
- 영문 패치는 주소와 구조를 대조하는 조사 자료일 뿐 번역 원문이나 제품 입력이 아니다.
- 번역 작업공간이 존재한다는 사실과 실제 ROM 소비자가 결속됐다는 사실을 구분한다. 저장소·생산자·선택자·소비자 수명이 연결된 항목만 설치 대상으로 센다.

이 범위를 먼저 고정하지 않으면 보존 코드와 한글 슬롯 예산, 일본어 잔존 판정이 모두 달라지므로 구현 편의를 이유로 바꾸지 않는다.

## 증명 관문을 합치지 않는다

원본 조사, 정적 설치, 단위 시험, 실행 관측, 사람의 번역·화면 검토와 배포는 서로 다른 주장이다. 한 단계의 성공을 다음 단계의 성공으로 승계하지 않는다.

- 정적 분석은 후보 주소와 유한 모집단을 닫을 수 있지만 실제 실행 시점과 화면 결과를 대신하지 않는다.
- 한 화면의 읽을 수 있는 한글은 다른 분기, 이탈·재진입, 다음 장이나 엔딩의 성공을 증명하지 않는다.
- 실행 증거는 exact ROM·SaveRAM·입력 계보에 귀속한다. 다른 ROM에서 통과한 실행은 새 ROM의 성공이 아니다.
- 배포는 깨끗한 원본에 패치를 적용한 결과와 승인 ROM의 동일성까지 별도로 닫는다.

## 관측 분모를 채운 뒤 제품을 고친다

여러 화면에서 가블·일본어 잔존·수명 결함이 반복되는 단계에서는 개발 후보 하나를 동결한다. [플레이와 런타임 검증](playtesting.md)의 네 목적 묶음에 있는 독립 경로를 먼저 모두 시도하고 각 결과를 `통과`, `실패`, `차단`으로 남긴다.

- 한 반례는 관측 캠페인의 종료 조건이 아니다. 그 결함과 독립적인 경로를 계속 본다.
- 실패를 발견할 때마다 제품 코드를 고치거나 ROM을 다시 만들지 않는다.
- 도달 가능한 분모를 모두 채운 뒤 반례를 생산자, 번역 재료, 상주 수명, 런타임과 소비자 가족으로 묶는다.
- 정적 분석은 모인 반례를 구분하거나 공통 원인을 닫는 범위에서 사용하고, 실행 순서·프레임 위상처럼 정적으로 결정할 수 없는 사실은 짧은 계측으로 확인한다.
- 공통 원인별 수정은 한 배치로 통합한다. 새 ROM에서는 이전 ROM의 통과 결과를 승계하지 않고 네 묶음을 다시 실행한다.

한 결함이 특정 경로를 막아도 다른 묶음을 먼저 소진한다. 모든 남은 관측이 같은 결함 때문에 불가능해졌을 때만 차단 근거를 남기고, 그 차단을 푸는 최소 공통 수정으로 새 캠페인을 연다. 이 예외는 화면 하나의 문구나 타일을 임시 허용하는 근거가 아니다.

## mapper 165와 원본 래치 의미를 보존한다

MMC5로 화면 상태를 재구성하거나 네임테이블 쓰기를 복제하는 실험은 원본 MMC4 래치의 의미와 소비 시점을 다시 구현해야 했다. 이 경로는 폐기했다. 채택한 mapper 165 변환은 원본 PRG·CHR 선택과 알려진 writer를 보존하고, 필요한 문자 쪽 CHR 창만 RAM으로 공급한다.

CHR helper는 상태 생산자가 아니다. 권위 있는 상태는 원본 중앙 writer와 결속한 그림자·생산자에 있고 helper는 그 결정을 소비한다. 직접 writer, 중앙 selector, NMI 복구와 화면 이탈은 같은 소유 계약에서 파생한다.

## 고정 페이지 카탈로그 대신 수명별 합성을 쓴다

전체 대사와 전투 조합을 완성 CHR 페이지로 미리 저장하면 매퍼의 페이지·PRG 상한을 넘는다. 번역 축소나 일본어 누락으로 맞추지 않고, 실행 중 현재 화면에 필요한 원본 패턴과 한글 글리프만 CHR-RAM 페이지로 합성한다.

- 전역 논리 글리프와 화면의 물리 타일 코드를 분리한다.
- 이름·병종·장비·지형·대사처럼 동적인 재료는 실제 생산자가 낼 수 있는 모집단에서 모은다.
- 준비 상태, 게시 상태와 실제 표시 완료 프레임을 구분한다.
- 같은 원문과 상주 그룹만 완성 페이지를 재사용한다. 원본 상태 처리를 생략하는 최적화는 허용하지 않는다.
- 합성 중 미완성 타일을 노출하지 않고 전용 빈 표시 페이지를 유지한다.

## 화면 수명이 코드북을 소유한다

페이지 번호나 외부 상태 하나만으로 글꼴을 고르지 않는다. 생산자에서 시작해 동시에 보이는 대사, 고정 라벨, 이름, 숫자·영어, 보더와 그래픽을 한 화면 수명으로 묶는다.

- 같은 레코드 번호라도 선택자·생산자가 다르면 다른 표시 경로일 수 있다.
- 레코드 전환이 네임테이블 삭제나 코드북 교체 경계라는 보장은 없다.
- 앞 화면의 행이나 고정 오버레이가 남으면 후속 대사와 같은 코드북 수명으로 계산한다.
- 전투는 플레이어·적 선공 표식 하나가 아니라 전투 엔진 수명과 모든 참가자·병종·장비·지형·대사 생산자를 함께 소유한다.
- 누적 설치의 임시 선택기와 최종 공용 선택기를 동시에 보존하지 않는다. 최종 소유자가 교체한 경로는 하나만 남긴다.

이 원칙은 화면 하나의 가블을 허용 목록으로 막지 않고 같은 생산자 가족의 결함을 한 번에 고치기 위해 필요하다.

## 원천 문자열과 물리 인코딩을 분리한다

공유 번역은 의미 원천이고, 각 소비자의 저장 바이트와 물리 코드북은 파생물이다. 한 소비자에서 우연히 맞은 코드 값을 다른 화면의 전역 코드로 해석하지 않는다.

동적 이름 뒤 조사는 입력에 따라 달라지는 형태 대신 `은(는)`처럼 입력 중립형으로 쓴다. 문자열 폭이 창을 넘으면 의미와 고정 행 구조를 보고 사람이 줄을 재배치한다. 모든 문자열에 적용하는 무조건 자동 줄바꿈은 선택지·동적 삽입·제어 코드의 경계를 파괴하므로 쓰지 않는다.

## 원본 상태와 행 교체 정책을 함께 보존한다

주 대사의 직접 진입, 호출자 인계와 게시 전이는 같은 레코드를 읽어도 앞 행 처리 방식이 다르다. 각 레코드는 진입 방식별 행 교체 정책을 명시하고 런타임은 현재 방식의 정책만 읽는다. 알 수 없는 방식이나 결속되지 않은 레코드는 실패 닫힘한다.

반복 생산자는 현재 완성 페이지와 게시 원문 정체성을 보존한다. 새 원문이 들어올 때만 다음 레코드로 승격하며, 수명이 끝나면 같은 정체성의 재진입도 다시 처리하도록 무효화한다.

## 용량과 현재 수요를 같은 상수로 만들지 않는다

런타임 RAM 필드 수, 한 페이지 활성 슬롯 상한과 현재 번역 입력의 고유 글리프 수는 서로 다른 값이다. 제품 정책은 용량과 범위를 소유하고 보고서는 현재 수요를 계산한다. 번역 한 글자가 바뀔 때마다 고쳐야 하는 정확한 개수는 안정된 테스트나 이름 있는 제품 상수가 아니다.

PRG와 CHR 상한을 넘으면 의미를 줄이기 전에 저장소 배치, 수명 분할과 합성 구조를 검토한다. 한계를 넘는 입력은 조용히 잘라내지 않고 어느 생산자와 수명이 초과했는지 보고한다.

## typed 설치와 최종 이미지 검증을 한 단위로 둔다

실행 코드는 typed RP2A03 방출기로 만들고, ROM 변경은 Expected Write 집합으로 합친다. 주소·필드 순서·selector 투영은 단일 소유자에서 파생하며 코드 생성기와 검증기가 별도 복사본을 갖지 않는다.

설치 성공은 중간 계획이 아니라 최종 이미지에서 다시 읽은 저장소, 포인터, 훅, 페이지, 소비 역할과 도메인 기여로 판정한다. 공용 소비자의 PPU 큐 길이처럼 downstream이 읽는 값은 의도한 상수가 아니라 실제 기록한 payload에서 계산한다.

## 정적 분석과 실행 관측의 경계

정적 분석은 지원 원본의 유한한 후보·직접 writer·포인터 표·도달 가능한 생산자 모집단을 줄일 때 계속한다. 간접 분기 값, 실행 순서, 프레임 위상처럼 정적으로 결정할 수 없는 지점은 계측 실행으로 넘긴다.

실행은 한 증상만 캡처하는 데 쓰지 않는다. 같은 exact ROM에서 목적별로 성공·취소·실패·결과·이탈을 묶고, 공통 반례가 나오면 생산자부터 소비자까지 같은 가족을 다시 연다. [플레이와 런타임 검증](playtesting.md)이 이 증거 형식을 소유한다.

## 폐기된 경로를 제품에 남기지 않는다

부분 대사 ROM, 한 전투 조합 전용 캐시, MMC4/MMC5 변환 실험과 대체된 CLI는 조사 당시 역할을 끝냈다. 채택된 지식이 제품 모듈과 안정 계약으로 이동한 뒤에는 구현·문서·전용 테스트를 함께 제거한다. “나중에 쓸 수 있음”은 유지 근거가 아니며 필요하면 Git 이력에서 원인을 다시 찾는다.
