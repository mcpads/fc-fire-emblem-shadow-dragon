# 현재 상태

기준일: 2026-08-10

## 현재 결론

매퍼 변환의 우선 후보를 MMC5에서 mapper 165로 바꿨다. mapper 165는 원본과 같은 배터리 SRAM을 제공하면서 MMC2식 FD/FE CHR 래치를 유지한다. 무번역 프로브는 원본 128 KiB CHR 앞에 8 KiB 예약 영역을 두고 원본 페이지를 그대로 재배치하며, PRG writer 12곳과 확인된 CHR writer 35곳을 변환한다.

실행 관측 화면 29개의 고유 FD/FE 쌍 18개를 비교해 오른쪽 `00/14`용 변형 CHR 페이지 1개를 만들고, 중앙 오른쪽 공급자가 FD/FE 그림자 쌍으로 이를 선택하게 했다. 설정의 `00/15`와 부대 목록·맵 유닛 UI·무기점·소지품 화면의 `00/15`, `00/18`, `00/19`, 양도 대상의 `15/15`는 원본 트리거 평면과 같아 자연 페이지를 쓴다. Mesen 콜드 실행의 프레임 800·1206·1928, 실제 입력 뒤 1장 인트로 대화와 2장 인트로 화면은 모두 기존 원본 PNG와 SHA-256이 정확히 같다. 전투의 직접 왼쪽 `02/06`, `06/06`과 오른쪽 `02/06`도 자연 페이지로 호환됐다.

G2는 통과했다. 직접 CHR writer 31곳을 정적 계약과 실제 전투 실행 쌍으로 모두 닫았고, 자연 중단·배터리 파일·전원 재인가·재개·일회성 소비와 턴 경계 게임 오버도 원본과 동등했다. 이어 실제 이동·턴 종료·전투로 보스를 쓰러뜨리고 성 명령을 선택해 1장을 완료한 뒤 정규 저장, native power cycle, `ロードする`와 2장 전환까지 비교했다. 같은 점멸 위상의 화면과 로드 뒤 네임테이블·OAM·팔레트가 일치해 mapper 165를 채택한다. 진행 가속으로 달라진 적 AI와 이동 경로 때문에 전체 SRAM·내부 RAM은 이 표본의 동등성 기준에서 제외했으며, 아직 게임 전체의 전수 회귀를 뜻하지 않는다. MMC5 프로브는 비교 근거와 기각된 설계의 재현 자료로 유지한다.

G3의 공급 방식은 확장 CHR-ROM 페이지 선택으로 확정했다. 보호 43코드와 레이아웃 3코드를 원본 그대로 복사하고 나머지 210코드만 한글에 배정한다. 설정 페이지 A/B는 공유 12자와 페이지별 100자로 각각 112자, 합집합 212자이며 물리 페이지 `34/35`, mapper 값 `88/8C`를 쓴다. 설정 화면 콜드 실행에서 `88 → 8C → 88`과 이탈 뒤 자연 페이지 복구를 확인했다.

부대 목록에는 물리 페이지 `36/37`, mapper 값 `90/94`의 화면 전용 A/B를 추가했다. 두 페이지는 `이/름`을 공유하고 화면에 보이는 원본 `LV/HP`·숫자·일본어 유닛명 코드를 그대로 보존하며, 각각 107자·합집합 212자로 한 페이지 예산을 실제로 넘는다. 진행 메뉴와 외부 상태·CHR 쌍 일부가 겹친다는 반례 뒤, 부대 목록 생성자 `0B:$89DB`의 고유 창 기술자와 위치 상태에 수명을 결속했다. 최종 콜드 실행의 연속 재진입에서 FE `19 → 15 → 19`, mapper 값 `90 → 94 → 90`과 한글 `이름`, 원본 `LV/HP`·숫자·일본어 유닛명·초상화의 공존을 확인했다. 불규칙 시간 표본과 이탈 뒤 진행 메뉴의 원본 일본어 복구도 통과해 G3를 완료했다.

주 대사 번역 뷰 2,812줄 가운데 의미 있는 일본어 2,541줄을 `needs_human_review` 한국어로 채우고 장면별 직접 2차 교정을 마쳤으며 승인 완료는 아직 0줄이다. 남은 일본어 판정 1줄은 완결 문장이 아닌 미사용 특수 레코드 잔편 후보라 임의 번역하지 않았다. 원본 영어·숫자·제어 토큰 보존 검증과 원본 무수정 왕복을 통과했다. 채워진 고유 한글은 697자이고 한 줄 고유 한글은 최대 14자다. 명시적인 `E4`/`E6` 대사 전이 사슬은 최대 175자로 활성 슬롯 210칸 안에 들어가며, 관측 화면 수명 최대치는 204슬롯이다. 배치 계획은 11구간·504레코드·517포인터를 유지하면서 29,948바이트를 쓰고 9,477바이트를 남긴다. 다음 관문은 검토 승인과 화면별 줄 폭·재삽입 실행 검증이다.

별도 형식의 전투 대사도 비공개 번역 작업공간으로 추출했다. 포인터 65개가 가리키는 고유 레코드 28개를 겹침 없는 1,152바이트 소유 범위에 결속했고, 4바이트 헤더 뒤 본문을 `ED/EE/EF` 단위 100줄·일본어 620바이트로 분리했다. `EC` 동적 문자열 선택자와 기존 영문·숫자·제어 코드는 보호 토큰으로 유지한다. 일본어가 있는 70줄은 모두 `needs_human_review` 한국어 초벌과 직접 2차 의미 검토를 마쳤고, 나머지 30줄은 제어만 있는 구조 줄이라 번역하지 않았다. 현재 작업공간 SHA-1은 `3cdec3a1efaab82ac49e713afabc37f5c7d4ff7d`다. 번역 레코드 논리 인코딩 1,025바이트와 미참조 원본 레코드 보존 16바이트를 합친 실제 계획은 1,041/1,168바이트로 127바이트가 남는다. 미참조 레코드의 원래 16바이트 위치를 경계로 소유 영역을 둘로 나누고 레코드를 자르지 않은 채 순서대로 배치했으며, 28개 새 주소와 별칭을 포함한 65개 포인터 쓰기를 모두 계산했다.

전체 전투 초벌을 한 번에 넣는 mapper 165 개발 ROM도 만들었다. 28레코드·70번역 줄·65포인터를 적용한 기존 프로브에서 실제 전투 소비자와 원본 `LV`·`HIT`·`EXP`·숫자 보존을 확인했다. 이후 병종·아이템·아군명·적군명 233개도 모두 번역하고 직접 2차 교정을 마쳤다. 기존 프로브는 원본 글꼴 페이지를 전역 교체해 고정 문자열이 깨지는 비배포 증거이므로, 다음 관문은 대사·동적 삽입·고정 문자열을 같은 전투 조합 코드북으로 인코딩하고 전투 수명에만 공급하는 것이다.

무기점의 품목 목록에서 첫 품목을 고른 `E7` 표본은 외부 상태 `04→05→07`, `$7809=01` 읽기 PC `06:$A144`로 결속했다. 인계 순간에는 6개 품목·가격 목록과 구매 질문이 함께 남아 있고 `はい/いいえ` 창은 아직 완성되지 않았다. 품목 목록에서 인계까지 네임테이블은 16바이트, 인계에서 안정 확인 화면까지 40바이트가 더 바뀌었다. 따라서 `$7809` 관측이나 상태 17에서 대사 전용 글꼴 페이지로 즉시 바꾸면 안 된다. 이 수명에서 보존해야 할 품목명·선택지 원본 코드는 17개이고, 동시에 보이는 대사 레코드 2개의 초벌 한글 합집합은 9자여서 총 26/210슬롯으로 한 페이지에 들어간다. 이는 관측한 상점 구매 인계만 닫으며 다른 `E7` 호출자를 대신하지 않는다.

자동 인물 후일담 화면군은 112개 보이는 엔트리의 560개 실행 표본을 한데 합친 보수적 예산으로 닫았다. 관측 네임테이블의 활성 원본 코드 99개를 모두 보존하고, 아직 실제 번역을 확정하지 않은 인물명 최대 7칸과 지명 최대 11칸을 별도 예약하며, 초벌 대사의 최대 전이 사슬 한글 33자를 더해도 150/210슬롯이다. 따라서 이 화면군은 페이지 분할 없이 수용 가능하지만, 이름·지명의 실제 한국어 문자열과 줄 폭은 아직 확정하지 않았다.

턴 경계 게임 오버는 불리한 일회성 개입으로 얻은 12개 불규칙 표본의 활성 원본 코드 90개를 모두 보존한다. 어느 엔트리가 패배 문구인지 추정하지 않고 `victory-and-defeat-dialogue` 11레코드 초벌 한글 합집합 112자를 전부 같은 페이지에 넣어도 202/210슬롯으로 수용된다. 이 결과는 관측한 게임 오버 수명만 닫으며 장 승리 대사의 화면 수명은 별도다.

개발용 mapper 165 대사 프로브는 첫 레코드를 원위치에 넣고 18글리프를 물리 글꼴 페이지 2에 공급했다. 콜드 실행의 결속된 새 게임 경로에서 세 줄 한글이 실제 표시됐고 7·19·43프레임 불규칙 추가 표본에서도 유지됐다. 슬롯 화면의 원본 `MAP`과 숫자는 보존됐다. 다만 페이지 00 전역 교체 때문에 앞선 일본어 메뉴와 대사 화면의 일본어 장 제목이 깨졌으므로 이 프로브는 배포 후보가 아니다. 다음 구현은 대사 화면 소유 수명에만 한글 페이지를 선택하고 이탈 때 원본 페이지를 복구해야 한다.

상위 화면 조사를 다시 수행해 맵 유닛 UI를 `unit_summary`, `unit_command_menu`, `unit_status`로 분리했다. 요약은 일본어 이름·병종·아이템과 원본 `S/HP`·숫자를, 상세는 일본어 능력치 9개와 같은 원본 영문·숫자를 함께 표시한다. 합성 상태 `04/05/07/0F`를 요약 상단·명령 목록·아이템 목록·상세 능력치 조립기에 결속했다. 상태 `05`는 유닛 능력·지형·인접 대상·인벤토리·시설에 따라 일본어 명령 15개를 선택한다. 무이동 `もちもの/たいき`, 타일 `46`의 `たずねる`, 1장 좌표 `$03/$1A`의 `ぶきや`까지 4개를 실행 화면으로 확인했다. 전체 고정 라벨 26개 중 일본어 25개만 번역 대상이고 원본 `HP`는 보호한다.

페이지 수명도 다시 닫았다. 요약과 명령 메뉴 진입은 각각 중앙 `$C9C2`를 통해 오른쪽 FD `00`을 공급하고, 상세만 요약의 페이지를 추가 공급 없이 상속한다. 기준 맵 `18/18`에서 요약 `00/19`, 상세 `13/13 + 00/19`, 이동 선택 `15/15`, 명령 메뉴 `00/15`가 이어졌다. `ぶきや`의 화면 조합을 아홉 역할로 나눴고 모두 `1E/1E + 00/15`였다. 소지품 가득 참과 금액 부족은 구매 전 비변경 실패지만, 아이템 조건 실패는 경고 뒤 구매를 허용한다. 둘째 품목 `11`은 현재 병종 `01`이 허용 목록 `0B/0C/0E/0F`에 없어 상태 `04→05→06→07`, 대사 `04`의 경고를 열었다. `B`는 상태 `07→08→09→0A→0B→0C`, 대사 `36`의 별도 계속 구매 화면으로 갔고, “예”는 비변경으로 목록을 다시 만들었다. 경고에서 “예”를 고르면 `400G`를 차감하고 품목·내구도 `11/21`을 실제 삽입한다. 이 표본은 마지막 빈칸을 채워 일반 결과 질문 대신 구매·자동 이탈 화면으로 갔다. 세 새 화면은 각각 152프레임 등간격과 168프레임 불규칙 표본에서 화면·CHR이 안정됐다. 무기점 화면군의 하류는 닫혔다.

소지품 흐름은 목록·조건부 행동 메뉴·양도 대상 선택·장비/사용/양도/폐기 결과의 일곱 역할로 나눴다. 목록과 행동 메뉴의 비변경 전이에 이어 장비는 둘째 슬롯을 첫 슬롯과 `02/2A,0F/16 → 0F/16,02/2A`로 교환하고 대사 `19`를 열었다. 양도 대상 선택은 텍스트 없는 `1A/1A + 15/15` 지도 오버레이이며 한 점멸 위상에서 후보 표시가 빠졌다. `B`는 원본 레코드를 보존하고 목록으로 돌아갔고, `A` 확정은 대상 빈칸에 `02/2A`를 옮긴 뒤 대사 `1B`를 열었다. 폐기는 첫 쌍을 지우고 `0F/16`을 앞으로 압축한 뒤 대사 `1C`를 열었다. 사용 아이템 `40`은 대사 `1A`를 자동으로 그린 뒤 진행 상태 2에서 회복을 적용하고 상태 3에서 입력을 기다렸다. HP `17/18`에서는 HP `+1`, 내구도 `5→4`; 최대 HP에서는 결과 코드 `30`과 함께 무변경; 내구도 1의 성공에서는 내구도와 아이템 슬롯을 차례로 0으로 만들었다. 세 변형 모두 `1A/1A + 00/15`를 썼고, 완료 뒤 `A`는 유닛 행동까지 끝냈다. 원본 `NO ITEM`과 내구도 숫자는 보존한다.

장 전환은 12장 도입까지의 기본 여섯 수명과 저장 완료 “아니오”의 종료 안내·사운드 테스트 두 수명으로 나눴다. `E5` 장 문맥과 제목 포인터는 각각 25개다. 2장·11장·12장 도입의 왼쪽 CHR은 `13/13`, `1A/1A`, `0F/0F`로 달랐고 오른쪽은 모두 `00/18`이었다. 저장 제안의 “아니오”는 활성 선택 `$7FF4:01→02`, 결과 `$05EB=02`, 하위 상태 `07→08→09→00`, `$24←01`, `1B/1B+18/18`의 별도 검은 전환으로 갔다. 저장 완료 질문의 “아니오”는 깊이 3의 `$7FF5:01→02`와 결과 `$05EB=02`에 결속했고, 바깥 `$24=0E`·주 상태 `$84=04`를 유지한 채 대사 하위 상태 `07→08→09→0A`의 일본어 종료 안내로 정착했다. 안내는 130~900프레임 표본에서 픽셀 단위로 같았다. 소스의 `08 04 02 01 08 80` 비교를 `위·아래·왼쪽·오른쪽·위·A`로 먼저 결속한 뒤 실행해, 원본 영어와 숫자만 있는 상태 `0C` 사운드 테스트도 확인했다.

사운드 테스트의 여섯 조작은 정적 결속과 실행 확인을 모두 닫았다. 위는 번호 `$775C:00→01`, 아래는 `00→50`으로 바뀌었고 화면에는 각각 `1`과 16진수 `50`의 십진 표시 `80`이 나타났다. `A`는 번호 1에서 `$06F0=02`, `B`는 `$06F0=01`을 썼다. 이 이벤트는 음원 소비자가 같은 프레임 안에서 지우므로 일반 프레임 표본이 아니라 쓰기 경계로 확인한다. `START`는 상태 `0D`의 반복 전투로 들어가 바깥 단계 `$7730=05` 안에서 유닛 정보·예측·공격·피해·필살·격파·EXP 화면을 자동 반복했다. 따라서 6단계를 별도 화면으로 늘리지 않고 기존 `battle_animation`의 가시 수명으로 결속한다. `SELECT`는 추가 입력 없이 상태 `$7731:01→08→10→1D`를 거쳐 원본 영어 도입·캐스트, 일본어 장 기록, 원본 영어 스태프, 일본어 인물 후일담, 정적인 원본 서명·저작권 종단 화면까지 진행했다. 단계 `1D`는 no-op 처리기 `$C73D`, `$7732=00`이며 12,000프레임 동안 스크린샷·네임테이블·OAM·팔레트가 같았다. 같은 상태 `01` 안에서도 번역 경계가 다른 영어 도입·캐스트와 일본어 장 기록은 별도 역할이다. 화면 레지스트리는 실행 관측 화면 45개이고 미분할 화면군은 없다.

인물 후일담은 자연 부대 7개, 전원 직접 분기 53개, 전원 라우팅의 보이는 분기 52개를 각각 7·19·43·82·171프레임에 표본화했다. 112개 보이는 엔트리의 560개 표본은 모두 화면·상태·RAM·네임테이블·OAM·팔레트를 갖추며, 왼쪽 CHR 13쌍과 오른쪽 `00/00`, 고유 화면 258개를 모았다. 라우팅 `41:01`은 상태 `10`으로 간 뒤 배경·스프라이트가 꺼진 채 600프레임 더 머물러 보이는 엔트리에서 제외했다. 직접 경로의 선택자 쓰기 이벤트는 후보 `01..35`와 확장 `36..39`, `3B..3D`, `3F..41`을 잡았고, 소스상 가능한 `3A/3E`는 이 실행에서 관측되지 않았다. 렌더링·제어 흐름 합집합은 닫혔지만, 합성한 `FF` 부대가 모든 자연 진행 원인을 사망으로 증명하지는 않는다.

11장 지도에서 행 8, 열 5·6의 성은 처음에 활성 적 슬롯 0과 6이 점유했다. 적 레코드는 ID·HP만이 아니라 오프셋 18의 행동 바이트가 `FF`인지까지 봐야 한다. 실제 이동·턴 종료·전투 중 슬롯 6이 행 5, 열 6으로 이동해 오른쪽 성이 열렸고, 마르스는 좌표 쓰기 없이 그 칸에 도달했다. 성 명령 메뉴는 `こうげき / しろ / もちもの / たいき` 네 줄이며 불규칙 표본에서 라벨은 유지되고 커서만 점멸했다. `しろ`의 `A`가 `$84:0F→10` 뒤 승리 상태 `3C`, 단계 `02`로 들어갔고, 종료 대사는 초상화 표시·표시·비표시·표시의 네 페이지였다. `NEXT STORY`는 1,200프레임 무입력 유지됐다. ## 현재 관문

동적 글꼴 공급 구조 G3는 통과했다. 원본 CHR 8,192타일 가운데 7,849타일이 비어 있지 않고 첫 글꼴 페이지의 빈 타일도 `95`, `FF`뿐이므로, 원본 MMC4의 고정 CHR-ROM에 완성형 한글을 상주시킨 안은 계속 제외한다. 현재 상위 관문은 남은 렌더 경로 G1과 전체 일본어 텍스트 모집단·무수정 왕복 G4를 닫는 것이다.

[작업 로드맵](roadmap.md)의 G1 가운데 정적 CHR 목록, 확인된 설정·상태 표의 초기 보호 판정, MMC4 공급 루틴 목록과 1장 초반의 주요 문자 화면 실측을 구현했다. 관측한 모든 문자 화면은 `$5B=00`을 사용하고 화면별 그래픽을 `$5C`에 짝지었다. 문자창이 없는 맵에서는 페이지 00이 빠지고 그래픽 페이지 `15`, `18`, `19`가 교체되므로 동적 글꼴 수명은 화면 전환과 결속해야 한다. 상세 근거는 [렌더 경로 조사](render-paths.md)에 있다.

첫 텍스트 모집단 7개 표는 소비자와 저장 경계를 확인했고, 적 이름·장 제목의 합성 파서에서는 `0F`·`1F`가 출력 폭을 늘리지 않는 결합부호이며 `FF`가 빈 오버레이임을 확인했다. 전투 대사의 원본 `!` 코드 `9D`까지 포함한 보호 43코드와 이 세 코드를 제외하면 현재 한글 활성 슬롯 상한은 210개다. 그러나 대사·메뉴·전투 메시지를 포함한 전체 모집단은 아니며, 이는 화면별 최종 예산이 아니다. 미분류 1,755바이트는 비공백 타일 대응 1,703바이트와 전부 0인 `FF` 타일 대응 52바이트로 나뉘지만, 다른 다운스트림 표시 의미가 확인되기 전에는 번역 대상으로 계수하지 않는다. 전투·상점·저장·장 전환·엔딩 렌더 경로와 다른 문자열·그래픽 참조자가 남았으므로 나머지 210개 미확정 글꼴 코드를 회수 후보로 승격하지 않는다.

실제 대사 본문은 `$8F39`이 아니라 뱅크 `0A`의 별도 경로임을 확인했다. ROM 스크립트는 `$E69C`를 통해 32바이트 간격인 SRAM 줄 버퍼로 옮겨지고, `$83BA` 계열이 같은 폭의 오버레이·기본 문자 두 평면을 만들어 공통 PPU 큐로 보낸다. 15개 제어의 현재 포인터 진행과 구조 효과도 닫았다. `E4/E6`는 현재 포인터를 한 바이트만 진행하지만 저장 형식상 뒤의 전환 대상 두 바이트까지 포함한 3바이트 토큰이므로, 추출·재삽입기는 세 바이트를 함께 보존해야 한다.

대사 구조 스캐너는 9개 진입 표의 588개 포인터와 534개 고유 진입점을 원문 없이 열거한다. 이 가운데 8개 표는 `$BFE0` 주 디렉터리 루트까지 연결했고, 전투 표는 뱅크 `04:$8000`의 별도 포인터 로더와 `$802D → $845B` 루트를 연결했다. 에필로그 라우팅 표는 `04:$A17E`의 선택자 코드와 `04:$BFE2 → $B96C` 루트를 함께 고정한다. 전투 형식을 주 대사 문법과 섞지 않으며, 전투 레코드 범위는 아직 닫지 않았으므로 전체 대사 추출 완료나 번역 준비 완료는 선언하지 않는다.

주 대사의 `$77F7` 18상태 디스패처와 첫 줄 앞 레코드 프리픽스도 연결했다. 영입 표의 `$AA2B`와 에필로그 라우팅 표의 `$C73D` 실행 처리자를 대사와 분리한 뒤, 504개 고유 대사 진입점에서 `E5` 선택 6바이트, 고정 4바이트, `E8` 선택 6바이트를 원본 명령대로 분리해 첫 줄 위치를 얻었다. 두 선택 프리픽스가 모두 있는 진입점은 15개, 둘 다 없는 진입점은 227개다. 아직 의미가 닫히지 않은 상태 처리자 10개와 호출자별 결과는 계속 미확정이다.

첫 줄에서 시작해 `ED/EE/EB` 뒤를 잇는 초기 선형 구간도 공통 15개 제어 계약으로 전수 검사했다. 504개 구간은 총 2,732줄, 최대 57줄이며 첫 비선형 경계는 `EF` 206, `E7` 85, `E4` 92, `E6` 121개다. `E4/E6` 전환 213개는 모두 선언 표 범위 안이다. 원문은 기록하지 않고 줄·구간별 저장 SHA-1·길이·제어 개수만 남겼으며 숫자·대문자 리터럴 37바이트는 번역 비대상으로 분리했다. 이 선형 검사만으로는 비선형 경계 뒤의 전체 엔트리 완료를 뜻하지 않는다.

각 주 대사 포인터에서 레코드 프리픽스와 이 초기 선형 구간을 합친 소비 범위도 닫았다. 504개 레코드의 소비량 합계는 39,642바이트지만 실제 고유 저장은 39,425바이트다. 마을·아웃트로, 영입, 상점·아이템, 에필로그 표에서 6쌍이 217바이트를 공유하며 최대 중첩 깊이는 2다. 이는 단순한 포인터 별칭과 별개이므로, 재삽입기는 엔트리 504개를 독립 덮어쓰기 단위로 쓰지 않고 공유 저장을 정규화해야 한다.

원문 왕복기는 이 504개 레코드를 PRG 뱅크 경계를 지키는 11개 비중복 소유 구간으로 합친다. 무시된 로컬 자산을 다시 읽어 각 구간의 길이·SHA-1·레코드 참조를 원본에서 재계산한 값과 대조하고, 중복 없는 추적 쓰기로 재구성한 ROM이 지원 원본과 바이트 단위로 같은지 확인했다. 이는 공유 저장 처리와 직렬화의 원문 왕복 관문이며, 아직 번역 입력이나 길이 변경을 허용하는 재삽입기는 아니다.

일본판 글꼴의 `00`~`5F` 가나·결합부호·문장부호, `84`~`8B` 작은 가나, `A6`~`AA` 작은 가타카나 모음과 `8E = 。`, `AB/AC = 「/」`를 일본어 원천으로 고정했다. 숫자·대문자 `60`~`83`, `9D = !`와 나머지 보존 기호는 비일본어로 남는다. 직접 진입 구조 뷰에서 중복을 제거한 일본어 리터럴은 28,048바이트이며 구조 충돌을 제외한 안전 원천은 28,032바이트다. 실제 전이 소비 뷰는 같은 보호 판정을 다시 계산해 안전한 일본어 원천 28,165바이트를 얻으며, 작업공간은 이 번역 뷰 수치와 교차검증한다.

직접 진입 구조 진단은 2,732줄이지만, `E4/E6` 전이 대상 139개에는 직접 진입용 4바이트 헤더가 다시 적용되지 않는다. 이 대상들을 선택적 `E8` 뒤에서 다시 읽어 저장 끝·그래프 경계·목적지가 그대로인지 전수 확인한 번역 뷰는 2,812줄이다. 비공개 작업 골격은 이 번역 뷰를 안정 ID, 번역 상태, 일본어 문자와 보존 토큰으로 분리한다. 숫자·대문자는 읽을 수 있는 원문 그대로 유지하고, 미확정 기호·공백·제어·피연산자는 토큰으로 잠근다. 검증기는 작업 파일의 원본 결속 필드를 지원 ROM에서 다시 계산하고, 기존 영문이나 토큰의 추가·삭제·변경 및 번역 필드의 일본어 잔존을 거부한다. 현재 첫 레코드 3줄만 검토 대기이며 재배치 필요 줄은 3개다.

가변 길이 배치기는 이 작업 골격을 원본의 11개 소유 구간과 포인터 쓰기 517곳에 결속한다. 무수정 입력은 공유 217바이트를 그대로 한 번만 소유해 39,425바이트 원본 배치를 재현한다. 번역으로 공유 내용이 달라지면 해당 레코드를 분리하고 뒤 레코드의 포인터를 다시 계산하며, 증명되지 않은 뱅크 여유나 다른 데이터를 침범하지 않는다. 현재 결과는 논리 글리프 길이와 포인터 계획일 뿐 한글 코드나 ROM을 생성하지 않는다.

이전 MMC5 후보에는 PRG/SRAM 정적 프로브를 추가했다. 리셋 벡터는 확인된 `FF` 구간의 초기화 루틴으로 보내고, PRG 모드 1·마지막 ROM 뱅크·PRG RAM 쓰기 허용을 설정한 뒤 원본 리셋으로 돌아간다. 중앙 뱅크·미러링 루틴과 부팅, `$E69C` 대사 바이트 읽기, `$E6B2` 인덱스 포인터 표 경로의 직접 PRG 뱅크 쓰기 여섯 곳도 원본 길이를 유지한 호출로 교체한다. 새 실행 코드는 typed RP2A03 명령으로만 조립하며 모든 ROM 변경은 예상 원본 바이트와 최종 변경 감사에 결속했다.

콜드 런치의 첫 PC와 다섯 MMC5 초기화 쓰기, 원본 리셋 진입, 부팅의 임시·복귀 PRG 뱅크 전환은 히트 시점 이벤트로 확인했다. 뱅크 계산 중 A와 상태 플래그도 원본 관찰값으로 복원됐다. 다만 실제 저장·불러오기는 아직 확인하지 않았고, MMC4 CHR 래치를 변환하지 않은 120프레임 실행은 CPU만 진행한 채 화면이 깨졌다. 따라서 G2 전체가 아니라 PRG 부팅 하위 관문만 통과한 상태다.

첫 CHR writer 프로브는 검증된 PRG 프로브를 그대로 재생성한 뒤 CHR 모드 1과 네 중앙 공급 루틴을 추가한다. 원본 그림자·A 반환값·루틴 길이를 유지하고 PPU `$0000/$1000` 창을 `$5123/$5127`에 연결하지만, 각 창의 FD/FE 쌍을 마지막 쓰기 하나로 축약한다. 중앙 루틴만 옮긴 빌드의 프레임 1928 실패를 같은 프레임 메모리와 매퍼 상태로 대조한 결과, 화면 데이터나 래치 공존이 아니라 뱅크 `0D`의 직접 쓰기 네 곳이 누락된 것이 원인이었다.

실행 PC와 명령 경계를 확인한 `0D:$8036/$8039`, `0D:$83AB/$83AE`를 원본 3바이트 길이 그대로 추가 변환했다. 보완 프로브는 무입력 프레임 1206 타이틀 해시 `7653368704bf030f7dcbcbfb64cf0d3c3a4bd039b8cba11ef88d3d1d0e674c59`와 프레임 1928 자동 병종 설명 해시 `e2893dd71c6f93d1a29e2bc40256e0563e75332c3d2f6eca98277435c06215a1`를 각각 원본과 정확히 재현했다. 이는 두 화면의 하위 관문만 통과한 것이며, 남은 직접 쓰기 후보와 실제 FD/FE 래치 공존 화면이 있으므로 G2 전체 통과 근거로 사용하지 않는다.

확장 CHR 프로브는 원본 CHR 전체를 상위 절반에 복제하고 검증된 store를 A·상태 플래그 보존 래퍼로 보내 페이지 번호에 `20`을 더한다. 상위 첫 페이지의 설정용 일본어 12타일만 한글 PoC로 바꾸므로 하위 원본 CHR과 기존 영어 타일은 수정하지 않는다. 프레임 1206은 원본 화면 해시를 유지했고 프레임 1928은 상위 한글 타일이 실제로 표시된 해시 `08ee146844737028ab17b18a4135ca6c44359407890bba6fe14d4f27334a835b`를 냈다.

같은 새 게임 입력에서 처음 확인한 분기는 `$E6B2` 인덱스 포인터 표 경로였다. `$E6BA/$E6F1`을 옮겨 carry 분기를 복구한 뒤에는 `$E69C`의 `$E6A1/$E6AB`가 선택 대사 뱅크 대신 현재 뱅크의 바이트를 읽는 다음 원인으로 드러났다. 이 두 쓰기도 옮기자 `$80AA` 비교 직전 A는 원본과 같은 `E5`였다. 프레임 3965에서 네임테이블·팔레트·OAM·PRG RAM, 프레임/사이클과 선택 PRG 뱅크도 원본과 같아졌다. 남은 직접 `$A000` 후보 다섯 곳은 이 표본에서 적중하지 않았다. 다만 내부 RAM 15바이트와 CPU PC 한 바이트, CHR 표시가 달라 전체 진행·화면 동등성은 아직 통과하지 못했다.

이 화면의 원본 MMC4 오른쪽 FD/FE 뱅크는 `00/18`로 달랐고, 네임테이블 1에는 FD 18개·FE 81개의 실제 래치 트리거가 있었다. 새 투영기는 각 트리거 타일에 이전 래치를 적용한 뒤 다음 타일부터 전환하고 원본 팔레트를 보존한다. 생성한 1 KiB를 MMC5 ExRAM에 제어 주입한 화면은 원본 본문 61,416픽셀과 일치했다.

다음 프로브는 정적 1 KiB를 ROM에 넣고 오른쪽 FD·FE 공급 루틴 양쪽에서 쌍 `00/18` 완성을 검사한다. 실제 실행에서 두 번째 공급 뒤 `$FAC0` 복사 루틴이 한 번 적중했고, 외부 메모리 쓰기 없이 같은 화면 결과를 재현했다. 복사는 A·X·상태 플래그를 보존한다. 이로써 목표 화면의 mode 2 쓰기와 mode 1 표시 소유는 ROM 안으로 들어왔지만, 제로 스크롤 단일 화면에 고정된 데이터다. 후속 네임테이블 갱신, 미세 스크롤·두 타일 선행 fetch·네임테이블 경계 정책은 아직 구현하지 않았다.

원본의 직접 `STA $2006/$2007` 후보는 각각 20곳과 7곳으로 전수 결속했다. 이들을 모두 바이트별 래퍼로 보내 PPU 쓰기 뒤 PRG RAM 뱅크 1의 2 KiB 그림자까지 갱신하는 프로브는 훅 적중 자체는 확인했지만 프레임 301에 실제 CIRAM과 128바이트가 갈리고 화면이 깨졌다. 원인은 각 바이트마다 추가한 레지스터 보존·뱅크 전환·주소 계산이 VBlank 전송 시간을 늘린 것이다. 따라서 이 방식은 런타임 소유자 후보에서 제외하고, `$C3E7` PPU 큐와 나머지 직접 전송 루틴의 시작·종료 경계에서 한 번에 반영하는 구조로 바꾼다.

`E4/E6` 213개는 대상 엔트리의 실제 포인터와 결속했다. 별칭을 같은 저장 노드로 합친 504개 그래프에는 코드 처리자 대상, 누락 간선, 순환이 없다. 명시 전이를 따라가면 최대 15단계 안에 336개 노드는 `EF`, 168개 노드는 `E7`에 도달한다. 새로 포함한 에필로그 라우팅 스크립트 52개는 일본어 본문이 아니라 모두 선택자 `40` 엔트리 0으로 합류하는 구조 엔트리다. `E7`은 공통 선택지 코드가 아니라 `$7809`를 통해 외부 호출자에 제어를 넘기는 경계다. 상태 17은 호출자가 고른 현재 엔트리를 `$E6B2`로 다시 결속하고 상태 9로 복귀한다. PRG의 `$7809` 읽기 5곳은 모두 고정했지만 각 호출자의 결과 의미는 아직 분리하지 않았다.

다섯 `$7809` 읽기 위치를 외부 상태표와 대조하면 네 처리자가 11개 디스패처의 22개 상태 슬롯에서 재사용된다. 특히 뱅크 `06:$A13E` 하나가 여섯 표의 15개 슬롯을 맡으므로 읽기 위치 수를 시나리오 수로 볼 수 없다. 뱅크 `04:$A20F`는 직접 상태표 결속을 아직 찾지 못했고 간접 호출 가능성도 닫지 않았다.

## 다음 작업

1. 원본 영어·로마자·숫자를 보호하면서 주 대사 번역·검토를 진행하고, 상태별 글리프 분석기로 승인된 실제 한글 작업 집합을 계속 갱신한다. 번역 뷰 2,812줄이 모두 완료되기 전에는 빈 집합이나 중간 집합의 210칸 수용을 최종 판정으로 쓰지 않는다. `FF` 부대의 자연 진행 원인을 세분하는 일과 다른 장의 종료 대사·초상화·CHR·제목 바 실행 변형은 의미·회귀 관문으로 따로 유지한다.
2. G3에서 확정한 화면 수명별 페이지 계약을 입력으로 삼아 G4의 남은 전투·비주대사 모집단과 소비자를 열거하고 무수정 왕복을 닫는다.
3. 진행 메뉴 `スイッチ` 하위 메뉴와 실제 설정 화면 진입 소유자를 입력·자동 전이와 함께 분리한다.
4. `unit_summary`·`unit_command_menu`·`unit_status`의 검토된 비대사 번역문에서 실제 한글 합집합을 계산하고, 210칸 단일 공용 페이지·내용 조합별 페이지·실행 중 공급을 비교한다. 소지품이 변하는 요약·상세를 유닛별 고정 페이지로 가정하지 않는다. 자동 `class_profile`의 일본어 설명·원본 능력치 약어·직접 CHR writer·자동 이탈 수명은 별도 계약으로 닫는다.
5. 아이템 사용의 나머지 계열과 양도 대상 소지품 가득 참, 장비·양도·폐기 결과의 대사 이탈/CHR 미관측 변형을 로컬 후속 관문으로 유지한다. 확인한 11개 외부 디스패처와 `E7` 결과도 계속 분류한다.

매퍼별 근거와 남은 한계는 [매퍼 후보 판정](mapper-candidates.md)에 둔다.

G3는 통과했지만 G4의 전체 모집단과 무수정 왕복이 닫히기 전에는 번역 범위를 전체 게임으로 확대하지 않는다.
