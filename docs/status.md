# 현재 상태

기준일: 2026-08-11

## 현재 결론

매퍼 변환의 우선 후보를 MMC5에서 mapper 165로 바꿨다. mapper 165는 원본과 같은 배터리 SRAM을 제공하면서 MMC2식 FD/FE CHR 래치를 유지한다. 무번역 프로브는 원본 128 KiB CHR 앞에 8 KiB 예약 영역을 두고 원본 페이지를 그대로 재배치하며, PRG writer 12곳과 확인된 CHR writer 35곳을 변환한다.

실행 관측 화면 29개의 고유 FD/FE 쌍 18개를 비교해 오른쪽 `00/14`용 변형 CHR 페이지 1개를 만들고, 중앙 오른쪽 공급자가 FD/FE 그림자 쌍으로 이를 선택하게 했다. 설정의 `00/15`와 부대 목록·맵 유닛 UI·무기점·소지품 화면의 `00/15`, `00/18`, `00/19`, 양도 대상의 `15/15`는 원본 트리거 평면과 같아 자연 페이지를 쓴다. Mesen 콜드 실행의 프레임 800·1206·1928, 실제 입력 뒤 1장 인트로 대화와 2장 인트로 화면은 모두 기존 원본 PNG와 SHA-256이 정확히 같다. 전투의 직접 왼쪽 `02/06`, `06/06`과 오른쪽 `02/06`도 자연 페이지로 호환됐다.

G2는 통과했다. 직접 CHR writer 31곳을 정적 계약과 실제 전투 실행 쌍으로 모두 닫았고, 자연 중단·배터리 파일·전원 재인가·재개·일회성 소비와 턴 경계 게임 오버도 원본과 동등했다. 이어 실제 이동·턴 종료·전투로 보스를 쓰러뜨리고 성 명령을 선택해 1장을 완료한 뒤 정규 저장, native power cycle, `ロードする`와 2장 전환까지 비교했다. 같은 점멸 위상의 화면과 로드 뒤 네임테이블·OAM·팔레트가 일치해 mapper 165를 채택한다. 진행 가속으로 달라진 적 AI와 이동 경로 때문에 전체 SRAM·내부 RAM은 이 표본의 동등성 기준에서 제외했으며, 아직 게임 전체의 전수 회귀를 뜻하지 않는다. MMC5 프로브는 비교 근거와 기각된 설계의 재현 자료로 유지한다.

G3의 공급 방식은 확장 CHR-ROM 페이지 선택으로 확정했다. 보호 43코드와 레이아웃 3코드를 원본 그대로 복사하고 나머지 210코드만 한글에 배정한다. 설정 페이지 A/B는 공유 12자와 페이지별 100자로 각각 112자, 합집합 212자이며 물리 페이지 `34/35`, mapper 값 `88/8C`를 쓴다. 설정 화면 콜드 실행에서 `88 → 8C → 88`과 이탈 뒤 자연 페이지 복구를 확인했다.

부대 목록에는 물리 페이지 `36/37`, mapper 값 `90/94`의 화면 전용 A/B를 추가했다. 최초 공급 관문에서는 `이/름`과 인공 작업 집합으로 한 페이지 예산 초과를 증명했고, 현재 누적 빌드는 두 페이지를 실제 아군명 52개·고유 한글 72자의 생산 페이지로 교체했다. 진행 메뉴와 외부 상태·CHR 쌍 일부가 겹친다는 반례 뒤, 부대 목록 생성자 `0B:$89DB`의 고유 창 기술자와 위치 상태에 수명을 결속했다. 현재 빌드에서 `이름`, `마르스`부터 이어지는 실제 이름, 원본 `LV/HP`·숫자와 인물 그래픽을 함께 확인했다.

주 대사 번역 뷰 2,812줄 가운데 의미 있는 일본어 2,541줄을 `needs_human_review` 한국어로 채우고 장면별 직접 2차 교정을 마쳤으며 승인 완료는 아직 0줄이다. 남은 일본어 판정 1줄은 완결 문장이 아닌 미사용 특수 레코드 잔편 후보라 임의 번역하지 않았다. 원본 영어·숫자·제어 토큰 보존 검증과 원본 무수정 왕복을 통과했다. 채워진 고유 한글은 697자이고 한 줄 고유 한글은 최대 14자다. 명시적인 `E4`/`E6` 대사 전이 사슬은 최대 175자로 활성 슬롯 210칸 안에 들어가며, 관측 화면 수명 최대치는 204슬롯이다. 배치 계획은 11구간·504레코드·517포인터를 유지하면서 29,948바이트를 쓰고 9,477바이트를 남긴다. 다음 관문은 검토 승인과 화면별 줄 폭·재삽입 실행 검증이다.

현재 기본 개발 산출물은 개별 프로브가 아니라 `build-kr-patch`가 불변 일본판에서 매번 재생성하는 8단계 누적 ROM이다. 앞 일곱 단계에 이어 여덟째 단계가 무기점 품목명 6개와 `예/아니오`를 기존 무기점 대사 페이지에 합치고, 목록·선택 품목·선택지 소비자만 전용 포인터 투영으로 연결한다. 최종 ROM SHA-1은 `4758d15b9beb9b075be6976508b90e17ef1ea54d`, 빌드 보고서 SHA-1은 `5f1475604ad62e598b371fc0f49c8f38f697ea44`이며 CHR 25뱅크·추적 쓰기 182개다.

콜드 무저장·정규 저장 경로의 시작·기록 메뉴와 2장 첫 대사는 앞 누적 계보에서 확인했다. 현재 최종 빌드는 알려진 맵 기준 상태로 진입해 부대 목록의 한글 이름 7개와 맵 유닛 요약·점멸 상태 화면의 `마르스`를 확인했고, 원본 `LV/HP/S`·숫자와 아직 미설치인 일본어 병종·아이템·능력치 라벨을 보존했다. 명단 화면은 +7/+19/+43프레임에서 같은 해시 `fa81697c…`를 유지했고, 상태 화면은 전환 직후 사라졌던 요약창이 +7프레임에 나타나는 위상도 확인했다. 이 표본은 현재 ROM에 결속됐지만 저장 상태를 이용한 가속 관측이므로 새 선택자 체인의 전체 콜드 회귀를 대신하지 않는다. 전투·엔딩 이름은 원본 표를 유지한다.

자동 병종 소개는 뱅크 `0D`의 인덱스 `$0559`, 제목 포인터 표 `$8C98`, 설명 포인터 표 `$8DCC`에 결속했다. 일본어 제목 22개와 설명 75줄의 한글 합집합 216자는 단일 페이지 상한 210자를 넘으므로 인덱스 `0..10`의 143자와 `11..21`의 161자로 나눴다. 무입력 콜드 실행에서 프로필 `0`, `8`, 페이지 경계 `11`, 마지막 `20`, `21`, 자동 검은 전환과 뒤의 원본 영어 도입까지 7개 불규칙 시점을 같은 ROM SHA-1에 결속했다. 경계 프로필에서 배경의 두 mapper 래치가 모두 `BC`였고, 원본 `STR/SKI/WLV/AGI/DEF/MOV/H.P/EXP`·숫자·UI와 화면 이탈 뒤 영어가 유지됐다. 이 화면군의 실행 결속은 완료했지만 22개 번역은 모두 `needs_human_review`이므로 사람 승인 완료는 아니다.

무기점은 첫 구매 확인을 거절한 비구매 경로에서 품목명 6개, 선택 품목, `예/아니오`, 한글 대사가 같은 창에 누적되는 것을 확인했다. 선택 확인·계속 질문·품목 목록 복귀·종료 문구·지도 복귀의 17개 불규칙 표본을 최종 ROM SHA-1에 결속했고, 원본 품목 표를 우회한 선택자 실행과 금액·소지품 무변경도 함께 검사한다. 원본 숫자와 `G`, 초상화와 지도는 유지됐다. 현재 실행 결속은 거절·목록 복귀·이탈 경로를 닫으며 실제 구매·금액 부족·소지품 가득 참·아이템 조건 경고 분기의 새 출력은 아직 확인하지 않았다.

별도 형식의 전투 대사도 비공개 번역 작업공간으로 추출했다. 포인터 65개가 가리키는 고유 레코드 28개를 겹침 없는 1,152바이트 소유 범위에 결속했고, 4바이트 헤더 뒤 본문을 `ED/EE/EF` 단위 100줄·일본어 620바이트로 분리했다. `EC` 동적 문자열 선택자와 기존 영문·숫자·제어 코드는 보호 토큰으로 유지한다. 일본어가 있는 70줄은 모두 `needs_human_review` 한국어 초벌과 직접 2차 의미 검토를 마쳤고, 나머지 30줄은 제어만 있는 구조 줄이라 번역하지 않았다. 현재 작업공간 SHA-1은 `3cdec3a1efaab82ac49e713afabc37f5c7d4ff7d`다. 번역 레코드 논리 인코딩 1,025바이트와 미참조 원본 레코드 보존 16바이트를 합친 실제 계획은 1,041/1,168바이트로 127바이트가 남는다. 미참조 레코드의 원래 16바이트 위치를 경계로 소유 영역을 둘로 나누고 레코드를 자르지 않은 채 순서대로 배치했으며, 28개 새 주소와 별칭을 포함한 65개 포인터 쓰기를 모두 계산했다.

전체 전투 초벌을 한 번에 넣는 mapper 165 개발 ROM도 만들었다. 28레코드·70번역 줄·65포인터를 적용한 기존 프로브에서 실제 전투 소비자와 원본 `LV`·`HIT`·`EXP`·숫자 보존을 확인했다. 병종·아이템·아군명·적군명 기존 233개는 직접 2차 교정을 마쳤고, 원본 표 경계를 바로잡아 찾은 69번째 적군명에도 초벌을 추가해 234개 모두 번역 상태다. 기존 프로브는 원본 글꼴 페이지를 전역 교체해 고정 문자열이 깨지는 비배포 증거이므로, 다음 관문은 대사·동적 삽입·고정 문자열을 같은 전투 조합 코드북으로 인코딩하고 전투 수명에만 공급하는 것이다.

무기점의 품목 목록에서 첫 품목을 고른 `E7` 표본은 외부 상태 `04→05→07`, `$7809=01` 읽기 PC `06:$A144`로 결속했다. 인계 순간에는 6개 품목·가격 목록과 구매 질문이 함께 남아 있고 `はい/いいえ` 창은 아직 완성되지 않았다. 품목 목록에서 인계까지 네임테이블은 16바이트, 인계에서 안정 확인 화면까지 40바이트가 더 바뀌었다. 따라서 `$7809` 관측이나 상태 17에서 대사 전용 글꼴 페이지로 즉시 바꾸면 안 된다. 이 수명에서 보존해야 할 품목명·선택지 원본 코드는 17개이고, 동시에 보이는 대사 레코드 2개의 초벌 한글 합집합은 9자여서 총 26/210슬롯으로 한 페이지에 들어간다. 이는 관측한 상점 구매 인계만 닫으며 다른 `E7` 호출자를 대신하지 않는다.

자동 인물 후일담 화면군은 112개 보이는 엔트리의 560개 실행 표본을 한데 합친 보수적 예산으로 닫았다. 관측 네임테이블의 활성 원본 코드 99개를 모두 보존하고, 아직 실제 번역을 확정하지 않은 인물명 최대 7칸과 지명 최대 11칸을 별도 예약하며, 초벌 대사의 최대 전이 사슬 한글 33자를 더해도 150/210슬롯이다. 따라서 이 화면군은 페이지 분할 없이 수용 가능하지만, 이름·지명의 실제 한국어 문자열과 줄 폭은 아직 확정하지 않았다.

턴 경계 게임 오버는 불리한 일회성 개입으로 얻은 12개 불규칙 표본의 활성 원본 코드 90개를 모두 보존한다. 어느 엔트리가 패배 문구인지 추정하지 않고 `victory-and-defeat-dialogue` 11레코드 초벌 한글 합집합 112자를 전부 같은 페이지에 넣어도 202/210슬롯으로 수용된다. 이 결과는 관측한 게임 오버 수명만 닫으며 장 승리 대사의 화면 수명은 별도다.

첫 주 대사 프로브의 전역 글꼴 교체를 폐기하고 1장 도입부 수명 전용 확장 페이지로 바꿨다. 원본 CHR은 한 바이트도 바꾸지 않고 물리 페이지 `34`, mapper 값 `88`에 원본 페이지 복제본과 한글 19자를 둔다. 동시 화면에서 관측한 활성 코드 76개와 첫 레코드 뒤 `E6` 전이 사슬 3레코드의 원문·보호 코드 58개를 합쳐 109개를 잠근 뒤 남은 슬롯에만 한글을 배정한다. 중앙 오른쪽 FD 공급 시점의 정확한 `$24/$84/$59/$5A/$5B/$5C/$77F7/$781D=0B/00/1A/1A/00/18/03/00`에서만 확장 페이지를 선택하고 그 밖에는 기존 쌍 인식 선택기로 돌아간다. 콜드 실행에서 일본어 새 게임 메뉴, 원본 `MAP`·숫자, 일본어 장 제목, 한글 첫 대사, 뒤의 일본어 다섯 화면, 초상화·맵·창을 함께 보존했으며 여섯 번째 완료 페이지 `A` 뒤 자연 맵 페이지로 복구됐다. 완료 표식과 맵 스프라이트는 7·19·43프레임 위상으로 확인했다. 이는 첫 화면 수명의 깨짐 0건이지 1장 전체나 G5 통과가 아니다.

상위 화면 조사를 다시 수행해 맵 유닛 UI를 `unit_summary`, `unit_command_menu`, `unit_status`로 분리했다. 요약은 일본어 이름·병종·아이템과 원본 `S/HP`·숫자를, 상세는 일본어 능력치 9개와 같은 원본 영문·숫자를 함께 표시한다. 합성 상태 `04/05/07/0F`를 요약 상단·명령 목록·아이템 목록·상세 능력치 조립기에 결속했다. 상태 `05`는 유닛 능력·지형·인접 대상·인벤토리·시설에 따라 일본어 명령 15개를 선택한다. 무이동 `もちもの/たいき`, 타일 `46`의 `たずねる`, 1장 좌표 `$03/$1A`의 `ぶきや`까지 4개를 실행 화면으로 확인했다. 전체 고정 라벨 26개 중 일본어 25개만 번역 대상이고 원본 `HP`는 보호한다.

완성 페이지 카탈로그는 폐기했다. 모델 튜플 156,183,838,720개는 실제 도달 수가 아니라 보수적 입력 곱이지만, 기반 자산 뒤 최대 56개인 확장 PRG의 4 KiB 페이지로 조합마다 완성본을 두는 방식이 전체 범위가 될 수 없음을 확인했다. 대신 공통 1개·아군명 52개·적군명 55개·병종 24개·장비 64개·지형 16개·대사 28개, 총 240개 추상 업로드 레시피와 대사 선택자 65개를 생성한다. 레시피 바이너리는 3,896바이트이며 1,079개 글리프 참조를 215개 고유 payload로 묶고, 없는 적군명·비후보 장비 인덱스 41개는 명시적인 결측값으로 둔다. SHA-1은 `e02a32df7409b20e88e322021e1b26bbf4cc75b1`다. 원본 페이지 4,096바이트와 최대 210글리프·3,360바이트를 전투 진입 때 합성하는 상한은 7,456바이트다. 현재 보고서 SHA-1은 `a705c31255d0e86674e95c199e871bda4ded7ccb`다.

mapper 165 캐시 기반은 추가 PRG의 MMC3 페이지 `20`에 전역 코드북 296글리프·4,736바이트 아틀라스를, 페이지 `21`의 앞뒤 절반에 원본 4,096바이트 페이지와 3,896바이트 레시피를 배치한다. 총 두 페이지이며 원래 PRG 접두부·활성 고정 뱅크·CHR은 보존한다. ROM SHA-1은 `e54698f3dc019f0f6cbd187a69d0270eb6f54d31`, 보고서 SHA-1은 `89e91e1ac5c4df1cbddb86dcf115f25935daecc1`이다. 레시피 소비 검증은 공용 사운드 테스트 11개·적 선공 11개·플레이어 선공 10개, 총 32개 불규칙 표본의 실제 전투 필드를 다섯 유효 튜플로 투영했다. `$7936=00`이 후반 `3E`가 되는 15표본도 원본 생산자 조건으로 장래 선택자를 미리 고른다. 모든 표본은 배경 `$1000`, 스프라이트 `$0000`이므로 CHR-RAM 대상 페이지에는 네임테이블 코드만 제약한다. 이를 무시해 같은 번호의 OAM 코드까지 합치면 전체 배정이 실패하고, 실제 PPU 소비자를 따르면 최대 68개 원본 활성 코드와 최대 88글리프를 함께 보존하면서 106색을 제약한 전역 물리 배정이 성립한다. 물리 배정 SHA-1은 `6412cefea09f8285098b061866712d8bdbda778c`, 보고서 SHA-1은 `0fd8a8340459286c45ff8f313b2a754b419859d2`다. 이 표본 카탈로그는 아직 전체 병종·무기·초상화·애니메이션 변형을 덮지 않는다.

전체 전투 텍스트 개발 기반은 이 물리 배정을 실제 바이트에 적용했다. 전투 레시피에 든 고정 원천 231개, 전투 대사 28레코드·65포인터, 예측창 라벨을 재인코딩했고, 공유 고정 작업공간 272개 중 전투 카탈로그 결측 41개는 원문 상태로 유지했다. 추적 쓰기는 325개다. 210바이트 물리 코드표는 아틀라스와 같은 MMC3 페이지 `20`의 `$9400`에 있으며 SHA-1은 `15210af90f1b75d8526460e4facb27276bf20cea`다. ROM SHA-1은 `edf467e181ecec68ac0138448573e53391aa8d2a`, 내용 비공개 보고서 SHA-1은 `4420891fcaf2878cc53d717dca3387349dae495f`다.

이 기반 위의 제한 합성 로더는 관측한 다섯 런타임 튜플만 허용한다. 10개 typed RP2A03 루틴 1,020바이트가 원본 4 KiB 페이지를 복원하고 현재 참가자·병종·장비·지형·대사의 레시피를 적용하며, 관측 상한은 88개 고유 오버레이·PPU 데이터 쓰기 5,728회다. 비전투 화면에서는 전투 활성 표식만으로 CHR-RAM을 선택하지 않고 주 상태가 플레이어 또는 적 선공 전투일 때만 전환한다. 현재 ROM SHA-1은 `a50daff80aec9f9476828f1fd3b985402aeacb0a`, 보고서 SHA-1은 `aee9fd26538465afbd4d1890769dc6c65f367623`다.

지원되는 512 KiB 계보의 지도 상태에서 턴 종료 메뉴 커서를 OAM 위치 변화에 결속해 실제 게임플레이 전투 하나로 진입했다. 합성 반환 시 독립 Rust 재구성기와 CHR-RAM 4,096바이트가 SHA-1 `ee52df57a237bf3b4d0e16b69f708f1b2b85c8c6`로 정확히 같았고 차이는 0바이트·0타일이었다. 불규칙 시간 표본에서 한글 전투 문자열과 원본 `LV`·`HIT`·숫자·창·스프라이트를 함께 확인했으며, 약 3.32프레임의 합성 뒤 전투가 자동 진행돼 지도 페이지로 복귀했다. 그러나 이는 다섯 튜플 중 하나뿐이고 게임 전반의 비전투 화면이나 모든 전투 변형을 증명하지 않는다. 주변 일본어가 깨지는 기존 전역 페이지 프로브도 여전히 개발 증거일 뿐이다. 나머지 네 튜플, 전체 물리 변형 카탈로그, 1장 전 경로의 깨진 그래픽 0건과 사람 검토가 남아 있어 전체 `runtime_verified`와 `release_eligible`은 계속 거짓이다.

동적 캐시 probe는 이 완성 페이지 4 KiB를 확장 PRG에 두고, 렌더가 꺼진 전투 NMI의 `$C191`에서 CHR-RAM으로 전송한다. 번역 원천 선택에서 생성한 상태 `16/32`, 순서 무관 참가자 `[04,85]`, 병종 `[01,08]`, 장착 무기 `[0C,1B]`, 지형 `[00,0B]`를 캐시 수용 범위로 삼고 런타임의 각 값을 포함 판정한다. 원본이 0/비0만 판정하는 전투 활성 바이트 `$047D`의 상위 비트 `80`을 1회성 표식으로 사용한다. 앞선 로컬 코드북 산출물은 플레이어 선공, 지형 `00/0B`인 첫 적 전투와 그 부분집합 `00/00`인 두 번째 적 전투에서 각각 `$047D`의 `01→81→00`, 원천과 CHR-RAM의 4,096/4,096바이트 일치, 한글 공격 문구와 원본 영어·숫자·그래픽을 통과했다. 새 전역 물리 배정 산출물의 ROM SHA-1은 `7191dc8043cd326d27c77794d01eb600b738519f`, 보고서 SHA-1은 `66445c113805047ed8d1373c094bc79363b1ab0d`이며 같은 콜드 회귀는 아직 다시 돌리지 않았다. 전체 캐시 카탈로그와 대사 selector 62 자연 표시가 남아 있어 `runtime_verified=false`다.

## 현재 관문

mapper 165 동등성 G2와 동적 글꼴 공급 G3는 통과했다. 주 대사와 별도 전투 대사, 전투 고정 문자열의 추출·초벌·논리 재배치 기반도 마련했지만, 로드맵상 G1과 G4는 남은 화면 변형과 비주대사 소비자를 닫을 때까지 진행 중이다.

현재 기본 실행 산출물은 검증한 표면을 합친 누적 ROM이지만 게임 전반에서 한글과 그래픽이 온전한 패치는 아니다. 1·2장 도입 화면, 자동 병종 소개, 무기점의 품목·선택지·대사 거절 경로는 수명별 페이지와 자연 이탈을 통과했다. 반면 전체 일본어 소비처의 설치 분모와 소비처별 글꼴 수명은 아직 하나의 기계 판정으로 결속되지 않았고, 제한 전투 합성 로더도 관측한 다섯 튜플 중 한 게임플레이 튜플만 정확한 합성·시간 표시·지도 복귀를 통과했다. 이 부분 증거를 전체 표시 완성도나 G5 통과로 일반화하지 않는다.

다음 통합 관문은 화면 성공 개수를 늘리는 것이 아니라 전체에서 가장 어려운 조건을 먼저 닫는 것이다.

- 모든 도달 가능한 일본어 항목을 소비자와 글꼴 수명에 배정해 전체 분모를 고정한다.
- 각 수명의 실제 번역문으로 최대 동시 한글 집합과 보호 코드를 계산하고, 가장 큰 수명이 공급 구조에 들어가는지 먼저 증명한다.
- 가장 긴 조판·저장 구간과 가장 복잡한 진입·이탈·재진입도 같은 누적 구조에서 통과한다.
- 최종 누적 ROM에서 대상 일본어 0건, 보호 영어·숫자·그래픽 손상 0건을 기계 검사와 실행 회귀로 함께 닫는다.
- 기준선 성공 경로와 치트를 끈 실패·패배 경로를 분리해 검증한다.

주 대사 2,541개 의미 줄은 모두 검토 대기 초벌이지만 승인 완료는 0줄이다. 전투 대사 70개 의미 줄도 검토 대기이며, 전투 고정 문자열 272개 중 22개만 승인 완료다. 따라서 번역 자산의 채움과 실제 표시 적용, 사람 승인을 각각 별도 진척으로 유지한다.

## 다음 작업

1. 모든 도달 가능한 일본어 텍스트·그래픽 항목을 소비자와 글꼴 수명에 배정하고 미분류·중복·누락이 0건인 전역 분모 보고서를 만든다.
2. 전체 번역 입력으로 수명별 동시 글리프·보호 코드·조판·저장 예산을 계산해 최악 수명을 식별하고, 현재 페이지 선택과 런타임 합성 구조가 이를 수용하는지 판정한다.
3. 판정된 전역 구조로 전체 번역을 누적 설치하고, 일본어 잔존 0건 검사를 빌드 실패 조건으로 만든다.
4. 구매·실패·패배·저장·장 전환·엔딩을 포함한 대표 극단 경로를 최종 동일 ROM 계보에서 검증한다.
