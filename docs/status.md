- 숫자·대문자·영어 부속 문장부호·텍스트 제어·MMC4 래치 42코드의 초기 보호 판정

- 같은 패치 ROM에서 기존 영어 능력치 약어 `STR`, `SKI`, `WLV`, `AGI`, `DEF`, `MOV`, `HP`, `EXP` 유지 확인

## 검증 결과

- 입력: 지원 일본판 SHA-1 `0179c550d424e0397496078789e7b116601d120c`
- PoC ROM SHA-1: `4529ea8d3724646dc8f4b19e68895b19ad95e2a8`
- 변경 바이트: 119개, 모두 등록된 설정 표·일본어 CHR 타일 쓰기 범위 안
- 영문 패치 ROM 입력: 일본판 원본 SHA-1 불일치로 거부, 산출물 없음
- 빌드 검사: `cargo test --all-targets` 15개 통과, `cargo clippy --all-targets -- -D warnings` 통과
- 글꼴 공급 보고서: CHR 32페이지·8,192타일, 비공백 7,849개, 전부 0인 패턴 343개
- 첫 글꼴 페이지: 보호 코드 42개, 미확정 코드 214개, 사용 가능 판정 0개
- 런타임 경로: 타이틀 → 처음부터 → 슬롯 1 → 1장 대화 진행 → SELECT 맵 메뉴 → 설정

현재 빌드는 전역 가나 타일 12개를 임시 재사용하므로 설정 화면 밖의 일본어가 깨진다. 이는 한글 표시 소비 경로만 검증하는 PoC 한계이며, 정식 패치에는 허용되지 않는다. 일본판에 원래 존재하는 영어를 번역하거나 손상하는 것도 허용되지 않는다.

## 현재 관문

전체 한글화의 선행 조건은 정식 글꼴 공급 구조다. 원본 CHR 8,192타일 가운데 7,849타일이 비어 있지 않고, 첫 글꼴 페이지에서 전부 0인 타일은 `95`, `FF`뿐이다. 원본 MMC4의 고정 CHR-ROM에 완성형 한글을 상주시키는 안은 채택하지 않는다.

[작업 로드맵](roadmap.md)의 G1 가운데 정적 CHR 목록과 확인된 설정·상태 표의 초기 보호 판정은 구현했다. 아직 다른 문자열·그래픽 참조자와 렌더 경로가 남았으므로 214개 미확정 코드를 회수 후보로 승격하지 않는다. 이를 확정한 다음 한글 없이 매퍼 변환의 그래픽 동등성을 검증하고, 서로 다른 화면별 글리프 집합을 실제로 교체하는 동적 글꼴 PoC를 통과시킨다.

## 다음 작업

1. 확인된 참조 목록을 설정·상태 표 밖의 문자열과 그래픽 소비자로 확장한다.
2. 대사·맵·상태·전투를 포함한 렌더 경로별 CHR 상태를 계측한다.
3. 214개 미확정 코드의 소비 여부를 판정하고 보호 고정 슬롯과 한글 활성 슬롯 예산을 확정한다.
4. 매퍼 후보와 지원할 에뮬레이터·플래시 카트 범위를 결정한다.

동적 한글 글꼴 관문이 통과하기 전에는 설정 PoC의 번역 범위를 늘리지 않는다.
