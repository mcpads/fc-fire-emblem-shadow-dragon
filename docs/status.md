- 지원 원본 SHA-1: `0179C550D424E0397496078789E7B116601D120C`
- 통합 ROM: `out/fire-emblem-fe1-korean-integrated.nes`
- 통합 ROM SHA-1: `89315359070F1DA09BE7941B1B55330CC630D68D`
- 설치 보고서: `out/full-translation-installation.json`
- 설치 보고서 SHA-1: `A326EFC71CE181B9D493F1F22F13BCB0E1F3AA75`

스키마 42 설치 보고서는 14개 설치 도메인과 821개 Expected Write를 포함한 정적 통합 검사를 통과했다. `declared_consumer_runtime_observation_complete`는 거짓이다. 누적 단계 ROM이나 이전 ROM의 실행 성공을 이 기준선의 성공으로 쓰지 않는다.

## 현재 단계: 동결 ROM 전범위 관측

제품 변경은 동결한다. 같은 ROM에서 아래 네 묶음의 독립 결과를 모두 `통과`, `실패`, `차단` 중 하나로 기록하기 전에는 제품 코드·번역 에셋을 고치거나 ROM을 다시 만들지 않는다. 한 실패를 발견해도 다른 묶음 관측을 계속한다.

| 목적 묶음 | 상태 | 현재 exact ROM에서 확인한 범위 |
| --- | --- | --- |
| 시작·저장·장 전환 | 일부 관측 | 콜드 무저장 타이틀에서 비전투 전투 캐시 정리만 확인 |
| 유닛·소지품·시설 | 미시작 | 없음 |
| 전투와 사망 | 일부 관측 | 지팡이 결과의 합성, 마지막 가시 위상 유지, 맵 인계만 확인 |
| 후반 진행과 엔딩 | 미시작 | 없음 |

`일부 관측`은 통과가 아니다. 현재 exact 실행은 emucap run `01M0P4AZR9J08VEN57ZD02Y0WE` 하나뿐이며, `.emucap`의 다른 run은 모두 과거 이력이다. 임시 경로에 있던 캡처·trace·도달용 상태와 8 KiB 무저장 SaveRAM은 `evidence/private/runtime-campaign/89315359/`에 보존한다. 도달용 상태는 downstream 전투 수명만 증명하며 자연 진행이나 다른 화면을 증명하지 않는다.

## 블로커와 영향

1. **네 묶음 관측 분모 미완료** — 공통 원인을 묶을 입력이 부족하므로 추가 제품 수정의 범위와 통합 안전성을 결정할 수 없다.
2. **whole-program 간접 매퍼 edge 미폐쇄** — 알려진 writer와 설치는 결속됐지만 원본 전체에 다른 writer가 없다는 주장은 아직 할 수 없다. 유한 후보를 줄이는 정적 분석 또는 실제 동적 edge 관측이 필요하되 현재 관측 캠페인을 중단시키지 않는다.
3. **실기와 배포 미검증** — 현재 결과는 개발 ROM이며 배포 후보가 아니다.

로드맵 위치는 설치 보고서가 선언한 G1·G4·G5·G6의 정적 범위만 통과한 상태다. G2는 부분 완료, G3·G7은 실행 증거 미완료, G8은 시작 전이며, 정적 범위 통과를 해당 로드맵 관문의 최종 완료로 읽지 않는다.

## 다음 세션의 첫 행동

1. `git status --short --branch`와 위 두 파일의 SHA-1을 확인한다.
2. 제품 빌드나 제품 파일 수정을 시작하지 않는다.
3. [플레이와 런타임 검증](playtesting.md)의 네 묶음에서 아직 안 본 독립 경로를 한 실행 계획에 여러 개 배치한다.
4. 각 경로를 통과·실패·차단으로 기록하고 실패가 나와도 도달 가능한 다른 경로를 계속 본다.
5. 네 묶음의 도달 가능한 분모를 모두 본 뒤에만 실패를 공통 생산자·상주 수명·런타임·소비자 가족으로 묶고 한 수정 배치를 설계한다.

한 결함이 모든 남은 경로를 막으면 도달 가능한 다른 묶음을 먼저 소진한다. 그래도 분모를 더 채울 수 없을 때만 차단 근거를 기록하고, 그 차단을 푸는 최소 공통 수정으로 새 기준선을 만든다.
