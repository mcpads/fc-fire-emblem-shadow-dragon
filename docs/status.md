## 직접 합성 상태 전수 결속과 유닛 선택 도움말

아이템·유닛·적군·병종 이름을 화면마다 따로 우회하던 경계를 원본의 공용 appender 진입점으로 올렸다. 아이템 ID를 직접 받는 네 호출자는 `$0B:$8E6F` 하나에서 카탈로그 포인터 형식으로 정규화하고, 레코드 기반 품목 호출은 기존 `$875F` 경로와 합류한다. 유닛·적군 이름은 `$8E88`, 병종명은 `$8EBA`의 공용 진입점을 각각 고정 뱅크 브리지로 바꿨다. 원본 호출자 census와 후보 바이트를 함께 묶으므로 새 화면을 발견할 때마다 같은 훅을 복제하지 않는다.

화면 상주 분모 37개를 모두 정적 페이지, 상위 선택기, 대사 수명, 원본 페이지, 공용 appender 또는 source-bound control-only 수명에 명시적으로 귀속했다. 상태 `11/17`은 각 handler 전체와 생산자 가족을 결속했고, 두 handler가 글리프를 복사하지 않고 `ED` 행 제어와 `EF` 종단만 만든다는 범위에서 현재 페이지를 유지한다. 상태 `25`는 유닛 선택 도움말의 실제 생산자 `06:$8605`, handler `0B:$81DB`, 연속된 원본 6줄뿐 아니라 다음 상태가 여는 `B1:52` 대사까지 한 화면 수명으로 묶었다. 도움말 40글자의 코드는 모든 화면 수명을 보는 전역 소비자 코드북이 고르고, 해당 대사의 가시 작업집합도 같은 코드를 보유한다. 보고서 하위 스키마는 14이고 분류는 `12 pure-static / 10 delegated / 2 source-page / 3 item-published / 1 class-published / 2 unit-or-enemy-published / 1 unit-status-retained / 2 completed-dialogue-retained / 1 storage-dialogue-or-static / 1 active-dialogue-restored / 2 control-only-retained / 0 unresolved`다.

전체 시험 1,043개와 경고 없는 `cargo check`가 통과했다. 지원 원본에서 다시 만든 정확 통합 ROM SHA-1은 `70158F8086886A996249A1DA188CA8E31B6E9291`, 스키마 35 보고서 SHA-1은 `92F49E79AFF6A657967E7FFF2D02AA91497EDE5F`다. 고정 UI 투영은 포인터 문자열 36개와 인라인 도움말 6줄을 분리해 세며, 전체 고정 메뉴 번역 재료는 13개다. 대사 상주 단계는 8개이고, 도움말이 겹치는 `shop-and-item-dialogue:082`의 보강 수요는 `195/210`이다. 방출된 6502 게시기를 직접 실행하는 시험은 `02..26`의 37개 상태를 전부 순회해 정적 선택, 원본 페이지 복귀, 상위 페이지 유지가 정책표와 같은지 검사한다.

이번 결과는 정적 통합 합격이다. 같은 exact ROM의 콜드 1장 지도에서 source-bound 상태 `24=06/84=02/05DB=00`만 진단 개입해 `05E8=25` 생산과 `B1:52` 완료를 순서대로 확인했고, 도움말 6줄과 아래 대사가 동시에 읽을 수 있는 한글로 유지됐다. 후속 묶음 실행에서는 선행 상태 `10→11`, `16→17`과 `25→B1:52→닫기`를 한 콜드 실행에서 차례로 통과시켰다. 상태 `11` 생산값, 상태 `17` 생산값, 상태 `25` 생산값을 각각 실제 `$05E8` 쓰기에서 잡았고, 상태 `25` 완료 화면은 SHA-256 `94251B1B2A6AAB13557D3E3A6022B14E01FCA97FC8426FF7B808E345EF4FF67E`였다. A 입력 뒤 원본 `06:$A132`가 `$05DB=00`을 쓰고 유닛 선택 화면으로 복귀한 화면 SHA-256은 `EE2D006C395A17E0DDEF122E74595A2A0B330B2366289C0AE29825B29CF90C13`다. 상태 `17`은 글자 없는 제어 전용 handler이므로 내용 없는 진단 화면을 실제 상위 문장 보존 증거로 세지 않는다. 자연 유닛 선택 진입과 최종 실행 manifest도 아직 없으므로 실행 역할은 계속 0개다.

원천 수명 결속은 매퍼 감사 안의 중첩 복제본에서 crate 공용 소유자로 옮겼고, 선택지와 도움말이 따로 복제하던 상주 코드 배정·작업집합 보강은 공용 구현 하나로 합쳤다. 삭제된 옛 모듈, unresolved enum, 기본 fallback과 낡은 보고 필드는 남기지 않았다. 현재 `apps/fc_fire_emblem_patch/src`의 Rust 파일 497개는 모두 `main.rs` 모듈 그래프에서 도달하며 고아 파일은 0개이고, `cargo check --all-targets`에도 미사용·죽은 코드 경고가 없다. 실행 분모를 보존하는 fail-closed 상태와 시험 입력은 사용 빈도가 낮다는 이유만으로 제거하지 않는다.

## 전투 후 결과와 NEXT STORY의 원본 글꼴 페이지 수명

합성 상태 `08`은 전투 후 EXP·LEVEL UP 결과이고, 상태 `10`은 장 저장 뒤 `NEXT STORY` 전환이다. 두 화면은 직전 한글 화면의 페이지를 유지하는 보조 합성이 아니라, 원본이 보존하는 영문·숫자 고정 문자열만 쓰는 독립 화면이다. 상태 `08`의 주 상태 `20/21` 처리기와 고정 문자열 `0B/12`, 상태 `10`의 장 저장 상태 `02/03` 처리기와 고정 문자열 `3E`, 두 합성기의 정확한 코드 구간을 한 원천 수명으로 결속했다. 세 고정 문자열에 일본어 코드가 생기거나 수명 안에 새 MMC4 쓰기가 들어오면 빌드가 실패한다.

런타임 중앙 정책은 두 상태에서 이전 번역 route를 지우고 원본 오른쪽 FD page 0을 명시적으로 다시 고른다. 상태 게시기와 복합 화면 열기가 각각 갖고 있던 동일한 원본-page 선택 코드는 한 내부 진입점으로 합쳤다. 이 정리는 새 상태 분기를 억지로 동굴 밖에 늘리지 않으면서 기존 7바이트 초과를 없앴고, 저장소 상태 `07`의 일반 카탈로그 분기도 이미 존재하는 카탈로그 route stub을 재사용한다. 설정 수명에만 있던 source 코드의 typed MMC4 무쓰기 검사도 공용 결속기로 옮겨 중복 구현 90줄을 제거했다.

전체 시험 1,029개가 통과했다. 처음부터 다시 만든 누적 ROM SHA-1은 `962C05E5A1B732B5F65AAAE3158B0B2B1475FAC1`, 누적 보고서 SHA-1은 `F0A7575CDBC914CAEBEBF3B40F03B6C82F888BB5`다. 이를 입력으로 만든 최종 통합 ROM SHA-1은 `EA8094066938C6762C339DB148D91A38E0153DB0`, 스키마 33 보고서 SHA-1은 `71FCEE6F0C072403C1575B01AA2416D6D89418F8`다. 화면 상주 분모는 `19 central / 10 delegated / 8 unresolved`이며 최종 산출물 실행 역할은 여전히 0개다. 따라서 이번 결과는 정적 통합 합격이고, 전투 후 결과·장 전환을 포함한 묶음 실행은 같은 exact ROM에서 별도로 해야 한다.

## 설정 목록과 값 결과의 한 화면 수명 결속

합성 상태 `19`를 보존 고정 문자열 두 개만 쓰는 독립 화면으로 분류하던 가정을 제거했다. 원본 주 상태 `38`의 상태기는 상태 0에서 설정 목록 `1B`를 만들고, 첫째·둘째 값을 고른 두 분기에서 같은 화면 위에 결과 상태 `19`를 덧그린다. 셋째 값만 별도 게임 속도 appender 상태 `1A`로 빠진다. 주 상태 표 `38→06:$B349`, 하위 상태 표 `00/01/02`, `1B/19/1A`의 네 직접 합성 생산자, 결과 handler `0B:$87C4`와 고정 문자열 `2E/2F`, 진입부터 이탈까지의 직접 mapper-write 부재를 한 원천 계약으로 묶었다. 따라서 `19`는 묵시적 직전 페이지가 아니라 `1B`에서 실제 페이지를 고른 options selector의 같은 수명으로 위임한다.

단일 `OPTIONS_FONT_PAGE_COMPOSITE_STATE` façade는 `19/1B` 수명 집합으로 바꾸고, 선택기 검증의 상태별 중복 행도 `owner + states` 한 항목으로 합쳤다. 이미 계산한 고정 문자열 소비자와 직접 생산자 census를 options 결속이 다시 스캔하던 중복도 제거했다. 컴파일러가 보고하는 시험용 `ProjectionLedgerCompleteness::Incomplete`는 전역 닫힘의 거짓 양성을 거부하는 fail-closed 입력이므로 죽은 코드로 삭제하지 않았다.

전체 시험 1,024개가 통과했다. 기존 누적 ROM을 입력으로 다시 만든 최종 통합 ROM SHA-1은 `7BD8B21FF8EB853CEC279CFB87AD5D855045B35C`로 직전 파일과 바이트 단위로 동일하고, 최종 보고서 SHA-1은 `5CC20C01369132803C8F18D344365ACA1A8B7812`다. 화면 상주 분모는 `17 central / 10 delegated / 10 unresolved`다. 이번 단위는 원천 수명과 최종 설치의 무변경을 닫았으며 새 실행 증거를 승계하지 않는다.

## 주 대사 보조 합성 상태의 페이지 소유자 결속

미해결 합성 상태 가운데 `12`, `1F`, `20`은 서로 다른 화면이 아니었다. 주 대사 상태 `02`, `04`, `06`이 선택적 `E5` 메타데이터, 고정 네 바이트 헤더, 선택적 `E8` 메타데이터를 해석한 뒤 공용 합성기로 넘기는 한 생산자 가족이다. 세 `LDA #state; JSR $E690` 명령을 각각의 원본 handler와 코드 구간에 묶고, 화면 페이지는 합성 상태값이 아니라 이미 활성인 주 대사 런타임 선택기가 계속 소유하도록 위임했다. 기존 원천 계약에서 `20` 생산 직전에 끝나던 `E8` 처리 구간도 실제 게시·표시 플래그 쓰기까지 확장했다.

프런트엔드와 유닛 이름 포워더가 같은 화면 상주 표를 다시 순회해 임시 벡터로 비교하던 중복 구현은 공용 정책 조회 하나로 바꿨다. 실행 분모를 보존하는 미해결 상태와 시험 전용 fail-closed 변형은 죽은 코드로 오인해 제거하지 않았다.

전체 시험 1,022개가 통과했다. 누적 ROM SHA-1은 `962C05E5A1B732B5F65AAAE3158B0B2B1475FAC1`, 최종 통합 ROM SHA-1은 직전 기준과 같은 `7BD8B21FF8EB853CEC279CFB87AD5D855045B35C`이며 직전 파일과 바이트 단위로 동일하다. 최종 보고서 SHA-1은 `C099C19049F3C1A956C8A4AAEAF1C80A0F20562F`다. 화면 상주 분모는 `17 central / 9 delegated / 11 unresolved`가 되었으며, 실행 증거를 새로 승계하지 않는다. 이 수치는 문서 맨 위의 현재 절에서 더 전진했으며, 현재 남은 생산자 가족은 [열려 있는 문제](open-problems.md#현재-우선-블로커-미해결-페이지-소유자-111725를-생산자-수명으로-닫아야-한다)가 맡는다.

## 직접 합성 상태 전수의 글꼴 페이지 소유자 분리

지원 원본이 직접 만드는 합성 상태 `02..26`의 37개 정책을 다시 대조했다. 기존 보고서는 중앙 게시자가 페이지를 고르는 17개 상태와 나머지 20개를 구분했지만, 뒤의 20개에는 실제 상위 선택기·문자열 appender가 소유하는 상태와 아직 소유자를 모르는 상태가 섞여 있었다. 이 포괄 분기를 제거하고 선택지 대사 `0C`, 부대 목록 `16`, 유닛 선택 `18`, 게임 속도 `1A`, 설정 `1B`, 보관 용량 안내 `26`의 6개를 각각 실제 상위 소유자에 결속했다. 선택지·부대 목록은 지원 원본의 고정 문자열 호출과 합성 상태를 함께 검사하고, 유닛 선택·게임 속도·보관 용량은 고정 메뉴 appender 경로를, 설정·부대 목록은 누적 선택기 그래프를 함께 검사한다.

나머지 14개는 안전한 상속으로 간주하지 않고 `unresolved_page_owner`로 남겼다. 정확 통합 재빌드의 ROM SHA-1은 직전 기준과 같은 `7BD8B21FF8EB853CEC279CFB87AD5D855045B35C`이며 바이트 단위로도 동일하다. 전체 시험 1,021개가 통과했고, 보고서만 화면 상주 하위 스키마 8과 선택기 포워더 하위 스키마 4로 바뀌어 `6 delegated / 14 unresolved`를 따로 기록한다. 새 보고서 SHA-1은 `87122224EC7D9296ACAE46E1829BF3859A0ED05F`다. 남은 상태와 다음 묶음은 [열려 있는 문제](open-problems.md#현재-우선-블로커-미해결-페이지-소유자-111725를-생산자-수명으로-닫아야-한다)가 맡는다.

## 2026-08-20 공유 상태 `07`의 생산자별 글꼴 상주권

대사 페이지가 무엇을 보존해야 하는지를 원본 소비자에서 다시 유도했다. 뱅크 `0A`의 줄 버퍼 writer는 여덟 곳이다. `$81FF`·`$8202`가 줄 머리 `FF` 두 칸, `$8219`·`$821E`가 `{EA}`의 화자 표식 `9E`·`AB`, `$8299`가 제어 15개를 모두 분기로 거른 뒤의 리터럴, `$82E6`·`$8524`가 줄 종료 `ED`, `$838A`가 `{EC}` 동적 문자열 바이트를 쓴다. 제어 명세의 `output_effect`도 `EA`와 `EC` 둘만 출력이 있고 나머지 열셋은 `none`이다. `$81EA` 상태 처리기가 줄 버퍼를 비우지 않고 현재 줄 머리 두 칸만 쓴다는 사실도 이 전수에서 확정했다.

제어 코드 자체는 되찾지 않는다. 대사 레코드의 저장 바이트가 다시 이 파서를 지나므로 글리프를 제어 코드에 배정하면 그 글자가 든 문장이 제어로 읽힌다. 되찾은 것은 제어의 피연산자다. `E9`·`E1`·`DF`·`EC`의 인라인 1바이트와 `E4`·`E6`의 전이 대상 2바이트는 그려지지 않고 제어 바로 뒤 자리에서만 피연산자로 읽힌다. 원문 줄의 리터럴도 번역문이 덮어쓰므로 대상 페이지에서 되찾는다. 두 규칙을 `rendered_active_codes`로 모으고 행동 시험 여섯 개로 고정했다.

효과는 정적 산출물에서 측정했다. 대사 정적 페이지 상한이 39에서 35로, 최대 작업집합 수요가 198에서 195로 줄었다. `{DF:55}`와 `{E4:B1:2D}`가 묶고 있던 코드가 풀려 균일 합집합 구현을 막던 `하`→`B1`, `우`→`2D`, `망`→`55` 충돌 세 개도 사라졌다. 전체 crate 시험은 1,005개가 통과했다.

그럼에도 보관소 균일 합집합은 성립하지 않았다. 19개 레코드 20개 페이지의 합집합은 글리프 206개인데 그 페이지들의 보존 코드 합집합이 17개라 배정 가능한 코드가 193개다. 열세 개가 모자라며, 이는 배정 탐색의 한계가 아니라 셈이 맞지 않는 것이다. 따라서 다음 단위는 레코드마다 실제로 앞설 수 있는 레코드의 글리프만 요구하는 선행 폐포다.

같은 입력의 재현 산출물은 누적 한글 ROM SHA-1 `962C05E5A1B732B5F65AAAE3158B0B2B1475FAC1`, 보고서 SHA-1 `F0A7575CDBC914CAEBEBF3B40F03B6C82F888BB5`이고, 최종 통합 ROM SHA-1은 `79C0F63EB611D062DD98CB1EB1077A17AEFEBDE8`, 보고서 SHA-1은 `DD236FBA303BA3F1D63FC3986E2094119D3B963C`다. 이는 정적 설치 합격이며 보관소 런타임 회귀는 아직 통과하지 않았으므로 런타임 합격으로 승격하지 않는다.

## 2026-08-18 호출자 인계 상태기의 정적 경계와 실행 묶음

이번 정적 단위는 고정 스케줄러의 알려진 정상 진입을 먼저 넓혔다. 스케줄러 게이트 `$23`은 0이 아닌 정확한 한 값이 아니라 비영 집합으로 모델링하고, 처리기 호출 요약이 현재 PRG 뱅크 그림자 `$29/$51`을 함께 보존하도록 했다. 게임플레이 진입이 중첩 주 상태 `$84=00`을 만드는 경로와 지연 상태 `$26={00,04,0C,13}`의 원천 writer를 결속해, 외부 화면 상태 `0C`로 돌아오는 네 문맥을 같은 고정 스케줄러 추적에 넣었다.

맵 시설 선택자의 미해결 분모도 원천 자료에서 닫았다. 25개 장 포인터와 94개 시설 레코드 전체를 읽어 시설 종류 `01..05`가 `0B:$A2E2`의 6항목 처리기 표 안에서만 선택됨을 확인하고, 종류를 만드는 네 명령 시작점까지 실행 그래프에 등록했다. 따라서 이 경로는 관측한 1장 무기점 하나를 전체 시설의 근거로 일반화하지 않고, 전체 장 레코드 모집단에서 선택자 범위를 유도한다.

화면 상태 생산자 추적은 `$05DB`를 선택자로 쓰는 호출자 인계 상태기 일곱 개까지 구조적으로 넓어졌다. 프런트엔드 기록 1개, 맵 시설 1개, 무기점·도구점·보관소·수송대 물품 이동·전투 저장 5개이며, 각 처리기 표의 크기와 직접 분기, 대사 진입 공통 경계 `02:$A9AD` 또는 `06:$A119`는 원본 코드에 결속했다. `$05DC`는 리셋의 0 초기화와 직접 읽기 두 곳까지 확인했다. 전투 저장은 아래 실행으로 실제 `$05DB/$7809` 인계와 재개까지 확인했고, 후속 8장 묶음은 도구점·투기장·보관소의 처리기 진입과 대사 인계를 추가로 확인했다. 무기점은 공용 상점 디스패처와 품목 목록까지만 확인했으며, 프런트엔드 기록·수송대 물품 이동·비밀 상점과 각 시설의 미관측 변경 분기는 그대로 남아 있다.

이 경계를 `0F:$C14B`까지 정적으로 밀어 넣는 시도는 폐기했다. 선택자 0은 전역 스케줄러 문맥이 없었고, 다른 선택자는 별도 인라인 디스패처와 호출 뒤 상태 writer로 이어졌다. 여기에 추정한 호출 복귀나 예외 목록을 계속 더하면 실제 실행 순서를 증명하는 대신 분석기가 원하는 흐름을 만들어 내게 된다. 현재 코드에는 이 시도에서 만든 조건부 복귀 요약이나 안전 목록을 남기지 않았으며, 해당 사실은 미해결로 유지한다. 정적·동적 분석의 전환 기준은 [의사결정 94](decisions.md#94-유한-분모를-닫는-정적-분석과-실제-시점을-묻는-실행-관측을-나눈다)에 기록했다.

같은 누적 입력으로 만든 정확 통합 ROM `0AE64C3677B71CDD55EB5EBA0CA7D0D62B155A43`에서 지도 유닛 간 직접 전달의 취소와 성공을 한 실행으로 확인했다. 취소는 대상 선택 상태에서 소지품 목록으로 돌아오며 양쪽 유닛 레코드를 바꾸지 않았고, 성공은 대상 레코드에 철검을 더한 뒤 한글 결과 대사를 표시하고 원본 유닛의 철검을 제거한 채 지도 상태로 복귀했다. 그러나 이 경로의 주 상태는 `1B→1C→1D→1E`이고 `$05DB/$05DC`와 일곱 인계 처리기에 들어가지 않았다. 원본 `06:$B10D` 상태기는 수송대 개수·물품 배열을 다루므로 직접 전달과 별개다. 상세 실행 경계는 [유효 중단 데이터에서 지도·소지품 메뉴 확인](playtesting.md#유효-중단-데이터에서-지도소지품-메뉴-확인)이 맡으며, 직접 전달 성공을 호출자 인계 상태기의 실행 증거로 세지 않는다.

전투 중단은 같은 통합 실행에서 진행 메뉴 네 번째 항목으로 들어갔다. 상태기는 `$05DB:00→01→02`로 진행했고, 주 대사의 호출자 인계가 `$7809:00→01`을 쓴 프레임에 공통 처리기 `06:$A13E`가 상태를 `01→02`로 넘겼다. 완료 처리기 `06:$B858`은 전원 차단 안내가 보이는 동안 반복 실행됐다. native power cycle 뒤 시작 메뉴에 `이어하기`가 실제로 나타나 같은 7장 지도로 복귀했고, 재개 뒤 두 번째 power cycle에서는 `이어하기`가 사라졌다. 중단 직후와 재개 뒤 8 KiB SaveRAM SHA-256도 각각 `B95CEC3963BF8C884C626654538CE902D7AF250FC696F3371F8178B6FAE66E69`, `CE14186E170BFC948C395A92E46C1FC5FAED9FD3247D6B1EE968BDDDBDEA5540`으로 달랐다. 이 실행은 중단 데이터의 생성·재개·일회성 소비를 같은 산출물에서 닫지만, 다른 호출자 인계 상태기를 대신하지 않는다.

재개한 지도에서 진행 메뉴의 `보관소`와 `소지품`도 같은 세션에 묶었다. 전자는 주 상태 `42`, 합성 상태 `17`에서 `$05DB:00→01→02→03` 뒤 `B`로 0에 복귀했고, 후자는 주 상태 `36`, 합성 상태 `13`에서 `00→01→02` 뒤 `A`로 0에 복귀했다. 두 화면 모두 원본 `06:$9DBE/$B10D/$A13E` 실행 중단점에는 적중하지 않았다. 따라서 `$05DB`라는 주소나 값만 보고 호출자 인계로 분류할 수 없으며, 정확한 디스패처·처리기와 함께 관측해야 한다. 상세 경계는 [중단 저장과 재개](playtesting.md#중단-저장과-재개)가 맡는다.

이 결과는 현재 정적 보고서와 회귀 시험의 역할 구분에 반영했고, 전체 시험·누적 빌드·최종 통합을 같은 입력으로 다시 통과시켰다. 뒤의 8장 실행 묶음은 실제 시설 라벨·종류·처리기·대사 인계·취소 또는 복귀를 한 ROM에서 비교했다. 반복 적중하는 바이트 파서나 매 프레임 디스패처를 관측 경계로 쓰지 않으며, 관측한 양성 순서를 호출자 전체의 음성 공간이나 다른 산출물의 동등성으로 일반화하지 않는다.

이 실행 묶음의 공통 기준 상태는 확보했다. 정확 통합 ROM `0AE64C3677B71CDD55EB5EBA0CA7D0D62B155A43`을 첫 명령 전 동결 상태에서 시작하고, SHA-256 `5919814DA4247E71AB1E52AF3555701EA3B343C92470D95192E0F6898403EB09`인 8 KiB 정규 SaveRAM을 파일 입력으로 한 번만 넣은 뒤 reset했다. 시작 메뉴의 `불러오기`, `기록1 MAP 8`을 거쳐 네 도입 대사를 각각 완료 상태 `$77F7=0E`에서만 진행했고, 8장 지도 입력 대기 `$84=00`에 도달했다. 지도 좌표를 직접 쓰지 않고 실제 방향 입력으로 행 19·열 14의 유닛까지 이동했으며, 같은 ROM에서 분기를 반복할 안전한 기준 상태를 CPU 명령 경계에 저장했다.

첫 실패 시도와 분리해 같은 기준 상태에서 네 시설을 다시 관측했다. 시설 종류 `01`은 `무기점`과 공용 상점 디스패처 `06:$99AC`, 종류 `02`는 `도구점`과 같은 디스패처, 종류 `03`은 `투기장`과 `06:$9C63`, 종류 `04`는 `보관소`와 `06:$9DBE`에 결속됐다. 도구점·투기장·보관소에서는 대사 쪽 `$7809=01`을 공통 관측자 `06:$A141`이 읽는 인계도 확인했다. 도구점과 보관소의 종료 대사는 `$7803=01` 완료 뒤 `$26`에 저장된 호출자 상태 `0F`를 `$84`로 복원했으며, 곧바로 지도 유휴로 간다는 과거의 보편적 설명은 틀렸다. 상세 입력·상태 경계는 [8장 맵 시설 호출자 묶음 기준선](playtesting.md#8장-맵-시설-호출자-묶음-기준선)이 맡는다.

이 실행은 경로 오분류보다 큰 통합 결함도 드러냈다. 무기점·도구점·투기장의 확인 화면은 판독 가능했지만, 보관소의 인사·`보관/찾기` 선택·종료 대사는 한글 글리프가 다른 문자로 치환돼 보였다. 시설 처리기와 취소·완료 신호는 정상 진행했고 보관 배열 `$7681..$76D1`도 취소 전후 모두 0이었으므로, 현재 블로커는 보관소 로직 미도달이나 문장 저장 바이트가 아니다.

후속 정적 결속으로 첫 잘못된 경계를 화면 글꼴 게시까지 좁혔다. 보관소 고정 메뉴 상태 `1D/23`은 라벨 `35/36/46`을 주 대사 위에 덧붙이지만 중앙 화면 상주 정책에는 들어 있지 않았다. 반면 고정 메뉴 라벨은 `unit_command_menu` 코드북으로 저장되고, 두 appender `0B:$8B1D/$8DA8`은 공용 wrapper를 통해 그 페이지 route `CC`를 `$07FD`에 게시했다. 활성 페이지 선택기는 `$07FD`가 0이 아니면 주 대사 selector보다 이를 먼저 적용하므로, 고정 라벨은 읽히지만 같은 화면에 남은 대사 코드는 서로 다른 배정표로 해석됐다. `0B:$8E31`의 상태 `26` 용량 안내 라벨 `47`은 독립 정적 화면이므로 기존 페이지 게시를 유지해야 한다. 도구점에서는 읽힌 종료 레코드 `06`이 보관소에서는 같은 레코드인데도 깨진 사실도 문장 자체보다 이 수명 충돌을 지지한다.

첫 구현은 두 상태기의 대사 선택 분모 19개를 유지하면서 실제 라벨 겹침 수명을 시설 첫 인사 레코드 `41`과 소지품 초과 첫 안내 레코드 `64`로 좁혔다. 전자는 `보관/찾기`, 후자는 `보관/하나버리기` 글리프만 요구한다. 두 appender의 정적 페이지 재게시를 제거하고, 물리 고정 문자열을 두 대사 수명에서 공통으로 쓸 수 있는 8개 안정 코드로 재인코딩했다. 이 단계의 정적 설치 보고서는 두 레코드의 가시 작업집합 3개만 증강했고 최대 수요는 `198/210`이다. 결과 대사 17개를 독립 경로로 남겨도 된다는 가정은 아래 실행에서 기각됐다. 상태 `26` 용량 안내는 아직 별도 정적 화면 경로를 유지한다.

지원 원본과 기존 누적 후보 `508068897C8527527E50C355B3277FB84474C3DC`를 다시 결속한 정적 통합 후보는 스키마 31, ROM SHA-1 `69C0F25FC3191114829C678A84ABB3BB14ABEA25`, 보고서 SHA-1 `CCB717E2F057959C03B7CCF9EBEDA960BB636380`이다. 504개 대사 레코드, 928개 가시 작업집합, 39페이지 정적 상한, 최대 `210/210` 물리 페이지 수요와 517개 포인터 쓰기를 통과했고 전체 crate 시험 988개와 형식·diff 검사도 통과했다. 이는 정적 설치 합격이다.

## 2026-08-17 화면 폰트 상주 리팩터링 진행

화면마다 따로 있던 합성 상태 분기, 글리프 공존 계산, 카탈로그 페이지 선택을 `screen_font_residency` 계획으로 모았다. 중앙 레지스트리는 합성 상태 14개와 그 원천 생산자 19곳을 소유한다. 프런트엔드 상태 `0D/0E/21/22`, 유닛·아이템·고정 메뉴, 장 저장·엔딩 기록을 같은 계획에 결속했다. 메인 대사는 계획 초안과 완성본을 별도 타입으로 나눴다. 동적 문자열, 장 제목, 선택지·앞면 메뉴, 결과 대사, 전이 수명의 다섯 단계가 앞 단계의 글리프와 고정 코드를 보존하고 최종 코드북 페이지가 이를 실제로 수용해야만 런타임 경로를 만들 수 있다.

전투의 최종 산출물 검사도 네 텍스트 도메인만 보던 범위를 넓혔다. 지형 미니어처용 CHR 생산자 1곳과 효과 스프라이트 생산자 21곳, 이들이 참조하는 원본 CHR 7페이지, 공통 left-FD 선택 루틴을 누적 후보와 통합 ROM에서 함께 재결속한다. 이는 전투의 정적 공급·설치 경계를 닫은 것이며 모든 전투 실행 경로나 직접 writer의 동적 공존 수명을 통과했다는 뜻은 아니다.

중앙 계획이 이미 전부 소유하는 프런트엔드 상태 `0D/0E/21/22`의 누적 선택기는 최종 산출물에서 제거했다. 누적 `$FC60..$FC98`의 57바이트 상태 판단과 유일한 직접 진입 `$F797 → $FC60`을 결속한 뒤, 같은 범위를 `$FBD4` 중앙 선택기로 바로 넘기는 `JMP`와 `NOP`으로 바꾼다. 전투 런타임의 넓은 보존 범위는 이 프런트엔드 구간 앞뒤로 분할했다. 따라서 중앙 결정과 누적 결정이 서로 다른 상태 집합을 읽는 첫 중복 소유가 없어졌고, 그 밖의 유닛·아이템 선택기는 중앙 게시 순서가 닫힐 때까지 그대로 남는다.

유닛 요약과 상태의 중앙 정책도 분리했다. 요약 상태 `04`는 낡은 route를 지운 뒤 이름 appender가 실제 카탈로그 페이지를 게시하고, 상태 `0F`는 요약이 게시한 route를 그대로 유지한다. 지원 원본에서 요약 이름 appender가 정확히 한 번 실행되고 상태 작성기는 독립 게시를 하지 않는 구조를 결속했다. 방출된 6502 코드를 실행하는 시험은 요약의 초기화·이름 게시와 상태의 `0`, 카탈로그 페이지 0, 페이지 1 유지 경우를 모두 검사한다. 이전 구현처럼 상태 진입에서 `$07FD`를 지우고 우연히 남은 하드웨어 페이지에 기대지 않는다.

이 의미 경계가 닫힌 뒤 누적 유닛 선택기 `$F700..$F747`도 최종 산출물에서 제거했다. 누적 선택기 72바이트, 명단 선택기의 유일한 직접 진입 `$FBD1 → $F700`, 다음 미이관 상점 선택기 `$F748`을 exact 후보에서 다시 읽고, 같은 범위를 `$F748`로 넘기는 `JMP`와 `NOP`으로 바꾼다. 중앙 정책이 제거한 판단을 모두 소유하지 않으면 포워더 계획 자체가 만들어지지 않는다. 따라서 최종 보고서는 프런트엔드 57바이트와 유닛 72바이트, 합계 129바이트의 선택기 2개를 별도 역할로 기록한다.

합성 행동 시험 861개가 통과했다. 지원 원본과 11단계 누적 후보로 다시 만든 누적 후보 SHA-1은 `0b507b7c9d0d97a483a04a27bf2821a82b1a9a14`이고, 전체 설치 후보 SHA-1은 `16caf99106f49c96de741e234c1f027b4bb6ee7a`, 스키마 30 전체 설치 보고서 SHA-1은 `57ba73bcbaceb8baf82342de47ae3bd6c966f0a0`이다. 전체 설치는 14개 선언 도메인, 504개 대사 레코드, 928개 페이지 작업집합, 715개 글리프, 38페이지 정적 상한과 최대 `210/210` 슬롯 수요, 805개 Expected Write와 806개 필수 변이 정체성을 최종 이미지에서 다시 결속했다. 화면 상주 계획의 하위 스키마는 4이며, 이름 페이지 게시 상태 1개와 유지 상태 1개를 서로 다른 정책으로 보고한다. 선택기 포워더 하위 스키마는 2이며 중앙 상태 6개와 번역 도메인 6개에 귀속된 두 교체를 따로 기록한다.

빌드 뒤 별도 CLI로 현재 코드에서 세 입력 보고서를 다시 만들고 새 누적 후보와 최종 ROM을 읽은 번역 커버리지 보고서 SHA-1은 `15ca5f43e8155ac979e36e2c6ca95ca64416ffae`이다. 전체 52개 화면 중 일본어 보유 화면은 43개이고, 번역 도메인 23개 모두 원천 입력과 선언 소비자 설치는 결속됐지만 소비자 전수 조사는 `0 / 23`, 최종 산출물 실행 결속도 `0 / 23`, 사람 검토 완료는 `1 / 23`이다. 알려진 소비자 경로가 결속된 도메인은 5개다. 측정한 글꼴 수명은 38개이며 5개 역할은 미측정이다. 이 수치는 정적 설치 성공을 런타임 완료로 승격하지 않는다. 이 빌드와 분석에는 Python이 개입하지 않았으며, Python은 향후에도 Rust가 재검증할 배치 후보 계산만 맡는다.

같은 SHA-1 `16caf991...`의 콜드 개발 실행에서 제목·시작·기록·첫 대사 뒤 설정·저장소·유닛 요약·상태·명령·소지품, 전달 취소와 실제 전달·버리기 결과를 한 계보로 확인했다. 그러나 이미지 표본 manifest에 결속하지 않았으므로 보고서의 실행 역할은 여전히 0개다. 사람 검토가 끝나지 않은 초안 ROM의 진단을 최종 증거로 만들면 번역 변경 뒤 전부 다시 실행해야 하므로, 현재 다음 관문은 사람 검토와 재빌드다. 검토 전 실행은 통합 결함 발견용으로 계속 묶어 수행하되 최종 완료로 승격하지 않는다.

도구 책임과 다음 이관 순서는 `refactoring.md`가 맡는다. Rust가 원천 결속, 화면 상주 계획, typed ISA, Expected Write, 최종 ROM 재검증과 합격 판정을 소유한다. CLI는 입력·출력과 보고서 전달만 맡고, Python은 필요할 때 JSON 최적화 후보만 반환한다. 이번 exact 빌드는 Rust의 결정적 best-fit 배치로 끝나 Python을 호출하지 않았다. 외부 solver를 쓰더라도 페이지 범위·정규 번호·용량·고정 코드 충돌은 Rust가 독립적으로 다시 검사한다.

CLI 분해도 진행했다. 모든 하위 명령의 실행 디스패치는 `command_line/dispatch.rs`로 이동했고, `main.rs`는 2,071줄에서 623줄로 줄었다. crate 진입점은 clap 선언과 `command_line::execute` 호출을 맡고, 경로 입출력은 CLI 어댑터, 원천 주소·글리프·설치·합격 판정은 Rust 라이브러리가 맡는다. 분해 뒤 exact 누적·최종·커버리지 명령을 연속 실행했으며 ROM 해시는 유지됐다. 보고서 해시는 사람 검토 전 최종 실행 증거를 요구하던 잘못된 다음 관문과 오디오 간접 점프 누락을 고쳐 의도적으로 바뀌었다.

현재 구현은 전송 완료 직전에 커서 두 칸을 원문 selector/index 게시 슬롯으로 바꾸고, 공유 요청 발행기가 같은 원문 또는 같은 상주 그룹을 확인하면 완성 페이지를 재사용한다. E6와 E7의 비표시 전이는 실제 작성자가 없으면 상주권을 유지하고, 전투의 4 KiB 합성 호출만 먼저 `ready`를 내린다. 다른 그룹·일반 종료 뒤의 재진입·보존이 증명되지 않은 수명은 계속 냉합성한다. 발행기와 표시 selector는 각각 고정 동굴 `$F400..$F4B0`, 별도 exact-`FF` 동굴 `$F558..$F700`에 분리했다.

탐침 `A4AE24B8DE40F2930FDC799C48A6D2C3E6E2894D`은 프레임 2929의 `ready(3)`와 게시 정체성 `[80,02]` 뒤 300프레임 동안 재합성이 없었으므로 반복 생산자 관문만 통과했다. 당시 화면을 한글 정상 표시로 판정한 것은 잘못이었다. 그 산출물은 새 전역 코드북에 맞는 대사 저장소를 설치하지 않아 네임테이블 코드와 CHR 코드북이 달랐다.

현재 탐침 `018EDE4D6E6E500D025CBCC5279194BB142161ED`은 정규 대사 저장소 11구간과 포인터 517개를 현재 코드북과 같은 추적 이미지에 설치하고, 최종 이미지 바이트를 다시 읽어 일치를 확인한다. 콜드 1장 프레임 2937의 `ready` 쓰기 중단점은 NMI 한가운데라 그 순간의 프레임버퍼가 새 CHR 상태를 아직 표시하지 않았다. 같은 상태에서 한 프레임 진행한 2938에는 대사 본문 한글이 읽혔고, 네임테이블 코드·현재 그룹 23 코드북·CHR-RAM의 16바이트 타일·PPU `$1000..$1FFF`가 모두 일치했다. 맵·창·초상화도 보존됐다.

다음 수명 결합점 두 가지도 설치·실행했다. `{EA}`가 논리 줄 안에 있으면 실행 중 원본 표식으로 출력하는 `9E AB`를 해당 페이지가 보호한다. 25개 장 제목은 각 장의 전체 인트로 전이 사슬을 따라 관련 가시 페이지 129개에 합류하며, 고유 제목 글리프 88자는 그 모든 페이지에서 같은 코드를 쓰는 결정적 전역 배정을 갖는다. 개별 작업집합의 최대 수요는 여전히 `188/210`, 합쳐진 페이지의 최대는 `210/210`, 정적 그룹 상한은 37이다. 제목 저장소 25개도 현재 코드북의 바이트로 같은 추적 이미지에 설치하고 최종 바이트를 다시 확인한다. 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`의 1장 첫 완료 화면에서 장 제목 `마르스의 여정`, 원본 생성 표식, 한글 본문, 맵·창·초상화가 함께 유지됐다. 이 표본은 1장 결합 수명만 닫으며 나머지 24장 표시 회귀를 대신하지 않는다.

레코드 전환의 새 요청은 이제 resolver가 얻은 페이지 그룹을 직전 상주 그룹과 비교한다. 같은 그룹이면 CHR-RAM을 다시 쓰지 않고 새 원문 selector/index와 `ready`만 게시하며, 다른 그룹만 `cold_requested`로 내려간다. E6의 상태 `10`은 종료가 아니라 다음 레코드 앞의 비표시 상태로 확인해 상주 그룹을 유지한다. 새 탐침 `F9DE7CF3218B3DE1CC6367270DDA461903CA17DF`의 1장 경로에서 이전에 프레임 2991에 시작하던 같은 그룹 냉합성은 사라졌다.

E7 공유 소유권 경계는 구현됐다. 누적 후보의 직접 CHR-RAM 선택 세 지점과 전투 합성 호출 `$FC49 → $FC99`를 전수 결속하고, 합성 직전에만 대사 `ready`를 내리는 래퍼를 넣었다. E7 인계 자체는 상태 17의 원본 selector fallback만 사용한다. 탐침 `EA07D1B7BCBB63590699163AA8AD098D5DCC0F40`의 프레임 3141 인계에서 `ready=03`, 그룹 `15`가 유지됐고 프레임 3261의 이어진 화면은 읽을 수 있었다.

필수 냉합성의 표시 글리치는 닫았다. CHR-RAM은 mapper 165에서 실제 4 KiB 한 장뿐이라 이중 버퍼를 만들지 않고, 회수 가능한 CHR-ROM 첫 페이지인 물리 `50`·mapper 값 `C8`을 냉간 표시 전용으로 예약했다. 이 페이지는 원본 FD 글꼴 페이지에서 보호된 영어·숫자·제어·레이아웃 46코드를 바이트 그대로 유지하고 한글 활성 슬롯 210개만 빈 타일로 만든다. 요청 발행기가 NMI를 되살리기 전, 중앙 selector가 cold 상태를 볼 때, 각 전송 프레임이 원본 FD/FE를 복원한 뒤의 세 소유권 지점에서 FD만 이 페이지로 고른다. 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`에서 요청 직후 첫 표시 프레임 15154부터 복원 단계 15185·15258, 덮기 단계 15289·15336까지 대사 슬롯은 비어 있었고 맵·창·초상화·원본 영문/숫자 UI는 유지됐다. 프레임 16336에는 `$07F4=03`과 읽을 수 있는 완성 한글이 함께 나타났다. 스키마 11 보고서 SHA-1은 `e8e935645cff13e5b9efc01821e4b74587574431`, Expected Write는 572개이고 전용 페이지 뒤에 CHR 13페이지가 남는다. 콜드 대기 약 3.9초를 줄이는 성능·표현 개선과 다른 그룹 전이 회귀는 계속 남는다.

## 누적 조사 기록

아래는 구현이 진행되며 쌓인 단계별 조사 기록이다. 현재 산출물·완료 수·다음 관문은 문서 맨 위의 [현재 통합 산출물과 남은 관문](#현재-통합-산출물과-남은-관문)을 기준으로 하며, 아래 문단의 `현재`는 각 기록이 작성된 당시를 뜻한다.

매퍼 변환의 우선 후보를 MMC5에서 mapper 165로 바꿨다. mapper 165는 원본과 같은 배터리 SRAM을 제공하면서 MMC2식 FD/FE CHR 래치를 유지한다. 무번역 프로브는 원본 128 KiB CHR 앞에 8 KiB 예약 영역을 두고 원본 페이지를 그대로 재배치하며, PRG writer 12곳과 확인된 CHR writer 35곳을 변환한다.

실행 관측 화면 29개의 고유 FD/FE 쌍 18개를 비교해 오른쪽 `00/14`용 변형 CHR 페이지 1개를 만들고, 중앙 오른쪽 공급자가 FD/FE 그림자 쌍으로 이를 선택하게 했다. 설정의 `00/15`와 부대 목록·맵 유닛 UI·무기점·소지품 화면의 `00/15`, `00/18`, `00/19`, 양도 대상의 `15/15`는 원본 트리거 평면과 같아 자연 페이지를 쓴다. Mesen 콜드 실행의 프레임 800·1206·1928, 실제 입력 뒤 1장 인트로 대화와 2장 인트로 화면은 모두 기존 원본 PNG와 SHA-256이 정확히 같다. 전투의 직접 왼쪽 `02/06`, `06/06`과 오른쪽 `02/06`도 자연 페이지로 호환됐다.

G2는 통과했다. 직접 CHR writer 31곳을 정적 계약과 실제 전투 실행 쌍으로 모두 닫았고, 자연 중단·배터리 파일·전원 재인가·재개·일회성 소비와 턴 경계 게임 오버도 원본과 동등했다. 이어 실제 이동·턴 종료·전투로 보스를 쓰러뜨리고 성 명령을 선택해 1장을 완료한 뒤 정규 저장, native power cycle, `ロードする`와 2장 전환까지 비교했다. 같은 점멸 위상의 화면과 로드 뒤 네임테이블·OAM·팔레트가 일치해 mapper 165를 채택한다. 진행 가속으로 달라진 적 AI와 이동 경로 때문에 전체 SRAM·내부 RAM은 이 표본의 동등성 기준에서 제외했으며, 아직 게임 전체의 전수 회귀를 뜻하지 않는다. MMC5 프로브는 비교 근거와 기각된 설계의 재현 자료로 유지한다.

G3의 공급 방식은 확장 CHR-ROM 페이지 선택으로 확정했다. 보호 43코드와 레이아웃 3코드를 원본 그대로 복사하고 나머지 210코드만 한글에 배정한다. 설정 페이지 A/B는 공유 12자와 페이지별 100자로 각각 112자, 합집합 212자이며 물리 페이지 `34/35`, mapper 값 `88/8C`를 쓴다. 설정 화면 콜드 실행에서 `88 → 8C → 88`과 이탈 뒤 자연 페이지 복구를 확인했다.

부대 목록에는 물리 페이지 `36/37`, mapper 값 `90/94`의 화면 전용 A/B를 추가했다. 최초 공급 관문에서는 `이/름`과 인공 작업 집합으로 한 페이지 예산 초과를 증명했고, 현재 누적 빌드는 두 페이지를 실제 아군명 52개·고유 한글 72자의 생산 페이지로 교체했다. 진행 메뉴와 외부 상태·CHR 쌍 일부가 겹친다는 반례 뒤, 부대 목록 생성자 `0B:$89DB`의 고유 창 기술자와 위치 상태에 수명을 결속했다. 현재 빌드에서 `이름`, `마르스`부터 이어지는 실제 이름, 원본 `LV/HP`·숫자와 인물 그래픽을 함께 확인했다.

주 대사 번역 뷰 2,814줄 가운데 의미 있는 일본어 2,548줄을 `needs_human_review` 한국어로 채우고 장면별 직접 2차 교정을 마쳤으며 승인 완료는 아직 0줄이다. 미번역 일본어와 재배치 필요 줄은 모두 0개다. 원본 영어·숫자·제어 토큰 보존 검증과 원본 무수정 왕복을 통과했다. 동적 이름·아이템·수량 뒤 조사는 `은(는)`·`이(가)`·`을(를)`·`(이)나`로 교정했고, 채워진 고유 글리프는 697자다. 명시적인 `E4`/`E6` 대사 전이 사슬의 최대 한글 집합은 `village-and-outro-dialogue` 레코드 24 한 건의 175자다. 소스 분석에서 7장 성 좌표 `(27,10)`의 이벤트가 이 레코드를 `C0:18`로 생산함을 결속했다. 11장의 같은 엔트리 번호 18은 별도 상태기의 `30:18`이므로 제외한다. 레코드 전체를 상주시키면 보존 코드 100개와 한글 175자, 합계 `275/210`이라 불가능하지만 최대 단일 페이지는 한글 35자를 합쳐 `135/210`으로 들어간다. 그래서 15페이지를 5페이지씩 세 글꼴 묶음으로 나누고 첫 진입과 완료 페이지 진행 때 해당 묶음을 다시 고르는 구조를 누적 패치에 설치했다. 상태를 연결한 실제 7장 성 명령 경로에서 초기 선택기, `C8 → CC → D0` 재적재, 15페이지의 90개 완료 상태 표본, 모든 페이지의 점멸 위상, 마지막 원본 영문 `NEXT STORY` 이탈을 정확한 출력 해시에 결속했다. 콜드 부팅부터 7장까지의 연속 경로는 아직 별도 관문이다.

현재 기본 개발 산출물은 개별 프로브가 아니라 `build-kr-patch`가 불변 일본판에서 매번 재생성하는 11단계 누적 ROM이다. 열째 단계의 7장 최대 대사 뒤 열한째 단계가 원본 에셋 기반 한글 제목을 설치한다. 현재 누적 후보 SHA-1은 `87176c60d9ebb3cfd28e9cc44c58954113863d0e`, 빌드 보고서 SHA-1은 `c968cc2d0efc333ab2dbd489f3f107b394668b25`이며 42대사 레코드·168번역 줄·1,151글리프 슬롯·추적 쓰기 548개다. 이번 빌드는 실행 증거를 유예했으므로 과거 최대 대사와 제목 실행 증거를 승계하지 않는다.

전역 커버리지, 소비 경로 조사, 기술 설치와 실행 결속의 현재 수치는 문서 머리의 [현재 통합 산출물과 남은 관문](#현재-통합-산출물과-남은-관문)을 따른다. 주 대사 504레코드는 표시 단위 하나씩을 가지며 미번역 일본어 줄은 0개다. 928개 가시 페이지의 최대 수요는 동적 문자열까지 `188/210`이라 글꼴 화면 최악 `209/210`을 넘지 않고, 별도 그래픽 예산을 쓰는 제목은 완료 연출까지 `117/121`이다. 현재 `release_eligible=false`다.

제목 화면은 원본의 다섯 32타일 전송 행에서 최대 열 2..28을 쓰지만, 원본 `TM`이 마지막 행의 `BA+BB` 두 셀에 걸친다는 실행 반례 뒤 두 셀을 모두 보존 영역으로 고쳤다. 따라서 실제 교체 범위는 134셀, 일본어 로고 전용 코드는 121개다. ImageGen 로고는 의미나 글자를 줄이지 않고 폭만 205에서 200픽셀로 조정해 고유 타일 `117/121`에 넣었다. 완성 연출은 `$2182`부터 원작 상단 장식 26셀을 추가하고 `$21A8` 5셀·`$21CD` 3셀·`$21ED` 3셀을 원작 타일로 다시 쓴다. 설치기는 상단 26셀을 빈 타일로 만들고 본체 11셀을 정적 한국어 로고로 재고정하되 명령·속성 바이트, 미배정 CHR 패턴, 칼 스프라이트, 두 셀 `TM`, 저작권 자산은 보존한다. 현재 누적 후보 `87176c60d9ebb3cfd28e9cc44c58954113863d0e`의 새 무입력 실행에서 프레임 1206·1331·1458의 초기 위상과 상단 돌출 없는 두 완료 위상을 확인했고 1912에서 자동 병종 소개로 정상 이탈했다. 이 `117/121` 수요는 37개 일본어 대상 화면 수명 중 하나로 정적 계산됐고, 누적 보고서의 런타임 역할은 증거 유예 상태라 아직 미결이다. 사람 시각 승인과 패배 뒤 제목 복귀도 별도 관문이다.

현재 최종 빌드는 콜드 무저장 경로에서 `처음부터`, 슬롯 화면, 1장 제목과 도입 여섯 페이지를 거쳐 지도에 도달했다. 시작 메뉴는 +7/+19프레임에도 같은 해시 `4d474610…`를 유지했고, 진행 메뉴의 첫 항목으로 연 부대 목록은 `이름`과 `마르스`·`제이건`·`카인` 등 실제 이름, 원본 `LV/HP`·숫자를 함께 표시해 +7/+19프레임에도 같은 해시 `2907ae02…`였다. `B` 뒤 지도 복귀, 첫 두 무전투 적 턴의 상태 `00` 복귀, 세 번째 턴의 자연 전투 두 건과 최종 지도 복귀까지 한 실행에서 이어졌다. 전투 이름 표는 이제 번역됐고 엔딩 이름 표만 자체 글꼴 수명 설치 전이다.

자동 병종 소개는 뱅크 `0D`의 인덱스 `$0559`, 제목 포인터 표 `$8C98`, 설명 포인터 표 `$8DCC`에 결속했다. 일본어 제목 22개와 설명 75줄의 한글 합집합 216자는 단일 페이지 상한 210자를 넘으므로 인덱스 `0..10`의 143자와 `11..21`의 161자로 나눴다. 무입력 콜드 실행에서 프로필 `0`, `8`, 페이지 경계 `11`, 마지막 `20`, `21`, 자동 검은 전환과 뒤의 원본 영어 도입까지 7개 불규칙 시점을 같은 ROM SHA-1에 결속했다. 경계 프로필에서 배경의 두 mapper 래치가 모두 `BC`였고, 원본 `STR/SKI/WLV/AGI/DEF/MOV/H.P/EXP`·숫자·UI와 화면 이탈 뒤 영어가 유지됐다. 이 화면군의 실행 결속은 완료했지만 22개 번역은 모두 `needs_human_review`이므로 사람 승인 완료는 아니다.

무기점 공용 C0 페이지는 대사 8레코드, 품목명 6개와 `예/아니오`의 한글 60자, 보존 코드 90개를 함께 담아 아홉 화면 역할 모두 `150/210`으로 수용한다. 이 용량 결속과 실행 결속은 분리한다. 첫 구매 확인을 거절한 비구매 경로의 17개 불규칙 표본은 여덟째 단계 출력 SHA-1 `4758d15b9beb9b075be6976508b90e17ef1ea54d`에 결속했고, 대사·품목명은 품목 목록·확인·계속 질문·종료 네 역할, 선택지는 확인 역할만 실행 결속한다. 원본 숫자와 `G`, 초상화와 지도는 유지됐고, 뒤 누적 단계의 Expected Write 검증은 페이지·선택기 보존을 확인한다. 최종 누적 출력의 실제 구매·금액 부족·소지품 가득 참·아이템 조건 경고 분기는 아직 exact-output 실행 확인 전이다.

별도 형식의 전투 대사도 비공개 번역 작업공간으로 추출했다. 포인터 65개가 가리키는 고유 레코드 28개를 겹침 없는 1,152바이트 소유 범위에 결속했고, 4바이트 헤더 뒤 본문을 `ED/EE/EF` 단위 100줄·일본어 620바이트로 분리했다. `EC` 동적 문자열 선택자와 기존 영문·숫자·제어 코드는 보호 토큰으로 유지한다. 일본어가 있는 70줄은 모두 `needs_human_review` 한국어 초벌과 직접 2차 의미 검토를 마쳤고, 나머지 30줄은 제어만 있는 구조 줄이라 번역하지 않았다. 이름·아이템·병종처럼 받침 여부가 입력에 따라 달라지는 선택자 뒤 조사는 `은(는)`·`이(가)`·`을(를)`·`(으)로`로 교정했으며, 검증기가 고정 단일 조사를 거부한다. 현재 작업공간 SHA-1은 `f21dd08254a7afe1a0a38d25dda2eb70dc9628b6`다. 번역 레코드 논리 인코딩 1,114바이트와 미참조 원본 레코드 보존 16바이트를 합친 실제 계획은 1,130/1,168바이트로 38바이트가 남는다. 미참조 레코드의 원래 16바이트 위치를 경계로 소유 영역을 둘로 나누고 레코드를 자르지 않은 채 순서대로 배치했으며, 28개 새 주소와 별칭을 포함한 65개 포인터 쓰기를 모두 계산했다. 배치 보고서 SHA-1은 `b6fb8dd55ae95ced551d72326358112dac6e60a1`이다.

전체 전투 초벌을 한 번에 넣는 mapper 165 개발 ROM도 만들었다. 28레코드·70번역 줄·65포인터를 적용한 기존 프로브에서 실제 전투 소비자와 원본 `LV`·`HIT`·`EXP`·숫자 보존을 확인했다. 병종·아이템·아군명·적군명 기존 233개는 직접 2차 교정을 마쳤고, 원본 표 경계를 바로잡아 찾은 69번째 적군명에도 초벌을 추가해 234개 모두 번역 상태다. 기존 프로브는 원본 글꼴 페이지를 전역 교체해 고정 문자열이 깨지는 비배포 증거이므로, 다음 관문은 대사·동적 삽입·고정 문자열을 같은 전투 조합 코드북으로 인코딩하고 전투 수명에만 공급하는 것이다.

무기점의 품목 목록에서 첫 품목을 고른 `E7` 표본은 외부 상태 `04→05→07`, `$7809=01` 읽기 PC `06:$A144`로 결속했다. 인계 순간에는 6개 품목·가격 목록과 구매 질문이 함께 남아 있고 `はい/いいえ` 창은 아직 완성되지 않았다. 품목 목록에서 인계까지 네임테이블은 16바이트, 인계에서 안정 확인 화면까지 40바이트가 더 바뀌었다. 따라서 `$7809` 관측이나 상태 17에서 대사 전용 글꼴 페이지로 즉시 바꾸면 안 된다. 이 수명에서 보존해야 할 품목명·선택지 원본 코드는 17개이고, 동시에 보이는 대사 레코드 2개의 초벌 한글 합집합은 9자여서 국소 수요는 26/210슬롯이다. 전역 비교에는 이 표본값이 아니라 실제 설치된 공용 페이지 전체의 `150/210`을 사용한다.

자동 인물 후일담 화면군은 112개 보이는 엔트리의 560개 실행 표본을 한데 합친 보수적 예산으로 닫았다. 관측 네임테이블의 활성 원본 코드 99개를 모두 보존하고, 아직 실제 번역을 확정하지 않은 인물명 최대 7칸과 지명 최대 11칸을 별도 예약하며, 초벌 대사의 최대 전이 사슬 한글 33자를 더해도 150/210슬롯이다. 따라서 이 화면군은 페이지 분할 없이 수용 가능하지만, 이름·지명의 실제 한국어 문자열과 줄 폭은 아직 확정하지 않았다.

턴 경계 게임 오버는 불리한 일회성 개입으로 얻은 12개 불규칙 표본의 활성 원본 코드 90개를 모두 보존한다. 모든 표본의 `$77F4:$77F1`이 `B0:0A`라서 정확한 패배 레코드 인덱스 10의 초벌 한글 30자만 같은 수명에 든다. 합계는 120/210슬롯이다. 이 결과는 관측한 게임 오버 수명만 닫으며 장 승리 대사의 화면 수명은 별도다.

첫 주 대사 프로브의 전역 글꼴 교체를 폐기하고 1장 도입부 수명 전용 확장 페이지로 바꿨다. 원본 CHR은 한 바이트도 바꾸지 않고 물리 페이지 `34`, mapper 값 `88`에 원본 페이지 복제본과 한글 19자를 둔다. 동시 화면에서 관측한 활성 코드 76개와 첫 레코드 뒤 `E6` 전이 사슬 3레코드의 원문·보호 코드 58개를 합쳐 109개를 잠근 뒤 남은 슬롯에만 한글을 배정한다. 중앙 오른쪽 FD 공급 시점의 정확한 `$24/$84/$59/$5A/$5B/$5C/$77F7/$781D=0B/00/1A/1A/00/18/03/00`에서만 확장 페이지를 선택하고 그 밖에는 기존 쌍 인식 선택기로 돌아간다. 콜드 실행에서 일본어 새 게임 메뉴, 원본 `MAP`·숫자, 일본어 장 제목, 한글 첫 대사, 뒤의 일본어 다섯 화면, 초상화·맵·창을 함께 보존했으며 여섯 번째 완료 페이지 `A` 뒤 자연 맵 페이지로 복구됐다. 완료 표식과 맵 스프라이트는 7·19·43프레임 위상으로 확인했다. 이는 첫 화면 수명의 깨짐 0건이지 1장 전체나 G5 통과가 아니다.

상위 화면 조사를 다시 수행해 맵 유닛 UI를 `unit_summary`, `unit_command_menu`, `unit_status`로 분리했다. 요약은 일본어 이름·병종·아이템과 원본 `S/HP`·숫자를, 상세는 일본어 능력치 9개와 같은 원본 영문·숫자를 함께 표시한다. 합성 상태 `04/05/07/0F`를 요약 상단·명령 목록·아이템 목록·상세 능력치 조립기에 결속했다. 상태 `05`는 유닛 능력·지형·인접 대상·인벤토리·시설에 따라 일본어 명령 15개를 선택한다. 무이동 `もちもの/たいき`, 타일 `46`의 `たずねる`, 1장 좌표 `$03/$1A`의 `ぶきや`까지 4개를 실행 화면으로 확인했다. 전체 고정 라벨 26개 중 일본어 25개만 번역 대상이고 원본 `HP`는 보호한다.

소지품 흐름은 목록·조건부 행동 메뉴·양도 대상 선택·장비/사용/양도/폐기 결과의 일곱 역할로 나눴다. 목록과 행동 메뉴의 비변경 전이에 이어 장비는 둘째 슬롯을 첫 슬롯과 `02/2A,0F/16 → 0F/16,02/2A`로 교환하고 대사 `19`를 열었다. 양도 대상 선택은 텍스트 없는 `1A/1A + 15/15` 지도 오버레이이며 한 점멸 위상에서 후보 표시가 빠졌다. `B`는 원본 레코드를 보존하고 목록으로 돌아갔고, `A` 확정은 대상 빈칸에 `02/2A`를 옮긴 뒤 대사 `1B`를 열었다. 폐기는 첫 쌍을 지우고 `0F/16`을 앞으로 압축한 뒤 대사 `1C`를 열었다. 사용 아이템 `40`은 대사 `1A`를 자동으로 그린 뒤 진행 상태 2에서 회복을 적용하고 상태 3에서 입력을 기다렸다. 완성 페이지 카탈로그는 폐기했다. 모델 튜플 156,183,838,720개는 실제 도달 수가 아니라 보수적 입력 곱이지만, 기반 자산 뒤 최대 56개인 확장 PRG의 4 KiB 페이지로 조합마다 완성본을 두는 방식이 전체 범위가 될 수 없음을 확인했다. 대신 공통 1개·아군명 52개·적군명 55개·병종 24개·장비 64개·지형 16개·대사 28개, 총 240개 추상 업로드 레시피와 대사 선택자 65개를 생성한다. 항상 선택되는 공용 글리프를 가족별 payload에서 제외해 레시피 바이너리는 3,028바이트, 783개 글리프 참조와 193개 고유 payload가 됐다. 없는 적군명·비후보 장비 인덱스 41개는 명시적인 결측값으로 두며 SHA-1은 `23410e8016d08f5a6496ec1ba415d0c5e4804bf7`다. 원본 페이지 4,096바이트와 같은 8 KiB 페이지에 넣고도 1,068바이트가 남는다. 한 전투의 정확한 모델 최대는 131글리프이고, 가족별 독립 최대를 합친 안전 상한은 134글리프·2,144바이트다. 원본 페이지와 합친 재구축 상한은 6,240바이트다.

mapper 165 캐시 기반은 추가 PRG의 MMC3 페이지 `20`에 전역 코드북 296글리프·4,736바이트 아틀라스를, 페이지 `21`에 원본 4,096바이트 페이지와 3,028바이트 레시피를 배치한다. 총 두 페이지이며 원래 PRG 접두부·활성 고정 뱅크·CHR은 보존한다. 현재 기반 ROM SHA-1은 `39ff6c1ab54b12e6aa31d48584681b22ffdbe545`, 보고서 SHA-1은 `c8b4e9262c7dda7bd2a694c87053b843dac00520`이다. 레시피 소비 검증은 공용 사운드 테스트 11개·적 선공 11개·플레이어 선공 10개, 총 32개 불규칙 표본의 실제 전투 필드를 다섯 유효 튜플로 투영했다. `$7936=00`이 후반 `3E`가 되는 15표본도 원본 생산자 조건으로 장래 선택자를 미리 고른다. 모든 표본은 배경 `$1000`, 스프라이트 `$0000`이므로 CHR-RAM 대상 페이지에는 네임테이블 코드만 제약한다. 원본 글꼴 페이지의 활성 210코드는 일본어 번역 소유 111개와 비일본어 보존 후보 99개로 완전 분할된다. 전투 텍스트 보수 상한 134개와 비일본어 전역 합집합 39개를 합친 상한은 173/210이다. 실제 정규 코드 배치는 공용 69색을 보존 코드에서 제외하고 참가자·적·두 지형·대사 가족에 분산했으며 각 가족의 보수 충돌은 2개, 합계는 최대 8개다. 현재 표면 제약 보고서는 108색 물리 배정과 정규 코드 배정 SHA-1 `6180ed55a3fb34a964e21b1b9466bad267a588f9`를 만들었고 보고서 SHA-1은 `2a832f930effdc49ccc45c38dc097f0b84191d4e`다. 공용 렌더러 투영, 17바이트 재배치 저장소와 모든 배경 게시자·간접 쓰기 결속은 그대로 유지한다.

첫 입력 일반형 실행에서 `$047D`는 합성 다음 프레임에 원본 writer가 전체 바이트를 0으로 써서 준비·쌍 수 저장소로 쓸 수 없음이 확인됐다. 원본 의미는 그대로 두고 `$07DF`에 준비 비트와 쌍 바이트 수를, `$07E0..$07EF`에 쌍을 두도록 계약을 수정했다. `$07DF`는 `$0781` 큐 시작에서 94바이트 떨어져 최대 두 줄 큐 뒤에도 27바이트가 남고, 기존 직접·인덱스·간접 writer는 `$07DF..$07EF`를 건드리지 않는다. 스키마 11 보고서 SHA-1은 `db8d7d5e10a865340c4622d33d2c030a7f59b2b9`이다.

전체 전투 텍스트 개발 기반은 정규 코드 배정을 실제 바이트에 적용했다. 전투 레시피에 든 고정 원천 231개, 전투 대사 28레코드·65포인터, 예측창 라벨을 재인코딩했고, 공유 고정 작업공간 272개 중 전투 카탈로그 결측 41개는 원문 상태로 유지했다. 추적 쓰기는 325개다. MMC3 페이지 `20`에는 `$9400`의 210바이트 정규 코드표, 보호 추상색 39개, 안전 추상색 171개와 비트 마스크를 연속 배치한다. 정규 코드표 SHA-1은 `e8bb39dc53336845cc6e4e6508577498ca9aa0d4`다. ROM SHA-1은 `15fa8c5781f82dd914b49eb18f3ad6b96f1e09ad`, 보고서 SHA-1은 `faea6ecbfc30b2254d2a86e874600224af279c12`다.

이 기반 위의 합성 로더는 관측 튜플 허용 목록을 제거하고, 소스 모델이 덮는 참가자·병종·장비·지형·대사 입력을 같은 알고리즘으로 처리한다. 추가 PRG의 7개 루틴 364바이트가 열 레시피의 선택 색을 `$07C4..$07DE` 비트맵에 모은 뒤 보호색 충돌만 최대 8쌍으로 `$07E0..$07EF`에 배정한다. 고정 뱅크의 14개 루틴 812바이트는 원본 4 KiB 페이지를 복원하고 같은 투영으로 오버레이를 올리며, `$E57F` 공용 텍스트 읽기도 지원 전투 수명과 `$07DF` 준비 표식이 모두 있을 때만 같은 쌍을 적용한다. 일반 전투는 직후 상태 `17/33`에서만 `$07DF`를 지운다. 같은 공용 표시 엔진을 쓰는 사운드 테스트는 전체 관측 구간의 `$84=04`, `$05EE=0D`, `$7730=05`를 함께 판정하고, 각 반복 전투의 원본 `$047D=1` writer `07:$AC17`에서만 `$07DF`를 지워 다음 조합의 재합성을 연다. 원래 `A`·플래그·`$047D` 효과는 typed 래퍼가 보존한다. 배정이 8쌍을 넘으면 CHR-RAM 선택과 PPU 쓰기 전에 중단한다. 현재 다섯 관측 튜플의 상한은 고유 오버레이 90개·원시 글리프 참조 94개·PPU 쓰기 5,600회이며 실행 허용 목록이 아니다. 총 21개 typed RP2A03 루틴은 1,176바이트다. 조사 교정 뒤 현재 ROM SHA-1은 `4fbd624801af9cf6f5fe6d67e8e18b2cb3294117`, 보고서 SHA-1은 `eca896fd7901f54c0f8ee68bd39897648a1e7667`이다. 콜드 자연 전투 두 건에서 +43프레임 CHR-RAM/PPU 4,096바이트 일치, 중립 조사와 보호 영어 표시, 두 번째 전투 뒤 지도 복귀를 다시 통과했다. 과거 손상 ROM과 그 원인 격리 자료는 진단 계보로만 유지한다.

손상 ROM에서도 사운드 테스트의 서로 다른 여섯 조합과 콜드 연속 일반 전투 두 건의 합성 반환점은 독립 Rust 계산과 CHR-RAM 4,096바이트가 같았다. `$07DF`와 재배치 쌍도 7·19·43·82·171프레임의 불규칙 표본 동안 유지된 뒤 반복 시작점 또는 종료 상태에서만 정리됐고, 일반 전투의 두 번째 조합은 원본 조건으로 대사 선택자 62를 자연 투영했다. 별도 자동 엔딩 실행에서는 합성·투영·`$07DF` 쓰기가 한 번도 없어 비개입을 확인했다. 이 증거는 생산과 수명만 닫았고 PPU가 실제로 소비한 페이지는 닫지 못했다.

정확 최대 탐색은 가능한 모델 튜플의 텍스트 최대가 131글리프임을 증명했다. 전역 보호 코드 39개를 더한 정확 최대는 `170/210`, 보수적 안전 상한은 `173/210`이다. ROM `3399a2ab385e00ffa4a28ef70b653c16a69a9ed2`에서는 제어된 131개 오버레이·152개 글리프 참조, 재배치 6쌍과 독립/실제 CHR-RAM 일치, 일반·사운드 테스트·콜드 자연 전투 두 건의 판독 가능한 한국어와 지도 복귀를 통과했다. 조사 교정 뒤 별도 전투 ROM `4fbd624801af9cf6f5fe6d67e8e18b2cb3294117`과 아홉째 전투 단계 출력 `f5b72f9dd1b3bd99f9e09c77fc6035d867777710`도 각각 콜드 자연 전투 두 건에서 합성·표시·수명·정리를 통과했다. 이로써 전투 로더의 누적 통합 게이트는 닫혔지만 열째 단계까지 포함한 콜드 전투 회귀와 나머지 화면·분기, 사람 검토가 남아 전체 `runtime_verified`와 `release_eligible`은 계속 거짓이다.

동적 캐시 probe는 이 완성 페이지 4 KiB를 확장 PRG에 두고, 렌더가 꺼진 전투 NMI의 `$C191`에서 CHR-RAM으로 전송한다. 번역 원천 선택에서 생성한 상태 `16/32`, 순서 무관 참가자 `[04,85]`, 병종 `[01,08]`, 장착 무기 `[0C,1B]`, 지형 `[00,0B]`를 캐시 수용 범위로 삼고 런타임의 각 값을 포함 판정한다. 원본이 0/비0만 판정하는 전투 활성 바이트 `$047D`의 상위 비트 `80`을 1회성 표식으로 사용한다. 앞선 로컬 코드북 산출물은 플레이어 선공, 지형 `00/0B`인 첫 적 전투와 그 부분집합 `00/00`인 두 번째 적 전투에서 각각 `$047D`의 `01→81→00`, 원천과 CHR-RAM의 4,096/4,096바이트 일치, 한글 공격 문구와 원본 영어·숫자·그래픽을 통과했다. 새 전역 물리 배정 산출물의 ROM SHA-1은 `7191dc8043cd326d27c77794d01eb600b738519f`, 보고서 SHA-1은 `66445c113805047ed8d1373c094bc79363b1ab0d`이며 같은 콜드 회귀는 아직 다시 돌리지 않았다. 전체 캐시 카탈로그와 대사 selector 62 자연 표시가 남아 있어 `runtime_verified=false`다.

원천 504레코드는 각각 표시 단위 하나다. 여기서 나온 928개 가시 페이지 작업집합을 페이지별 코드북으로 묶은 결정적 정적 상한은 35페이지다. 실행 중 합성을 위한 실제 단일 페이지 수요는 최대 `188/210`이고 리터럴·동적 글리프 합집합은 713자다. 504레코드를 실제 페이지 코드로 인코딩한 결과 저장 `29,792/39,425`바이트와 517개 포인터가 11개 원천 소유 구간을 모두 통과했고 9,633바이트가 남는다.

동적 문자열 소비처도 전수 결속했다. `{EC:xx}` 소비 수요 142개가 공급 142개와 정확히 맞물리며 미결속·불일치·초과 공급이 모두 0이다. 생산자는 여섯 갈래다. 인물 후일담 106개는 `04:$A366`이 아군명을 슬롯 0에 넣고 전사 지명을 슬롯 1에 넣는 하나의 순회에서 나오고, 소지품 사용·결과 20개, 마을 사건 7개, 상점 4개, 소지품 초과 처리 3개, 투기장 내기 2개가 뒤를 잇는다. 저장 11구간, 포인터 517개와 hook을 합친 Expected Write가 만드는 변경 20,097바이트는 메모리 안에서 전수 추적했다. 대사 합성 재료는 MMC3 페이지 `2C..2E`, 나머지 12개 도메인의 공용 재료 풀은 `2F..3D` 15페이지로 분리했고 고정 코드 cave와 교체 가능 CHR 14페이지도 같은 배치도에서 계수했다. atlas 5,704바이트, 실제 스캔 자료 13,138바이트, 동적 remap 547바이트와 전역 런타임 식별표 1,350바이트를 직렬화해 합성 재료 Expected Write도 같은 이미지에 넣었다. 식별표는 `$77F4/$77F1`만으로 8개 디렉터리의 523슬롯을 해석해 517개 엔트리 결속과 6개 핸들러 빈칸을 거쳐 504레코드 전부를 주소화한다. 이 payload 20,739바이트와 5개 섹션 위치, 뒤의 실행 코드 3,791바이트 자리를 24,576바이트 고정 컨테이너로 묶어 다른 도메인의 시작점이 후속 구현에서 움직이지 않게 했다. 기여 도메인은 대사 하나, 실행·글꼴·전체 소비자까지 갖춘 완료 도메인은 0개다. 공용 풀 충분 판정은 아직 거짓이며 ROM은 만들지 않았다.

전역 제어 흐름도 원본 상태 머신에 결속했다. 초기·`E4`·`E6`·`E7` 복귀와 페이지 완료·외부 호출·종료만 요청 생산자이며, 기존 전투 NMI `$C191 → $FC20` 하나가 전투 우선순위를 보존한 채 요청을 소비한다. 콜드 재구성은 기존 페이지 `21`의 원본 글꼴을 기반으로 하고, 실행 코드는 페이지 `2E`에서 자료가 끝나는 자리부터 `$C000`까지, 고정 trampoline은 `$F400..$F4B0`을 쓴다. 현재 확보한 실행 코드 자리는 3,791바이트다. 기존 최대 대사 샘플용 훅 세 곳은 전역 구현에서 교체한다. 휘발 상태 5바이트는 `$07F0..$07F4`로 선택했다. 18개 처리기에서 도달하는 typed RP2A03 명령 1,173개를 추적해 직접 충돌 0곳, `$0781,X` 계산 쓰기 3곳, 간접 접근 32곳을 얻었다. 계산 쓰기는 큐 hard limit `$07DF`로 닫고, 간접 접근은 줄 버퍼·동적 슬롯·복사·직렬화·스크립트·애니메이션·스프라이트의 10개 생산자 역할로 완전 분할했다. 스프라이트 2단계 포인터는 선택자 `00..FE`의 510개 값을 전수 열거해 모두 `$8000..$BFFF` 안임을 확인했다. 16개 PRG 뱅크 전체 직접 피연산자 스캔의 세 후보는 모두 명령 내부 바이트로 판정했다. 동시에 실행되는 원본 NMI 277개 명령과 bank 0E 오디오 959개 명령에는 직접·인덱스 후보가 없다. 간접 읽기 38곳은 별도 6역할로 완전 분할했고, 원본 15뱅크의 `$BFC0` 기반 유효 주소도 전수 계산해 후보를 배제했다. 기존 전투 상태의 끝 `$07EF`도 단일 원천 상수로 다시 결속했다. 이 범위는 주 대사 활성 중에만 소유하며 모든 진입에서 5바이트를 콜드 초기화하고, `E7` 이탈·종료·reset·save/load·비활성 선택에서 무효화해야 한다. 초기화 코드와 hook은 아직 쓰지 않았고 ROM도 새로 만들지 않았다. 스키마 9 전체 설치 보고서 SHA-1은 `9d432edb8f349f848c5bf6f492fad8a0601ab3b6`이다.

## 과거 관문 기록

mapper 165 동등성 G2와 동적 글꼴 공급 G3, 전체 텍스트 모집단 G4는 통과했다. 504레코드를 실제 페이지에 합친 최대 대사 수요는 `188/210`이며 기존 전체 화면 최악 `209/210`을 넘지 않았다. 표시 단위·수명·정확 저장을 함께 닫아 G5를 완료했다. G6의 전역 상태 저장소 선택도 닫혔고, 다음 관문은 같은 계약에서 생산자·단일 NMI 소비자·선택자·동적 remap을 한 번에 생성해 누적 Expected Write에 넣는 것이다. 그 전에는 국소 설치 수를 완료율로 세지 않는다.

현재 기본 실행 산출물은 검증한 표면을 합친 누적 ROM이지만 게임 전반에서 한글과 그래픽이 온전한 패치는 아니다. 1·2장 도입 화면, 자동 병종 소개, 무기점의 품목·선택지·대사 거절 경로와 전투 합성 로더는 수명별 공급과 자연 이탈을 통과했다. 전체 번역 입력과 정규화 대사 저장 계획, 동적 문자열 생산자·소비자 결속은 닫혔지만 hook과 전체 동적 페이지 합성은 아직 ROM에 설치하지 않았다. 이 결과를 게임 전반의 한글화 완료로 일반화하지 않는다.

다음 통합 관문은 화면 성공 개수를 늘리는 것이 아니라 전체에서 가장 어려운 조건을 먼저 닫는 것이다.

- 완료한 전투 누적 통합을 기준선으로 유지하며 이후 단계가 같은 고정 뱅크와 선택자 범위를 침범하지 않게 한다.
- `C0:18`의 완료 페이지 재적재와 출력 해시 결속을 기준선으로 유지한다.
- 완료: 제목 그래픽의 `117/121` 타일 수요를 전역 커버리지의 36번째 화면으로 등록하고 G5 전역 최악 `209/210`을 확정했다.
- 가장 긴 조판·저장 구간과 가장 복잡한 진입·이탈·재진입도 같은 누적 구조에서 통과한다.
- 최종 누적 ROM에서 대상 일본어 0건, 보호 영어·숫자·그래픽 손상 0건을 기계 검사와 실행 회귀로 함께 닫는다.
- 기준선 성공 경로와 치트를 끈 실패·패배 경로를 분리해 검증한다.

주 대사 2,541개 의미 줄은 모두 검토 대기 초벌이지만 승인 완료는 0줄이다. 전투 대사 70개 의미 줄도 검토 대기이며, 전투 고정 문자열 272개 중 22개만 승인 완료다. 따라서 번역 자산의 채움과 실제 표시 적용, 사람 승인을 각각 별도 진척으로 유지한다.

## 과거 작업 목록

1. 완료: 조사 교정 뒤 전투 ROM과 누적 ROM의 자연 전투를 재검증했다.
2. 완료: 전투 합성 로더를 누적 ROM 경로에 합치고 기존 시작·도입·부대 목록과 전투를 같은 콜드 산출물에서 재검증했다.
3. 완료: 주 대사의 175자 최대 레코드를 구조로 식별했다.
4. 완료: 11장 장 종료 표본의 선택자 `C0:1C`가 최대 레코드와 다름을 확인해 잘못된 수명 결속을 폐기했다.
5. 완료: 7장 성 이벤트가 최대 레코드를 `C0:18`로 생산하고 11장의 같은 번호는 `30:18`임을 소스에 결속했다.
6. 완료: 7장 `C0:18`의 15페이지·90표본을 관측해 전체 상주 불가·페이지 단위 수용 가능을 확정했다.
7. 완료: 15페이지를 세 글꼴 묶음으로 설치하고 초기 선택기·완료 페이지 재적재·점멸 위상·`NEXT STORY` 이탈을 정확한 출력 해시에 결속했다.
8. 완료: 504레코드 한국어를 합친 최대 대사 수요 `188/210`이 기존 36개 화면의 최악 `209/210`을 넘지 않음을 다시 계산했다.
9. 완료: 레코드 프리픽스를 실제 여덟 배치대로 읽어 직접·전이 두 모드가 갈라져 보이던 원인을 없앴다. 번역 뷰는 2,814줄 하나이며 미번역 일본어는 0줄이다.
10. 완료: 504개 표시 단위를 정확한 저장 `29,792`바이트와 517개 포인터에 결속하고, `{EC:xx}` 소비 수요 142개를 모두 원본 생산자에 이었다.
11. 진행 중: 검증한 대사 계획과 동적 페이지 합성, 나머지 텍스트 도메인을 하나의 추적 이미지에 합친다. 504레코드의 공통 상태 머신과 단일 NMI 소비자는 고정했고 5바이트 휘발 상태 `$07F0..$07F4`의 수명 소유권도 선택했다. 동적 문자열은 소비 수요 142개가 공급 142개와 맞물렸다. 다음에는 소비자·선택자·동적 remap과 콜드 초기화를 한 단위로 생성한다.
12. 구매·실패·패배·저장·장 전환·엔딩을 포함한 대표 극단 경로를 최종 동일 ROM 계보에서 검증한다.
