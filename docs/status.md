# 현재 상태

마지막 확인: 2026-08-22

이 문서는 현재 기준선과 바로 다음 관문만 기록한다. 과거 원인과 판단은 `decisions.md`, 실행 계보와 화면 근거는 `playtesting.md`, 아직 열린 문제는 `open-problems.md`가 맡는다.

## 현재 작업 모드

새 화면·번역·기능 진전은 동결한 채 유지한다. 이미 존재하는 한글화 경로의 소유권 통합은 끝났고, 리팩터링과 lint 정리 전 exact 기준선은 다음과 같다.

- 누적 ROM SHA-1: `B9A5F6E8A71259BA83103AF0EA5E0FF57569DF53`
- 누적 보고서 SHA-1: `4BA4D398420C09E47AA20BD27E453B0177DEC037`
- 통합 ROM SHA-1: `C50BC2E15EB51CB482DB906DB3BFF1FFC24C5F67`
- 통합 설치 보고서 SHA-1: `33E50FCDD24E68447190734E00D410224BD54625`
- 리팩터링 전 전체 Rust 시험: 1,101개 통과

현재 소스에서 제품 산출물을 다시 만들었고 네 해시가 모두 위 기준선과 일치했다. 구조 정리 뒤 전체 Rust 시험은 죽은 프로브 전용 시험을 제거한 1,094개가 통과했다. `cargo check`, `cargo fmt --check`, `cargo clippy -p fc-fire-emblem-patch --all-targets -- -D warnings`, `git diff --check`도 통과했다. 따라서 이번 리팩터링과 전용 lint 정리는 ROM과 보고서 바이트를 바꾸지 않았다.

## 통합 구조

전투와 주 대사의 원본 런타임 ABI는 각각 한 모듈이 소유한다.

- `battle_runtime_state.rs`: 전투 레코드, 스테이징 필드, 공용 전투 위상, 활성 플래그, 대사 선택자 투영, 새 합성 수명 시작 writer
- `dialogue_runtime_state.rs`: 주 대사 엔트리·디렉터리·상태·완료·호출자 인계와 공용 외부 상태 주소
- `mapper165/battle_composition_runtime/`: 누적 빌드와 진단 CLI가 함께 쓰는 제품 전투 합성기
- `mapper165/battle_text_material.rs`: 전투 atlas·코드표·레시피 재료 배치
- `mapper165/dialogue_font_page.rs`: 공용 한글 글리프 코드 배정과 페이지 생성
- `mapper165/ui_page_install.rs`: 설정·명단 UI 페이지 설치

분석, 코드 생성, 설치 검증, 시간축 검증이 위 상태 계약에서 주소와 필드 순서를 파생한다. `$7936`의 전투 대사 엔트리 선택자와 `$FBD4`의 대사 글꼴 페이지 선택 루틴도 서로 다른 역할명으로 분리했다.

구형 `battle-combination`과 고정 `battle-cache-upload` 프로브는 현재 제품 경로가 아니었다. 두 CLI와 전용 모듈, 전용 캐시 범위 계산, 뒤에 남은 죽은 코드북 API를 제거했다. 1장 관측 활성 코드 집합은 그것을 실제로 소비하는 코드북 용량 분석으로 옮겼다. 제품 빌드가 `_probe` 모듈을 라이브러리처럼 가져오는 경로도 없앴고, 프로브 명령은 제품 API를 호출하는 얇은 CLI 어댑터만 남긴다.

## 제품 기준선

정적 설치 기준은 바뀌지 않았다.

- 지원 원본 SHA-1은 `0179C550D424E0397496078789E7B116601D120C`다.
- 선언된 설치 도메인은 14개다.
- 주 대사는 504레코드, 2,814줄, 928개 페이지 작업집합이다.
- 일본어 대상 44개 화면 수명은 모두 정적 페이지 예산 안에 들어가며 미측정 역할은 0개다.
- 전투 런타임은 이름·병종·장비·지형·대사를 한 recipe-field 계획으로 수집하고 적용한다.
- 번역 기준안은 채택됐고, 일본어 번역 대상의 작업공간 잔존은 0줄이다. 사람별 승인 표식은 출시 판정과 별도로 남는다.

이는 설치·수용량 계약이다. 게임 전체 실행 완료나 배포 가능성을 뜻하지 않는다.

## 현재 열린 관문

1. 기능 동결을 해제한 뒤에만 다른 장의 대표 시설과 장 종료 뒤 잔류 맵·초상화·대사 변형을 같은 exact ROM의 목적별 묶음으로 실행한다.
2. whole-program 매퍼 간접 edge는 정적으로 유한하게 줄어드는 구간만 분석하고, 동적 값이 필요한 경계는 실행 계측으로 넘긴다.
3. 전체 소비 경로 분모, 실기 범위, 최종 패치 패키징이 닫히기 전에는 배포 후보로 부르지 않는다.

한 화면의 단독 성공은 통합 완료로 세지 않는다. 새 결함은 화면 문구 예외가 아니라 생산자 → 재료 → 상주 계획 → 런타임 투영 → 최종 소비의 첫 공통 불일치에서 고친다.
