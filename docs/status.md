## 현재 관문

전체 한글화의 선행 조건은 정식 글꼴 공급 구조다. 원본 CHR 8,192타일 가운데 7,849타일이 비어 있지 않고, 첫 글꼴 페이지에서 전부 0인 타일은 `95`, `FF`뿐이다. 원본 MMC4의 고정 CHR-ROM에 완성형 한글을 상주시키는 안은 채택하지 않는다.

[작업 로드맵](roadmap.md)의 G1 가운데 정적 CHR 목록, 확인된 설정·상태 표의 초기 보호 판정, MMC4 공급 루틴 목록과 1장 초반의 주요 문자 화면 실측을 구현했다. 관측한 모든 문자 화면은 `$5B=00`을 사용하고 화면별 그래픽을 `$5C`에 짝지었다. 문자창이 없는 맵에서는 페이지 00이 빠지고 그래픽 페이지 `15`, `18`, `19`가 교체되므로 동적 글꼴 수명은 화면 전환과 결속해야 한다. 상세 근거는 [렌더 경로 조사](render-paths.md)에 있다.

첫 텍스트 모집단 7개 표는 소비자와 저장 경계를 확인했고, 적 이름·장 제목의 합성 파서에서는 `0F`·`1F`가 출력 폭을 늘리지 않는 결합부호이며 `FF`가 빈 오버레이임을 확인했다. 기존 보호 42코드와 이 세 코드를 제외하면 현재 한글 활성 슬롯 상한은 211개다. 그러나 대사·메뉴·전투 메시지를 포함한 전체 모집단은 아니며, 이는 화면별 최종 예산이 아니다. 미분류 1,743바이트는 비공백 타일 대응 1,693바이트와 전부 0인 `FF` 타일 대응 50바이트로 나뉘지만, 다른 다운스트림 표시 의미가 확인되기 전에는 번역 대상으로 계수하지 않는다. 전투·상점·저장·장 전환·엔딩 렌더 경로와 다른 문자열·그래픽 참조자가 남았으므로 나머지 211개 미확정 글꼴 코드를 회수 후보로 승격하지 않는다.

실제 대사 본문은 `$8F39`이 아니라 뱅크 `0A`의 별도 경로임을 확인했다. ROM 스크립트는 `$E69C`를 통해 32바이트 간격인 SRAM 줄 버퍼로 옮겨지고, `$83BA` 계열이 같은 폭의 오버레이·기본 문자 두 평면을 만들어 공통 PPU 큐로 보낸다. 15개 제어의 현재 포인터 진행과 구조 효과도 닫았다. `E4/E6`는 현재 포인터를 한 바이트만 진행하지만 저장 형식상 뒤의 전환 대상 두 바이트까지 포함한 3바이트 토큰이므로, 추출·재삽입기는 세 바이트를 함께 보존해야 한다.

대사 구조 스캐너는 8개 진입 표의 534개 포인터와 481개 고유 진입점을 원문 없이 열거한다. 이 가운데 7개 표는 `$BFE0` 주 디렉터리 루트까지 연결했고, 전투 표는 뱅크 `04:$8000`의 별도 포인터 로더와 `$802D → $845B` 루트를 연결했다. 전투 형식을 주 대사 문법과 섞지 않으며, 안전한 엔트리 끝을 아직 닫지 않았으므로 대사 추출 완료나 번역 준비 완료는 선언하지 않는다.

주 대사의 `$77F7` 18상태 디스패처와 첫 줄 앞 레코드 프리픽스도 연결했다. 영입 표에서 네 엔트리가 공유하는 `$AA2B` 실행 처리자를 대사와 분리한 뒤, 452개 고유 대사 진입점에서 `E5` 선택 6바이트, 고정 4바이트, `E8` 선택 6바이트를 원본 명령대로 분리해 첫 줄 위치를 얻었다. 두 선택 프리픽스가 모두 있는 진입점은 15개, 둘 다 없는 진입점은 227개다. 아직 의미가 닫히지 않은 상태 처리자 11개와 분기 뒤의 전체 도달 가능성은 계속 미확정이다.

첫 줄에서 시작해 `ED/EE/EB` 뒤를 잇는 초기 선형 구간도 공통 15개 제어 계약으로 전수 검사했다. 452개 구간은 총 2,680줄, 최대 57줄이며 첫 비선형 경계는 `EF` 206, `E7` 85, `E4` 40, `E6` 121개다. `E4/E6` 전환 161개는 모두 선언 표 범위 안이다. 원문은 기록하지 않고 줄·구간별 저장 SHA-1·길이·제어 개수만 남겼으며 숫자·대문자 리터럴 37바이트는 번역 비대상으로 분리했다. `E7/E4/E6` 이후는 아직 연결하지 않았으므로 전체 엔트리 완료를 뜻하지 않는다.

## 다음 작업

1. `E7/E4/E6` 경계의 후속 상태 진행과 전이 간선을 연결해 주 대사 제어 흐름 그래프를 만든다.
2. 그래프의 도달 가능성·종료성과 아직 의미가 닫히지 않은 상태 처리자를 확인한다.
3. 같은 구조 계약을 쓰는 대사 재삽입기를 만들고 개수·해시·경계 왕복으로 검증한다.
4. 메뉴·전투 메시지의 포인터·인라인 문자열을 소비자별로 추가한다.
5. 214개 미확정 코드의 소비 여부를 판정하고 보호 고정 슬롯과 한글 활성 슬롯 예산을 확정한다.
6. 매퍼 후보와 지원할 에뮬레이터·플래시 카트 범위를 결정한다.

매퍼 비교와 첫 실험 조건은 [매퍼 후보 판정](mapper-candidates.md)에 정리한다. 현재 우선 실험 후보는 MMC5지만 아직 채택하지 않았다.

동적 한글 글꼴 관문이 통과하기 전에는 설정 PoC의 번역 범위를 늘리지 않는다.
