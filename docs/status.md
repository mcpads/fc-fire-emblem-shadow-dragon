## 현재 관문

전체 한글화의 선행 조건은 정식 글꼴 공급 구조다. 원본 CHR 8,192타일 가운데 7,849타일이 비어 있지 않고, 첫 글꼴 페이지에서 전부 0인 타일은 `95`, `FF`뿐이다. 원본 MMC4의 고정 CHR-ROM에 완성형 한글을 상주시키는 안은 채택하지 않는다.

[작업 로드맵](roadmap.md)의 G1 가운데 정적 CHR 목록, 확인된 설정·상태 표의 초기 보호 판정, MMC4 공급 루틴 목록과 1장 초반의 주요 문자 화면 실측을 구현했다. 관측한 모든 문자 화면은 `$5B=00`을 사용하고 화면별 그래픽을 `$5C`에 짝지었다. 문자창이 없는 맵에서는 페이지 00이 빠지고 그래픽 페이지 `15`, `18`, `19`가 교체되므로 동적 글꼴 수명은 화면 전환과 결속해야 한다. 상세 근거는 [렌더 경로 조사](render-paths.md)에 있다.

첫 텍스트 모집단 7개 표는 소비자와 저장 경계를 확인했고, 적 이름·장 제목의 합성 파서에서는 `0F`·`1F`가 출력 폭을 늘리지 않는 결합부호이며 `FF`가 빈 오버레이임을 확인했다. 기존 보호 42코드와 이 세 코드를 제외하면 현재 한글 활성 슬롯 상한은 211개다. 그러나 대사·메뉴·전투 메시지를 포함한 전체 모집단은 아니며, 이는 화면별 최종 예산이 아니다. 미분류 1,743바이트는 비공백 타일 대응 1,693바이트와 전부 0인 `FF` 타일 대응 50바이트로 나뉘지만, 다른 다운스트림 표시 의미가 확인되기 전에는 번역 대상으로 계수하지 않는다. 전투·상점·저장·장 전환·엔딩 렌더 경로와 다른 문자열·그래픽 참조자가 남았으므로 나머지 211개 미확정 글꼴 코드를 회수 후보로 승격하지 않는다.

실제 대사 본문은 `$8F39`이 아니라 뱅크 `0A`의 별도 경로임을 확인했다. ROM 스크립트는 `$E69C`를 통해 32바이트 간격인 SRAM 줄 버퍼로 옮겨지고, `$83BA` 계열이 같은 폭의 오버레이·기본 문자 두 평면을 만들어 공통 PPU 큐로 보낸다. 15개 제어의 현재 포인터 진행과 구조 효과도 닫았다. `E4/E6`는 현재 포인터를 한 바이트만 진행하지만 저장 형식상 뒤의 전환 대상 두 바이트까지 포함한 3바이트 토큰이므로, 추출·재삽입기는 세 바이트를 함께 보존해야 한다.

대사 구조 스캐너는 9개 진입 표의 588개 포인터와 534개 고유 진입점을 원문 없이 열거한다. 이 가운데 8개 표는 `$BFE0` 주 디렉터리 루트까지 연결했고, 전투 표는 뱅크 `04:$8000`의 별도 포인터 로더와 `$802D → $845B` 루트를 연결했다. 에필로그 라우팅 표는 `04:$A17E`의 선택자 코드와 `04:$BFE2 → $B96C` 루트를 함께 고정한다. 전투 형식을 주 대사 문법과 섞지 않으며, 전투 레코드 범위는 아직 닫지 않았으므로 전체 대사 추출 완료나 번역 준비 완료는 선언하지 않는다.

주 대사의 `$77F7` 18상태 디스패처와 첫 줄 앞 레코드 프리픽스도 연결했다. 영입 표의 `$AA2B`와 에필로그 라우팅 표의 `$C73D` 실행 처리자를 대사와 분리한 뒤, 504개 고유 대사 진입점에서 `E5` 선택 6바이트, 고정 4바이트, `E8` 선택 6바이트를 원본 명령대로 분리해 첫 줄 위치를 얻었다. 두 선택 프리픽스가 모두 있는 진입점은 15개, 둘 다 없는 진입점은 227개다. 아직 의미가 닫히지 않은 상태 처리자 10개와 호출자별 결과는 계속 미확정이다.

첫 줄에서 시작해 `ED/EE/EB` 뒤를 잇는 초기 선형 구간도 공통 15개 제어 계약으로 전수 검사했다. 504개 구간은 총 2,732줄, 최대 57줄이며 첫 비선형 경계는 `EF` 206, `E7` 85, `E4` 92, `E6` 121개다. `E4/E6` 전환 213개는 모두 선언 표 범위 안이다. 원문은 기록하지 않고 줄·구간별 저장 SHA-1·길이·제어 개수만 남겼으며 숫자·대문자 리터럴 37바이트는 번역 비대상으로 분리했다. 이 선형 검사만으로는 비선형 경계 뒤의 전체 엔트리 완료를 뜻하지 않는다.

각 주 대사 포인터에서 레코드 프리픽스와 이 초기 선형 구간을 합친 소비 범위도 닫았다. 504개 레코드의 소비량 합계는 39,642바이트지만 실제 고유 저장은 39,425바이트다. 마을·아웃트로, 영입, 상점·아이템, 에필로그 표에서 6쌍이 217바이트를 공유하며 최대 중첩 깊이는 2다. 이는 단순한 포인터 별칭과 별개이므로, 재삽입기는 엔트리 504개를 독립 덮어쓰기 단위로 쓰지 않고 공유 저장을 정규화해야 한다.

원문 왕복기는 이 504개 레코드를 PRG 뱅크 경계를 지키는 11개 비중복 소유 구간으로 합친다. 무시된 로컬 자산을 다시 읽어 각 구간의 길이·SHA-1·레코드 참조를 원본에서 재계산한 값과 대조하고, 중복 없는 추적 쓰기로 재구성한 ROM이 지원 원본과 바이트 단위로 같은지 확인했다. 이는 공유 저장 처리와 직렬화의 원문 왕복 관문이며, 아직 번역 입력이나 길이 변경을 허용하는 재삽입기는 아니다.

일본판 글꼴의 `00`~`5F` 가나·결합부호·문장부호와 `84`~`8B` 작은 가나를 일본어 원천으로 고정했다. 숫자·대문자 `60`~`83`과 나머지 기호는 비일본어로 남는다. 주 대사에서 중복을 제거한 일본어 리터럴은 27,916바이트지만, 공유 레코드에서 다른 엔트리의 프리픽스·제어·피연산자로도 읽히는 16바이트는 직접 수정 대상에서 제외한다. 따라서 현 구조에서 안전하게 번역 입력으로 승격할 수 있는 일본어 원천은 27,900바이트이며 비일본어 리터럴 2,877바이트는 그대로 보존한다.

비공개 작업 골격은 504개 레코드의 2,732줄을 안정 ID, 번역 상태, 일본어 문자와 보존 토큰으로 분리한다. 숫자·대문자는 읽을 수 있는 원문 그대로 유지하고, 미확정 기호·공백·제어·피연산자는 토큰으로 잠근다. 검증기는 작업 파일의 원본 결속 필드를 지원 ROM에서 다시 계산하고, 기존 영문이나 토큰의 추가·삭제·변경 및 번역 필드의 일본어 잔존을 거부한다. 현재 `korean` 필드는 모두 비어 있으며 구조 충돌 16바이트가 든 6개 줄만 재배치 필요 상태다.

가변 길이 배치기는 이 작업 골격을 원본의 11개 소유 구간과 포인터 쓰기 517곳에 결속한다. 무수정 입력은 공유 217바이트를 그대로 한 번만 소유해 39,425바이트 원본 배치를 재현한다. 번역으로 공유 내용이 달라지면 해당 레코드를 분리하고 뒤 레코드의 포인터를 다시 계산하며, 증명되지 않은 뱅크 여유나 다른 데이터를 침범하지 않는다. 현재 결과는 논리 글리프 길이와 포인터 계획일 뿐 한글 코드나 ROM을 생성하지 않는다.

MMC5 우선 후보에는 PRG/SRAM 정적 프로브를 추가했다. 리셋 벡터는 확인된 `FF` 구간의 초기화 루틴으로 보내고, PRG 모드 1·마지막 ROM 뱅크·PRG RAM 쓰기 허용을 설정한 뒤 원본 리셋으로 돌아간다. 중앙 뱅크·미러링 루틴과 부팅, `$E69C` 대사 바이트 읽기, `$E6B2` 인덱스 포인터 표 경로의 직접 PRG 뱅크 쓰기 여섯 곳도 원본 길이를 유지한 호출로 교체한다. 새 실행 코드는 typed RP2A03 명령으로만 조립하며 모든 ROM 변경은 예상 원본 바이트와 최종 변경 감사에 결속했다.

콜드 런치의 첫 PC와 다섯 MMC5 초기화 쓰기, 원본 리셋 진입, 부팅의 임시·복귀 PRG 뱅크 전환은 히트 시점 이벤트로 확인했다. 뱅크 계산 중 A와 상태 플래그도 원본 관찰값으로 복원됐다. 다만 실제 저장·불러오기는 아직 확인하지 않았고, MMC4 CHR 래치를 변환하지 않은 120프레임 실행은 CPU만 진행한 채 화면이 깨졌다. 따라서 G2 전체가 아니라 PRG 부팅 하위 관문만 통과한 상태다.

첫 CHR writer 프로브는 검증된 PRG 프로브를 그대로 재생성한 뒤 CHR 모드 1과 네 중앙 공급 루틴을 추가한다. 원본 그림자·A 반환값·루틴 길이를 유지하고 PPU `$0000/$1000` 창을 `$5123/$5127`에 연결하지만, 각 창의 FD/FE 쌍을 마지막 쓰기 하나로 축약한다. 중앙 루틴만 옮긴 빌드의 프레임 1928 실패를 같은 프레임 메모리와 매퍼 상태로 대조한 결과, 화면 데이터나 래치 공존이 아니라 뱅크 `0D`의 직접 쓰기 네 곳이 누락된 것이 원인이었다.

실행 PC와 명령 경계를 확인한 `0D:$8036/$8039`, `0D:$83AB/$83AE`를 원본 3바이트 길이 그대로 추가 변환했다. 보완 프로브는 무입력 프레임 1206 타이틀 해시 `7653368704bf030f7dcbcbfb64cf0d3c3a4bd039b8cba11ef88d3d1d0e674c59`와 프레임 1928 자동 능력치 해시 `e2893dd71c6f93d1a29e2bc40256e0563e75332c3d2f6eca98277435c06215a1`를 각각 원본과 정확히 재현했다. 이는 두 화면의 하위 관문만 통과한 것이며, 남은 직접 쓰기 후보와 실제 FD/FE 래치 공존 화면이 있으므로 G2 전체 통과 근거로 사용하지 않는다.

확장 CHR 프로브는 원본 CHR 전체를 상위 절반에 복제하고 검증된 store를 A·상태 플래그 보존 래퍼로 보내 페이지 번호에 `20`을 더한다. 상위 첫 페이지의 설정용 일본어 12타일만 한글 PoC로 바꾸므로 하위 원본 CHR과 기존 영어 타일은 수정하지 않는다. 프레임 1206은 원본 화면 해시를 유지했고 프레임 1928은 상위 한글 타일이 실제로 표시된 해시 `08ee146844737028ab17b18a4135ca6c44359407890bba6fe14d4f27334a835b`를 냈다.

같은 새 게임 입력에서 처음 확인한 분기는 `$E6B2` 인덱스 포인터 표 경로였다. `$E6BA/$E6F1`을 옮겨 carry 분기를 복구한 뒤에는 `$E69C`의 `$E6A1/$E6AB`가 선택 대사 뱅크 대신 현재 뱅크의 바이트를 읽는 다음 원인으로 드러났다. 이 두 쓰기도 옮기자 `$80AA` 비교 직전 A는 원본과 같은 `E5`였다. 프레임 3965에서 네임테이블·팔레트·OAM·PRG RAM, 프레임/사이클과 선택 PRG 뱅크도 원본과 같아졌다. 남은 직접 `$A000` 후보 다섯 곳은 이 표본에서 적중하지 않았다. 다만 내부 RAM 15바이트와 CPU PC 한 바이트, CHR 표시가 달라 전체 진행·화면 동등성은 아직 통과하지 못했다.

이 화면의 원본 MMC4 오른쪽 FD/FE 뱅크는 `00/18`로 달랐고, 네임테이블 1에는 FD 18개·FE 81개의 실제 래치 트리거가 있었다. 새 투영기는 각 트리거 타일에 이전 래치를 적용한 뒤 다음 타일부터 전환하고 원본 팔레트를 보존한다. 생성한 1 KiB를 MMC5 ExRAM에 제어 주입한 화면은 원본 본문 61,416픽셀과 일치했다.

다음 프로브는 정적 1 KiB를 ROM에 넣고 오른쪽 FD·FE 공급 루틴 양쪽에서 쌍 `00/18` 완성을 검사한다. 실제 실행에서 두 번째 공급 뒤 `$FAC0` 복사 루틴이 한 번 적중했고, 외부 메모리 쓰기 없이 같은 화면 결과를 재현했다. 복사는 A·X·상태 플래그를 보존한다. 이로써 목표 화면의 mode 2 쓰기와 mode 1 표시 소유는 ROM 안으로 들어왔지만, 제로 스크롤 단일 화면에 고정된 데이터다. 후속 네임테이블 갱신, 미세 스크롤·두 타일 선행 fetch·네임테이블 경계 정책은 아직 구현하지 않았다.

`E4/E6` 213개는 대상 엔트리의 실제 포인터와 결속했다. 별칭을 같은 저장 노드로 합친 504개 그래프에는 코드 처리자 대상, 누락 간선, 순환이 없다. 명시 전이를 따라가면 최대 15단계 안에 336개 노드는 `EF`, 168개 노드는 `E7`에 도달한다. 새로 포함한 에필로그 라우팅 스크립트 52개는 일본어 본문이 아니라 모두 선택자 `40` 엔트리 0으로 합류하는 구조 엔트리다. `E7`은 공통 선택지 코드가 아니라 `$7809`를 통해 외부 호출자에 제어를 넘기는 경계다. 상태 17은 호출자가 고른 현재 엔트리를 `$E6B2`로 다시 결속하고 상태 9로 복귀한다. PRG의 `$7809` 읽기 5곳은 모두 고정했지만 각 호출자의 결과 의미는 아직 분리하지 않았다.

다섯 `$7809` 읽기 위치를 외부 상태표와 대조하면 네 처리자가 11개 디스패처의 22개 상태 슬롯에서 재사용된다. 특히 뱅크 `06:$A13E` 하나가 여섯 표의 15개 슬롯을 맡으므로 읽기 위치 수를 시나리오 수로 볼 수 없다. 뱅크 `04:$A20F`는 직접 상태표 결속을 아직 찾지 못했고 간접 호출 가능성도 닫지 않았다.
