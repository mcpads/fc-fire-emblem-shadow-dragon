## 2026-08-14 동적 문자열 가블 원인과 현재 경계

현재 이름·아이템 가블의 직접 원인은 글리프 저장량 부족이 아니라 인코딩 계층 혼용이다. 전투·메뉴 공유 표는 화면별 색칠 코드북이라 동일 바이트가 여러 글리프를 뜻하는데, 주 대사 `{EC}` 경로가 이를 전역 canonical 코드처럼 소비하려 했다. 현재 설치 계획은 공유 표를 바꾸지 않고 아이템 91개·아군명 53개·지명 24개, 합계 168개를 전용 무충돌 저장소로 만들며 다섯 생산자 훅을 그 저장소에 결속한다. 원문 표에서 누락됐던 마지막 인물 `가토`도 색인 52로 포함했다.

소비자에 별도 remap 훅을 더하지 않았다. 동적 글리프 187개에 대해 각 글리프가 나타날 수 있는 모든 페이지의 보존 코드를 금지 조건으로 모으고, 충돌 없는 canonical 물리 코드를 이분 매칭으로 배정했다. 전체 928개 작업집합과 장 제목·전이 수명을 다시 묶은 36개 그룹이 `210/210` 안에 들며, 세 동적 그룹의 366개 결속은 전부 `canonical 코드 = 페이지 물리 코드`다. 따라서 페이지 선택자는 순수 그룹 색인이고 remap 재료는 0바이트이며, 전투가 소유한 공용 reader `$E57F`도 그대로다.

정적 전체 설치 계획은 15개 런타임 훅, 고정 루틴 16개, 실행 페이지 루틴 4개를 하나의 Expected Write 집합으로 받아들였다. 최신 정확 개발 출력의 SHA-256은 `d766f9f9a06c359daabc6d56cf0d0b8e2d22722720b0e0c82ce2b54cacc42b55`다. 생산자·소비자 인코딩 결속은 정적으로 닫혔다. 같은 정확 출력의 콜드 실행에서 제목, 시작 메뉴, 1장 첫·둘째 대사 페이지를 확인했고, 둘째 페이지는 콜드 합성 중간 300프레임에는 빈 보호 화면을 유지한 뒤 합계 800프레임에 `ready(3)`와 읽을 수 있는 한글을 함께 보였다. 기존 소지품 사용 도달 상태에서는 유닛 `도가`, 아이템 `상처약`, 숫자 `1`이 한 화면에 표시됐고 동적 슬롯 바이트 `98 21 EF / AA 4E 96 EF / 61 EF`가 정확 출력의 전용 저장소와 일치했다.

같은 정확 출력의 현재 mapper 계보에서 사운드 테스트의 검증된 `SELECT` 효과로 자동 엔딩에 들어가 첫 `$A168` 선택 경계를 다시 만들었다. 명단 영역만 바꿔 identity `35`·routing action `FF`·location `05` 한 후보를 남기고 흐름 상태 네 바이트는 보존했다. 인물 슬롯 `F6 0E EF`, 지명 슬롯 `8E 0A C5 1A 08 B3 EF`, selector `41:35`가 현재 ROM 재료와 일치했고 225프레임 뒤 `ready(3)`에 도달했다. 이후 불규칙 표본에는 `가토`, `가토 / 오렐르앙`, `오렐르앙북부에서 / 쓰러졌다`가 초상화·창과 함께 읽히고 후속 direct `40:00`으로 정상 진행했다. 따라서 인물·아이템·지명·숫자 대표 동적 소비는 저장부터 실제 표시까지 통과했다. 이 명단 개입은 자연 게임에서 action `FF`가 된 원인이나 정상 완주 경로를 증명하지 않으며, 나머지 화면군은 계속 별도 실행 관문이다.

그 뒤 전체 설치 계획은 비대사 12개 도메인의 실제 한국어 논리열도 버리지 않고 공유 글리프 atlas 색인으로 직렬화한다. 공유 atlas는 대사 코드북 714자와 거기에 없던 9자를 합친 723타일·5,784바이트다. 비대사 재료는 12섹션·323엔트리·payload 3,786바이트이고 16바이트 정렬을 포함한 범위는 3,866바이트다. MMC3 페이지 `31..3D`의 106,496바이트 안에 들어가며, 각 섹션은 번역 입력·엔트리 정체성·내용 digest와 별도 Expected Write를 가진다. 통합 쓰기는 598개이고 13개 필수 도메인이 모두 같은 이미지에 기여한다.

스키마 13 계획은 화면 레지스트리의 소비자 분모, 정확 누적 후보가 이미 가진 투영, 새 전역 대사 런타임이 실제로 추가하는 투영을 한 표로 합친다. 현재 후보 SHA-1 `1ddc435b5e678c214c2273ce7a665ba4bf0ade13`와 보고서 SHA-1 `a7d971b6ffd4ffe9fc5cb5b97afec6f55720d52c`에 결속한 결과, 13개 중 소비자까지 정적으로 닫힌 도메인은 `main_dialogue`와 후일담의 `location_names`, 합계 **2 / 13**이다. `unit_names`는 후일담 소비자가 새로 닫혔지만 후보가 52명만 싣고 현재 정본이 53명이므로 전투·부대 명단·요약·상태는 남는다. 기존 소비자를 가진 도메인은 7개, 새 전역 경로가 화면 또는 같은 화면의 전체 모집단을 전진시킨 도메인은 4개, 미완료 도메인은 11개다. 따라서 `cross_domain_consumer_writes_planned=false`, `integrated_candidate_ready=false`는 그대로다.

52명 후보를 현재 53명 입력의 완료 산출물로 가장하지 않는다. 53명 정본이 만든 212색 clique는 전역 논리 코드북의 하한이지만 한 전투가 동시에 요구하는 물리 슬롯의 하한은 아니다. 현재 설계는 논리색 212개를 유지하고, 모든 보존 전투 리터럴에 없는 표시 코드 2개만 논리 원천으로 빌린 뒤 선택된 전투를 활성 물리 코드 210개에 투영한다. 보수적 텍스트 수요 134개와 보호 그래픽 39개는 `173/210`, 정확 모델 최대는 `170/210`이며 재배치 수요는 `7/8`이다. 깨끗한 누적 빌드는 전투 기반과 합성 로더까지 생성했으므로 의미나 글리프를 줄이는 회피는 필요 없다.

7장 최대 대사의 전체 작업공간 SHA 결박도 좁혔다. 페이지 경계가 실제로 의존하는 레코드 포인터·626바이트의 글리프/제어 구분·57개 줄 경계만 정규화한 topology SHA-1은 `5ee3b66823c66070447a180a63058a2e1277b75a`다. 과거 최종 출력 `1ddc435b5e678c214c2273ce7a665ba4bf0ade13`은 이 15페이지 topology와 481개 한글 바이트 자리를 보존했고, 현재 최대 대사 단계 `80f63bc4cb6afa977ade127af60aafd4f17275b0`은 현재 글리프 래스터까지 정확히 만족했다. 빌드는 열째 단계를 지나 현재 제목 단계 출력 `aa8464a9c47786c07e6111e2b13a14675c207c7b`을 만들고, 제목 실행 증거가 이전 출력에 묶였다는 다음 관문에서 실패 닫힘한다. 현재 최대 대사 15페이지와 제목을 각각 새 출력에서 실행 결속하기 전에는 최종 ROM으로 세지 않으며, 앞 문단의 v30 실행 증거도 승계하지 않는다.

과거 32페이지 계보의 사운드 테스트·엔딩 세이브스테이트는 이 정확 출력의 실행 증거로 쓰지 않는다. 해당 상태를 불러오면 현재 ROM 파일의 고정 뱅크 `$F79A`에 존재하는 생산자 bridge가 실행 메모리에서는 32바이트 `FF`로 매핑돼 화면과 신규 hook이 함께 깨진다. 같은 관리 실행을 native power cycle하면 `$F79A..$F7B9`가 `08 48 8A 48 98 48 A9 00 4C D1 F7 ...`로 즉시 복구되고 콜드 제목 SHA-256도 기존 정상값 `51a7379343410a51954864ee534a28155945720b09a5e53e1182f174814ca218`과 같다. 구형 상태에서는 배터리 SaveRAM 8KiB만 자료로 추출해 현재 mapper 상태에 주입하며, 상태 전체를 복원해 나타난 가블은 최신 ROM 회귀로 판정하지 않는다.

## 2026-08-13 전역 대사 런타임 재검토

전역 대사 런타임의 제어 역할 10개는 모두 통합 쓰기 계획에 들어갔다. 초기 진입, `E4/E6` 전이, `E7` 복귀, 페이지 완료의 `09/0F/10` 세 결과, E7 인계의 상주권 보류, 실제 전투 합성기의 상주권 무효화, `$C179` NMI 소비자, 디스패처 게이트, CHR-RAM selector를 원본 또는 누적 후보 바이트에 결속했다. 페이지 resolver를 실행하려고 `$A000`을 빌리는 두 경로는 NMI를 끄고 원본 PRG와 PPU 제어를 되돌린 뒤에만 요청을 공개한다.

다른 작업자가 추가한 CHR 복원 상태는 그대로 채택하지 않았다. 임시 그림자 `$07EB`는 mapper165 전투 런타임이 소유하는 `$07E0..$07EF` 안에 있었다. 또한 `$FA80/$FAA0` 직접 helper를 관측해 `$5B/$5C`를 바꾸는 안은, 직접 기록기를 stateless로 둔 mapper165 계약과 충돌한다. 현재 구현은 중앙 FD/FE 기록기 `$C9BE/$C9C6`가 이미 소유하는 `$5B/$5C`와 상위 비트 `$52`를 읽기만 하고 두 helper로 독립 복원한다. 중앙 기록기와 helper 네 곳은 후보 ROM의 정확한 typed RP2A03 바이트에 결속했다.

CHR helper의 공용 131사이클 상수도 없앴다. 후보의 typed RP2A03 CFG에서 FD와 FE를 따로 따라 얻은 callee 상한은 각각 140사이클이며, 호출자 `JSR` 6사이클은 방출 명령 쪽에서 별도로 센다. 범위 밖 전이·간접 점프·루프·재귀는 실패 닫힘이고 수정된 값으로도 현재 vblank 예산 시험은 통과한다.

큰그림을 다시 확인한 결과, FD/FE 배경을 한 RAM 페이지로 합치는 관문 자체를 폐기했다. mapper165의 오른쪽 FD와 FE는 같은 4 KiB 주소의 서로 다른 타일 네임스페이스이고, 실제 7장 대사 네임테이블도 양쪽에서 같은 코드를 서로 다른 패턴으로 요구한다. 화면이 깨진 원인은 PRG 페이지 `21`이 틀린 것이 아니라 표시 selector가 레지스터 2(FD)와 4(FE)를 모두 CHR RAM으로 바꾼 것이었다. 현재 구현은 전송 중에만 양쪽을 RAM에 걸고 이탈 때 둘 다 복원한 뒤, 준비된 표시에서는 원본 대사 글꼴 페이지 0과 결속한 FD만 RAM으로 바꾼다. FE 맵 배경은 원본 CHR ROM에 남는다. 이 방식은 앞선 개별 대사 페이지가 이미 실행 검증한 래치 분리를 전역 런타임에 일반화한다.

첫 FD-only 탐침에서 1장 맵·창·초상화 보존과 전송의 `ready(3)` 도달은 확인했다. `$29`를 수명으로 보던 첫 selector 결함을 고친 두 번째 탐침에서는 네임테이블의 재배치 코드가 FD 래치를 고르고 CHR RAM에 한글 저 bitplane이 있음을 확인했다. `0A:$85F8`의 E4 전환 생산자가 `ready` 뒤에도 같은 요청을 반복 발행해 상태를 `1`로 내리던 문제는 쓰기 중단점 `$F473`과 스택 복귀 `$85FA`로 결속했다.

현재 구현은 전송 완료 직전에 커서 두 칸을 원문 selector/index 게시 슬롯으로 바꾸고, 공유 요청 발행기가 같은 원문 또는 같은 상주 그룹을 확인하면 완성 페이지를 재사용한다. E6와 E7의 비표시 전이는 실제 작성자가 없으면 상주권을 유지하고, 전투의 4 KiB 합성 호출만 먼저 `ready`를 내린다. 다른 그룹·일반 종료 뒤의 재진입·보존이 증명되지 않은 수명은 계속 냉합성한다. 발행기와 표시 selector는 각각 고정 동굴 `$F400..$F4B0`, 별도 exact-`FF` 동굴 `$F558..$F700`에 분리했다.

탐침 `A4AE24B8DE40F2930FDC799C48A6D2C3E6E2894D`은 프레임 2929의 `ready(3)`와 게시 정체성 `[80,02]` 뒤 300프레임 동안 재합성이 없었으므로 반복 생산자 관문만 통과했다. 당시 화면을 한글 정상 표시로 판정한 것은 잘못이었다. 그 산출물은 새 전역 코드북에 맞는 대사 저장소를 설치하지 않아 네임테이블 코드와 CHR 코드북이 달랐다.

현재 탐침 `018EDE4D6E6E500D025CBCC5279194BB142161ED`은 정규 대사 저장소 11구간과 포인터 517개를 현재 코드북과 같은 추적 이미지에 설치하고, 최종 이미지 바이트를 다시 읽어 일치를 확인한다. 콜드 1장 프레임 2937의 `ready` 쓰기 중단점은 NMI 한가운데라 그 순간의 프레임버퍼가 새 CHR 상태를 아직 표시하지 않았다. 같은 상태에서 한 프레임 진행한 2938에는 대사 본문 한글이 읽혔고, 네임테이블 코드·현재 그룹 23 코드북·CHR-RAM의 16바이트 타일·PPU `$1000..$1FFF`가 모두 일치했다. 맵·창·초상화도 보존됐다.

다음 수명 결합점 두 가지도 설치·실행했다. `{EA}`가 논리 줄 안에 있으면 실행 중 원본 표식으로 출력하는 `9E AB`를 해당 페이지가 보호한다. 25개 장 제목은 각 장의 전체 인트로 전이 사슬을 따라 관련 가시 페이지 129개에 합류하며, 고유 제목 글리프 88자는 그 모든 페이지에서 같은 코드를 쓰는 결정적 전역 배정을 갖는다. 개별 작업집합의 최대 수요는 여전히 `188/210`, 합쳐진 페이지의 최대는 `210/210`, 정적 그룹 상한은 37이다. 제목 저장소 25개도 현재 코드북의 바이트로 같은 추적 이미지에 설치하고 최종 바이트를 다시 확인한다. 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`의 1장 첫 완료 화면에서 장 제목 `마르스의 여정`, 원본 생성 표식, 한글 본문, 맵·창·초상화가 함께 유지됐다. 이 표본은 1장 결합 수명만 닫으며 나머지 24장 표시 회귀를 대신하지 않는다.

레코드 전환의 새 요청은 이제 resolver가 얻은 페이지 그룹을 직전 상주 그룹과 비교한다. 같은 그룹이면 CHR-RAM을 다시 쓰지 않고 새 원문 selector/index와 `ready`만 게시하며, 다른 그룹만 `cold_requested`로 내려간다. E6의 상태 `10`은 종료가 아니라 다음 레코드 앞의 비표시 상태로 확인해 상주 그룹을 유지한다. 새 탐침 `F9DE7CF3218B3DE1CC6367270DDA461903CA17DF`의 1장 경로에서 이전에 프레임 2991에 시작하던 같은 그룹 냉합성은 사라졌다.

E7 공유 소유권 경계는 구현됐다. 누적 후보의 직접 CHR-RAM 선택 세 지점과 전투 합성 호출 `$FC49 → $FC99`를 전수 결속하고, 합성 직전에만 대사 `ready`를 내리는 래퍼를 넣었다. E7 인계 자체는 상태 17의 원본 selector fallback만 사용한다. 탐침 `EA07D1B7BCBB63590699163AA8AD098D5DCC0F40`의 프레임 3141 인계에서 `ready=03`, 그룹 `15`가 유지됐고 프레임 3261의 이어진 화면은 읽을 수 있었다.

필수 냉합성의 표시 글리치는 닫았다. CHR-RAM은 mapper 165에서 실제 4 KiB 한 장뿐이라 이중 버퍼를 만들지 않고, 회수 가능한 CHR-ROM 첫 페이지인 물리 `50`·mapper 값 `C8`을 냉간 표시 전용으로 예약했다. 이 페이지는 원본 FD 글꼴 페이지에서 보호된 영어·숫자·제어·레이아웃 46코드를 바이트 그대로 유지하고 한글 활성 슬롯 210개만 빈 타일로 만든다. 요청 발행기가 NMI를 되살리기 전, 중앙 selector가 cold 상태를 볼 때, 각 전송 프레임이 원본 FD/FE를 복원한 뒤의 세 소유권 지점에서 FD만 이 페이지로 고른다. 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`에서 요청 직후 첫 표시 프레임 15154부터 복원 단계 15185·15258, 덮기 단계 15289·15336까지 대사 슬롯은 비어 있었고 맵·창·초상화·원본 영문/숫자 UI는 유지됐다. 프레임 16336에는 `$07F4=03`과 읽을 수 있는 완성 한글이 함께 나타났다. 스키마 11 보고서 SHA-1은 `e8e935645cff13e5b9efc01821e4b74587574431`, Expected Write는 572개이고 전용 페이지 뒤에 CHR 13페이지가 남는다. 콜드 대기 약 3.9초를 줄이는 성능·표현 개선과 다른 그룹 전이 회귀는 계속 남는다.

## 현재 결론

매퍼 변환의 우선 후보를 MMC5에서 mapper 165로 바꿨다. mapper 165는 원본과 같은 배터리 SRAM을 제공하면서 MMC2식 FD/FE CHR 래치를 유지한다. 무번역 프로브는 원본 128 KiB CHR 앞에 8 KiB 예약 영역을 두고 원본 페이지를 그대로 재배치하며, PRG writer 12곳과 확인된 CHR writer 35곳을 변환한다.

실행 관측 화면 29개의 고유 FD/FE 쌍 18개를 비교해 오른쪽 `00/14`용 변형 CHR 페이지 1개를 만들고, 중앙 오른쪽 공급자가 FD/FE 그림자 쌍으로 이를 선택하게 했다. 설정의 `00/15`와 부대 목록·맵 유닛 UI·무기점·소지품 화면의 `00/15`, `00/18`, `00/19`, 양도 대상의 `15/15`는 원본 트리거 평면과 같아 자연 페이지를 쓴다. Mesen 콜드 실행의 프레임 800·1206·1928, 실제 입력 뒤 1장 인트로 대화와 2장 인트로 화면은 모두 기존 원본 PNG와 SHA-256이 정확히 같다. 전투의 직접 왼쪽 `02/06`, `06/06`과 오른쪽 `02/06`도 자연 페이지로 호환됐다.

G2는 통과했다. 직접 CHR writer 31곳을 정적 계약과 실제 전투 실행 쌍으로 모두 닫았고, 자연 중단·배터리 파일·전원 재인가·재개·일회성 소비와 턴 경계 게임 오버도 원본과 동등했다. 이어 실제 이동·턴 종료·전투로 보스를 쓰러뜨리고 성 명령을 선택해 1장을 완료한 뒤 정규 저장, native power cycle, `ロードする`와 2장 전환까지 비교했다. 같은 점멸 위상의 화면과 로드 뒤 네임테이블·OAM·팔레트가 일치해 mapper 165를 채택한다. 진행 가속으로 달라진 적 AI와 이동 경로 때문에 전체 SRAM·내부 RAM은 이 표본의 동등성 기준에서 제외했으며, 아직 게임 전체의 전수 회귀를 뜻하지 않는다. MMC5 프로브는 비교 근거와 기각된 설계의 재현 자료로 유지한다.

G3의 공급 방식은 확장 CHR-ROM 페이지 선택으로 확정했다. 보호 43코드와 레이아웃 3코드를 원본 그대로 복사하고 나머지 210코드만 한글에 배정한다. 설정 페이지 A/B는 공유 12자와 페이지별 100자로 각각 112자, 합집합 212자이며 물리 페이지 `34/35`, mapper 값 `88/8C`를 쓴다. 설정 화면 콜드 실행에서 `88 → 8C → 88`과 이탈 뒤 자연 페이지 복구를 확인했다.

부대 목록에는 물리 페이지 `36/37`, mapper 값 `90/94`의 화면 전용 A/B를 추가했다. 최초 공급 관문에서는 `이/름`과 인공 작업 집합으로 한 페이지 예산 초과를 증명했고, 현재 누적 빌드는 두 페이지를 실제 아군명 52개·고유 한글 72자의 생산 페이지로 교체했다. 진행 메뉴와 외부 상태·CHR 쌍 일부가 겹친다는 반례 뒤, 부대 목록 생성자 `0B:$89DB`의 고유 창 기술자와 위치 상태에 수명을 결속했다. 현재 빌드에서 `이름`, `마르스`부터 이어지는 실제 이름, 원본 `LV/HP`·숫자와 인물 그래픽을 함께 확인했다.

주 대사 번역 뷰 2,814줄 가운데 의미 있는 일본어 2,548줄을 `needs_human_review` 한국어로 채우고 장면별 직접 2차 교정을 마쳤으며 승인 완료는 아직 0줄이다. 미번역 일본어와 재배치 필요 줄은 모두 0개다. 원본 영어·숫자·제어 토큰 보존 검증과 원본 무수정 왕복을 통과했다. 동적 이름·아이템·수량 뒤 조사는 `은(는)`·`이(가)`·`을(를)`·`(이)나`로 교정했고, 채워진 고유 글리프는 697자다. 명시적인 `E4`/`E6` 대사 전이 사슬의 최대 한글 집합은 `village-and-outro-dialogue` 레코드 24 한 건의 175자다. 소스 분석에서 7장 성 좌표 `(27,10)`의 이벤트가 이 레코드를 `C0:18`로 생산함을 결속했다. 11장의 같은 엔트리 번호 18은 별도 상태기의 `30:18`이므로 제외한다. 레코드 전체를 상주시키면 보존 코드 100개와 한글 175자, 합계 `275/210`이라 불가능하지만 최대 단일 페이지는 한글 35자를 합쳐 `135/210`으로 들어간다. 그래서 15페이지를 5페이지씩 세 글꼴 묶음으로 나누고 첫 진입과 완료 페이지 진행 때 해당 묶음을 다시 고르는 구조를 누적 패치에 설치했다. 상태를 연결한 실제 7장 성 명령 경로에서 초기 선택기, `C8 → CC → D0` 재적재, 15페이지의 90개 완료 상태 표본, 모든 페이지의 점멸 위상, 마지막 원본 영문 `NEXT STORY` 이탈을 정확한 출력 해시에 결속했다. 콜드 부팅부터 7장까지의 연속 경로는 아직 별도 관문이다.

현재 기본 개발 산출물은 개별 프로브가 아니라 `build-kr-patch`가 불변 일본판에서 매번 재생성하는 11단계 누적 ROM이다. 열째 단계의 7장 최대 대사 뒤 열한째 단계가 원본 에셋 기반 한글 제목을 설치한다. 최종 ROM SHA-1은 `1ddc435b5e678c214c2273ce7a665ba4bf0ade13`, 빌드 보고서 SHA-1은 `a7d971b6ffd4ffe9fc5cb5b97afec6f55720d52c`이며 42대사 레코드·168번역 줄·1,148글리프 슬롯·추적 쓰기 548개다. 최대 대사와 제목의 선언한 실행 증거가 모두 각 설치 출력에 결속됐다.

전역 커버리지 보고서는 45개 화면을 일본어 대상 36개·원문 문자만 보존 5개·텍스트 없음 4개로 분할하고, 일본어 대상 전부를 22개 번역 도메인에 연결한다. 주 대사 504레코드는 표시 단위 하나씩을 가지며 미번역 일본어 줄은 0개다. 928개 가시 페이지의 최대 수요는 동적 문자열까지 `188/210`이라 기존 전체 화면 최악 `209/210`을 넘지 않는다. 사람 승인 완료는 1개, 현재 누적 ROM에서 모든 소비자에 설치된 도메인은 9개다. 별도 그래픽 예산을 쓰는 제목은 완료 연출까지 `117/121`이다. 현재 `release_eligible=false`다.

제목 화면은 원본의 다섯 32타일 전송 행에서 최대 열 2..28을 쓰지만, 원본 `TM`이 마지막 행의 `BA+BB` 두 셀에 걸친다는 실행 반례 뒤 두 셀을 모두 보존 영역으로 고쳤다. 따라서 실제 교체 범위는 134셀, 일본어 로고 전용 코드는 121개다. ImageGen 로고는 의미나 글자를 줄이지 않고 폭만 205에서 200픽셀로 조정해 고유 타일 `117/121`에 넣었다. 완성 연출은 `$2182`부터 원작 상단 장식 26셀을 추가하고 `$21A8` 5셀·`$21CD` 3셀·`$21ED` 3셀을 원작 타일로 다시 쓴다. 설치기는 상단 26셀을 빈 타일로 만들고 본체 11셀을 정적 한국어 로고로 재고정하되 명령·속성 바이트, 미배정 CHR 패턴, 칼 스프라이트, 두 셀 `TM`, 저작권 자산은 보존한다. 출력 `1ddc435b5e678c214c2273ce7a665ba4bf0ade13`의 무입력 프레임 1206·1331·1458에서 초기 위상과 상단 돌출 없는 두 완료 위상을 확인했고 1912에서 자동 병종 소개로 정상 이탈했다. 이 `117/121` 수요는 전역 커버리지의 36번째 수명으로 등록됐다. 사람 시각 승인과 패배 뒤 제목 복귀는 여전히 별도 관문이다.

현재 최종 빌드는 콜드 무저장 경로에서 `처음부터`, 슬롯 화면, 1장 제목과 도입 여섯 페이지를 거쳐 지도에 도달했다. 시작 메뉴는 +7/+19프레임에도 같은 해시 `4d474610…`를 유지했고, 진행 메뉴의 첫 항목으로 연 부대 목록은 `이름`과 `마르스`·`제이건`·`카인` 등 실제 이름, 원본 `LV/HP`·숫자를 함께 표시해 +7/+19프레임에도 같은 해시 `2907ae02…`였다. `B` 뒤 지도 복귀, 첫 두 무전투 적 턴의 상태 `00` 복귀, 세 번째 턴의 자연 전투 두 건과 최종 지도 복귀까지 한 실행에서 이어졌다. 전투 이름 표는 이제 번역됐고 엔딩 이름 표만 자체 글꼴 수명 설치 전이다.

자동 병종 소개는 뱅크 `0D`의 인덱스 `$0559`, 제목 포인터 표 `$8C98`, 설명 포인터 표 `$8DCC`에 결속했다. 일본어 제목 22개와 설명 75줄의 한글 합집합 216자는 단일 페이지 상한 210자를 넘으므로 인덱스 `0..10`의 143자와 `11..21`의 161자로 나눴다. 무입력 콜드 실행에서 프로필 `0`, `8`, 페이지 경계 `11`, 마지막 `20`, `21`, 자동 검은 전환과 뒤의 원본 영어 도입까지 7개 불규칙 시점을 같은 ROM SHA-1에 결속했다. 경계 프로필에서 배경의 두 mapper 래치가 모두 `BC`였고, 원본 `STR/SKI/WLV/AGI/DEF/MOV/H.P/EXP`·숫자·UI와 화면 이탈 뒤 영어가 유지됐다. 이 화면군의 실행 결속은 완료했지만 22개 번역은 모두 `needs_human_review`이므로 사람 승인 완료는 아니다.

무기점 공용 C0 페이지는 대사 8레코드, 품목명 6개와 `예/아니오`의 한글 60자, 보존 코드 90개를 함께 담아 아홉 화면 역할 모두 `150/210`으로 수용한다. 이 용량 결속과 실행 결속은 분리한다. 첫 구매 확인을 거절한 비구매 경로의 17개 불규칙 표본은 여덟째 단계 출력 SHA-1 `4758d15b9beb9b075be6976508b90e17ef1ea54d`에 결속했고, 대사·품목명은 품목 목록·확인·계속 질문·종료 네 역할, 선택지는 확인 역할만 실행 결속한다. 원본 숫자와 `G`, 초상화와 지도는 유지됐고, 뒤 누적 단계의 Expected Write 검증은 페이지·선택기 보존을 확인한다. 최종 누적 출력의 실제 구매·금액 부족·소지품 가득 참·아이템 조건 경고 분기는 아직 exact-output 실행 확인 전이다.

별도 형식의 전투 대사도 비공개 번역 작업공간으로 추출했다. 포인터 65개가 가리키는 고유 레코드 28개를 겹침 없는 1,152바이트 소유 범위에 결속했고, 4바이트 헤더 뒤 본문을 `ED/EE/EF` 단위 100줄·일본어 620바이트로 분리했다. `EC` 동적 문자열 선택자와 기존 영문·숫자·제어 코드는 보호 토큰으로 유지한다. 일본어가 있는 70줄은 모두 `needs_human_review` 한국어 초벌과 직접 2차 의미 검토를 마쳤고, 나머지 30줄은 제어만 있는 구조 줄이라 번역하지 않았다. 이름·아이템·병종처럼 받침 여부가 입력에 따라 달라지는 선택자 뒤 조사는 `은(는)`·`이(가)`·`을(를)`·`(으)로`로 교정했으며, 검증기가 고정 단일 조사를 거부한다. 현재 작업공간 SHA-1은 `f21dd08254a7afe1a0a38d25dda2eb70dc9628b6`다. 번역 레코드 논리 인코딩 1,114바이트와 미참조 원본 레코드 보존 16바이트를 합친 실제 계획은 1,130/1,168바이트로 38바이트가 남는다. 미참조 레코드의 원래 16바이트 위치를 경계로 소유 영역을 둘로 나누고 레코드를 자르지 않은 채 순서대로 배치했으며, 28개 새 주소와 별칭을 포함한 65개 포인터 쓰기를 모두 계산했다. 배치 보고서 SHA-1은 `b6fb8dd55ae95ced551d72326358112dac6e60a1`이다.

전체 전투 초벌을 한 번에 넣는 mapper 165 개발 ROM도 만들었다. 28레코드·70번역 줄·65포인터를 적용한 기존 프로브에서 실제 전투 소비자와 원본 `LV`·`HIT`·`EXP`·숫자 보존을 확인했다. 병종·아이템·아군명·적군명 기존 233개는 직접 2차 교정을 마쳤고, 원본 표 경계를 바로잡아 찾은 69번째 적군명에도 초벌을 추가해 234개 모두 번역 상태다. 기존 프로브는 원본 글꼴 페이지를 전역 교체해 고정 문자열이 깨지는 비배포 증거이므로, 다음 관문은 대사·동적 삽입·고정 문자열을 같은 전투 조합 코드북으로 인코딩하고 전투 수명에만 공급하는 것이다.

무기점의 품목 목록에서 첫 품목을 고른 `E7` 표본은 외부 상태 `04→05→07`, `$7809=01` 읽기 PC `06:$A144`로 결속했다. 인계 순간에는 6개 품목·가격 목록과 구매 질문이 함께 남아 있고 `はい/いいえ` 창은 아직 완성되지 않았다. 품목 목록에서 인계까지 네임테이블은 16바이트, 인계에서 안정 확인 화면까지 40바이트가 더 바뀌었다. 따라서 `$7809` 관측이나 상태 17에서 대사 전용 글꼴 페이지로 즉시 바꾸면 안 된다. 이 수명에서 보존해야 할 품목명·선택지 원본 코드는 17개이고, 동시에 보이는 대사 레코드 2개의 초벌 한글 합집합은 9자여서 국소 수요는 26/210슬롯이다. 전역 비교에는 이 표본값이 아니라 실제 설치된 공용 페이지 전체의 `150/210`을 사용한다.

자동 인물 후일담 화면군은 112개 보이는 엔트리의 560개 실행 표본을 한데 합친 보수적 예산으로 닫았다. 관측 네임테이블의 활성 원본 코드 99개를 모두 보존하고, 아직 실제 번역을 확정하지 않은 인물명 최대 7칸과 지명 최대 11칸을 별도 예약하며, 초벌 대사의 최대 전이 사슬 한글 33자를 더해도 150/210슬롯이다. 따라서 이 화면군은 페이지 분할 없이 수용 가능하지만, 이름·지명의 실제 한국어 문자열과 줄 폭은 아직 확정하지 않았다.

턴 경계 게임 오버는 불리한 일회성 개입으로 얻은 12개 불규칙 표본의 활성 원본 코드 90개를 모두 보존한다. 모든 표본의 `$77F4:$77F1`이 `B0:0A`라서 정확한 패배 레코드 인덱스 10의 초벌 한글 30자만 같은 수명에 든다. 합계는 120/210슬롯이다. 이 결과는 관측한 게임 오버 수명만 닫으며 장 승리 대사의 화면 수명은 별도다.

첫 주 대사 프로브의 전역 글꼴 교체를 폐기하고 1장 도입부 수명 전용 확장 페이지로 바꿨다. 원본 CHR은 한 바이트도 바꾸지 않고 물리 페이지 `34`, mapper 값 `88`에 원본 페이지 복제본과 한글 19자를 둔다. 동시 화면에서 관측한 활성 코드 76개와 첫 레코드 뒤 `E6` 전이 사슬 3레코드의 원문·보호 코드 58개를 합쳐 109개를 잠근 뒤 남은 슬롯에만 한글을 배정한다. 중앙 오른쪽 FD 공급 시점의 정확한 `$24/$84/$59/$5A/$5B/$5C/$77F7/$781D=0B/00/1A/1A/00/18/03/00`에서만 확장 페이지를 선택하고 그 밖에는 기존 쌍 인식 선택기로 돌아간다. 콜드 실행에서 일본어 새 게임 메뉴, 원본 `MAP`·숫자, 일본어 장 제목, 한글 첫 대사, 뒤의 일본어 다섯 화면, 초상화·맵·창을 함께 보존했으며 여섯 번째 완료 페이지 `A` 뒤 자연 맵 페이지로 복구됐다. 완료 표식과 맵 스프라이트는 7·19·43프레임 위상으로 확인했다. 이는 첫 화면 수명의 깨짐 0건이지 1장 전체나 G5 통과가 아니다.

상위 화면 조사를 다시 수행해 맵 유닛 UI를 `unit_summary`, `unit_command_menu`, `unit_status`로 분리했다. 요약은 일본어 이름·병종·아이템과 원본 `S/HP`·숫자를, 상세는 일본어 능력치 9개와 같은 원본 영문·숫자를 함께 표시한다. 합성 상태 `04/05/07/0F`를 요약 상단·명령 목록·아이템 목록·상세 능력치 조립기에 결속했다. 상태 `05`는 유닛 능력·지형·인접 대상·인벤토리·시설에 따라 일본어 명령 15개를 선택한다. 무이동 `もちもの/たいき`, 타일 `46`의 `たずねる`, 1장 좌표 `$03/$1A`의 `ぶきや`까지 4개를 실행 화면으로 확인했다. 전체 고정 라벨 26개 중 일본어 25개만 번역 대상이고 원본 `HP`는 보호한다.

페이지 수명도 다시 닫았다. 요약과 명령 메뉴 진입은 각각 중앙 `$C9C2`를 통해 오른쪽 FD `00`을 공급하고, 상세만 요약의 페이지를 추가 공급 없이 상속한다. 기준 맵 `18/18`에서 요약 `00/19`, 상세 `13/13 + 00/19`, 이동 선택 `15/15`, 명령 메뉴 `00/15`가 이어졌다. `ぶきや`의 화면 조합을 아홉 역할로 나눴고 모두 `1E/1E + 00/15`였다. 소지품 가득 참과 금액 부족은 구매 전 비변경 실패지만, 아이템 조건 실패는 경고 뒤 구매를 허용한다. 둘째 품목 `11`은 현재 병종 `01`이 허용 목록 `0B/0C/0E/0F`에 없어 상태 `04→05→06→07`, 대사 `04`의 경고를 열었다. `B`는 상태 `07→08→09→0A→0B→0C`, 대사 `36`의 별도 계속 구매 화면으로 갔고, “예”는 비변경으로 목록을 다시 만들었다. 경고에서 “예”를 고르면 `400G`를 차감하고 품목·내구도 `11/21`을 실제 삽입한다. 이 표본은 마지막 빈칸을 채워 일반 결과 질문 대신 구매·자동 이탈 화면으로 갔다. 세 새 화면은 각각 152프레임 등간격과 168프레임 불규칙 표본에서 화면·CHR이 안정됐다. 무기점 화면군의 하류는 닫혔다.

소지품 흐름은 목록·조건부 행동 메뉴·양도 대상 선택·장비/사용/양도/폐기 결과의 일곱 역할로 나눴다. 목록과 행동 메뉴의 비변경 전이에 이어 장비는 둘째 슬롯을 첫 슬롯과 `02/2A,0F/16 → 0F/16,02/2A`로 교환하고 대사 `19`를 열었다. 양도 대상 선택은 텍스트 없는 `1A/1A + 15/15` 지도 오버레이이며 한 점멸 위상에서 후보 표시가 빠졌다. `B`는 원본 레코드를 보존하고 목록으로 돌아갔고, `A` 확정은 대상 빈칸에 `02/2A`를 옮긴 뒤 대사 `1B`를 열었다. 폐기는 첫 쌍을 지우고 `0F/16`을 앞으로 압축한 뒤 대사 `1C`를 열었다. 사용 아이템 `40`은 대사 `1A`를 자동으로 그린 뒤 진행 상태 2에서 회복을 적용하고 상태 3에서 입력을 기다렸다. 첫 입력 일반형 실행에서 `$047D`는 합성 다음 프레임에 원본 writer가 전체 바이트를 0으로 써서 준비·쌍 수 저장소로 쓸 수 없음이 확인됐다. 원본 의미는 그대로 두고 `$07DF`에 준비 비트와 쌍 바이트 수를, `$07E0..$07EF`에 쌍을 두도록 계약을 수정했다. `$07DF`는 `$0781` 큐 시작에서 94바이트 떨어져 최대 두 줄 큐 뒤에도 27바이트가 남고, 기존 직접·인덱스·간접 writer는 `$07DF..$07EF`를 건드리지 않는다. 스키마 11 보고서 SHA-1은 `db8d7d5e10a865340c4622d33d2c030a7f59b2b9`이다.

전체 전투 텍스트 개발 기반은 정규 코드 배정을 실제 바이트에 적용했다. 전투 레시피에 든 고정 원천 231개, 전투 대사 28레코드·65포인터, 예측창 라벨을 재인코딩했고, 공유 고정 작업공간 272개 중 전투 카탈로그 결측 41개는 원문 상태로 유지했다. 추적 쓰기는 325개다. MMC3 페이지 `20`에는 `$9400`의 210바이트 정규 코드표, 보호 추상색 39개, 안전 추상색 171개와 비트 마스크를 연속 배치한다. 정규 코드표 SHA-1은 `e8bb39dc53336845cc6e4e6508577498ca9aa0d4`다. ROM SHA-1은 `15fa8c5781f82dd914b49eb18f3ad6b96f1e09ad`, 보고서 SHA-1은 `faea6ecbfc30b2254d2a86e874600224af279c12`다.

이 기반 위의 합성 로더는 관측 튜플 허용 목록을 제거하고, 소스 모델이 덮는 참가자·병종·장비·지형·대사 입력을 같은 알고리즘으로 처리한다. 추가 PRG의 7개 루틴 364바이트가 열 레시피의 선택 색을 `$07C4..$07DE` 비트맵에 모은 뒤 보호색 충돌만 최대 8쌍으로 `$07E0..$07EF`에 배정한다. 고정 뱅크의 14개 루틴 812바이트는 원본 4 KiB 페이지를 복원하고 같은 투영으로 오버레이를 올리며, `$E57F` 공용 텍스트 읽기도 지원 전투 수명과 `$07DF` 준비 표식이 모두 있을 때만 같은 쌍을 적용한다. 일반 전투는 직후 상태 `17/33`에서만 `$07DF`를 지운다. 같은 공용 표시 엔진을 쓰는 사운드 테스트는 전체 관측 구간의 `$84=04`, `$05EE=0D`, `$7730=05`를 함께 판정하고, 각 반복 전투의 원본 `$047D=1` writer `07:$AC17`에서만 `$07DF`를 지워 다음 조합의 재합성을 연다. 원래 `A`·플래그·`$047D` 효과는 typed 래퍼가 보존한다. 배정이 8쌍을 넘으면 CHR-RAM 선택과 PPU 쓰기 전에 중단한다. 현재 다섯 관측 튜플의 상한은 고유 오버레이 90개·원시 글리프 참조 94개·PPU 쓰기 5,600회이며 실행 허용 목록이 아니다. 총 21개 typed RP2A03 루틴은 1,176바이트다. 조사 교정 뒤 현재 ROM SHA-1은 `4fbd624801af9cf6f5fe6d67e8e18b2cb3294117`, 보고서 SHA-1은 `eca896fd7901f54c0f8ee68bd39897648a1e7667`이다. 콜드 자연 전투 두 건에서 +43프레임 CHR-RAM/PPU 4,096바이트 일치, 중립 조사와 보호 영어 표시, 두 번째 전투 뒤 지도 복귀를 다시 통과했다. 과거 손상 ROM과 그 원인 격리 자료는 진단 계보로만 유지한다.

손상 ROM에서도 사운드 테스트의 서로 다른 여섯 조합과 콜드 연속 일반 전투 두 건의 합성 반환점은 독립 Rust 계산과 CHR-RAM 4,096바이트가 같았다. `$07DF`와 재배치 쌍도 7·19·43·82·171프레임의 불규칙 표본 동안 유지된 뒤 반복 시작점 또는 종료 상태에서만 정리됐고, 일반 전투의 두 번째 조합은 원본 조건으로 대사 선택자 62를 자연 투영했다. 별도 자동 엔딩 실행에서는 합성·투영·`$07DF` 쓰기가 한 번도 없어 비개입을 확인했다. 이 증거는 생산과 수명만 닫았고 PPU가 실제로 소비한 페이지는 닫지 못했다.

정확 최대 탐색은 가능한 모델 튜플의 텍스트 최대가 131글리프임을 증명했다. 전역 보호 코드 39개를 더한 정확 최대는 `170/210`, 보수적 안전 상한은 `173/210`이다. ROM `3399a2ab385e00ffa4a28ef70b653c16a69a9ed2`에서는 제어된 131개 오버레이·152개 글리프 참조, 재배치 6쌍과 독립/실제 CHR-RAM 일치, 일반·사운드 테스트·콜드 자연 전투 두 건의 판독 가능한 한국어와 지도 복귀를 통과했다. 조사 교정 뒤 별도 전투 ROM `4fbd624801af9cf6f5fe6d67e8e18b2cb3294117`과 아홉째 전투 단계 출력 `f5b72f9dd1b3bd99f9e09c77fc6035d867777710`도 각각 콜드 자연 전투 두 건에서 합성·표시·수명·정리를 통과했다. 이로써 전투 로더의 누적 통합 게이트는 닫혔지만 열째 단계까지 포함한 콜드 전투 회귀와 나머지 화면·분기, 사람 검토가 남아 전체 `runtime_verified`와 `release_eligible`은 계속 거짓이다.

동적 캐시 probe는 이 완성 페이지 4 KiB를 확장 PRG에 두고, 렌더가 꺼진 전투 NMI의 `$C191`에서 CHR-RAM으로 전송한다. 번역 원천 선택에서 생성한 상태 `16/32`, 순서 무관 참가자 `[04,85]`, 병종 `[01,08]`, 장착 무기 `[0C,1B]`, 지형 `[00,0B]`를 캐시 수용 범위로 삼고 런타임의 각 값을 포함 판정한다. 원본이 0/비0만 판정하는 전투 활성 바이트 `$047D`의 상위 비트 `80`을 1회성 표식으로 사용한다. 앞선 로컬 코드북 산출물은 플레이어 선공, 지형 `00/0B`인 첫 적 전투와 그 부분집합 `00/00`인 두 번째 적 전투에서 각각 `$047D`의 `01→81→00`, 원천과 CHR-RAM의 4,096/4,096바이트 일치, 한글 공격 문구와 원본 영어·숫자·그래픽을 통과했다. 새 전역 물리 배정 산출물의 ROM SHA-1은 `7191dc8043cd326d27c77794d01eb600b738519f`, 보고서 SHA-1은 `66445c113805047ed8d1373c094bc79363b1ab0d`이며 같은 콜드 회귀는 아직 다시 돌리지 않았다. 전체 캐시 카탈로그와 대사 selector 62 자연 표시가 남아 있어 `runtime_verified=false`다.

전역 제어 흐름도 원본 상태 머신에 결속했다. 초기·`E4`·`E6`·`E7` 복귀와 페이지 완료·외부 호출·종료만 요청 생산자이며, 기존 전투 NMI `$C191 → $FC20` 하나가 전투 우선순위를 보존한 채 요청을 소비한다. 콜드 재구성은 기존 페이지 `21`의 원본 글꼴을 기반으로 하고, 실행 코드는 페이지 `2E`에서 자료가 끝나는 자리부터 `$C000`까지, 고정 trampoline은 `$F400..$F4B0`을 쓴다. 현재 확보한 실행 코드 자리는 3,791바이트다. 기존 최대 대사 샘플용 훅 세 곳은 전역 구현에서 교체한다. 휘발 상태 5바이트는 `$07F0..$07F4`로 선택했다. 18개 처리기에서 도달하는 typed RP2A03 명령 1,173개를 추적해 직접 충돌 0곳, `$0781,X` 계산 쓰기 3곳, 간접 접근 32곳을 얻었다. 계산 쓰기는 큐 hard limit `$07DF`로 닫고, 간접 접근은 줄 버퍼·동적 슬롯·복사·직렬화·스크립트·애니메이션·스프라이트의 10개 생산자 역할로 완전 분할했다. 스프라이트 2단계 포인터는 선택자 `00..FE`의 510개 값을 전수 열거해 모두 `$8000..$BFFF` 안임을 확인했다. 16개 PRG 뱅크 전체 직접 피연산자 스캔의 세 후보는 모두 명령 내부 바이트로 판정했다. 동시에 실행되는 원본 NMI 277개 명령과 bank 0E 오디오 959개 명령에는 직접·인덱스 후보가 없다. 간접 읽기 38곳은 별도 6역할로 완전 분할했고, 원본 15뱅크의 `$BFC0` 기반 유효 주소도 전수 계산해 후보를 배제했다. 기존 전투 상태의 끝 `$07EF`도 단일 원천 상수로 다시 결속했다. 이 범위는 주 대사 활성 중에만 소유하며 모든 진입에서 5바이트를 콜드 초기화하고, `E7` 이탈·종료·reset·save/load·비활성 선택에서 무효화해야 한다. 초기화 코드와 hook은 아직 쓰지 않았고 ROM도 새로 만들지 않았다. 스키마 9 전체 설치 보고서 SHA-1은 `9d432edb8f349f848c5bf6f492fad8a0601ab3b6`이다.

## 현재 관문

mapper 165 동등성 G2와 동적 글꼴 공급 G3, 전체 텍스트 모집단 G4는 통과했다. 504레코드를 실제 페이지에 합친 최대 대사 수요는 `188/210`이며 기존 전체 화면 최악 `209/210`을 넘지 않았다. 표시 단위·수명·정확 저장을 함께 닫아 G5를 완료했다. G6의 전역 상태 저장소 선택도 닫혔고, 다음 관문은 같은 계약에서 생산자·단일 NMI 소비자·선택자·동적 remap을 한 번에 생성해 누적 Expected Write에 넣는 것이다. 그 전에는 국소 설치 수를 완료율로 세지 않는다.

현재 기본 실행 산출물은 검증한 표면을 합친 누적 ROM이지만 게임 전반에서 한글과 그래픽이 온전한 패치는 아니다. 1·2장 도입 화면, 자동 병종 소개, 무기점의 품목·선택지·대사 거절 경로와 전투 합성 로더는 수명별 공급과 자연 이탈을 통과했다. 전체 번역 입력과 정규화 대사 저장 계획, 동적 문자열 생산자·소비자 결속은 닫혔지만 hook과 전체 동적 페이지 합성은 아직 ROM에 설치하지 않았다. 이 결과를 게임 전반의 한글화 완료로 일반화하지 않는다.

다음 통합 관문은 화면 성공 개수를 늘리는 것이 아니라 전체에서 가장 어려운 조건을 먼저 닫는 것이다.

- 완료한 전투 누적 통합을 기준선으로 유지하며 이후 단계가 같은 고정 뱅크와 선택자 범위를 침범하지 않게 한다.
- `C0:18`의 완료 페이지 재적재와 출력 해시 결속을 기준선으로 유지한다.
- 완료: 제목 그래픽의 `117/121` 타일 수요를 전역 커버리지의 36번째 화면으로 등록하고 G5 전역 최악 `209/210`을 확정했다.
- 가장 긴 조판·저장 구간과 가장 복잡한 진입·이탈·재진입도 같은 누적 구조에서 통과한다.
- 최종 누적 ROM에서 대상 일본어 0건, 보호 영어·숫자·그래픽 손상 0건을 기계 검사와 실행 회귀로 함께 닫는다.
- 기준선 성공 경로와 치트를 끈 실패·패배 경로를 분리해 검증한다.

주 대사 2,541개 의미 줄은 모두 검토 대기 초벌이지만 승인 완료는 0줄이다. 전투 대사 70개 의미 줄도 검토 대기이며, 전투 고정 문자열 272개 중 22개만 승인 완료다. 따라서 번역 자산의 채움과 실제 표시 적용, 사람 승인을 각각 별도 진척으로 유지한다.

## 다음 작업

1. 완료: 조사 교정 뒤 전투 ROM과 누적 ROM의 자연 전투를 재검증했다.
2. 완료: 전투 합성 로더를 누적 ROM 경로에 합치고 기존 시작·도입·부대 목록과 전투를 같은 콜드 산출물에서 재검증했다.
3. 완료: 주 대사의 175자 최대 레코드를 구조로 식별했다.
4. 완료: 11장 장 종료 표본의 선택자 `C0:1C`가 최대 레코드와 다름을 확인해 잘못된 수명 결속을 폐기했다.
5. 완료: 7장 성 이벤트가 최대 레코드를 `C0:18`로 생산하고 11장의 같은 번호는 `30:18`임을 소스에 결속했다.
6. 완료: 7장 `C0:18`의 15페이지·90표본을 관측해 전체 상주 불가·페이지 단위 수용 가능을 확정했다.
7. 완료: 15페이지를 세 글꼴 묶음으로 설치하고 초기 선택기·완료 페이지 재적재·점멸 위상·`NEXT STORY` 이탈을 정확한 출력 해시에 결속했다.
8. 완료: 504레코드 한국어를 합친 최대 대사 수요 `188/210`이 기존 36개 화면의 최악 `209/210`을 넘지 않음을 다시 계산했다.
9. 완료: 레코드 프리픽스를 실제 여덟 배치대로 읽어 직접·전이 두 모드가 갈라져 보이던 원인을 없앴다. 번역 뷰는 2,814줄 하나이며 미번역 일본어는 0줄이다.
10. 완료: 504개 표시 단위를 정확한 저장 `29,792`바이트와 517개 포인터에 결속하고, `{EC:xx}` 소비 수요 142개를 모두 원본 생산자에 이었다.
11. 진행 중: 검증한 대사 계획과 동적 페이지 합성, 나머지 텍스트 도메인을 하나의 추적 이미지에 합친다. 504레코드의 공통 상태 머신과 단일 NMI 소비자는 고정했고 5바이트 휘발 상태 `$07F0..$07F4`의 수명 소유권도 선택했다. 동적 문자열은 소비 수요 142개가 공급 142개와 맞물렸다. 다음에는 소비자·선택자·동적 remap과 콜드 초기화를 한 단위로 생성한다.
12. 구매·실패·패배·저장·장 전환·엔딩을 포함한 대표 극단 경로를 최종 동일 ROM 계보에서 검증한다.
