화면별 조사는 먼저 화면 역할과 진입·이탈, 번역 대상과 보호할 원문, 배경·초상화·창·스프라이트의 합성, 점멸·자동 출력, 입력별 부작용을 정한 뒤 국소 주소와 실행 경로로 각 빈칸을 닫는다. 이 순서를 따르면 같은 CHR 쌍을 쓴 저장 완료 질문·종료 안내·사운드 테스트를 한 화면으로 잘못 합치지 않는다.

## 정적 결속

- 장 인트로 표의 고유 `E5` 문맥은 25개다. 5바이트 페이로드는 차례로 `$71`, `$70`, `$05CF`, `$05D0`, `$781D`에 들어가며 마지막 값은 `00..18`로 연속된다.
- 장 제목 소비자 `0B:$88C4`는 `$781D`를 읽어 고정 뱅크 `$EE08`의 포인터 표를 고른다. 표는 24개가 아니라 25개이며, 마지막 포인터 `$EFA8`의 문자열은 다음 장소 이름 표가 시작되는 파일 `3EFC7` 직전에서 끝난다.
- 장 제목 25개에는 원본 장 번호 숫자 41바이트가 있다. 숫자는 보호하고 일본어 제목 부분만 번역한다.
- `NEXT STORY`는 고정 라벨 인덱스 `3E`, `$91FB`이고 `0B:$886A`가 합성한다. 번역하지 않는다.
- 첫 저장 질문 `セーブしますか?`는 고정 라벨 인덱스 `32`, `$91AA`이고 `0B:$8AE6`가 합성한다.
- 바깥 `$24=0D`의 `06:$B5AC`가 `$84` 하위 상태를 분배한다. 저장 질문의 상태 `07/08/09`는 각각 `06:$B6F3/$B726/$B737`이다. 상태 `07`은 `$05EB==02`를 “아니오”로 판정해 저장 화면 `$24=0E` 경로를 타지 않고 상태 `08`로 간다. 상태 `09`는 `$84`를 `00`으로 지운 뒤 `06:$B76E`에서 `$24=01`을 쓴다.

- 바깥 `$24=0E`는 `06:$B771`에서 `$84`를 분배하고, 관측한 주 상태 `04`는 `06:$B7CB`에서 뱅크 `0B:$995F`의 `$05EE` 하위 상태표를 호출한다. 저장 완료 질문의 선택 상태 `07`은 `0B:$9B35`다. 깊이 `$05CE=03`의 활성 슬롯은 `$7FF5`이며 “아니오” 결과 `02`는 상태 `08/09/0A`의 종료 안내 경로로 간다. 기본 “예” 결과는 `$05EE=FF` 뒤 증가로 상태 `00`에 복귀해 다음 장 계속 경로를 연다.

선택된 “아니오” 화면은 입력 없이 0·7·19·43·82·171·308·565프레임에서 모두 같은 PNG SHA-256 `a05ea43bc1844701650cfee6d441862d16d60fc1f7f0035704ce15dbbcfb352c`였다. 이 표본에서는 선택 커서나 배경이 점멸하지 않았지만, 다른 장의 retained-map 변형까지 같다는 뜻은 아니다.

저장 완료 질문에서도 `$7FF5:01→02` 뒤 선택 화면은 같은 불규칙 여덟 표본에서 SHA-256 `c160f6fe5645e90e0f003dd1ccf64aef60b5a516eb2e09232e3717bb6f9f0496`로 같았다. 확정 뒤 안내는 1·11·30·67프레임에 자동으로 그려졌고, 130·259·516·900프레임은 모두 SHA-256 `c7e16901de2ed4e73c3cc6534e8a478e07ae61630ab7f7b43120f352f7c03ff1`로 정착했다. 숨은 입력은 각 단계에서 `$775B=00→05`를 확인하고 마지막 `A`가 `$05EE:0A→0B`를 만든 뒤에만 실행했다. 추가 입력 없이 상태 `0C`의 사운드 테스트가 나타났으며, 화면의 영어와 숫자는 번역하지 않는다.

사운드 테스트 기준 상태에서 위는 `$775C:00→01`, 아래는 `00→50`으로 바뀌었다. `A`는 선택 번호 1을 `$06F0=02`로, `B`는 `$06F0=01`로 기록했다. 두 음원 이벤트는 소비자가 프레임 안에서 다시 0으로 지우므로 일반 정지 화면의 사후 메모리만으로는 보이지 않고, 원천 쓰기 경계와 값 필터로 확인했다. 화면의 영어 라벨과 숫자는 모든 조작에서 보존한다.

`START` 뒤에는 입력을 더 주지 않았다. 불규칙 표본 0·1·7·19·43·82·171·308·565·711·934·1273·1691·2200·3000프레임에서 검은 전환, 한쪽·양쪽 유닛 정보, 전투 예측, 공격, 피해, 필살, 격파와 EXP, 다음 유닛 쌍의 공격까지 나타났다. 바깥 `$7730`은 19프레임부터 계속 `05`였으므로 이 표면들은 테스트 전용 6화면이 아니라 공용 `battle_animation` 안의 가시 수명이다. 일본어 유닛명·무기·행동·결과 문구만 번역하고 `LV`, `HIT`, `EXP`, HP 막대와 숫자는 보존한다.

`SELECT` 뒤에도 입력을 더 주지 않았다. `$7731=01`은 원본 영어 엔딩 문장과 `CAST`·로마자 이름을 자동 스크롤한 뒤 일본어 장 제목·턴 기록을 같은 스크롤에 합성했다. 상태 `08`은 원본 영어 스태프, 상태 `10`은 초상화와 일본어 인물 후일담의 자동 반복, 상태 `1D`는 원본 서명·`©1990 Nintendo`의 정적 종단이었다. 영어·로마자·숫자·서명·저작권은 보존하고 일본어 장 기록과 인물 후일담만 번역한다. 상태 `1D`는 no-op 처리기 `$C73D`를 쓰고 `$7732=00`이며, 21,000·24,000·28,000·33,000프레임의 스크린샷·네임테이블·OAM·팔레트가 모두 같았다. 이전의 검은 표본은 종단 진입 전 전환이지 서명 점멸이 아니었다.

`analyze-chapter-transitions`는 이 소비 코드·포인터·라벨과 25개 장 문맥을 지원 일본판에서 다시 검사하고 `out/chapter-transitions.json`을 만든다. 장 종료 대사와 저장 완료 대사의 원문은 보고서에 넣지 않는다.

## 전투와 엔딩의 상위 원천 결속

사운드 테스트의 `START`는 뱅크 `05:$8161`의 공용 전투 엔진을 부르며 `$047C`의 32개 내부 단계를 자동 진행한다. 보이는 유닛명·적 이름·병종·아이템은 기존 공용 네 표를 사용하고, 전투 메시지는 뱅크 `04:$845B`의 65포인터 별도 표를 `$8000` 로더로 읽는다. 별도 상태기 `$7937`은 4바이트 헤더 뒤 `EC`의 선택자 한 바이트를 확장하고 `EF`에서 끝낸다. 고유 포인터 대상 28개는 겹치지 않는 1,152바이트이고, 포인터 없는 16바이트 레코드 하나는 번역 대상으로 추정하지 않고 보존한다. 따라서 디버그 화면만 따로 번역하지 않고 실제 전투 소비자 하나를 기준으로 관리한다.

엔딩 상태 `01`의 `$A826..$ACC8` 스트림은 113레코드다. 앞 43개는 보존할 원본 영어·캐스트·레이아웃이고, 이어지는 25개 장 행은 장 제목 표와 의미상 같은 일본어를 다른 레이아웃으로 중복 저장하며 `ED 00..18`로 장별 턴 수를 삽입한다. 합계 행은 `ED 19`를 쓴다. 승인된 장 제목 번역 하나가 장 제목 표와 엔딩 행 두 물리 인코딩을 함께 생성해야 하며, 장 번호 41바이트와 실행 중 생성되는 턴 숫자는 보존한다. 인물 후일담은 상태 `0E`가 후보 커서 `$773B=35`를 만들고 상태 `0F`가 후보 ID `35..01`을 역순으로 훑는다. `$6A90`의 54개 27바이트 레코드에서 같은 ID를 찾지 못하면 건너뛰고, 일치 레코드의 행동 바이트 `12`가 비활성·격파 값 `FF`이면 표 `41`과 레코드 오프셋 `0E`의 장별 장소 이름을, 아니면 표 `40`을 고른다. 상태 `10`은 공용 대사 완료를 기다린 뒤 추가 입력 없이 진행한다. 생산자까지 결속했지만 `FF`의 모든 원인을 사망으로 한정하는 일은 실행 변형 관측 뒤로 남긴다.

번역 표면 결속은 원문을 내보내지 않고 실제 리터럴 위치만 합쳐 일본어·보존 원문·레이아웃 코드 집합을 계산한다. 전투 고정 표 107코드는 `100/6/1`, 전투 대사 834바이트는 `620/167/47`, 엔딩 장 기록 439바이트는 `349/47/43`, 인물 후일담 1,649바이트는 `1,529/9/111`로 나뉘며 미해결 코드는 없다. CHR과 사용 문맥에서 `8E = 。`, `AB/AC = 「/」`는 일본어 원문, `9D = !`는 보존 원문으로 확정했다. 선택자 `41`의 52개 라우팅 스크립트는 표시 리터럴 없이 모두 포함된 선택자 `40` 표로 전이하므로 후일담 집합에서 빠지는 외부 표가 없다.

## 후반 장 도달 표본

정규 파일 1은 1-based 장 번호를 `$6519`에 둔다. 로더는 `$6000..$6542`의 모든 바이트를 16비트 가산한 값이 little-endian `$6542/$6543`과 같을 때만 파일을 받아들인다. 체크섬 계산기는 `0B:$9D52`, 파일 1 기록 분기는 `0B:$9AD0`, 검증 분기는 `0B:$9FA8`이다.

격리된 원본 실행에서 1장 완료 파일의 장 번호와 체크섬만 함께 바꿔 12장 도입을 열었다. 이는 자연스럽게 11장을 완료한 결과가 아니라 화면 도달 개입이다.

| 표본 | 진입 | `$7674` / `$781D` | CHR `$59..$5C` | 확인 범위 |
| --- | --- | --- | --- | --- |
| 2장 | 1장 완료 및 정규 파일 콜드 로드 | `02 / 01` | `13 13 00 18` | 장 제목·맵·초상화·대사 합성 화면 |
| 11장 | 장 번호·체크섬을 바꾼 정규 파일 1 | `0B / 0A` | `1A 1A 00 18` | 같은 합성 역할, 초상화 없는 표본 페이지, 점멸 완료 표식의 표시·비표시 위상 |
| 12장 | 11장 성 명령부터 이어진 연속 경로; 콜드 로드도 별도 확인 | `0C / 0B` | `0F 0F 00 18` | 같은 합성 역할, 다른 왼쪽 CHR 쌍, 점멸 완료 표식의 표시·비표시 위상 |

11장과 12장 표본은 장 번호 숫자를 원본으로 보존하면서 일본어 장 제목과 대사가 함께 살아 있는 후반 변형을 확인한다. 세 도입 표본의 왼쪽 쌍은 모두 달랐고, 캡처한 11장 완료 페이지에는 2장·12장과 달리 초상화가 없었다. 25개 장이 이 셋 중 하나만 쓰거나 장마다 초상화 유무가 고정된다는 뜻은 아니다.
