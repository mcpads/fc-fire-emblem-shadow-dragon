# 플레이와 런타임 검증

이 문서는 실행 증거의 형식과 목적별 회귀 묶음을 정한다. 현재 exact ROM과 바로 다음 실행은 [현재 상태](status.md), 남은 제품 블로커는 [열려 있는 문제](open-problems.md)가 맡는다. 화면별 시행착오, 세션 ID와 개별 캡처 해시는 운영 문서에 누적하지 않고 exact-ROM manifest와 Git 이력에 둔다.

## 증거의 시간 경계

실행 결과는 다음 입력이 모두 같은 경우에만 한 증거 묶음으로 취급한다.

- ROM 전체 SHA-1
- 콜드 부팅, SaveRAM 파일 또는 source-bound 체크포인트의 출처
- 실행 전에 가한 메모리 개입과 그 목적
- 입력 순서, 누름·해제 프레임과 자동 진행 구간
- 관측한 진입, 변형, 결과, 이탈 체크포인트
- 화면뿐 아니라 해당 소비를 식별하는 RAM·CHR·mapper 상태

다른 ROM의 세이브스테이트에서 CPU·mapper·CHR 상태를 통째로 승계하지 않는다. SaveRAM은 8 KiB 파일로 보존하고 대상 ROM을 reset한 뒤 게임의 불러오기 경로로 소비한다. source-bound 체크포인트는 같은 ROM의 downstream 소비자 진단에만 쓰며 자연 도달이나 전체 진행을 증명하지 않는다.

## 검증 모드

| 모드 | 허용하는 개입 | 증명하는 범위 | 단독으로 증명하지 못하는 것 |
| --- | --- | --- | --- |
| 기준선 | 깨끗한 시작 또는 게임이 만든 SaveRAM | 정상 진행, 저장·불러오기, 자연 전투와 화면 결과 | 방문하지 않은 분기 |
| 진행 가속 | 검증된 장 번호·좌표·금액·적 HP 등 최소 입력 | 후반 장, 시설, 희귀 소비자의 downstream 동작 | 난이도, 자연 획득과 개입 전 진행 |
| 불리한 경계 | 아군 HP·자금·내구도 등 검증된 값을 제한적으로 낮춤 | 패배, 사망, 파손, 구매 실패 같은 경계 | 정상 플레이에서의 발생 빈도 |
| 독립 재합성 | 실행 중 생산된 입력을 별도 합성기에 전달 | 실제 CHR-RAM·remap과 계획의 byte equality | 화면 진입과 게임 진행 |

개입은 도달 조건만 만든다. 게임의 생산자가 그 뒤의 상태·대사·아이템·화면을 만들게 하고, 개입하지 않은 부분만 증거로 주장한다. 잘못된 실험 입력은 허용 목록이나 제품 결함으로 기록하지 않는다.

## 목적별 회귀 묶음

최종 후보는 화면을 하나씩 무작위로 여는 대신 다음 네 묶음으로 검증한다.

### 시작·저장·장 전환

- 콜드 새 게임, 저장 없음·정규 저장·중단 저장의 메뉴 변형
- 불러오기, 기록 삭제, 중단 재개의 일회성 소비와 다시 켠 뒤 상태
- 1장과 후반 장 도입, 장 제목, 여러 페이지 대사와 지도 정착
- 장 완료의 저장 제안·저장 완료 각각의 예/아니오, 다음 장 전환

### 유닛·소지품·시설

- 부대 명단, 요약·상세·명령 메뉴의 진입·취소·재진입
- 장비, 전달, 버리기, 사용의 성공·취소·실패와 결과 뒤 데이터 변화
- 무기점·도구점·보관소·투기장·비밀상점의 인사, 목록, 확인, 자금 부족, 용량 초과와 이탈
- 보관·찾기·전투 보상으로 소지품이 넘는 경로의 배열·금액·유닛 레코드 보존

### 전투와 사망

- 플레이어 선공·적 선공·일반 전투·투기장·사운드 테스트
- 이름, 병종, 장비, 지형, 기술명, 공격·피해·회복·보상 대사와 HP바
- 첫 라운드, 다음 라운드, 대사 직접 갱신과 전투 이탈 뒤 원상 복귀
- 일반 아군 사망·영구 이탈, 마르스 패배, 계속·제목 복귀

### 후반 진행과 엔딩

- 영입 전후, 영입 거절이나 불가 조건, 사망 캐릭터의 후속 분기
- 11장 성 명령 같은 특수 진행과 후반 장 연속 정착
- 자동 엔딩, 원본 영어 도입·스태프, 한국어 장 기록·인물 후일담과 정적 종단
- 생존·영입 상태에 따른 후일담 변형의 대표와 경계 조합

한 묶음에서 공통 가블이나 일본어 잔존이 나오면 화면별 예외를 추가하지 않는다. `생산자 → 번역 재료 → 상주 계획 → 런타임 → 소비자`의 공통 가족을 먼저 찾고 같은 ROM에서 관련 변형을 다시 묶는다.

## 체크포인트와 판정

화면 PNG만으로 통과시키지 않는다. 각 소비자 역할은 가능한 범위에서 다음을 함께 기록한다.

- 게임 상태와 원본 생산자 주소 또는 설치된 역할에서 유도한 진입점
- 선택자, 레코드·페이지 정체성, 행 교체 방식과 상주 그룹
- mapper 그림자, 실제 CHR-RAM digest와 네임테이블의 활성 코드
- 돈, HP, 내구도, 소지품·보관 배열처럼 분기 결과를 나타내는 데이터
- 완료 뒤 입력을 받는 상태와 원래 호출자·지도·다음 장으로의 이탈

동적 합성 경로는 준비 표식만 보지 않는다. 게시 한 프레임 뒤 저장 문자열, 런타임 코드북, 독립 재합성 CHR과 실제 CHR-RAM이 일치하고 화면이 읽혀야 한다. 합성 중간의 빈 표시 페이지는 허용하지만 일본어·이전 코드북·부분 글리프 노출은 실패다.

선택 커서, 표식과 맵 애니메이션 때문에 화면 해시는 정상적으로 바뀔 수 있다. 7·19·43프레임처럼 서로 다른 간격의 표본을 사용하고, 고정 창·문자·보더와 의도된 동적 요소를 분리해 판정한다. 자동 장면에는 임의 입력을 보내지 않고, 대사 완료나 입력 대기 상태를 확인한 뒤 한 번만 입력한다.

## 과거 exact-ROM 증거 색인

아래는 현재 후보의 성공이 아니라 재현 경로와 소비자 원인을 이미 확인한 과거 계보다. 상세 화면 해시와 세션 기록은 해당 커밋의 `playtesting.md` 이력과 비공개 manifest에서 찾는다.

| ROM SHA-1 | 닫았던 범위 | 현재 사용할 수 있는 주장 |
| --- | --- | --- |
| `6E7604E23F506B87C8C800B4DDF86A4B6E441489` | 마르스 패배, 일반 아군 사망·다음 장 영구 이탈 | 상태 생산자와 재현 경로 |
| `DFE31A6807DCCFADE6EF7D20F2060E45A95308CF` | 투기장 전투와 부대 명단 상주 | 해당 소비자 입력·이탈 경계 |
| `C50BC2E15EB51CB482DB906DB3BFF1FFC24C5F67` | 일반·사운드 전투, 병종·장비 경계, 유닛·소지품·시설 묶음 | 공용 합성·시설 생산자와 분기 결과 |
| `9418796F51B39CF316B78148E2D16410A42AF620` | 회복 HP바, 투기장, 상처약, 무기점·도구점·보관소·비밀상점 | 결함 재현과 교정 전후 비교 경로 |

이 표의 성공은 이후 ROM에 자동 승계하지 않는다. 현재 후보는 네 목적 묶음의 새 manifest를 가져야 한다.

## 실패 처리

- 같은 입력에서 원본과 후보가 다르면 먼저 ROM·SaveRAM·개입·정착 시간을 맞춘다.
- 가블, 일본어 잔존, 보더 손상, 진행 불가와 잘못된 데이터 변화는 모두 제품 반례다.
- 원인이 공통 계약이면 관련 소비자 전체를 정적 목록으로 묶고 한 번에 고친다.
- 원인이 실행 순서나 프레임 위상에만 나타나면 정적 추측을 늘리지 않고 짧은 계측 실행으로 결속한다.
- 고친 뒤에는 반례 경로뿐 아니라 같은 소유자를 쓰는 성공·취소·실패·이탈을 같은 exact ROM으로 다시 본다.
