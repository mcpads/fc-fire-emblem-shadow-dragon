# 플레이와 런타임 검증

기준일: 2026-08-22

이 문서는 지원 일본판을 플레이하는 데 필요한 최소 조작과, 한글 패치의 실행 검증에서 치트를 다루는 원칙을 기록한다. 치트는 화면 도달 시간을 줄이는 시험 개입이지 정상 동작의 증거를 대신하지 않는다.

## 확장 ROM과 세이브스테이트 계보

세이브스테이트는 화면 위치만 담지 않고 mapper의 PRG/CHR 뱅크 선택도 복원한다. 따라서 과거 32페이지 ROM에서 만든 상태를 현재 512KiB 확장 ROM에 불러오면, 신규 고정 뱅크 코드가 있는 `$F79A`가 `FF`로 보이면서 한글뿐 아니라 화면 전체가 가블될 수 있다. 이 상태는 최신 ROM 결함의 실행 증거가 아니다.

emucap의 `native_halt_savestate`는 주 CPU 명령 경계에서 멈춘 채 save/load 호출과 복원 직후 CPU 투영을 안전하게 서비스한다는 보장이다. 다른 ROM의 mapper·PRG/CHR 상태가 현재 ROM과 호환된다는 보장은 아니다. `status.freeze_policy.savestate_safe`가 참인 정지에서만 전체 상태 I/O를 하고, 서로 다른 ROM 계보 사이에서는 상태 전체가 아니라 별도로 검증한 SaveRAM만 옮긴다.

현재 정확 통합 출력 SHA-1 `DFE31A6807DCCFADE6EF7D20F2060E45A95308CF`은 콜드 실행 또는 같은 생성 계보의 상태로만 판정한다. 구형 상태에서 진행 자료가 필요하면 SaveRAM만 덤프하고, 현재 ROM을 native power cycle한 뒤 SaveRAM 영역에만 주입한다. 그 뒤 다음 세 가지를 모두 확인한다.

- 고정 뱅크 표본 `$F79A..$F7B9`가 `FF`가 아니라 현재 ROM의 bridge 바이트와 같다.
- 콜드 제목 또는 이미 결속한 기준 화면 해시가 정상 계보와 같다.
- 구형 상태의 CPU·mapper·CHR 상태는 실행 근거나 회귀 기준으로 재사용하지 않았다.

## 부대 명단의 최종 코드북 회귀

직전 exact ROM의 확대 캡처에서 헤더 `이름` 저장 코드가 최종 유닛명 카탈로그 페이지에서는 `검는`으로 해석되는 교차 모듈 결함을 확인했다. 명단 본문과 보더만 보는 판정은 이 결함을 놓치므로, 명단 회귀는 헤더 의미, 모든 가시 이름, `LV/HP`·숫자, 커서·유닛 그래픽과 전체 보더를 한 화면에서 함께 판정한다.

직전 exact ROM에는 게임이 만든 8 KiB SaveRAM SHA-256 `1F5714C1BCEC8D16C72ABED9D5053A4A54D40A756730AC997103E004B4B53402`만 파일로 넣고 reset했다. `불러오기 → 기록1 MAP 8 → 도입 4페이지 → SELECT → 첫 항목`으로 자연 진입했으며, 다른 ROM의 CPU·mapper·CHR 상태는 복원하지 않았다. 정착 뒤 +7/+19/+43프레임 화면 SHA-256은 모두 `282B67A0D779F42865F21E390B65A5E8E427F314520DFF60539758542341DD72`였다. `B`로 지도에 돌아간 뒤 `SELECT`로 진행 메뉴도 다시 열렸다. 실행 ID는 `01M0K3QQEBGW240Z2P58K2CS23`이다.

카탈로그 재배정은 헤더 두 바이트뿐 아니라 같은 코드북을 쓰는 이름·병종·품목·유닛 UI 저장 문자열과 두 글꼴 페이지를 함께 바꾼다. 따라서 같은 콜드 실행에서 만든 현재-ROM 지도 상태를 한 번 저장하고, 유닛 요약·상태·소지품·행동, 보관소 보관·취소, 무기점과 도구점을 독립 분기했다. 유닛 화면의 이름·병종·능력 라벨·품목, 보관소 대사와 고정 라벨, 무기점 7품목, 도구점 `상처약/문의 열쇠/라이브/파이어/선더`, 가격·초상화·보더가 함께 읽혔다. 도구점 B 취소 뒤에는 종료 대사와 `소지품/도구점/대기` 명령 메뉴까지 돌아왔다. 실행 ID는 `01M0K45B8P6AR56HH6C6JHK62Q`다.

현재 exact ROM `DFE31A6807DCCFADE6EF7D20F2060E45A95308CF`에서는 아래 투기장 회귀 뒤 같은-ROM 8장 지도 기준 상태를 복원해 `SELECT → 첫 항목`으로 명단을 다시 열었다. `이름`, 여덟 한글 이름, `LV/HP`, 숫자, 커서·유닛 그래픽과 전체 보더가 함께 읽혔고 600프레임 뒤에도 PNG SHA-256 `044B2CCD863E7B4D76C7C378A589BCDC64D632615666537A0F14476C46C6D1D6`으로 같았다. 이 표본이 내용 있는 합성 상태 `17`의 보존 관문을 현재 산출물에 결속한다.

## 기본 조작과 진행

- 방향키: 커서 이동과 항목 선택
- `A`: 결정, 유닛 선택, 메시지 넘기기
- `B`: 취소
- `START`: 타이틀에서 메뉴 진입
- `SELECT`: 진행 메뉴 열기

새 게임은 타이틀에서 `START`를 누르고 패치판의 `처음부터`와 저장 슬롯을 고른다. 패치판의 `불러오기`는 장 클리어 때 저장한 파일을 불러오고, `이어하기`는 중단 데이터를 재개한다. 원본 일본판에서는 각각 `さいしょから`, `ロードする`, `つづきをする`이며 중단 데이터는 재개하면 사라진다.

아군 유닛을 선택해 이동과 행동을 끝낸 뒤 진행 메뉴의 `ターンおわる`로 적 턴을 시작한다. 보스를 쓰러뜨리고 마르스를 성이나 왕좌에 이동시켜 `しろ` 또는 `ぎょくざ`를 선택하면 장을 완료한다. 마르스가 쓰러지면 게임 오버이고, 다른 아군이 쓰러지면 원칙적으로 이후 장에서 돌아오지 않는다. 정규 저장은 장 완료 때만 가능하며 파일은 2개다.

1장에서는 서쪽 마을에서 리프를 영입하고 동쪽 마을에서 `10000G`를 얻을 수 있다. 요새 회복과 지형 효과, 비행 유닛의 활 약점을 익히는 첫 실전 구간이다.

## 확인한 화면 상태 전이

버튼은 현재 화면의 입력 대기 상태가 확인된 뒤에만 보낸다. 자동 장면인지 모를 때는 먼저 입력 없이 짧게 프레임을 진행해 화면 변화 여부를 본다. 화면 의미를 모르는 상태에서 `A`나 `START`를 탐색 입력으로 반복하지 않는다.

```text
자동 시연 ── START ──> 타이틀 연출 ── 대기 ──> 타이틀 입력 대기
자동 병종 소개 ── 무입력 ──> 다음 병종 소개 ── 반복 ──> 검은 전환 ──> 원본 영어 도입
타이틀 입력 대기 ── START ──> 처음부터/재개 메뉴
처음부터 ── A ──> 저장 슬롯 ── A ──> 1장 인트로
1장 인트로 완료 대사 ── A ──> 다음 완료 대사 또는 맵
맵 유닛 위 ── A ──> 유닛 요약·이동 선택 ── 같은 자리 A ──> 유닛 상세
유닛 상세 ── B ──> 이동 선택 ── B ──> 맵 유휴
이동 선택 ── 이동할 칸 A ──> 자동 이동 ── 완료 ──> 유닛 명령 메뉴 ── B ──> 유닛 요약
유닛 명령 메뉴 ── もちもの A ──> 소지품 목록 ── 아이템 A ──> 조건부 행동 메뉴

조건부 행동 메뉴 ── そうび A ──> 장비 결과 대사
조건부 행동 메뉴 ── つかう A ──> 초기 사용문 ── 자동 효과 ──> 일반 결과 상태 03 ── 완료 뒤 A ──> 맵

대지의 오브 ── 32단계 무입력 ──> 결과 33·상태 03 ── 완료 뒤 A ──> 맵
조건부 행동 메뉴 ── わたす A ──> 점멸 대상 선택 ── B ──> 소지품 목록
점멸 대상 선택 ── 대상 A ──> 양도 결과 대사
조건부 행동 메뉴 ── すてる A ──> 폐기 결과 대사
맵 ── SELECT ──> 진행 메뉴
진행 메뉴 ── DOWN 5회 ──> ターンおわる ── A ──> 적 턴 자동 진행
적 턴 ── 자동 ──> 이동·전투 애니메이션 ── 자동 ──> 다음 입력 대기
```

현재 콜드 기준 경로는 첫 명령 전 정지에서 1,450프레임을 진행해 타이틀 입력 대기를 확인한 뒤 `START`를 10프레임 누르고 110프레임 진행한다. 이 입력은 `처음부터` 화면으로 들어가지만 관측한 종료 RAM 값 하나의 변화로 결속하지 않으므로 화면 확인을 생략하지 않는다. 기본 항목의 `A`는 10프레임 누르고 300프레임 뒤 저장 슬롯, 슬롯 1의 `A`는 10프레임 누르고 1,000프레임 뒤 1장 완료 대사에 도달했다. 2프레임 입력은 이 경로에서 충분하지 않았다.

제목 자산을 설치한 현재 누적 후보 `87176c60d9ebb3cfd28e9cc44c58954113863d0e`는 첫 명령 전 동결 상태에서 입력 없이 진행했다. 프레임 1206의 보라색 초기 위상, 1331의 완성 위상, 1458의 저작권 표시, 1912의 자동 병종 소개 이탈을 각각 새로 확인했다. 화면 SHA-256은 `484a5ab12bee505c6699e943e6c9ddc9f48e27fae6a948c7abbbeb0884f40657`, `c2688a613d9803b7dff0f96b64a62932fa3b30e091b005937b21a52a42e8cdcf`, `51a7379343410a51954864ee534a28155945720b09a5e53e1182f174814ca218`, `ea7634a3b2be2e31a4fa9dce2e97b2ef73f47bbf22a37b14f09e5b7f01d3f903`이다. 완성 연출 뒤 `$2182`의 원작 상단 장식 26셀은 비어 있고 `$21A8/$21CD/$21ED` 11셀은 정적 한국어 로고와 같으며, 흰 전경과 원본 칼, 두 셀 `TM`, `©1990 Nintendo`가 함께 유지됐다. 누적 빌드 보고서는 실행 증거 유예 상태이므로 아직 런타임 완료로 세지 않으며, 이 증거는 패배 뒤 제목 복귀나 사람 시각 승인을 대신하지 않는다.

1장 완료 대사에서의 `A`는 소스·실행 양쪽에서 다음 `chapter_intro_title_dialogue_composite` 또는 맵으로 가는 비영구 진행 입력으로 결속돼 있다. 누적 ROM `0962476ed480bcd0e874fc0d40041218b8270727`의 콜드 실행에서는 10프레임 `A`와 300프레임 자동 진행을 화면마다 한 번씩 보내 여섯 도입 화면이 모두 한글로 완성된 뒤 맵으로 복귀했다. 화면 SHA-256은 차례로 `5fff10268d3dec93e6cf2c3574d6109c796621ac871d56fd47302b54d5244fd4`, `87faf8cf46391d7083f1559d91b2539b0b77448372177c853e1a5fc8f7722dcc`, `4c0eda5c5babc6f556c193c8618c56d2d5a16f5f8fea56e8e9e8810728e0c464`, `43e86b52d1d67b33a8ede32644490a0eb6f50dec9a7f65385b04f046b99dd36f`, `bae4f159eafd39abfa446058b3659fb4e412a4a6fd3d8c853125b8561683328e`, `9471672d2ca92e698e3f9fbe6b6d1cecd77258c73a11473ab1cec8761166d6c2`이고, 자연 맵 복귀는 `3831facf91038633042614423b774f8b76771f263f0b13c9bc0656a4cca4ede5`다. 각 입력 전에는 완료 표식 또는 완료 상태를 확인하며 자동 출력 중에는 보내지 않는다. 완료 표식은 7·19·43프레임 표본에서 표시와 비표시가 교차하므로 한 캡처의 부재를 미완료로 판정하지 않는다.

장 제목과 런타임 제어 출력 보호를 합친 당시 누적 ROM `cebcfa310206df05525d0d2e5a08a4c24ff97af0`에서도 같은 콜드 경로를 다시 실행했다. 1장 제목 `1 마르스의 여정`과 여섯 대사 페이지의 SHA-256은 `d0cf3b42...`, `fbc3948c...`, `bc0deddc...`, `d0645ae1...`, `26fd461f...`, `76159429...`이고 자연 지도 복귀는 위의 `3831facf...`와 같았다. `{EA}`는 원문에 출력 글리프 `9E AB`를 직접 갖지 않고 실행 중 생성하므로, 수명 계획은 제어 바이트뿐 아니라 이 두 출력 코드도 보존해야 한다. 이 보호 뒤 모든 페이지에서 원본 `※` 표식이 유지되고 가짜 한글 접두는 사라졌다.

같은 실행에서 검증된 정규 파일 1 SRAM 8 KiB를 선언해 주입하고 reset handler에서 멈춘 뒤, 장 번호 오프셋 `0x519=02`와 체크섬 오프셋 `0x542=1B 06`을 다시 읽었다. 타이틀에서 `START`, `DOWN`, `A` 뒤 원본 영어 `MAP 2`가 붙은 파일을 확인하고 `A`를 10프레임 누른 뒤 1,000프레임 자동 전환을 기다렸다. 최종 ROM의 2장 첫 페이지는 `2 가르다의 해적들`, 한글 대사와 원본 `※` 표식을 함께 표시했고 SHA-256은 `db5173380b2b01728589f5fd4fddf780b44b44c0a822d2b630f5aa3b756f7539`다. 이 가속 실행은 2장 제목·첫 페이지의 소비자 증거이며 나머지 2장 페이지나 자연 1장 완료를 대신하지 않는다.

시작·기록 메뉴를 누적한 ROM `9d9b4b39ac96c528ef544cc28cb1c3bbc9c1d120`은 같은 1,450프레임 냉간 기준과 120프레임 `START`만 사용했다. 무저장 `처음부터` 화면 SHA-256은 `4d4746102079398bda73d0dbbd99b7f4dcbb71a049dd3938a6afef5727800a61`, 정규 저장의 4항목 화면은 `82ceb2d827a756993b19a38a4e5d611a316f422a13e90f82cc356710b11cf77f`였고, 둘 다 +7/+19/+43프레임에서 같은 해시와 mapper 값 `A8`을 유지했다. 저장 메뉴에서 `DOWN` 한 번 뒤 커서가 `불러오기`에 있는지 확인하고 `A`를 보냈다. 기록 화면은 `기록1 MAP 2`를 표시해 SHA-256 `e0499863bc8f4c9bb5894d64b96640378c8d41134a88725f0e812cc844d9b253`였으며, 다시 `A`와 1,000프레임 자동 전환 뒤 2장 첫 화면 `6a52173b1ffc67abf6b192445056cba33b614ae19419e7a0d11b52d750f49d2f`에 도달했다. 중단 데이터가 없으므로 `이어하기` 변형은 이 실행으로 검증하지 않는다.

통합 ROM `f6376472dc923575f7d33355befbd12a8f63fec9`에서는 타이틀 입력 대기에서 `START` 10프레임과 110프레임 진행으로 `처음부터`를 확인하고, `A` 10프레임과 300프레임 진행으로 빈 저장 슬롯 화면에 들어갔다. 이 화면의 `$05E8=21`, CHR 그림자 `1A/1A + 00/00`, mapper 레지스터 `A8`과 한글 `처음부터/기록1/기록2`, 원본 `MAP/숫자/대시`를 함께 확인했다. 화면 SHA-256 `860628693852e2b00f49ba873f2c8386008db37a05cc66fc9dccba387e50fc6c`은 0/+47/+130프레임 불규칙 표본에서 유지됐다. 이 실행에는 세이브스테이트나 메모리 주입을 쓰지 않았고, 유효 저장·중단 데이터 변형은 별도 관문이다.

수정된 통합 ROM `97da073050e437c9d2ec32c852c2623dd6c0b368`도 같은 콜드 경로에서 저장 슬롯 화면을 재현했다. 슬롯 1에서 입력 대기임을 확인한 뒤 `A`를 10프레임 누르고 1,300프레임 자동 진행해 1장 첫 완료 대사에 도달했다. `마르스의 여정`, 한글 본문, 원본 장 번호·초상화·창이 함께 유지됐고 0·7·19·43·82프레임 표본은 점멸 표식의 표시·비표시 위상을 모두 포함했다. `$77F7=0E`를 확인한 뒤에만 `A`를 한 번 보내고 800프레임 진행했으며, 다음 화자·대사 페이지가 읽을 수 있는 한글로 완성됐다. 이 경로는 대사가 자동으로 멈춘 것이 아니라 완료 페이지에서 진행 입력을 기다린다는 실행 증거다.

최신 통합 ROM `3c8c86110451b7b9177eb554500ea2b5e5353a6e`에서는 위 한 화면을 넘은 뒤의 레코드 003을 별도 관문으로 삼았다. 첫 페이지 완료 뒤 30프레임 동안 활성 포인터 `$7812..$7815`와 전이 플래그 `$780B` 쓰기를 감시해 0건을 확인한 다음에만 `A`를 보냈다. 그 입력은 런타임 페이지를 `0→1`로 올리고 서로 다른 한국어 둘째 페이지를 표시했다. 다음 `A`는 다음 레코드, 이어진 입력은 후속 페이지와 대사창 종료·맵 진입으로 진행했다. 최종 실행 manifest에서 주 대사 역할을 결속하려면 이제 서로 다른 페이지 둘, 다음 레코드, 역할 이탈의 digest-bound 표본이 모두 필요하다. 한 완료 화면이나 한 번의 화면 변경만으로는 주 대사 진행을 통과 처리하지 않는다.

통합 ROM `5e8eaaf096dc5a18e6501be1007064f1831d7a62`의 유효 저장 시작 메뉴 검증은 8 KiB SaveRAM의 장 번호 `07`과 저장 체크섬을 먼저 검증한 뒤, 상태 전체를 불러오지 않고 SaveRAM만 주입하고 현재 ROM을 reset했다. 타이틀 입력 대기에서 `START` 10프레임과 110프레임 진행 뒤 4항목 화면의 `$05E8=0D`, 그림자 `1A/1A + 00/D8`, mapper 레지스터 2의 `A8`을 확인했다. `처음부터/불러오기/이어하기/기록지우기` 화면 SHA-256 `ce3b2f16...`은 0/+7/+19/+43프레임에서 같았다. 입력 효과가 결속된 `DOWN` 한 번 뒤 커서가 `불러오기`에 있는 화면 `9e93aea4...`를 확인하고서만 `A`를 보냈으며, 기록 화면은 `기록1`과 원본 `MAP 7`을 함께 표시했다. 이 실행은 유효 저장 메뉴와 불러오기 기록 화면을 닫지만, 실제 중단 데이터가 있는 `이어하기` 변형이나 새 산출물의 주 대사 진행 증거를 대신하지 않는다.

같은 정확 ROM을 SaveRAM 8 KiB가 모두 `00`인 첫 명령 전 상태에서 별도로 시작해 무저장 콜드 경로도 다시 실행했다. 레코드 003 첫 완료 페이지에서 30프레임 동안 `$7812..$7815`와 `$780B` 쓰기는 0건이었다. 완료 상태 `0E`에서만 `A`를 한 번씩 보낸 결과 서로 다른 페이지 `87e909be... → d0645ae1...`, 다음 레코드 `26fd461f...`, 후속 페이지 `76159429...`, 맵 이탈 `fb077a6a...` 순서를 재현했다. 새 manifest가 이 현재 산출물의 네 digest를 직접 검사한다.

같은 정확 ROM의 7장 최악 대사는 구 ROM의 CPU·mapper 상태를 불러오지 않았다. 자연 이동·턴 종료·보스 전투로 성에 접근한 구 체크포인트에서 마르스가 성 위 `대기`를 실행한 뒤, 결속된 `SELECT → DOWN 3회 → 중단`으로 게임 자체가 중단 SaveRAM을 직렬화했다. native power cycle 전후 8 KiB SHA-256 `3737e4c2...`가 같음을 확인하고, 이 SaveRAM만 현재 ROM의 첫 명령 전 상태에 넣은 뒤 현재 ROM을 reset했다. 시작 메뉴의 첫 항목 `이어하기`로 성 위 좌표와 행동 상태를 복원하고 실제 `턴 종료`와 성 명령을 거쳤다. 진행 가속은 중단 자료에 포함된 `MOV 15`와 선언한 적 HP 1 묶음뿐이며 좌표·행동·승리 단계는 쓰지 않았다.

대상 선택자 `C0:18`과 완료 상태 `$77F7=0E`에서만 `A`를 보냈다. 현재 런타임 가시 페이지 `$07F2`는 `00..0E`를 한 번씩 순서대로 거쳤고, 각 페이지를 0·7·19·43·82·171프레임에 표본화했다. 마지막 입력 뒤 `$24/$84=0D/03`, 대사 상태 `00`과 원본 영문 `NEXT STORY`를 확인했다. 최종 manifest는 15개 완료 페이지와 그 뒤 이탈 표본을 요구하며 전체 설치 보고서 SHA-1은 `0127863a...`다.

이 경로에서 진행 메뉴와 유닛 요약·성 명령의 한글 바이트가 다른 코드북으로 표시되는 가블도 재현됐다. `$7FF3=01→06`과 명령 커서 위치로 입력 의미는 확인했지만, 이 화면들을 정상 표시로 통과시키지 않는다. 7장 대사 전진 성공은 맵 메뉴·유닛 UI 소비자의 실패를 가리지 않는다.

진행 메뉴는 6항목이며 첫 항목에서 열린다. `ターンおわる`는 여섯 번째이므로, 턴 종료는 `DOWN` 5회 뒤 커서가 마지막 항목에 도달한 화면을 확인하고 결정한다.

첫 항목 `いちらん`은 `A`로 부대 목록에 들어가고 `B`로 맵에 돌아온다. 다섯째 `スイッチ`가 설정 화면의 정상 진입 항목이며, `SELECT → DOWN` 4회로 선택값 `$7FF3=05`를 확인한 뒤 `A`를 누르면 `サウンド / アニメーション / ウエイトタイマー`가 열린다. 누적 통합 ROM에서는 이 경로가 주 상태 `$84=38`, 합성 상태 `$05E8=1B`에 정착했다. 행 이동은 글꼴 페이지 `0x88/0x8C`를 실제로 바꾸며, 대기시간과 애니메이션 하위 선택지를 연 뒤 `B`를 누르면 상위 설정 목록이 아니라 맵으로 돌아간다. 따라서 취소 뒤 재검증은 맵에서 같은 `SELECT → DOWN` 4회 → `A` 경로로 다시 진입해야 한다.

같은 누적 콜드 실행에서 맵의 `SELECT`는 원본 진행 메뉴 `c39871a67a4568ffd581e6c9bdb0171aecaf69b882643dc05305a871fb8606b3`을 열었다. 첫 항목 `A` 뒤 부대 목록은 한글 `이름`, 원본 `LV/HP`·숫자·일본어 유닛명·초상화를 함께 표시했고 화면 SHA-256 `f96db41a428bc0c78857615b0f283d139c03208010694232fb6fa7975838d976`이 7·19·43프레임 추가 표본에서 유지됐다. `B` 뒤에는 지도 화면으로 돌아갔다. 설정 화면은 위의 정상 진입 경로와 주 상태·합성 상태를 함께 확인한 뒤 판정한다.

아군명 단계 ROM `97bc9be510a0a69c54ea725324f23b809a618a0b`에서는 같은 `SELECT → 첫 항목 A`가 한글 `이름`과 `마르스/제이건/카인/아벨/도가/고든/시더`, 원본 `LV/HP`·숫자를 표시했다. 화면 SHA-256 `fa81697ccce00068bd2c8866f41ee2fba251e97b102aa9159adeafe966c4f11e`은 +7/+19/+43프레임에서 같았다. `B`로 맵에 복귀한 뒤 유닛 위 `A`는 한글 `마르스`와 원본 `S/HP`·숫자, 일본어 병종·아이템을 함께 표시했고 다음 `A`의 상세 화면은 전환 직후 요약창이 보이지 않다가 +7프레임에 다시 나타났다. 한 프레임만 보고 상단 요소 누락으로 판정하지 않는다. 이 실행은 과거 맵 상태를 도달 가속에 사용했으므로 콜드 회귀와는 구분한다.

병종 소개 단계 ROM `63d36eb2c182979873ea662eb27a9afcdbbbb88c`은 콜드 시작 뒤 입력을 한 번도 보내지 않았다. 프레임 1790·6352·7752·12452·12952에서 프로필 인덱스 `0/8/11/20/21`의 한글 제목·설명과 원본 `STR/SKI/WLV/AGI/DEF/MOV/H.P/EXP`·숫자를 확인했다. 페이지 경계 인덱스 11에서는 mapper 레지스터 2와 4가 모두 `BC`였고, 프레임 13352의 검은 자동 전환과 13852의 원본 영어 도입까지 자연 진행했다. 일곱 화면은 서로 다른 이미지이며 프레임 간격도 불규칙하다. 이 경로는 자동 장면이므로 검증 중 버튼 입력을 보내지 않는다.

현재 제어된 Mesen 실행에서는 2프레임 방향키·취소 탭이 메뉴와 상태 화면에서 입력 폴링에 잡히지 않았고, 10프레임 탭은 한 번의 동작으로 안정적으로 등록됐다. 별도 화면에서 확인하기 전까지 직접 입력은 `press_frames=10`을 기준으로 하며, 방향키를 길게 눌러 자동 반복에 맡기지 않는다. 각 입력 뒤 기대 화면이나 커서 위치가 확인되지 않으면 다음 입력을 보내지 않는다.

관리 실행은 첫 명령 전 동결 시작과 네이티브 CPU 정지를 지원한다. 세이브 상태 로드는 같은 ROM이라도 현재 정지가 안전한 CPU 경계일 때만 성공하며, 프레임 step이나 중단점으로 멈춘 상태에서는 `unsafe_halt`로 거부된다. 이때 뒤 입력을 계속 보내지 않는다. 실행을 재개한 뒤 네이티브 pause로 다시 멈추고, 로드의 `status=completed`와 기준 화면·CHR 그림자를 별도 호출에서 확인한 뒤 다음 입력을 보낸다. 과거 세이브 상태는 화면 도달 가속에만 쓰고, 판정할 실행 이벤트는 로드 이후 같은 관리 실행 세대에서 새로 수집한다.

1장 맵에서 커서 RAM `$008E/$008F=08/18`과 아군 27바이트 레코드의 좌표가 일치하는 유닛을 사용해 위 전이를 확인했다. 첫 `A` 뒤에는 이름·병종·레벨·HP·아이템 요약이 유지되고, 같은 자리의 두 번째 `A`가 상세 능력치를 연다. 상세에서 `B` 한 번은 맵 유휴가 아니라 이동 선택으로 돌아가므로, 맵 유휴까지는 `B`를 한 번 더 보내고 화면을 확인한다. 이동 선택에서 같은 자리를 확정하면 `もちもの / たいき` 명령 메뉴가 열린다. 다른 칸을 확정하면 즉시 메뉴로 가지 않고 자동 이동이 진행되므로 입력 없이 완료를 기다린다. 메뉴의 `B`는 행동을 끝내지 않고 유닛 요약으로 돌아가며, 이동한 두 표본에서는 커서와 유닛 레코드 좌표도 원래 `$08/$18`로 복구됐다.

명령 조립기는 공격·지팡이·변신·지형·대화·소지품·시설·대기를 이 순서로 판정해 `$05EB` 비트 0~7을 사용한다. 합성 중 임시 값인 `$05EB`을 안정 화면의 영구 명령 마스크로 해석하지 않는다. 메뉴가 열린 뒤에는 입력 대기이며 152프레임 동안 글자 페이지는 바뀌지 않았다. `もちもの`의 결과 6은 소지품 목록을 여는 비변경 전이까지 결속했지만, 나머지 명령의 `A`는 개별 handler를 결속하기 전에는 보내지 않는다. 대표 지형·시설 변형은 목적 칸으로 이동한 뒤 메뉴를 읽고 `B`로 빠지는 데까지만 관측하며, 이동 자체의 영향을 없애야 할 비교에서는 같은 관리 실행의 안전한 기준 상태를 다시 로드한다.

품목 `A` 뒤 상태 `04→05→06→07`, 대사 `04`가 부적합 경고와 “그래도 살 것인가?” 질문을 연다. 여기서 `B`나 “아니오”는 구매하지 않고 상태 `07→08→09→0A→0B→0C`, 대사 `36`의 별도 계속 구매 화면으로 간다. 이 화면의 “예”는 상태 `03→04`로 품목 목록을 다시 만든다. 반대로 경고에서 “예”를 고르면 보통 구매 블록이 실행된다. 관측 표본에서는 `400G`가 차감돼 저장 금액 `00A8→0080`, 마지막 빈칸 `$770A/$770E`에 품목·내구도 `11/21`이 들어갔다. 이 구매로 소지품이 가득 차서 일반 구매 결과의 계속 질문 대신 상태 `08`, 대사 `05→06`의 구매·자동 이탈 화면이 열렸고, 그 화면의 `A`가 시설 행동을 완료했다. 따라서 “조건 실패”, “구매 거절”, “마지막 칸을 채운 구매”를 같은 화면이나 같은 버튼 효과로 합치지 않는다.

선택 커서와 메시지 표식처럼 점멸하는 UI는 단일 스크린샷에서 꺼진 위상으로 잡힐 수 있다. 한 프레임에서 요소가 보이지 않았다는 이유로 선택 상태나 입력 실패를 판정하지 않는다. 입력 전후의 상태 판정은 입력 없이 간격을 둔 복수 프레임을 보고 점멸 위치의 합집합을 비교하거나, 커서·상태 메모리와 실행 이벤트를 함께 사용한다. 화면 해시가 달라도 국소 점멸 위상만 다른지 먼저 분리하며, 픽셀 단위 원본 비교는 같은 실행 경계와 위상에 귀속한다.

짧게 나타났다 사라지는 화면은 과거 실행의 프레임 위치나 화면을 지나친 뒤의 캡처로 검증하지 않는다. 같은 실행에서 해당 화면을 만드는 소스 이벤트를 먼저 관측하고, 그 이벤트를 기준으로 불규칙 간격 표본을 모아야 한다. 현재 지형 효과 창은 뱅크 `05:$96B6` 이벤트 뒤 `+3/+7/+19/+35`프레임을 다시 표본화해 `battle_animation` 역할에 결속했다. 화면이 이미 닫힌 뒤 과거 프레임 위치를 적용한 첫 캡처는 폐기했으며 실행 증거 수에 포함하지 않는다.

1장 기준선에서 `ターンおわる` 결정 뒤의 카메라 이동, 적 이동과 전투 애니메이션은 추가 입력 없이 진행됐다. 다음 아군 입력 대기는 카메라·유닛 위치가 복수 표본에서 유지되는지 확인해 판정한다. 맵 유닛 스프라이트의 애니메이션 위상이나 점멸 때문에 PNG 전체 해시는 달라질 수 있으므로, 해시 동일만을 안정 상태 조건으로 쓰지 않는다.

깨끗한 1장 기준 상태에서 지도 입력 대기는 주 상태 `$84=00`으로 확인한다. `$29=06`은 적 자동 처리 사이에도 나타나므로 이것만으로 다음 입력을 보내지 않는다. `SELECT` 뒤 진행 메뉴는 `$84=01`, 선택값 `$7FF3=01`로 열렸다. 각 `DOWN`은 이 값을 `02→03→04→05→06`으로 한 단계씩 바꿀 때까지만 유지한 뒤 해제했고, `06`의 `A`는 `$84:01→20`에서 해제했다. 적이 접근만 한 첫 두 적 턴은 중단점 없이 완주해 각각 `$84=00` 복귀와 전투 이벤트 0건을 확인했다. 세 번째 적 턴 직전에만 공용 writer `$C1F2` 중단점을 설치했고, 적 `ガザック` 선공과 `カイン` 반격의 정규 전투에 이벤트 누락 없이 멈췄다. 진행 가속이나 HP 개입이 없는 불리한 전투 도달 경로다.

적 자동 처리 중에는 `$29=06`과 `$7FF3=06`이 남아 있어도 진행 메뉴가 아니었다. 자동 처리가 끝나 `$84=00`이 된 뒤 `SELECT`를 보내면 메뉴가 `$84=01`, 선택값 `01`로 새로 열렸다. 따라서 모든 턴에 `SELECT`와 `DOWN`을 기계적으로 반복하지 않고, 화면과 `$84/$7FF3`을 함께 읽어 현재 입력 대기 소유자를 판정한다.

불리 전투는 최초 `$C1F2` 실행에서 저장한 상태를 기준으로 1·7·19·43·82·127·191·263·383·565·711프레임을 불규칙 표본화했다. 예측, 적 공격, 아군 피격, 카인 반격, 성장, 경험치 결과까지 `battle_animation` 수명 안에서 확인했고 934프레임에는 지도로 복귀했으므로 그 표본은 전투 합집합에서 제외했다.

같은 무개입 기준선의 다음 아군 입력 대기에서 카인을 좌표 `08/17`로 이동시켜 가자크 `07/17`을 공격했다. 입력 효과는 `$84=00→09→0B→23→25→26→0C→0D→0F→10→11→12→13` 상태열과 최초 공용 writer `$C1F2` 1회로 결속했으며, 치트나 메모리 쓰기는 사용하지 않았다. 플레이어 선공 전투는 그 writer 진입 상태에서 1·7·19·43·82·127·191·263·383·565프레임을 표본화해 예측, 카인 공격, 속도 성장, 가자크 반격과 피해 결과를 확인했다. 711프레임에는 `$84=00`인 지도로 복귀했으므로 전투 합집합에서 제외했다.

1장 첫 인트로 메시지부터 맵까지는 화면별로 `A`를 15회 결정하면 도달한다. 이는 한 번의 연속 입력이나 자동 넘김 수가 아니라, 각 메시지 화면이 입력 대기임을 확인하고 10프레임 탭을 한 번씩 보낸 현재 기준선 경로다.

## 중단 저장과 재개

맵의 진행 메뉴는 첫 항목에서 시작하며 `ちゅうだん`은 네 번째다. 따라서 `SELECT`로 메뉴를 연 뒤 `DOWN` 3회로 네 번째 커서를 확인하고 `A`로 결정한다. 완료 화면은 추가 선택지가 아니라 다음 안내 메시지다.

```text
ゲームをおわらせるときは
リセットボタンをおしながら
でんげんをきってください
```

즉 게임은 중단 직후 바로 전원을 끄는 흐름이 아니라 리셋을 누른 채 전원을 끄도록 안내한다. 에뮬레이터 검증에서도 중단 메시지만 확인하고 프로세스를 강제 종료한 결과를 정상 저장 증거로 취급하지 않는다.

정상 중단 검증은 상태 주입 없이 위 조작을 수행한 뒤 에뮬레이터의 native power cycle을 사용한다. 이 동작은 같은 관리 실행 세대와 같은 ROM이 다시 연결될 때까지 기다리는 전원 재인가 경계다. 전원 재인가 성공 응답만으로 배터리 파일 기록을 주장하지 않고, 중단 직후 8 KiB SRAM과 생성된 `.sav`가 바이트 단위로 같은지 별도로 확인한다.

지원 원본과 mapper 165 프로브에서 이 경로를 각각 실행했다. 두 ROM의 중단 직전 SRAM, 중단 직후 SRAM, `つづきをする` 재개 뒤 SRAM이 단계별로 서로 같았고, 첫 전원 재인가 뒤에는 이어하기가 나타나 같은 맵으로 복귀했다. 재개 뒤 다시 전원을 재인가하면 이어하기가 사라져 중단 데이터의 일회성 소비도 같았다.

현재 통합 ROM `0AE64C3677B71CDD55EB5EBA0CA7D0D62B155A43`에서도 같은 경계를 다시 확인했다. 7장 지도에서 `SELECT`, `DOWN` 세 번으로 진행 메뉴 네 번째 `중단`을 고른 뒤 `$05DB`는 `00→01→02`로 진행했다. 주 대사 인계가 `$7809:00→01`을 쓴 프레임에 `06:$A13E`가 상태를 2로 넘겼고, `06:$B858`은 완성된 전원 차단 안내 화면 동안 반복 실행됐다. 안내 화면 SHA-256은 `9310BF3B44711D67D7730FCEF384C98310CFB40CC73121CCA619C4270F623E16`이다.

중단 직후 8 KiB SaveRAM SHA-256은 `B95CEC3963BF8C884C626654538CE902D7AF250FC696F3371F8178B6FAE66E69`였다. 같은 관리 실행 세대의 native power cycle 뒤 시작 메뉴 첫 항목 `이어하기`가 나타났고 화면 SHA-256은 `2D9017E72AF30DF33A38118EF7F116904F7CC3A35556E57749FAD9CEAAA5F4C7`이다. 이를 선택하면 같은 7장 지도에 복귀했고, 재개 뒤 SaveRAM SHA-256은 `CE14186E170BFC948C395A92E46C1FC5FAED9FD3247D6B1EE968BDDDBDEA5540`으로 바뀌었다. 다시 native power cycle한 메뉴에는 `이어하기`가 없었으며 네 항목 화면 SHA-256은 `82CEB2D827A756993B19A38A4E5D611A316F422A13E90F82CC356710B11CF77F`였다. 이는 현재 통합 산출물에서 중단 데이터의 생성·재개·일회성 소비를 닫지만, 배터리 파일과 메모리 덤프의 바이트 동등성을 별도로 주장하지 않는다.

재개 직후 진행 메뉴의 `보관소`는 주 상태 `42`, 합성 상태 `17`에서 “40개 보관가능” 화면을 만들었다. `$05DB`는 `00→01→02→03`으로 진행하고 `B`에서 0으로 돌아갔다. `소지품`은 주 상태 `36`, 합성 상태 `13`에서 금액과 무기 수량 요약을 만들고 `$05DB:00→01→02` 뒤 `A`에서 0으로 돌아갔다. 두 경로 모두 관측 중 `06:$9DBE`, `$B10D`, `$A13E`에는 들어가지 않았다. 이 표본은 같은 `$05DB`를 쓰는 진행 메뉴 화면과 주 대사 호출자 인계 상태기가 별개임을 보여 주며, 주소 하나의 감시 결과만으로 인계 경로를 판정하지 못하게 한다.

새 관리 프로세스 실행은 격리된 실행 묶음을 다시 만들기 때문에 이전 실행의 `Saves` 디렉터리를 이어받는 배터리 지속성 시험이 아니다. 프로세스 강제 종료나 새 관리 실행 결과를 위 native power cycle 검증과 혼동하지 않는다.

## 장 완료 뒤 숨은 사운드 테스트

1~24장을 완료한 뒤 첫 저장 질문에서 “예”로 저장하고, 이어지는 계속 질문에서 “아니오”를 고르면 데이터 손실을 막기 위해 전원을 끄라는 일본어 안내에 정착한다. 이 화면에서 다음 순서를 입력하면 사운드 테스트로 들어간다.

```text
UP, DOWN, LEFT, RIGHT, UP, A
```

지원 ROM의 뱅크 `0B:$9BA0`은 현재 입력을 `08 04 02 01 08 80`과 비교하고 일치한 단계 수를 `$775B`에 저장한다. 실행에서는 각 입력마다 `$775B=00→05`를 확인했고 마지막 `A` 뒤 `$05EE=0B→0C`를 거쳐 `SOUND TEST MODE` 화면을 열었다. 사운드 테스트의 영문 라벨과 숫자는 원래 영어이므로 번역하지 않는다.

현재 ROM의 `0B:$9C17`은 위·아래를 번호 `$775C` 변경, `A`를 `$06F0..$06F7`의 선택 이벤트 비트 기록, `B`를 `$06F0=01` 기록으로 분기한다. 실행에서는 위 `00→01`, 아래 `00→50`의 번호·표시 변화를 확인했다. `A`는 선택 번호 1에서 `$06F0=02`, `B`는 `$06F0=01`을 썼지만 음원 소비자가 같은 프레임에 지우므로 쓰기 경계로 검증한다.

`START`는 상태 `0D`의 뱅크 7 전투 애니메이션 테스트로, `SELECT`는 상태 `0E/0F`의 뱅크 4 엔딩 상태기로 이탈한다. 공개 자료도 `START`의 반복 전투 테스트와 `SELECT`의 현재 진행도 엔딩을 설명한다. 복원 가능한 기준 상태에서 `hold_until`로 `$05EE`가 `START:0C→0D`, `SELECT:0C→0E`로 바뀌는 것까지 확인하고 입력을 해제했으며, 그 뒤에는 입력하지 않았다. `START`는 유닛 정보·예측·공격·피해·필살·격파·EXP를 거쳐 다음 전투 쌍으로 자동 반복했다. `SELECT`도 추가 입력 없이 원본 영어 도입·캐스트, 일본어 장 기록, 원본 영어 스태프, 일본어 인물 후일담, 원본 서명·저작권 화면까지 갔다. 마지막 `$7731=1D`는 no-op 처리기 `$C73D`를 쓰고 `$7732=00`이라 엔딩 시간 상태 갱신이 꺼져 있다. 21,000·24,000·28,000·33,000프레임의 스크린샷·네임테이블·OAM·팔레트가 모두 같았으므로 서명은 점멸하지 않는다. 앞서 종단 진입 전 검은 전환 프레임을 종단 점멸로 묶었던 판단은 폐기한다.

## 확인된 일본판 치트

불리한 치트나 메모리 주입은 주소와 값의 의미를 해당 일본판에서 먼저 확인한 뒤 사용한다. 아직 확인하지 않은 주소를 추측해 공개 코드나 회귀 절차로 승격하지 않는다.

### 확인된 마르스 패배 개입

1장 맵의 첫 아군 레코드는 CPU 주소 `$6A90`에서 시작하며 크기는 27바이트다. `$6A90=01`은 마르스 ID이고 `$6A93/$6A94=12/12`는 현재/최대 HP `18/18`이다. `$6A93`을 일회성으로 `01`에 썼을 때 부대 목록의 마르스 HP가 `1`로 바뀌어 실제 소비 주소임을 확인했다.

패배 표본은 깨끗한 1장 맵에서 `$6A93`만 일회성으로 `00`에 쓴 뒤 입력 없이 120프레임을 확인하고, `SELECT`와 `DOWN` 5회로 `ターンおわる`를 선택한다. 유휴 상태에서는 패배가 발동하지 않았고 턴 전환에서 게임 오버 메시지가 나타났다. 계속 적용되는 치트로 만들거나 다른 아군 레코드까지 바꾸지 않는다. mapper 165 실행에서는 게임 오버 CHR 쌍 `07/07 + 00/19`의 최초 쓰기에 멈춘 뒤 1·7·19·43·82·127·191·263·383·565·934·1,273프레임을 불규칙 표본화했다. 완성 문구는 383~1,273프레임에 동일하게 유지돼 입력 대기였고, 그 뒤 `A`는 `$29:0A→06`에서 해제돼 원본 부팅·타이틀 복귀 연출을 시작했다. 원본 영문·숫자는 번역하지 않는다.

이 개입은 턴 전환의 마르스 패배 판정, 게임 오버 표시와 타이틀 복귀를 비교하는 불리한 경계 증거다. 자연 전투의 피해 계산·사망 애니메이션·전투 종료 처리를 대신하지 않는다. 이 무저장 1장 경로의 12개 표본은 모두 대사 선택자 `$77F4:$77F1=B0:0A`를 유지한다. 이는 해당 실행 경로의 선택자 결속이지 게임 전체의 유일한 게임 오버 레코드라는 뜻이 아니다.

지원 원본의 bank `0B:$A09F..$A100` 선택기는 저장·생존 인물·장 번호 조건에 따라 `B0:06/07/08/09/0A` 가운데 하나를 `$77F1`에 쓴다. 정규 8장 SaveRAM에서 마르스 HP 한 바이트만 0으로 만든 뒤 실제 턴 종료를 고른 진단 경로는 `B0:06`을 선택했고, 완성 화면의 한글 패배 문구가 읽혔다. 페이지 예산은 원본 선택기 가족 다섯 레코드의 초벌 한글 합집합 71자와 기존 12표본의 보존 코드 90개를 합친 `161/210`이다. 이 진단은 8장 패배 표시 경로를 확인하지만 자연 전투의 사망 처리나 레코드 `07/08/09`의 실행 표본을 대신하지 않는다.

당시 exact ROM `6E7604E23F506B87C8C800B4DDF86A4B6E441489`에서는 같은 8장 정규 SaveRAM을 콜드 시작 전에 파일로 넣고 `불러오기 → 기록1 MAP 8`의 실제 입력과 도입 대사를 통과해 지도 입력 대기 `$84=00`을 만들었다. 마르스 현재 HP `13→00`의 일회성 개입 뒤 120프레임 유휴에는 패배가 발생하지 않았고, 진행 메뉴의 실제 `턴종료` 선택에서 `$77F4:$77F1=B0:06`, `$77F7=0E`가 됐다. 완성 패배 화면과 계속 선택창의 PNG SHA-256은 각각 `0EEDF396DC06D850BBCE5C23CE71FEE3A6DD5B35EDB346BA5130822D62357F7D`, `A532A1BC90E55B436E036D5958B5ECFF0AA6517CC65DF1CC4097FC87DDA24DA4`다. 선택창의 `B`는 원본 영어 부팅·제목 연출로, `A`는 8장 한국어 제목·첫 대사로 돌아갔다. 두 후속 화면 SHA-256은 각각 `CBA47F699812C3EB21F80E3CB6C3DA1953CD3DF8BB4ED1B62247FBBACFF3E3B`, `847A8510476A7D38E8D51CA2D3EB70B18A3EC54FAD178DCB651668038A6D5B7E`다. emucap 실행 ID는 `01M0JGQA4EAVZ048X4ZS3CMZPV`다.

글리프 예산과 시간축 실행 분석은 이제 같은 원본 선택자 소유자를 읽는다. 기존 62표본 보고서를 다시 만들었을 때 무저장 1장 표본은 실제 `B0:0A`로 남았고 보고서 SHA-1도 `D1390D192C071EE6E1CC5E7BCF2ECAA19774165B`로 같았다. 다섯 레코드는 같은 게시기와 표시 소비자를 공유하고 번역·폭·페이지 예산이 모두 정적으로 결속됐으므로, 중간 레코드 `07/08/09`의 화면 수만 늘리는 반복은 별도 필수 관문으로 세지 않는다. 일반 아군 사망·영구 이탈과 자연 전투의 사망 처리는 이 게임 오버 표시 증거와 분리한다.

### 확인된 일반 아군의 실제 전투 사망과 영구 이탈

당시 exact ROM `6E7604E23F506B87C8C800B4DDF86A4B6E441489`에 게임이 만든 7장 중단 SaveRAM을 파일로 넣고 콜드 재개했다. 시다 ID `02`의 현재 HP만 `0x10→0x01`로 낮추고 공격 대상의 현재 HP만 `0x01→0x10`으로 원래 최대치까지 복구했다. 두 값은 경계 도달을 위한 일회성 개입이며 이동, 공격 명령, 무기와 대상 선택, 전투, 장 완료와 다음 장 진입은 실제 입력과 게임 처리로 수행했다. 같은 대상 확정 상태를 저장한 뒤 마지막 `A` 입력 시점만 제한적으로 바꿔 실제 반격 명중을 얻었다.

전투 중 첫 전투 슬롯 HP `$76F7=00`과 실제 시다 레코드의 행동 상태 `$6B44=FF`가 연속 프레임에 기록됐다. 한글 사망 대사 화면 PNG SHA-256은 `219F64AAC4D13A83048329C07557341FA27C09FC3F84532704EC1B1BF3CF53DA`다. 지도 복귀 뒤 실제 `성` 명령, 7장 완료 15페이지, `NEXT STORY`, 저장, 8장 도입 네 페이지를 연속 진행했다. 8장 명단의 ID는 `01,03,04,05,06,07,1A,1B`였고 시다 ID `02`는 없었다. 명단 화면 PNG SHA-256은 `1BA7FF97E7CA632D25CEF283140F924A44E1112EC7873DD45577BC348587032F`, 최종 SaveRAM SHA-256은 `1F5714C1BCEC8D16C72ABED9D5053A4A54D40A756730AC997103E004B4B53402`, emucap 실행 ID는 `01M0JJ0HX25NKDK3JHQE1RPKWW`다. 이 증거는 실제 전투 사망 처리, 한글 사망 대사, 장 사이 영구 이탈을 한 계보로 닫지만 개입하지 않은 정상 난이도에서의 발생 빈도까지 증명하지 않는다.

### 확인된 1장 완료 가속

첫 아군 레코드의 `$6A9D`는 이동력이다. 일회성으로 `0F`를 쓴 뒤 부대 목록이 `MOV 15`를 표시해 소비 주소를 확인했다. 이 값과 적 HP 1 묶음은 화면 도달을 줄이는 데만 사용하며, 좌표 직접 쓰기나 행동 완료 플래그 해제는 장 완료 증거로 사용하지 않는다. 마르스는 실제 이동 명령으로 진행하고 적 턴은 실제 `ターンおわる`로 넘긴다.

보스는 턴 사이에 이동하거나 회복할 수 있으므로 실제 공격 직전에 해당 슬롯의 HP 1을 다시 확인한다. 실제 전투로 보스를 제거하고 마르스를 성에 이동했을 때 `しろ`가 나타나야 한다. `しろ` 결정 뒤의 원본 영어 `NEXT STORY`는 1,200 유휴 프레임 동안 유지돼 입력 대기 화면임을 확인했다. 일본판 원본 영어이므로 번역 대상이 아니다.

이후 `セーブしますか?`의 기본 `はい`를 선택하고 다음 맵으로 진행한다. 저장 지속성은 같은 관리 실행에서 native power cycle을 수행한 뒤 타이틀의 `ロードする`, `きろく1: MAP 2`, 2장 복귀를 순서대로 확인한다. 2장 화면의 아래 화살표는 점멸하므로 단일 프레임 해시가 다르면 같은 비점멸 위상을 표본화해 비교한다. 진행 가속으로 적 AI와 이동 경로가 달라진 실행끼리는 전체 SRAM이나 내부 RAM의 동일성을 요구하지 않고, 진행 상태와 같은 위상의 PPU 상태를 비교한다.

### 확인된 후반 장 도달 개입

정규 파일 1은 1-based 장 번호를 `$6519`에 두고, `$6000..$6542`의 16비트 가산 체크섬을 little-endian `$6542/$6543`에 둔다. 장 번호만 `02→0C`로 바꾸면 파일 선택 화면은 원본 영어 `MAP 12`를 표시하지만 로더는 검은 전환 뒤 파일을 거부한다. 체크섬도 `062E→0638`로 함께 바꾼 격리 실행에서 12장 도입에 도달했고, 현재 장 `$7674=0C`, 대사 문맥 `$781D=0B`, CHR `$59..$5C=0F 0F 00 18`을 확인했다.

같은 계약으로 장 번호 `0B`, 체크섬 `0637`을 쓴 파일은 11장 도입에 도달했고 `$7674=0B`, `$781D=0A`, CHR `1A 1A 00 18`이었다. 캡처한 완료 페이지에는 2장·12장 표본과 달리 초상화가 없었다. 파일 선택 상태에서 2프레임 `A`는 800프레임 동안 소비되지 않았지만, `$7674` 변경을 종료 조건으로 둔 `hold_until`은 63프레임 뒤 `02→0B`에서 입력을 해제했다. 선택 화면마다 짧은 탭이 충분하다고 일반화하지 않고, 기대 상태 변경과 묶인 조건부 입력을 우선한다. 완료 표식은 11장과 12장 모두 불규칙 간격 표본에서 표시·비표시 위상을 확인했다.

이 개입은 후반 장의 장 제목·맵·초상화·대사 합성 화면에 빨리 도달하기 위한 진행 가속이다. 10장이나 11장 완료, 종료 대사, 저장 제안·완료 또는 정상 유닛 생존 상태의 증거가 아니다. 장 번호와 체크섬 외의 저장 필드는 바꾸지 않으며, 개입한 파일과 세이브 스테이트는 기준선이나 자연 진행 증거로 재사용하지 않는다.

### 7장 최대 대사 수명 관문

7장은 문서화한 MOV 15·적 현재 HP 1 진행 가속을 쓰되, 좌표나 외부 화면 상태를 직접 쓰지 않고 실제 이동·턴 종료·전투로 성 좌표 `(27,10)`에 도달했다. 이 장의 이동 선택 중 세계 좌표는 `$0506/$0507=(열,행)`에서 읽었다. 맵이 스크롤되는 동안 `$008E/$008F`가 고정될 수 있으므로 이 값을 항상 세계 좌표로 간주하지 않는다.

성 이벤트는 실행 선택자 `$77F4:$77F1=C0:18`에 결속됐다. 본문은 자동 출력되고 `$77F7=0E`에서만 페이지 완료로 판정한다. 2프레임 `A` 탭이 소비되지 않은 반례가 있어, `$77F7`의 변화를 종료 조건으로 두는 `hold_until`로 4~5프레임 후 입력을 해제했다. 완료 페이지는 15개고, 각 페이지를 시작으로부터 0·7·19·43·82·171프레임에서 표본화해 점멸과 점진 표시를 놓치지 않았다. 15번째 완료 상태의 `A`는 `$77F7:0E→0F`를 거쳐 `$24/$84=0D/03`의 원본 영어 `NEXT STORY`로 이탈했다. 따라서 선택자 진입, 15개 페이지, 종단 효과가 하나의 입력·상태 계약으로 닫힌다.

현재 번역은 과거 관측본과 일부 글리프가 달라졌지만 레코드 포인터, 626개 1바이트 자리의 글리프/제어 구분과 57개 줄 경계는 같은 topology SHA-1 `5ee3b66823c66070447a180a63058a2e1277b75a`를 가진다. 과거 출력에는 제어 topology만, 현재 최대 대사 출력에는 현재 글리프 래스터까지 요구해 정적 재결박을 통과했다. 이것은 현재 화면 증거를 승계한다는 뜻이 아니다. 위의 15페이지·불규칙 위상·종단 효과를 현재 출력에서 다시 실행해 새 manifest를 만든 뒤에만 실행 관문을 닫는다.

### 11장 성 명령과 연속 전환 관문

지원 원본의 11장 지도는 행 8, 열 5·6에 성 타일 `4B` 두 개를 둔다. 인트로 직후에는 적 슬롯 0의 ID `83`이 행 8, 열 5를, 슬롯 6의 ID `BF`가 행 8, 열 6을 점유했다. 런타임 지도 버퍼의 두 칸이 유닛 점유 값 `1B`였던 것은 성이 없다는 뜻이 아니다. 적 레코드는 ID와 HP만으로 활성 여부를 판정하지 않는다. 레코드 오프셋 18의 행동 바이트가 `FF`면 사망·비활성이고, ID와 일부 값은 남을 수 있다.

마르스는 좌표 쓰기 없이 실제 이동 명령, `ターンおわる`, 전투를 거쳐 접근했다. 이동 중 `$008E/$008F`는 커서·선택 좌표이고, 명령 메뉴가 열린 뒤 확정된 행동 좌표는 `$0500/$0501`에서 읽는다. 적 턴 처리로 슬롯 6이 행 5, 열 6으로 이동해 행 8, 열 6의 성이 열렸고, 마르스가 그 칸에 도달했다.

진행 가속으로 마르스 MOV 15, 현재 HP 복원, 문서화된 적 현재 HP 1 묶음을 사용했다. 메모리의 일회성 쓰기는 에뮬레이터의 지속 치트와 다르며 게임 처리에서 적 HP가 다시 채워질 수 있다. 따라서 필요한 경우 묶음 전체를 다시 적용하고 전투 직전에 활성 상태와 HP를 재확인한다. 이 실행은 명중률을 바꾸지 않았고 빗나감도 실제로 발생했다. 좌표 `$0500/$0501`, 주 상태 `$84`, 승리 단계 `$053E`, 외부 화면 상태 `$24`를 직접 쓰지 않았다.

성 위 명령 메뉴는 위에서부터 `こうげき / しろ / もちもの / たいき`였고 `$84=0F`, `$24=0C`, 선택 원시값 `$7FF3=02`에서 `しろ`가 선택됐다. 안정 화면과 불규칙 간격 표본에서 네 라벨은 유지되고 커서만 점멸했다. `A`는 `$84:0F→10`을 일으킨 뒤 `$84=3C`, `$053E=02`의 승리 처리로 들어갔다.

11장 종료 대사는 네 완료 페이지였고 초상화는 표시·표시·비표시·표시 순서였다. 승리 단계 `02`는 페이지 사이에 바뀌지 않으므로 각 `A`는 `$053E`가 아니라 대사 완료 상태 `$77F7=0E`에 결속한다. 뒤의 화면 수명은 다음과 같다.

- 종료 대사: `$24/$84/$053E/$77F7=0C/3C/02/0E`, CHR `11 11 00 18`
- 원본 영어 `NEXT STORY`: `$24/$84=0D/03`, CHR `1B 1B 00 18`, 1,200프레임 무입력 유지
- 저장 제안: `$24/$84=0D/07`, CHR `1B 1B 00 18`; 기본 “예”의 `A`는 저장을 기록
- 저장 완료·계속 질문: `$24/$84/$77F7=0E/04/11`, CHR `1C 1C 00 18`
- 검은 자동 전환: `$24/$84=09/00`, CHR `1A 1A 18 18`, 입력 불필요
- 12장 제목·대사 합성: `$7674/$24/$84/$77F7=0C/0B/00/0E`, CHR `0F 0F 00 18`

이 표본은 선언한 가속을 사용한 도달 증거다. 기준 난이도, 무개입 전투 동등성, 저장 질문의 “아니오”, 패배·자원 부족을 증명하지 않는다. 패배·불리한 검증에서는 승리 가속을 끄거나 목적에 맞는 불리한 개입을 별도 실행으로 사용한다.

### 능력치 상승 아이템과 잘린 레코드 프리픽스

지원 원본 `0179c550d424e0397496078789e7b116601d120c`를 콜드로 띄워 1,450프레임 뒤 타이틀, 120프레임 `START`, 10프레임 `A`와 300프레임, 슬롯 1의 10프레임 `A`와 1,000프레임으로 1장 도입에 도달했다. 도입 화면 해시는 기존 기록과 같은 `b4b13ec2...`였고 여섯 번의 10프레임 `A` 뒤 지도 복귀도 기존 `3831facf...`와 같았다.

지도의 좌표 `08/18` 유닛은 아군 레코드 3 `$6AE1`(ID `05`)이다. 아군 27바이트 레코드는 오프셋 16·17이 좌표, 19~22가 아이템, 23~26이 내구도다. 화면이 실제로 읽는 값은 이 레코드가 아니라 선택 유닛 작업 복사본 `$7707..$770E`이며, 레코드만 바꾸고 메뉴를 다시 열어도 복사본은 갱신되지 않았다. 따라서 도달 개입은 두 곳에 함께 쓴다.

되돌릴 수 있는 도달 개입으로 아이템 `0x4C`와 내구도 `01`을 세 번째 칸에 넣었다. 소지품 목록에 `トオメガネ / 1`이 나타났고 행동 메뉴는 `つかう / わたす / すてる`를 표시했다. `つかう` 뒤 화면은 다음과 같았다.

```text
アベル は
トオメガネ をつかった
さくてきが 5 あがった
```

화면 SHA-256은 `99b66b1788a715f4d5562e9568f3c71cfe4a4f2776c2567349a6c2e2b0699ece`다. 능력치 이름 `さくてき`가 화면에 그대로 나오므로, 이 레코드의 앞 네 바이트는 창 기술자가 아니라 표시 텍스트다. 유닛 상세 화면에는 `ちから / わざ / ぶきレベル / すばやさ / うんのよさ / しゅびりょく / いどうりょく / まほうぼうぎょ / けいけんち`만 있고 `さくてき`는 없다. 즉 숨은 능력치이며 이 아이템 문구에서만 이름이 보인다.

이 실행은 의사결정 57번의 잘린 프리픽스 판정을 확정하는 증거다. `stat_boost` 계열의 첫 실행 관측이기도 하므로 아이템 흐름의 `source_bound_only` 표기는 이 계열에 한해 갱신한다. 도달 개입을 썼으므로 자연 획득이나 정상 난이도 진행의 증거로는 쓰지 않는다.

## 필수 실패 경로

최종 회귀는 승리 경로만 통과해서는 안 된다. 적어도 다음 경로를 기준선 또는 명시한 불리한 개입으로 확인한다.

- 마르스 패배 → 게임 오버 → 저장 지점에서 재개
- 일반 아군 패배 → 해당 전투 종료 → 다음 장에서 영구 이탈 유지 — 현재 exact ROM에서 통과
- 적 턴과 반격에서의 피해·사망·메시지 표시 — 반격 사망은 현재 exact ROM에서 통과, 적 턴 사망은 남음
- 자금 부족 상태의 구매 거부와 정상 메뉴 복귀
- 무기 내구도 소진과 아이템·장비 표시 갱신
- 중단 저장 → `つづきをする` 재개 → 중단 데이터 소멸
- 장 완료 저장 → 콜드 런치 → `ロードする` 재개

진행 가속 치트가 켜진 실행은 패배·자원 부족 경로의 통과 증거로 사용하지 않는다. 해당 경로는 치트를 끄고 다시 실행하거나, 목적에 맞는 불리한 개입을 별도 실행으로 적용한다.

## 전투 합성 로더 경로

세이브 스테이트는 같은 매퍼뿐 아니라 같은 ROM 생성 계보에 결속한다. 256 KiB PRG 시점의 상태를 512 KiB 확장 ROM에 불러와 화면이 진행되더라도 캐시·뱅크·코드 실행 증거로 사용하지 않는다. 전투 합성 로더는 같은 512 KiB 계보의 상태 또는 콜드 경로에서만 검증한다.

현재 같은 계보의 무전투 적 턴 두 번 완료 상태에서는 `SELECT`가 진행 메뉴를 열며 주 상태를 `00→01`로 바꾼다. 커서는 OAM 엔트리 0의 Y 좌표 `1F→2F→3F→4F→5F→6F`에 대응하므로, 아래 입력은 고정 프레임 탭이 아니라 이 값의 한 단계 변화에 결속한다. 이 경로에서는 2프레임 탭이 누락됐지만 4프레임 입력 뒤 4프레임 해제는 한 행씩 안정적으로 이동했다. 첫 유효 `DOWN`은 점멸 중이던 첫 행 커서를 다시 보이게 했고, 그 뒤 다섯 번 더 이동해 여섯째 `ターンおわる`를 확인했다. 여기서 `A`를 누르면 주 상태가 `01→20`으로 바뀌고 턴을 실제 종료한다. 이 입력은 단순 화면 이동이 아니므로 메뉴 구조와 효과를 확인하지 않은 다른 행에서 반복하지 않는다.

합성 진입과 반환 뒤에는 1·7·19·43·82·171·308·351·400·565·934프레임처럼 불규칙 간격으로 전투 창·글자·점멸·스프라이트를 확인한다. 손상 ROM과 직전 정상 ROM은 같은 전투 진입 상태를 진단 기준으로만 공유해 합성 전 매퍼 상태와 입력을 고정했다. 손상 ROM은 합성 CHR-RAM은 맞지만 페이지 0의 오른쪽 FE 선택에서 `$8000=4` 없이 `$8001=0`만 써 PPU가 다른 페이지를 읽었고, 수정 ROM은 `$8000=4 → $8001=0`을 복구해 +43프레임의 CHR-RAM과 PPU `$1000` 페이지가 같았다. 이 동일 상태 A/B는 원인 격리 증거이며 자연 진행 증거를 대신하지 않는다.

현재 수정 증거는 ROM `3399a2ab385e00ffa4a28ef70b653c16a69a9ed2`에 묶인다. 사운드 테스트의 공용 전투는 `$84=04`, `$05EE=0D`, `$7730=05`를 함께 활성 조건으로 쓰고, 반복 단계 `04`의 `07:$AC17`이 `$047D=1`을 쓴 뒤 `$7730=05`로 넘어가는 원본 경계에서 `$07DF`만 지운다. 수정 뒤 연속 두 `$FB30` 합성은 서로 다른 재배치 쌍을 만들었고 각각 +43프레임에 CHR-RAM과 PPU `$1000` 페이지가 일치했다. 이전 ROM의 여섯 반복·자동 엔딩 비개입 증거는 원인 격리의 비교 자료로 유지하되 수정 ROM 전체로 자동 승계하지 않는다.

수정 ROM은 콜드 부팅에서 제목·새 게임·슬롯 선택·도입 대사 여섯 화면을 정상 입력으로 지나 지도에 도달했다. 각 턴은 `SELECT`로 `$84=00→01`, 커서 `$7FF3=01→06`, `A`로 `$84=01→20`을 확인한 뒤 진행했고, 무전투 적 턴 두 번은 상태 `00` 지도에 복귀했다. 세 번째 적 턴의 첫 자연 합성은 프레임 13,970의 `$FB30`에서 시작했다. +43프레임에 CHR-RAM과 PPU `$1000` 4,096바이트가 같고, `가르다병`·`해적 :도끼`와 원본 `LV/HIT`·숫자·막대가 함께 읽혔다. `$07DF..$07EF=86 C2 03 E4 08 F5 0C ...`는 +82·+171프레임까지 유지됐고 상태 `33`, PC `$FE5D`의 단일 쓰기에서 첫 바이트가 0이 됐다. 뒤의 두 번째 자동 전투도 별도 입력 없이 합성됐고 같은 종료 지점에서 정리된 뒤 최종 상태 `00`, `$07DF=00`으로 지도에 복귀했다.

동적 조사 교정 뒤 전투 프로브 ROM `4fbd624801af9cf6f5fe6d67e8e18b2cb3294117`도 콜드 경로로 다시 검증했다. 방향 입력은 4프레임 누름과 4프레임 해제를 한 쌍으로 보내 매 턴 커서가 `$7FF3=01→02→03→04→05→06`으로 한 행씩 움직이는지 확인했고, 턴 종료 `A`는 `$84=01→20`에 결속했다. 첫 두 적 턴은 입력 없이 상태 `00`으로 돌아왔으며, 세 번째 턴의 프레임 11,739과 이어진 프레임 12,703에서 두 자연 합성이 시작됐다. 둘 다 +43프레임의 CHR-RAM과 PPU `$1000`가 4,096/4,096바이트 같았고, `$07DF..$07EF=86 C2 03 E3 08 E4 0C ...`는 전투 수명 동안 유지됐다. 10~20프레임 간격의 세밀 표본에서 `카인의 반격`과 `카인은(는) 11의 경험치를 얻었다`가 완성됐고, 원본 `LV/HIT/EXP`·숫자·막대와 양측 그래픽도 유지됐다. 두 번째 전투 뒤 프레임 14,505에는 상태 `00`, `$07DF=00`인 지도로 복귀했다.

이 검증 산출물은 `build-battle-composition-loader-probe`의 전투 단독 ROM이며, 누적 통합 전의 기준선으로 유지한다. 제목 뒤 시작·기록·도입 화면에 원본 일본어가 보이는 것은 이 프로브의 의도된 범위였다.

누적 통합 ROM `f5b72f9dd1b3bd99f9e09c77fc6035d867777710`은 프레임 0의 콜드 시작에서 같은 경로를 다시 실행했다. `처음부터`는 +7/+19프레임에도 화면 SHA-256 `4d4746102079398bda73d0dbbd99b7f4dcbb71a049dd3938a6afef5727800a61`로 같았고, 1장 제목·도입 여섯 페이지와 지도 복귀 뒤 부대 목록은 `이름`·실제 한글 이름·원본 `LV/HP`를 함께 표시해 +7/+19프레임에도 `2907ae020e7e548c91b346ea17ca648dcb3431c81701ef79e94a21fc4fe97562`로 같았다. `B`로 지도에 돌아온 뒤 각 턴의 `SELECT`, `$7FF3=01→06`, `$84=01→20`을 다시 확인했고, 첫 두 적 턴은 전투 없이 상태 `00`으로 복귀했다.

세 번째 턴의 두 자연 합성은 프레임 13,230과 14,195의 누적 주소 `$FC99`에서 시작했다. 각 +43프레임에 CHR-RAM과 PPU `$1000`가 4,096/4,096바이트 같았고 `$07DF..$07EF=86 C2 03 E3 08 E4 0C ...`가 준비됐다. 7·19·43·82·128·171프레임과 후반 13~24프레임 간격 표본에서 `가르다병의 공격`, `카인의 반격`, `카인은(는) 11의 경험치를 얻었다`, 원본 `LV/HIT/EXP`·숫자·막대·양측 그래픽을 함께 읽었다. 두 번째 전투 뒤 프레임 15,997에 상태 `00`, `$07DF=00`, 남은 중단점 0개로 지도에 복귀했다. 이 콜드 실행은 앞 화면과 전투 통합 회귀를 같은 ROM 계보에서 닫지만 아직 설치하지 않은 일본어 화면의 잔존 판정이나 전체 플레이를 대신하지 않는다.

정확 최대 수요는 자연 진행에서 우연히 기다리지 않고, 정상 턴 종료 입력으로 합성 창에 들어간 뒤 `$FB30` 직전에만 모델 증인 입력을 주입했다. 수정 ROM에서도 선택된 결과는 131개 고유 오버레이·152개 글리프 참조, 재배치 6쌍이며 독립 계산과 실제 CHR-RAM SHA-1이 모두 `e0facc315aa43d02f987009abfa6b91f93e6b18b`였다. +43프레임에는 PPU `$1000` 전체가 CHR-RAM과 같고 한국어 이름·병종·장비, 원본 `LV/HIT`·숫자·그래픽이 함께 읽혔다. 상태와 쌍은 +171프레임까지 유지됐고 +341프레임에 원래 종료 상태 `33`으로 나간 뒤 첫 바이트가 0이 됐다. 이 입력 주입은 최악 구조의 실행 가능성과 표시 용량을 증명하지만 자연 도달 증거는 아니다.

## 투기장 전투 생산자와 공용 수명 회귀

현재 exact ROM `DFE31A6807DCCFADE6EF7D20F2060E45A95308CF`에 게임이 만든 8장 SaveRAM만 넣고 reset한 뒤, `불러오기 → 기록1 MAP 8 → 도입 4페이지`로 지도에 들어갔다. 좌표 `19/0E`의 유닛을 골라 실제 이동 입력으로 투기장 `1A/10`에 도달하고, 명령의 둘째 항목과 내기 `예`를 실제 입력으로 확정했다. 다른 ROM의 CPU·mapper·CHR 상태는 쓰지 않았다.

수명 판정만 공용 전투 위상으로 바꾼 직전 후보는 주 상태 `$84=1F`, 위상 `$047C/$047D=00/01`에서 합성 호출까지 들어갔지만 재배치 10쌍이 8쌍 표를 넘어서 `$07FE=00`으로 안전 중단됐다. 이는 투기장 한 화면의 문구 결함이 아니라 지도·증원 적만 포함한 정적 입력 분모의 누락이었다. 현재 후보는 bank `0B:$A32D` 생성기의 기본·대체 병종/장비 39조합을 전역 코드북에 합친다.

내기 확정 뒤 `$07FE`의 준비 비트 write 중단점은 프레임 4,201에서 값 `82`를 잡았다. hit-time 스냅샷 `$0304..$0307=1A AC 06 01`, `$0320..$0323=02 0B 0E 0E`은 양측 정체성 `1A/AC`, 병종 `06/01`, 장비 `02/0B`, 지형 `0E/0E`이다. 직전 실패 조합과 다른 난수 결과가 1쌍 재배치로 통과했으므로 관측 적 하나의 하드코딩이 아니다. 승리·경험치 화면 SHA-256 `F4AC3A61C98CACB8D1B9A41BC4C94E271420B52E12FB7B727A6B5C1A43FD8654`는 읽을 수 있는 한글과 원본 전투 그래픽을 함께 유지했다.

결과를 닫은 뒤 시설 대사에서는 `$047C/$047D=FF/FF`, `$07FE=00`이었고, 다시 닫으면 주 상태 `$84=00`인 지도로 돌아왔다. 시설·지도 PNG SHA-256은 각각 `3849BB1A0BBCF83E1AB95A50F21A6DA918D203483B71A6DF908B819FBDE1EA68`, `2BF8AB468AF61F7A52FBDA64D8CFFF48864FB7D7CE0A4D3957D9786AD6A3114F`다. 실행 ID는 `01M0KA3PMZ31E9EH3E7DTK2HF4`다. 이 실행은 투기장 생성기 상위집합의 대표 런타임 소비와 수명 정리를 닫지만 39개 난수 조합을 화면으로 각각 재생했다는 뜻은 아니다.

## 유효 중단 데이터에서 유닛 요약·상태 확인

정확 통합 ROM `5fda755073d41b56b1c9b695374151703a22a5f4`는 프레임 0 첫 명령 전에 검증된 8 KiB SaveRAM만 넣고 현재 ROM을 reset했다. 다른 ROM의 세이브스테이트는 사용하지 않았다. 타이틀에서 10프레임 `START`, 유효 저장 메뉴의 첫 `이어하기`에서 10프레임 `A` 뒤 800프레임 자동 진행으로 7장 지도 입력 대기 `$84=00`, `$29=06`에 도달했다.

초기 커서 `$8E/$8F=17/08`에서 오른쪽 둘·아래 넷은 각각 좌표를 `17/09→17/0A→18/0A→19/0A→1A/0A→1B/0A`로 바꿨다. 이 대기 상태에서는 2프레임 누름과 8프레임 후속 진행이 모두 무시됐고, 10프레임 누름과 16프레임 후속 진행은 한 칸씩 작동했다. 좌표 `1B/0A`에서 `A`는 마르스 요약을 열고, 확인된 요약에서 다음 `A`는 상태 화면을 연다. 방향 입력의 축과 각 좌표 변화를 확인하지 않은 다른 지도에서 이 횟수를 재사용하지 않는다.

요약에는 `레이피어/21`, `상처약/5`, 원본 X형 장비 불가 표식과 `은검/17`이 표시됐다. X는 아이템명의 일부가 아니며, 현재 무기 레벨 5가 은검 요구치 9에 못 미쳐 나타난다. 상태에는 `무기레벨:5`, `마법방어:0`이 보였고 아홉 콜론은 모두 열 25, 숫자는 열 26~27이었다. 두 화면은 각각 0·7·19·43프레임에서 같은 이미지 SHA-256 `8ee712676211fd693a918cc66bc0cdffa4912c7b098137e5de09f9b240102c25`, `192e02a26905e28d84a62e07dd818dd97d23b85623fbbcdeb61b0e35dc03eb37`을 유지했다.

## 유효 중단 데이터에서 지도·소지품 메뉴 확인

지도 입력 대기 `$84=00`, `$29=06`에서 `SELECT` 10프레임과 후속 24프레임은 `$84=01`, `$7FF3/$7FF4=01/01`의 지도 메뉴를 열었다. 화면의 첫 행이 `부대명단`임을 확인한 뒤에만 `A`를 보냈고 `$84=04`의 명단으로 전환됐다. `B`는 지도 대기 상태로 돌아왔다. 두 화면은 각각 0·7·19·43프레임을 표본화하며, 명단의 머리말·일곱 한글 이름·원본 `LV/HP`가 유지되는지 본다.

명령 메뉴는 행동값이 `00`인 유닛만 사용한다. 이 중단 데이터에서는 좌표 `04/09`의 시더 레코드가 해당했고, 같은 칸 이동 확정 뒤 `$84=0F`, `$05E8=05`에서 `소지품/대기`를 확인했다. 첫 행 `A`는 `$84=1B`, `$05E8=07`의 `철검/42` 목록으로, 그 첫 아이템 `A`는 `$84=1C`, `$05E8=09`의 `장비/전달/버리기` 행동 메뉴로 갔다. 이 시점까지 선택 유닛 레코드는 바뀌지 않는다.

행동 메뉴 안의 `A`는 장비·전달·폐기를 실제 실행할 수 있으므로 검증 목적의 무작위 입력으로 사용하지 않는다. 현재 안전 이탈은 `B`로 행동 메뉴→소지품→명령→요약→지도를 역순으로 확인했으며, 전후 27바이트 레코드는 `020301101000320306070c0907080500040900020000002a000000`으로 같았다. 세 메뉴도 0·7·19·43프레임을 표본화했고, digest 차이는 커서·유닛 애니메이션 위상에만 있었다.

현재 통합 ROM `0AE64C3677B71CDD55EB5EBA0CA7D0D62B155A43`에서는 같은 시더의 철검을 인접한 유닛에게 전달하는 취소와 성공도 한 실행에서 나눠 확인했다. `전달`을 고르면 주 상태가 `1B→1C→1D`로 진행한다. 대상 선택에서 `B`를 누르면 `1D→1B`로 돌아오고, 원본·대상 유닛의 27바이트 레코드는 모두 그대로였다. 다시 같은 대상을 고른 성공 경로는 상태 `1E`에서 대상 레코드에 철검을 먼저 더하고, 입력 없이 결과 대사가 완성될 때 `$77F7=0E`에 정착했다. 결과 화면은 한글 유닛 이름·철검·전달 문장을 표시했고 화면 SHA-256은 `CF3491A1387342FFD8C126E6E752C9103099153530498EE1E3F322934074CFC4`이다. `A`로 닫은 뒤에는 `$84=00`, `$77F7=00`으로 지도에 복귀했으며 원본 레코드에서 철검이 없어지고 대상 레코드에는 추가 항목이 남았다.

이 직접 전달 경로는 `$05DB/$05DC` 호출자 인계 상태기를 사용하지 않는다. 원본 `06:$B10D`의 별도 9항목 상태기는 수송대 개수 `$7681`과 물품 배열 `$7682/$76AA`를 조작하므로, 직접 유닛 간 전달의 성공을 그 상태기의 실행 증거로 일반화하지 않는다. 현재 확인은 전달 취소의 무변이, 성공의 양쪽 레코드 변경, 한글 결과 화면과 지도 복귀까지만 닫는다. 다른 아이템 수용량, 대상 부재, 수송대 입출고, 폐기 확인과 특수 아이템 분기는 각자의 상태 경계가 필요하다.

## 8장 맵 시설 호출자 묶음 기준선

맵 시설의 호출자 인계 상태기는 정확 통합 ROM `0AE64C3677B71CDD55EB5EBA0CA7D0D62B155A43` 한 개에서 묶어 확인한다. 시작할 때는 첫 명령 전 동결 상태에서 SHA-256 `5919814DA4247E71AB1E52AF3555701EA3B343C92470D95192E0F6898403EB09`인 8 KiB 정규 SaveRAM을 파일 입력으로 넣고 reset한다. 거대한 인라인 16진수 쓰기나 다른 ROM의 세이브스테이트는 사용하지 않는다. `불러오기 → 기록1 MAP 8` 뒤 네 도입 대사는 각 화면의 `$77F7=0E`를 확인한 다음에만 `A`를 한 번 보내며, 지도 입력 대기 `$84=00`을 확인한 뒤 시설 조작을 시작한다.

첫 기준 실행에서는 초기 커서에서 실제 방향 입력만 사용해 행 19·열 14의 유닛으로 이동했다. 지도 좌표·유닛 좌표·행동 완료 값은 직접 쓰지 않았다. 유닛 레코드의 행·열·행동 값 `19/0E/00`과 지도 입력 대기를 확인한 뒤, 같은 ROM에서 각 시설 분기를 독립적으로 다시 시작할 CPU 명령 경계의 기준 상태를 저장했다. 이 상태는 화면 도달 비용을 줄이기 위한 같은 빌드의 진단 체크포인트이며, 콜드 부팅·SaveRAM 호환 진입 자체는 그 앞의 실제 경로가 맡는다.

첫 시설 이동 시도는 시설 경로로 분류하지 않는다. 시도 뒤에도 유닛 레코드는 `19/0E/00`이었고, 명령 메뉴는 `$84=0F`, 합성 상태 `$05E8=05`, `$05DB/$05DC=00/00`에서 `소지품/대기`만 표시했다. 즉 목적 칸 이동과 시설 종류 생산이 일어나지 않았다. 원천 시설 레코드의 좌표나 종류만 보고 도구점·보관소라고 이름 붙이지 않으며, 이 실패를 해당 처리기의 미도달 증거로도 일반화하지 않는다.

각 시설 분기는 같은 기준 상태를 복원한 뒤 다음 순서로 판정한다.

1. 방향 입력마다 실제 유닛 좌표가 목적 칸으로 바뀌고 이동 처리가 끝났는지 확인한다.
2. 열린 명령 메뉴에서 시설 라벨과 종류 선택값을 함께 확인한다.
3. 시설 공통 처리기와 무기점·도구점·투기장·보관소의 개별 처리기 진입을 구분해 관측한다.
4. `$05DB/$05DC`의 값은 주소만 보지 않고 해당 처리기와 대사 인계 이벤트에 묶는다.
5. 진입, 입력 대기, `B` 취소 또는 완료 입력, 지도 복귀를 같은 분기에서 확인한다.
6. 다음 시설은 현재 분기의 변경 상태에서 이어 가지 않고 기준 상태를 다시 복원한다.

이 묶음은 같은 장에서 가까운 시설을 한 번의 통합 실행으로 비교해 반복 부팅 비용을 줄이기 위한 것이다. 한 시설의 성공을 다른 시설이나 수송대 물품 이동의 증거로 승계하지 않는다.

### 실제 분기 결과

같은 기준 상태에서 실제 이동 입력으로 네 시설을 독립 관측했다. 첫 방향 입력은 주 상태 `0B→0C` 전이만 만들고, 같은 방향의 두 번째 입력부터 실제 좌표가 바뀌는 화면 특성을 매 분기에서 확인했다. 시설 종류와 화면 라벨은 `01=무기점`, `02=도구점`, `03=투기장`, `04=보관소`였다. 종류 `05` 비밀 상점과 수송대 물품 이동은 이 장의 묶음에 포함하지 않는다.

- 무기점은 행 19·열 16에서 공용 상점 디스패처 `06:$99AC`에 들어가 품목 목록을 표시했다. 명령 화면 SHA-256은 `82AA01FAA3C67171D41AFA0FE7BD99164C0E5073308AC7D2D2BB1D36DCCEC489`, 품목 목록은 `7424E1FE00288762DEF068C5D7A0C5803BA8614952029FFD5028741888265CE6`이다. 이 분기에서는 전체 대사 인계와 종료까지 반복하지 않았으므로, 아래 도구점의 공용 처리기 관측을 무기점의 모든 결과 분기로 승계하지 않는다.
- 도구점은 행 19·열 15에서 같은 `06:$99AC`에 들어갔다. 대사 처리기 `0A:$8560`이 `$7809=01`을 쓴 뒤 공통 관측자 `06:$A141`의 읽기가 완료된 PC `$A144`에서 값을 확인했다. 품목 목록의 `B`는 `06:$A122` 이탈 처리기로 들어가 종료 대사를 열었고, `0A:$862B`의 `$7803=01` 완료 뒤 `$05DB=0`, `$84=0F`의 호출자 명령 화면으로 돌아왔다. 이는 이탈이 항상 지도 유휴로 가는 것이 아니라 `$26`에 저장된 복귀 상태를 `$84`로 되돌린다는 실행 증거다. 명령·인사·종료·복귀 화면 SHA-256은 각각 `A14AA0B88335B093001BC1A288234C2A65F8846161541A1D80EB99471F377F26`, `C721F17C9D66C07BBD4BF896FF2D26D757BEC62DF9B560F60668A2A7F47FCA3C`, `39D8CC796BE4A3FB618B21E04D14EAECCBA872523E87FE95F1625407BBAE4E61`, `E5C639809B4C9E178AB31EFA675BB2DDB95F56D012B535ECE7D8B010B4683C6C`이다.
- 투기장은 행 26·열 16의 종류 `03`이다. 명령의 두 번째 항목은 `투기장`이며, 대사 인계의 `$7809=01`을 같은 `$A144` 경계에서 확인한 뒤 전용 디스패처 `06:$9C63`에 들어갔다. 명령 화면 SHA-256은 `837E7EB63AF31E026FC8B21EE5D600EF4BD2EAB71039862901964E1046598604`, 노인 초상과 두 선택지가 보이는 화면은 `961DA74F39A70B1EB4A93FAC7517F491DEDB213D0456E00B05BAB010CDFF6BF4`다. 이 화면을 보관소로 분류했던 첫 판독은 폐기한다.
- 보관소는 행 24·열 16의 종류 `04`다. 전용 디스패처 `06:$9DBE`, 대사 인계 `$7809=01`, `보관/찾기` 입력 대기를 차례로 확인했다. `B` 취소는 `$05DB=10`과 종료 대사로 진행했고, `$7681..$76D1` 81바이트는 진입 전후 모두 0이었다. `$7803=01` 완료 뒤에는 도구점과 같이 `$05DB=0`, `$84=0F`의 호출자 명령 화면으로 돌아왔다. 따라서 이 표본은 취소의 무변이와 복귀를 증명하지만 실제 보관·찾기의 배열 변경은 증명하지 않는다.

보관소 경로는 기능적으로 진행됐지만 표시 판정은 실패다. 명령 화면의 `소지품/보관소/대기`는 읽혔으나, 인사·`보관/찾기` 선택·종료 대사에는 다른 한글 글리프로 치환된 문자가 보였다. 각각의 화면 SHA-256은 `846C01CC7A04B389F113387FF966E0D3E91E91A5644828540B90765B52385DD2`, `B67BE214C1A09DEC3269912E5B26ED9686EFE6072727F34039FD1E27AD1167A4`, `3609759A891570C77B79D1E1EDC71AB03AA17E8C51B6D3C66B895AFC86942DC4`다. 같은 ROM에서 상점·투기장 대사는 읽히고 보관소 대사만 깨졌으므로, 다음 진단은 문장별 치환이 아니라 시설 대사 진입 시점의 글꼴 페이지·코드북 게시와 보존 수명을 비교한다. 이 결함을 고치기 전에는 시설 화면군을 런타임 합격으로 세지 않는다.

정적 교차 확인은 표시 결함의 첫 잘못된 경계를 더 좁혔다. 보관소 상태 `1D/23/26`의 고정 메뉴는 라벨 `35/36/46/47`을 `unit_command_menu` 코드로 읽고, 첫 appender 세 곳은 공용 wrapper를 통해 route `CC`를 `$07FD`에 게시한다. 활성 페이지 선택기는 0이 아닌 `$07FD`를 주 대사 페이지보다 우선하므로, 고정 라벨은 정상이고 함께 남은 대사만 다른 글리프로 재해석되는 관측과 일치한다. 도구점과 보관소가 같은 종료 대사 레코드 `06`을 사용하면서 전자만 읽힌 것도 저장 문자열 손상과 구별되는 근거다. 이 결론은 원인을 결속한 것이며 아직 수정 통과 증거는 아니다.

줄 슬롯 수명 설치 뒤의 정확 통합 ROM `AF942D786D82FF8A5D0BFFD6AA3900B83176F7A1`도 같은 SHA-256 `5919814DA4247E71AB1E52AF3555701EA3B343C92470D95192E0F6898403EB09`인 SaveRAM과 실제 지도 입력으로 다시 확인했다. 레코드 `41` 첫째·둘째 완료 페이지는 읽을 수 있었다. 둘째 페이지에서 `$07F0..$07FD`는 `21 01 01 00 03 B1 29 33 00 01 49 B1 29 00`이었고 mapper165 CHR 레지스터 2는 `00`이었다. 이 표본은 레코드·페이지 정체성, 현재 페이지 상주 색인 0, 준비 완료 상태 3과 CHR-RAM 선택이 함께 유지된 실제 통과점이다.

같은 실행에서 `A`를 눌러 `보관/찾기` 선택 화면으로 넘어가면 `$07F0..$07FD`는 `21 01 02 00 00 B1 29 33 00 01 49 B1 29 00`으로 바뀌고 CHR 레지스터 2는 `D0`이 됐다. 가시 페이지 색인만 2로 진행한 채 요청 상태가 0으로 내려가 대사 CHR-RAM 대신 지도 메뉴 원본 페이지가 선택된 것이다. 줄 버퍼와 네임테이블 코드는 지워지지 않아 화면이 깨졌고, `B` 취소 뒤 레코드 `06`에서도 같은 문제가 이어졌다. `$7681..$76D1`은 취소 전후 모두 0이었다.

따라서 줄 슬롯 코드 배정은 실제 완성 페이지에서 통과했고, 최신 실패는 그 뒤 상주권 전환에 있다. 상태 `1D/23`은 완료 대사 위에 고정 라벨을 얹는 화면이므로 완료 페이지를 명시적으로 다시 활성화해야 한다. 상태 `26`은 독립 정적 화면이라 기존 정적 페이지를 유지한다. 이 실행은 새 상주 정책의 회귀 입력이며, 아직 수정 통과 증거가 아니다.

보류 상태를 넣은 진단 ROM `2F22144D851ED8033469FBE5AAA05275D40C1AA4`에서는 마지막 페이지 입력 뒤 `$07F4` 쓰기 `00→00→04`를 같은 경로에서 관측했다. 상태 `04`가 쓰인 순간 `$05E8=20`, 최종 선택 화면에서는 `$05E8=1D`였으므로, 원본 합성 상태 게시가 resolver보다 늦다는 순서를 회귀 조건에 추가한다. `04`가 보였다는 사실만으로 성공으로 세지 않고, `1D/23` 게시 뒤 mapper165 CHR 레지스터 2와 대사 route가 함께 0으로 돌아와야 한다.

정적 설치 ROM `1603EF4A8C14E9880010C6435D71F5D1EC8A980D`은 실행 회귀 입력에서 제외한다. 고정 게시자가 현재 PRG 뱅크를 바꾸지 않은 채 `$A000`의 재투영 helper로 직접 점프하는 구조여서, 게임플레이 뱅크에서는 helper 바이트를 실행하지 않는다. 이 후보를 불러온 진단 상태에서 보인 리셋형 이탈은 참고만 하며, 구조 결함이 제거된 새 산출물의 증거로 승계하지 않는다.

수정 뒤에는 같은 exact 통합 ROM과 같은 8장 기준 상태에서 다음을 한 묶음으로 확인한다.

1. 보관소 인사와 `보관/찾기`가 동시에 읽히고, 취소 뒤 종료 대사까지 같은 호환 코드 배정을 유지한다.
2. 보관 취소는 `$7681..$76D1`을 바꾸지 않고 `$7803=01` 뒤 호출자 상태 `0F`로 돌아간다.
3. source-bound 보관소 분기들이 사용하는 다른 고정 라벨 상태 `23/26`도 선택된 대사 작업집합과 코드 충돌이 없음을 정적으로 검사한다.
4. 고정 메뉴 공용 경로를 공유하는 유닛 선택·속도 선택과, 인접한 무기점·도구점·투기장·유닛·소지품 화면이 같은 산출물에서 회귀하지 않는다.
5. 고정 뱅크 게시 경로가 switchable runtime helper를 호출한다면 호출 전 코드 페이지 선택과 호출 뒤 원래 PRG 뱅크 복원이 같은 실행에서 유지된다.

통합 ROM `F131572B32675DD29703B271D829B1F44CFB5D24`의 첫 묶음 실행에서는 도구점 다섯 품목과 무기점 일곱 품목이 각 목록 시작점부터 연속으로 합성됐고, 도구점에서 `B` 취소 뒤 종료 문구와 호출자 명령 메뉴까지 돌아왔다. 수정 전 후보는 같은 호출점에서 출력 X가 `0→37→74→111→148`로 변해 목록이 비었는데, 수정 뒤 합성 버퍼는 각 품목 문자열·종료자·가격 구분을 순서대로 유지했다. 이 결과는 공통 목록 appender와 두 상점 분기의 회귀만 닫으며, 아래 나머지 시설·유닛 화면을 대신하지 않는다.

같은 실행 세션에서 같은 ROM의 8장 기준 저장상태를 분기마다 다시 불러 보관소 인사 두 페이지→`보관/찾기`→취소 결과, 투기장 `예/아니오`→취소 결과, 유닛 상세→아이템 목록→`전달` 대상 선택→취소 복귀, `버리기` 결과 문구를 확인했다. 모든 화면은 같은 통합 코드와 글꼴 재료를 소비했지만 저장상태 재시작은 진단 개입이므로 자연 진행 연속성으로 세지 않는다. `버리기`는 별도 확인창 없이 즉시 결과 대사로 가는 원본 상태기였고, 기준 SaveRAM 파일 자체는 쓰지 않았다. 다음 묶음은 보관 용량 초과·결과, 다른 장 시설, 장 전환·패배·결말 수명이다.

## 유닛 선택 도움말과 후속 대사의 겹침 회귀

정확 통합 ROM `70158F8086886A996249A1DA188CA8E31B6E9291`을 독립 emucap 세션에서 시작하고, SHA-256 `9F1DCBC35C350D6027F98BE0F5C8B43B42CA52B7604459C0C42BE3AA88913D47`인 8 KiB 영 파일을 SaveRAM에 넣은 뒤 reset했다. 타이틀의 `처음부터`, 빈 기록 1, 여섯 도입 완료 페이지를 각각 실제 입력으로 지나 `$77F7=00/$84=00`인 1장 지도에 도달했다. 다른 ROM의 세이브스테이트는 쓰지 않았다.

자연 유닛 선택 경로 전체를 주장하지 않고 원본에 결속한 분기만 재현하기 위해 지도에서 `$24=06`, `$84=02`, `$05DB=00`을 진단 개입했다. 게임 코드는 프레임 12,893에 스스로 `$05E8=25`를 썼고, 그때 `$05DB=01`로 진행했다. 이어 원본 `06:$8608` 인계가 디렉터리·항목 `B1:52`를 열었다. 완료 상태 `$77F7=0E`인 프레임 13,393에서 위 창의 도움말 여섯 줄과 아래 대사가 동시에 읽을 수 있는 한글로 남았고, 화면 SHA-256은 `81F9555A3CAA16C37A80DAE4F0FC213349EA25E08676A54F1D38A8E23453327C`다.

이 표본은 기존처럼 상태 `25`를 독립 unit-command 페이지로만 취급하면 다음 대사 페이지가 남은 도움말 타일을 다른 글리프로 재해석한다는 회귀를 닫는다. source-bound 진단 개입을 썼으므로 자연 유닛 선택 진입·닫기·지도 복귀나 최종 실행 역할은 증명하지 않는다. 관측 뒤에는 이 실행 세대만 종료했고 다른 emucap 세션은 건드리지 않았다.

같은 ROM의 다음 콜드 실행에서는 도입 대사를 실제 입력으로 모두 지나간 1장 지도 하나에서 세 합성 전이를 묶었다. 상태 `17`은 `$24=06/$84=06`으로 선행 상태 `16`부터, 상태 `11`은 `$24=06/$84=10/$05E4=00`으로 선행 상태 `10`부터 시작했다. 두 경로 모두 런타임 합성기의 `$05E8=17/11` 쓰기를 잡았고 보더와 제어 타일이 깨지지 않았다. 상태 `17`은 자체 글리프를 만들지 않으므로 내용 없는 진단 창은 상위 문장 보존의 합격 표본으로 승격하지 않는다.

이어 `$24=06/$84=02/$05DB=00`에서 상태 `25`의 `$05E8=25`를 잡고, 완료된 `B1:52` 화면에서 도움말과 아래 대사가 함께 읽히는 것을 확인했다. 완료 화면 SHA-256은 `94251B1B2A6AAB13557D3E3A6022B14E01FCA97FC8426FF7B808E345EF4FF67E`다. 이 상태에서 A를 눌렀을 때 원본 `06:$A132`의 `$05DB=00` 쓰기와 복귀 상태 복원이 발생했고, 300프레임 뒤 유닛 선택 화면 SHA-256은 `EE2D006C395A17E0DDEF122E74595A2A0B330B2366289C0AE29825B29CF90C13`였다. 이는 진단 진입 뒤 닫기·복귀와 누적 CHR 상태를 증명하지만 자연 유닛 선택 진입 조건은 증명하지 않는다.

## 7장 완료에서 8장 지도까지의 자연 전환 묶음

정확 통합 ROM `F9D97FB349DB4D38EEE8617944B0A26BD420D865`을 첫 명령 전 동결 상태에서 시작하고, 게임의 중단 직렬화로 만든 7장 SaveRAM 8 KiB만 파일 입력으로 넣은 뒤 reset했다. 타이틀에서 `이어하기`를 골라 7장 지도에 들어간 다음 진행 메뉴의 `턴종료`, 적 턴 자동 복귀, 마르스의 `성` 명령을 실제 입력으로 실행했다. 다른 ROM의 세이브스테이트나 흐름 상태 주입은 쓰지 않았다.

7장 완료 대사는 가시 색인 `00..0E`의 15페이지였다. 각 페이지는 `$77F7=0E` 입력 대기를 확인한 다음 A를 눌러 실제로 `0E`를 벗어났고, 다음 입력은 다시 완료 상태에 들어온 뒤에만 보냈다. 이 규칙은 한 번의 짧은 입력이 무시됐는데도 같은 `0E`를 새 페이지로 오인하는 타이밍 오류를 막는다. 첫째 페이지 SHA-256은 `0725B8CBAF6837C412E444E037F360727B2B1803B5E57C6222181C901839FA17`, 마지막은 `F945EF0D90E42065B28A1A63D20C4E6EBBD7DBA2E700B8F3604118F784E9373D`다.

마지막 페이지 뒤에는 같은 실행에서 `NEXT STORY` `851064A8FC1853A3C4667DCAE63A48A87A09EF91DDCF937E724C9FD1A4ADABE1`, `저장할까요?` `7ED1CEBB1ACAE67EBEF8A4DA3982CD7FDB930092F2D4EF8D34E95334189BEE89`, 저장 완료·계속 질문 `C97173ED337E336F3D85577640E6FA31309BFCF1D41099F6416240F511C47AD2`를 차례로 확인했다. 계속을 고른 뒤 8장 첫 도입 페이지 `95283DF616B0076C50B156CA02A928BB425ABB1CA90C6535E38B60B5423D1A1A`와 뒤의 세 페이지를 각각 완료 상태에서 진행해 지도에 도달했다. 지도 진행 메뉴의 첫 항목 `부대명단`을 선택한 화면은 `AF9F4D6DCD89E7CBFCDC05E8C17E915E0B4777144183FB7CF3EE2B12D18AE8CB`이고, B로 닫은 지도 SHA-256은 `685874DEDDCCE855616D867192815973BDA1B875826597FFC5DAE29979BAD282`다.

이 SaveRAM의 명단 화면에는 8명이 있었고 장 전환은 상태 `25` 도움말을 거치지 않았다. 이후 exact ROM에서 writer를 직접 관측해 당시 임계값 설명을 교정했다. 원본 bank `06:$8A92..$8AD5`는 선택 후보 수를 `$776C`에 게시한다. `$B8B3..$B8DE`, `$8905..$8919`가 `$05EA`에 쓰는 값은 앞선 유닛 상태 수이고, bank `08:$BA7A..$BA93`가 장 번호로 `$8790` 포인터 표를 찾아 장 레코드 첫 바이트인 배치 한도로 다시 덮어쓴다. 정규 8장 SaveRAM은 후보 수 `07`, 8장 배치 한도 `0D`를 만들었으므로 도움말을 거치지 않는 것이 정상이다. 지원 원본의 `$05EA` 직접 writer 15곳은 bank `02/06/07/08/0C`에 있으며, 한 주소의 첫 writer만 결속했던 이전 설명은 폐기했다.

같은 정확 통합 ROM `6E7604E23F506B87C8C800B4DDF86A4B6E441489`에서 `$05EA=0D`를 실제로 쓴 bank `08:$BA8F` 직후를 동결했다. 원본 비교·전이·소비자를 그대로 시험하기 위해 유효한 아군 레코드 일곱 개와 후보 ID·병종 배열을 진단용으로 더하고 `$776C=0E`로 만들었다. bank `06:$8627..$867B`는 `14 > 13`을 판정해 프레임 33,223에 `$05E8=25`를 스스로 썼다. 120프레임 뒤 `$05DB=02`, `$77F4:$77F1=B1:52`, `$77F7=0E`에서 도움말과 아래 한국어 대사가 함께 읽혔고 화면 SHA-256은 `B85C1C2B94DA9B4459CC6D8AA6F6E4561E50B6B5B760BE906BB8D5F8A41357B0`다. A를 10프레임 누르고 90프레임 진행하자 `$05DB=00`, 전역 상태 `02`의 한글 유닛 선택 화면으로 복귀했으며 화면 SHA-256은 `B72EB2D2383164F7CE24F25D2BF8FD6EF55E2DF0AAF8B56969B1F9F341D1BF26`이다. emucap 실행 ID는 `01M0JN9579PEQE9AAPYGM28WJN`이다. 이 표본은 실제 최종 생산자 뒤의 원본 분기와 `25 → B1:52 → 닫기 → 복귀`를 닫지만, 아군 14명의 자연 영입·저장 재구성 이력은 증명하지 않는다.

## 현재 exact ROM의 자동 엔딩·후일담 묶음

같은 exact ROM `6E7604E23F506B87C8C800B4DDF86A4B6E441489`에서 위 7장 지도 명령 경계 상태를 불러왔다. 실제 `SELECT → DOWN×5 → 턴종료`, 적 턴 자동 완료, 마르스 선택과 `성` 명령을 실행하고 완료 대사 15페이지를 각각 `$77F7=0E` 이탈·재진입 뒤에만 넘겼다. 마지막 페이지 뒤 `NEXT STORY`, 저장 “예”, 계속 “아니오”를 골랐고, 종료 안내에서 `위·아래·왼쪽·오른쪽·위·A`가 `$775B=00→05`, `$05EE=0A→0C`를 만드는 것을 확인했다. 사운드 테스트의 `SELECT` 뒤에는 입력하지 않았다.

자동 엔딩은 원본 영어 도입·캐스트, 한국어 장 기록, 원본 영어 스태프, 자연 명단 후일담, 서명 종단 순서로 진행했다. 장 기록 초반·중반·후반 PNG SHA-256은 `D9C8C24BE3E363A9E29AE6A1BC5EB5CD74A684CA481CF090FA98658F30130777`, `8B97455DD3BCCBF54BBECDA5C366E771934CAEA544985C7AA75BABEDA6969246`, `E81D03379721EB8BA73B964E66B527D28A825D0DED8288228C233BC23AD8CB31`이다. 1~25장 제목, 원본 번호·턴 수와 합계가 같은 스크롤에서 읽혔다. 스태프 화면은 `E0FD0E637631CB3102DEB86FD859A87395F64BC98D8F697CFEE8ADAB3EC13BCB`, 자연 후일담 대표 화면은 `18FB518042AB0FF3DBC6ECD69310F3C4DAA5502F08593FE61F046E56183DB6EC`다. 단계 `$7731=1D/$7732=00`의 서명 화면은 SHA-256 `119FF85511FB1D4EEDE5B58336BB74AE813C2B95C5C9D2E16A7DAC4D7F8963E2`였고 1,000프레임 뒤에도 같았다.

자연 실행의 첫 `04:$A165` 선택자 명령을 지나 PC `$A168`, 후보 커서 `$773B=34`에서 만든 같은-ROM 기준 상태를 변형 실행마다 복원했다. 허용 쓰기는 SaveRAM `$0A90`부터 1,458바이트뿐이고 `$7731/$773B/$77F1/$77F4`는 보존했다. 과거 전수 표본의 CHR 수명별 대표 ID를 모은 직접형 `35,32,2E,29,21,14,08,06,04,03,02,01`은 선택자 `40`으로, 라우팅형 `35,32,2E,29,21,14,08,06,04,03,02`는 선택자 `41`로 각각 한 자동 실행에서 통과했다. 후보 게시 관측은 값뿐 아니라 실제 writer PC `04:$A19D`까지 필터링해 본문 내부 레코드 전이를 새 후보로 세지 않았다. 두 실행은 모두 한국어 이름·본문 또는 지명·결과, 초상화와 창을 유지하고 단계 `1D`로 끝났으며 종단 화면은 자연 기준과 바이트 해시가 같았다.

명단 레코드의 행동 필드는 10진수 12가 아니라 16진수 오프셋 `0x12`다. 첫 임시 라우팅 파일이 잘못된 오프셋을 바꿔 선택자 `40`을 만든 시도는 즉시 폐기했고 증거로 세지 않았다. 교정 파일은 `0x12=FF`, 장소 `0x0E=05`를 썼고 첫 후보에서 `41:35`와 `오렐르앙북부에서 / 쓰러졌다`를 확인했다. 별도 `41:01` 파일은 입력 없이 601프레임 뒤에도 단계 `10`, 배경·스프라이트 비활성, 검은 화면 SHA-256 `788D6984576BB13490A00DF106EC8EC4A1C2F966E544DEBD99F7FFCE8D65C029`를 유지했다. 이는 지연 표시가 아니라 기존 원천 계약의 무표시 no-op과 일치한다.

이 묶음에는 일본어 잔존, 한글 코드 오독, 보더 손상이나 자동 진행 정지가 없었다. 자연 기준은 실제 장 종료부터 종단까지의 통합 경로를 증명한다. 명단 전용 개입은 렌더링·분기 합집합만 증명하며 각 인물의 자연 운명이나 완주 조건은 증명하지 않는다. emucap 실행 ID는 `01M0JS7TYJ2D60ECP8MCSQS9P0`이다.

## 8장 유닛·소지품·시설 복합 회귀

같은 exact ROM `70158F8086886A996249A1DA188CA8E31B6E9291`을 새 emucap 세션에서 시작하고, SHA-256 `5919814DA4247E71AB1E52AF3555701EA3B343C92470D95192E0F6898403EB09`인 8 KiB 정규 SaveRAM을 파일 입력으로 넣은 뒤 reset했다. 타이틀 애니메이션이 끝난 실제 메뉴에서 `불러오기 → 기록1 MAP 8`을 골랐고, 네 도입 페이지는 `$77F7=0E`일 때만 A를 눌러 지도 대기 `$77F7=00/$84=00`에 도달했다. 다른 ROM의 세이브스테이트는 사용하지 않았다.

초기 커서에서 실제 방향 입력으로 좌표 `19/0E`의 유닛을 고른 뒤 요약과 상태 화면을 차례로 열었다. 상태 화면은 `$84=25/$05E8=11`에서 이름 `시저`, 병종 `용병`, 레벨·HP와 아홉 능력치가 읽혔고 PNG SHA-256은 `D29FE6A47F20145D88D78FB8869233E1B7084241D82858782A33A68F57597EB2`다. 상태에서 B로 이동 선택에 돌아간 뒤 같은 칸을 확정해 `소지품/대기`, `강철검/38`, `장비/전달/버리기`를 열었다. 화면 SHA-256은 차례로 `988A344A2C8DF687F9A86FC0FB6FEA5E240767B050CA6F515428EEE85B3D9A3E`, `53A1F94AF07769838D4E2996AEEB01BF52ED4AFA6ADBAF8E084DC18BBA9C58E0`, `4EAE9F250DE7ECF66823721A4074AA758796D3227BF77181EDA5B87A66E792AF`다. B 네 번은 `1C→1B→0F→0B→00`으로 역순 복귀했고, 최종 지도는 기준과 같은 SHA-256 `D9658FB50E46CF7D7D090A80EF4387ADCA12822528CAFA9F8FEAFD6F4902F4B9`였다.

이 자연 도달점에서 같은 ROM의 CPU 명령 경계 상태를 한 번 저장하고, 시설별로 그 상태만 복원해 실제 이동과 입력을 반복했다. 원본 8장 시설 기록은 `19/10·19/11·1A/11` 무기점, `19/0F·1A/0F` 도구점, `1A/10` 투기장, `18/10·09/1B` 보관소다. 각 분기에서 실제 커서 좌표가 목적 칸에 도달한 뒤 같은 칸을 확정했고, 명령 메뉴의 시설 라벨을 확인한 다음에만 진입했다.

- 무기점은 일곱 품목과 가격, `2000G`, 점주 대사가 함께 읽혔다. 목록 SHA-256은 `561AD155863DBEC3FDFD4C7594CDCC3CC98D5CE25CFCC8AAF903A1152E698F48`이다. B 취소 결과는 `A1500D5FA32A23E4140A58713B6656DF7476BD5066419EFDA1544C23CAFF5620`이고 A 뒤 상태 `0F` 명령 메뉴로 돌아왔다.
- 도구점은 다섯 품목과 가격, `2000G`, 라라벨 인사 대사가 함께 읽혔다. 목록 SHA-256은 `34E202889979750190F2F9521FB33A08258965858D283884247B47BCA8E2B1D5`이다. B 취소 결과 `4C2DA08781B3BC94D367503E578A0C11E53D8F33AE59885CD3C899E015B111C9` 뒤 `$05DB=0/$84=0F`로 돌아왔다.
- 투기장은 `예/아니오`와 노인 대사가 함께 읽혔다. 선택 화면 SHA-256은 `19FFB68D5A6FC0F826719BEA9BE986C28475AAE2C8695C8CF89D5103372DD06F`, B 취소 결과는 `21A84175F3773B5EACD3ABA65F0D6E6CD54A8CD0DC3E2A8ED86634ADCB3AA564`이고 A 뒤 상태 `0F`로 돌아왔다.
- 보관소는 인사 두 페이지, `보관/찾기`와 직전 대사, B 취소 결과를 모두 읽을 수 있었다. 선택 화면 SHA-256은 `E79E67DC523337B6412A472B614CF8113B68A7342E54DE330023FBCE1AC9420D`, 취소 결과는 `551504CE1565BE5F1F4C7BC61C3C892AB3900A805FB7F24E6C1ED0C621E9B735`다. 취소 전후 `$7681..$76D1` 81바이트는 모두 0으로 동일했고, A 뒤 `$05DB=0/$84=0F`로 복귀했다.

첫 화면·취소 묶음에서는 일본어 잔존, 한글 코드 재해석, 보더 파손이나 진행 정지를 찾지 못했다. 같은-ROM 체크포인트 분기는 빠른 통합 회귀이지 한 자연 진행의 연속 증거가 아니며, 이 단계만으로는 영속 상태를 바꾸는 성공 경로를 증명하지 않는다. 성공 경로는 아래의 별도 분기가 맡는다. 실행 역할을 보고서에 결속하지 않았으므로 완료 수치도 올리지 않는다.

같은 체크포인트로 영속 변경 분기를 다시 나눴다. 선택 유닛은 SaveRAM 오프셋 `$0B4D`의 27바이트 레코드이고, 바로 위의 대상은 `$0B68`이다. 전달 대상 화면의 B 취소는 양쪽 레코드를 바이트 단위로 보존하고 상태 `1B`의 `강철검/38` 목록으로 돌아왔다. 다시 전달을 확정하면 결과 대사 동안 대상의 둘째 빈 슬롯에 품목 `03`, 내구도 `26`이 먼저 들어가고 원본 슬롯은 남아 있었다. 결과 대사 SHA-256은 `12050241C4FEF09A6F85B0BBB7D76C64BA81FC2B470B98DC5E968976F4503CB9`다. A로 닫은 뒤에는 원본 슬롯이 비고 대상 슬롯만 남은 채 `$84=00/$77F7=00` 지도로 복귀했다. 별도 기준 분기의 `버리기`도 결과 대사 `74C3E9D4A3FE69E9F24E1C48AFB64F90EE5B2D567C700C473FEC5E8D8E1E38C6` 동안 원본 슬롯을 보존한 뒤 닫기에서 품목과 내구도를 함께 지웠다.

보관소 성공 분기는 `보관/찾기`에서 `보관`을 고르고 상태 `07`의 `강철검/38` 목록이 안정될 때까지 입력하지 않았다. 목록 SHA-256은 `06FC4C663B69461BD823F12F8787BD4250FBF560D76B080CCB097A7F48EA7A63`다. A 뒤 보관 배열 `$7681..$76D1`은 개수 `01`, 품목 `03`, 내구도 `26`을 담았고 자금 표시는 `2000G→1990G`로 바뀌었다. `다른용건도있어`의 긍정 경로로 돌아가 `찾기`를 고르면 같은 품목과 내구도가 보이는 목록 `4C650FFA19DBB4E88B6471D0E3BE8C8DF1284B85FACD499EDC7CD6924738775C`가 나타났다. 이를 찾아서 이탈한 왕복 분기는 배열 81바이트를 다시 0으로 만들고 원본 품목 슬롯을 유지했다. 별도 기준 분기에서 보관 직후 B로 이탈하면 원본 슬롯은 비고 배열의 `01/03/26`은 유지됐다. 따라서 보관·찾기 양방향과 결과 확정 시점은 현재 exact ROM에서 서로 모순 없이 닫힌다.

이 성공 분기들은 같은 ROM의 진단 체크포인트에서 시작했으므로 자연 획득·장 진행 증거가 아니다.

같은 체크포인트에서 유닛과 커서를 보관소 좌표에 두고 `$7681..$76D1`만 파일 입력으로 바꿔 40개 경계를 별도 실행했다. 81바이트는 `개수 28 + 품목 03×40 + 내구도 26×40`이고 SHA-256은 `3FA5C7492CC1BCFB5B5666409274066BACCE63891D93D8617B4341AE47F35535`다. 보관 선택은 코드의 `CMP #$28` 경계대로 레코드 `2E`를 열었고, 글자가 완성된 프레임 `FD92501AE750AE234E8D54D3FA60E5348858F3835181353BF1B869C3643CD90D`에서 가득 참 문구 세 줄이 모두 읽혔다. 이후 다른 용건 질문을 B로 취소하고 종료 대사 A를 누르면 `$84=0F/$05DB=00`으로 돌아오며 81바이트는 입력과 같았다. 출력 중간 프레임에는 아직 지워지지 않은 타일과 부분 문장이 함께 보이므로 글리프 결함 판정은 레코드와 진행 상태를 같이 보고 완성 프레임에서 한다.

두 번째 파일은 `개수 27 + 품목 03×39 + 빈칸 + 내구도 26×39 + 빈칸`, SHA-256 `E1B700DB4CDD84F0713A3D0339D509A9A021FD2A1ABBBC830717AE0C80FBA996`다. `앞으로 1개 맡길 수 있어`와 품목 목록이 안정된 화면 `AFBA5B3CA90CF8FC5E415C465894B7068CCCA398B747BFF98F3A02FCA8460818`에서 강철검을 보관하면 마지막 칸에 `03/26`이 들어가고 개수는 `28`, 자금은 `1990G`가 된다. 결과 질문에서 이탈한 뒤 유닛의 품목·내구도 8바이트는 0이고 보관소 마지막 칸은 유지됐다. 이로써 시설 보관의 39→40 성공, 40개 초과, 초과 뒤 취소·복귀를 닫는다. 별도 `06:$B10D` 소지품 초과 상태기의 `보관/하나버리기`는 당시 다음 묶음으로 남겼다.

## 소지품 초과의 보관·버리기·취소 회귀

정확 통합 ROM `F9D97FB349DB4D38EEE8617944B0A26BD420D865`을 새 emucap 세션의 첫 명령 전 상태에서 시작했다. SHA-256 `5919814DA4247E71AB1E52AF3555701EA3B343C92470D95192E0F6898403EB09`인 8 KiB 정규 SaveRAM을 파일 입력으로 넣고 reset한 뒤, 실제 `불러오기 → 기록1 MAP 8`과 네 완료 대사를 각각 `$77F7=0E`에서 진행해 `$77F7=00/$84=00`인 지도에 도달했다. 여기서 저장한 같은-ROM CPU 명령 경계 상태만 분기 기준으로 썼다.

원본 `06:$B10D`의 소지품 초과 상태기를 고립해 보기 위해 선택 유닛 레코드의 품목 네 칸, 새 품목 `$77B0`, 호출자 상태와 주 상태를 source-bound 값으로 진단 개입했다. 300프레임 뒤 `보관/하나버리기`와 안내 대사가 함께 읽혔고 화면 SHA-256은 `A489E3203EA578ADFB5B2F59A3B742BD09FC11B8AEA09B0073099060BF0C5D03`이다. 보관을 고른 결과는 자금 `2000G→1990G`와 보관 완료 대사를 표시했고 SHA-256은 `55BEA1FAD23B56F705C0616BC7A522BCBFC2C78281926348969804B91AF687AE`다.

독립 분기에서 `하나버리기`를 고르면 합성 상태 `$05E8=24`, 호출자 정착 상태 `$05DB=07`의 다섯 품목 목록이 한글로 표시됐다. 화면 SHA-256은 `9F4994A699DF96A1665617125DA4A0571C545187E5C2FB0995497CABD4095817`이다. B 취소 뒤에는 대사 레코드 `44`가 화면에 남은 채 고정 라벨이 다시 그려졌지만 깨짐이 없었고, 복귀 화면은 최초 선택 화면과 PNG 바이트 해시까지 같았다. 다시 목록에서 기존 품목을 선택하면 원본 결과 레코드 `$77F1=45`가 선택되고 실제 유닛 레코드 슬롯이 변경된 뒤 지도 `$84=00`으로 돌아왔다.

이 묶음은 동일한 최종 ROM에서 보관 성공, 버리기 목록, 목록 취소, 기존 품목 버리기까지 한 기준 상태로 비교한 진단 회귀다. 품목과 상태 바이트를 개입했으므로 자연 전투 보상·획득 경로, 모든 유닛 레코드, 최종 실행 manifest를 대신하지 않는다. 같은 실행에서 시작 메뉴 커서 이동 전후 PNG를 직접 비교한 결과 변화는 커서 영역 50픽셀뿐이었으므로, 한때 기록한 라벨·보더 소실은 이 묶음의 별도 결함이 아니라 이미지 표시 오판으로 폐기했다.

## 자연 전투 보상에서 소지품 초과까지의 통합 회귀

현재 정확 통합 ROM `6E7604E23F506B87C8C800B4DDF86A4B6E441489`의 7장 실제 공격 대상 선택 상태를 기준으로 썼다. 시다와 대상의 현재 HP를 안전한 전투 조건으로 두고 적의 원본 드롭 필드 `+14`만 품목 `03`으로 바꾼 뒤 실제 대상 확정과 전투를 진행했다. breakpoint는 bank `06:$AD83`이 `$0328=03`을 생산한 사건, 주 상태 `$84=17`의 `$9363`이 `$77B0=03`을 게시한 사건, 상태 `18`의 `$B10A` 진입을 순서대로 잡았다. 드롭 0 기준 분기는 상태 `19`로 건너뛰고 품목을 바꾸지 않았으며, 빈칸 분기는 품목 `03`, 내구도 `26`을 둘째 슬롯에 넣고 지도 `$84=00`으로 돌아왔다. 빈칸 지도 PNG SHA-256은 `043542B92B4AACEDC20F31C80D4CDB20D218C44201706A31C15EE7905C53B24C`다.

공격 대상 선택 체크포인트에서는 지도 유닛 레코드에서 전투 참가자 `$76F4/$7715` 복사본이 이미 만들어져 있었다. 첫 가득 참 시도는 지도 레코드만 네 칸으로 바꿨기 때문에 소비기가 전투 참가자 복사본의 빈칸을 찾아 정상 삽입했고 초과 화면은 열리지 않았다. 이 실행은 실패한 제품 분기가 아니라 잘못 잡은 조건화 경계로 기록했다. 교정 실행은 두 표현의 품목·내구도를 함께 `02/04/05/06 + 2A/16/1C/10`으로 두었다. 전투가 첫 무기의 내구도를 `29`로 줄인 뒤 `$B10A` snapshot에서 네 슬롯이 모두 찬 것을 확인했고, 한글 `보관/하나버리기` 화면 SHA-256은 `06FD2246CE9950E9F8142D6BCBFDF4819AA8FA48EAC5AB5F6D1A2089F957804E`다.

이 명령 경계 상태를 저장해 독립 분기를 연속 비교했다.

- `보관`은 자금 `2000G→1990G`, 보관 배열 개수 `01`, 품목 `03`, 내구도 `26`을 만들었다. 완료 대사 SHA-256은 `7F358EA6074FC845595E065D1C44B59E13E0E371E4AA4CAD3D440575E39C77EF`이고, 원래 네 품목과 사용 뒤 내구도를 유지한 채 지도 `00`으로 돌아왔다.
- `하나버리기`는 새 보상과 기존 네 품목을 합친 다섯 줄을 한글로 표시했다. 목록 SHA-256은 `B143278FD1C5591DBDA326873DA01F5F42D5B056D4F6B7701423CE1832B448F7`다. B 취소 뒤 선택 화면 PNG는 기준과 바이트 해시가 같았고 참가자 레코드와 빈 보관 배열도 같았다.
- 첫 줄의 새 보상을 버리면 레코드 `46`과 `강철검 버렸다`가 표시되고 원래 네 품목이 남았다. 완료 화면 SHA-256은 `46B8B1001352DAB77B714E8DB9B0509F2D8D998EED8B8A7606A0590F5F274E99`다.
- 둘째 줄의 기존 철검을 버리면 레코드 `45`와 `철검 버렸다`가 표시됐다. 품목 `02`가 빠지고 새 보상 `03/26`이 들어간 뒤 지도에 복귀했다. 완료 화면 SHA-256은 `DB4E08F2AC0D497E70108CEAB1848462B12F5CDDA6638E10EB3F0A97819FAF19`다.
- SHA-256 `3FA5C7492CC1BCFB5B5666409274066BACCE63891D93D8617B4341AE47F35535`인 81바이트 파일로 보관소를 40개 채운 분기는 레코드 `42`의 한글 가득 참 안내를 표시했다. 화면 SHA-256은 `508D4627BFB8B4B63B4A651F785B08D8EA52A7FE64C0FDE9291BFCBD27496DFE`다. 이어 강제 다섯 품목 목록에서 새 보상을 버리고 지도에 돌아왔으며 보관 배열은 입력 파일과 바이트 단위로 같았다.

이 묶음은 보상의 자연 드롭 생산·주 상태 인계·소비기 진입과 그 뒤 모든 핵심 행동 분기를 같은 ROM에서 닫는다. 가득 참 조건은 이미 만들어진 두 런타임 표현을 함께 조건화했으므로 네 품목을 자연 수집한 이력까지 증명하지 않는다. 실행 ID는 `01M0JWA7XNRDYJB8T1KQTG68TB`다.

## 현재 exact ROM의 게임 속도 선택 경계·취소 회귀

현재 exact ROM `DFE31A6807DCCFADE6EF7D20F2060E45A95308CF`과 같은 ROM에서 만든 8장 지도 기준 상태를 불러왔다. 실제 입력 `SELECT → 표시전환 → 대기시간`으로 합성 상태 `$05E8=1A`의 다섯 단계 선택창을 열었다. `빠름`과 `느림`, 숫자, 커서, 창과 지도 그래픽이 함께 읽혔으며 초기 화면 PNG SHA-256은 `F976E63C9DDFD80334DC91079FBC2838E5B61F215E1D0D8A6DDBF0B1D3FAEC01`이다.

초기 설정 `$767C=02`의 같은 CPU 명령 경계 상태를 분기했다. 가장 빠름을 고르면 `$767C=00`, 가장 느림을 고르면 `04`가 됐고 두 분기 모두 지도 상태 `$84=00`으로 돌아왔다. 두 경계 선택 화면 PNG SHA-256은 `64578A1B8E26E0EC88D1C7E4081C0291B2D46DCDDF5774445CBC41891C626996`, `CEEBD645C1A0B1A471092486148B1A8667C9603E182D148CDB972DC3743CC0CA`다. 별도 분기의 `B`는 설정 `02`를 보존한 채 지도에 복귀했고 화면 SHA-256은 `E4F739A307824831D3510B6DCF033D276DF251ED98DD6CF35864470C73E8D526`이다.

이 실행으로 마지막 미관측 화면 역할을 닫았지만, 중간 속도 1·2·3을 같은 처리기의 별도 화면 역할로 늘리지 않는다. 이 실행에서는 정확한 좌우 CHR 쌍을 별도 캡처하지 않았으므로 공급 페이지 결속은 남긴다. 등록된 53개 역할은 모두 실행 관측됐다. 당시 남아 있던 다른 장 도입 변형은 바로 아래의 최신 묶음에서 닫았고, 현재 잔여는 CHR 쌍이 없는 아홉 역할과 다른 장의 시설·종료 같은 역할 내부 변형이다. 실행 ID는 `01M0KBSDR2Q15RJJ9411DM8VPH`다.

## 현재 exact ROM의 25개 장 제목·첫 본문 전수 묶음

정확 통합 ROM `97034214F12D5F6165C808097294566BE3616D00`에 유효한 8 KiB SaveRAM SHA-256 `F87C76C09F7D5724A07A158A19633C916617C3C16E12DCE6E21D954B9A6FA5DC`를 파일로 넣고 reset한 뒤, 실제 부팅·제목·시작 메뉴를 지나 현재 ROM의 기록 선택 직전 CPU 명령 경계 상태를 만들었다. 다른 ROM의 CPU·mapper·CHR 상태는 사용하지 않았다.

장별 분기는 같은 현재-ROM 기록 선택 상태를 복원한 뒤 SaveRAM의 파일 1 장 번호 `$0519`와 체크섬 `$0542/$0543`만 원본 직렬화 계약에 따라 바꿨다. 1-based 장 번호 `n`의 체크섬은 `0x062C+n`이었고, 각 분기에서 기록 1을 `A`로 실제 불러왔다. 이 개입은 장별 렌더 경로를 묶어 도달하기 위한 source-bound 진단 입력이며 앞 장을 자연 완료했다는 증거가 아니다.

25개 첫 완료 페이지는 모두 현재 장 `$7674=n`, 대사 문맥 `$781D=n-1`, 완료 상태 `$77F7=0E`를 만족했다. 좌우 CHR `$59..$5C`는 `07/07+00/18`, `0B/0B+00/18`, `0F/0F+00/18`, `11/11+00/18`, `13/13+00/18`, `1A/1A+00/18`, `1D/1D+00/18`, `1F/1F+00/18`의 여덟 변형이었다. 각 완료 write 다음 프레임의 화면을 모은 접촉판 SHA-256은 `DF80F3AE212F420BD79C71C149D28199D0A695905A3EE801E372BB0A7494E893`다. 전수 화면에서 한국어 장 제목·첫 본문, 초상화가 있는 구성과 없는 구성, 맵·창·보더가 함께 유지됐고 일본어 잔존·가블·진행 정지는 없었다. emucap 실행 ID는 `01M0KGTCCAW34HTWW787Q7MGGN`이다.

이 묶음은 25개 장의 제목+첫 완료 본문 결합을 닫는다. 각 도입 사슬의 모든 후속 페이지나 자연 장 완료는 대신하지 않는다. 후속 페이지는 1장 다중 레코드 이탈과 7장 15페이지 최악 사슬의 별도 증거를 유지하며, 전체 자연 진행은 G7에 남긴다.

## 실행 증거 규칙

각 실행 기록에는 ROM SHA-1, 시작 상태, 입력 경로, 활성 치트의 주소·값, 켠 구간, 기대 결과와 실제 결과를 남긴다. 치트가 활성화된 세이브 스테이트는 오염된 상태로 표시하며 기준선 실행의 시작점으로 재사용하지 않는다. 치트를 끈 뒤에는 깨끗한 저장 데이터나 콜드 런치로 기준선을 다시 만든다.

가속 실행은 화면 도달과 렌더 경로 증거가 될 수 있지만 게임 진행 동등성의 단독 증거는 아니다. G5의 전역 최악 수명 관문과 G7의 전체 회귀는 기준선 성공 경로와 실패 경로를 각각 가져야 한다.
