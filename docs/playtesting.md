# 플레이와 런타임 검증

기준일: 2026-08-11

이 문서는 지원 일본판을 플레이하는 데 필요한 최소 조작과, 한글 패치의 실행 검증에서 치트를 다루는 원칙을 기록한다. 치트는 화면 도달 시간을 줄이는 시험 개입이지 정상 동작의 증거를 대신하지 않는다.

## 기본 조작과 진행

- 방향키: 커서 이동과 항목 선택
- `A`: 결정, 유닛 선택, 메시지 넘기기
- `B`: 취소
- `START`: 타이틀에서 메뉴 진입
- `SELECT`: 진행 메뉴 열기

새 게임은 타이틀에서 `START`를 누르고 `さいしょから`와 저장 슬롯을 고른다. `ロードする`는 장 클리어 때 저장한 파일을 불러오고, `つづきをする`는 중단 데이터를 재개한다. 중단 데이터는 재개하면 사라진다.

아군 유닛을 선택해 이동과 행동을 끝낸 뒤 진행 메뉴의 `ターンおわる`로 적 턴을 시작한다. 보스를 쓰러뜨리고 마르스를 성이나 왕좌에 이동시켜 `しろ` 또는 `ぎょくざ`를 선택하면 장을 완료한다. 마르스가 쓰러지면 게임 오버이고, 다른 아군이 쓰러지면 원칙적으로 이후 장에서 돌아오지 않는다. 정규 저장은 장 완료 때만 가능하며 파일은 2개다.

1장에서는 서쪽 마을에서 리프를 영입하고 동쪽 마을에서 `10000G`를 얻을 수 있다. 요새 회복과 지형 효과, 비행 유닛의 활 약점을 익히는 첫 실전 구간이다.

## 확인한 화면 상태 전이

버튼은 현재 화면의 입력 대기 상태가 확인된 뒤에만 보낸다. 자동 장면인지 모를 때는 먼저 입력 없이 짧게 프레임을 진행해 화면 변화 여부를 본다. 화면 의미를 모르는 상태에서 `A`나 `START`를 탐색 입력으로 반복하지 않는다.

```text
자동 시연 ── START ──> 타이틀 연출 ── 대기 ──> 타이틀 입력 대기
자동 병종 소개 ── 무입력 ──> 다음 병종 소개 ── 반복 ──> 검은 전환 ──> 원본 영어 도입
타이틀 입력 대기 ── START ──> 처음부터/재개 메뉴
처음부터 ── A ──> 저장 슬롯 ── A ──> 1장 인트로
1장 인트로 완료 대사 ── A ──> 다음 완료 대사 또는 맵
맵 유닛 위 ── A ──> 유닛 요약·이동 선택 ── 같은 자리 A ──> 유닛 상세
유닛 상세 ── B ──> 이동 선택 ── B ──> 맵 유휴
이동 선택 ── 이동할 칸 A ──> 자동 이동 ── 완료 ──> 유닛 명령 메뉴 ── B ──> 유닛 요약
유닛 명령 메뉴 ── もちもの A ──> 소지품 목록 ── 아이템 A ──> 조건부 행동 메뉴
조건부 행동 메뉴 ── B ──> 소지품 목록 ── B ──> 유닛 명령 메뉴
조건부 행동 메뉴 ── そうび A ──> 장비 결과 대사
조건부 행동 메뉴 ── わたす A ──> 점멸 대상 선택 ── B ──> 소지품 목록
점멸 대상 선택 ── 대상 A ──> 양도 결과 대사
조건부 행동 메뉴 ── すてる A ──> 폐기 결과 대사
맵 ── SELECT ──> 진행 메뉴
진행 메뉴 ── DOWN 5회 ──> ターンおわる ── A ──> 적 턴 자동 진행
적 턴 ── 자동 ──> 이동·전투 애니메이션 ── 자동 ──> 다음 입력 대기
```

현재 콜드 기준 경로는 첫 명령 전 정지에서 1,450프레임을 진행해 타이틀 입력 대기를 확인한 뒤 `START`를 120프레임 유지한다. 이 입력은 `さいしょから` 화면으로 들어가지만 관측한 종료 RAM 값 하나의 변화로 결속하지 않으므로 화면 확인을 생략하지 않는다. 기본 항목의 `A`는 10프레임 누르고 300프레임 뒤 저장 슬롯, 슬롯 1의 `A`는 10프레임 누르고 1,000프레임 뒤 1장 완료 대사에 도달했다. 2프레임 `A`는 이 경로에서 충분하지 않았다.

1장 완료 대사에서의 `A`는 소스·실행 양쪽에서 다음 `chapter_intro_title_dialogue_composite` 또는 맵으로 가는 비영구 진행 입력으로 결속돼 있다. 누적 ROM `0962476ed480bcd0e874fc0d40041218b8270727`의 콜드 실행에서는 10프레임 `A`와 300프레임 자동 진행을 화면마다 한 번씩 보내 여섯 도입 화면이 모두 한글로 완성된 뒤 맵으로 복귀했다. 화면 SHA-256은 차례로 `5fff10268d3dec93e6cf2c3574d6109c796621ac871d56fd47302b54d5244fd4`, `87faf8cf46391d7083f1559d91b2539b0b77448372177c853e1a5fc8f7722dcc`, `4c0eda5c5babc6f556c193c8618c56d2d5a16f5f8fea56e8e9e8810728e0c464`, `43e86b52d1d67b33a8ede32644490a0eb6f50dec9a7f65385b04f046b99dd36f`, `bae4f159eafd39abfa446058b3659fb4e412a4a6fd3d8c853125b8561683328e`, `9471672d2ca92e698e3f9fbe6b6d1cecd77258c73a11473ab1cec8761166d6c2`이고, 자연 맵 복귀는 `3831facf91038633042614423b774f8b76771f263f0b13c9bc0656a4cca4ede5`다. 각 입력 전에는 완료 표식 또는 완료 상태를 확인하며 자동 출력 중에는 보내지 않는다. 완료 표식은 7·19·43프레임 표본에서 표시와 비표시가 교차하므로 한 캡처의 부재를 미완료로 판정하지 않는다.

장 제목과 런타임 제어 출력 보호를 합친 당시 누적 ROM `cebcfa310206df05525d0d2e5a08a4c24ff97af0`에서도 같은 콜드 경로를 다시 실행했다. 1장 제목 `1 마르스의 여정`과 여섯 대사 페이지의 SHA-256은 `d0cf3b42...`, `fbc3948c...`, `bc0deddc...`, `d0645ae1...`, `26fd461f...`, `76159429...`이고 자연 지도 복귀는 위의 `3831facf...`와 같았다. `{EA}`는 원문에 출력 글리프 `9E AB`를 직접 갖지 않고 실행 중 생성하므로, 수명 계획은 제어 바이트뿐 아니라 이 두 출력 코드도 보존해야 한다. 이 보호 뒤 모든 페이지에서 원본 `※` 표식이 유지되고 가짜 한글 접두는 사라졌다.

같은 실행에서 검증된 정규 파일 1 SRAM 8 KiB를 선언해 주입하고 reset handler에서 멈춘 뒤, 장 번호 오프셋 `0x519=02`와 체크섬 오프셋 `0x542=1B 06`을 다시 읽었다. 타이틀에서 `START`, `DOWN`, `A` 뒤 원본 영어 `MAP 2`가 붙은 파일을 확인하고 `A`를 10프레임 누른 뒤 1,000프레임 자동 전환을 기다렸다. 최종 ROM의 2장 첫 페이지는 `2 가르다의 해적들`, 한글 대사와 원본 `※` 표식을 함께 표시했고 SHA-256은 `db5173380b2b01728589f5fd4fddf780b44b44c0a822d2b630f5aa3b756f7539`다. 이 가속 실행은 2장 제목·첫 페이지의 소비자 증거이며 나머지 2장 페이지나 자연 1장 완료를 대신하지 않는다.

시작·기록 메뉴를 누적한 ROM `9d9b4b39ac96c528ef544cc28cb1c3bbc9c1d120`은 같은 1,450프레임 냉간 기준과 120프레임 `START`만 사용했다. 무저장 `처음부터` 화면 SHA-256은 `4d4746102079398bda73d0dbbd99b7f4dcbb71a049dd3938a6afef5727800a61`, 정규 저장의 4항목 화면은 `82ceb2d827a756993b19a38a4e5d611a316f422a13e90f82cc356710b11cf77f`였고, 둘 다 +7/+19/+43프레임에서 같은 해시와 mapper 값 `A8`을 유지했다. 저장 메뉴에서 `DOWN` 한 번 뒤 커서가 `불러오기`에 있는지 확인하고 `A`를 보냈다. 기록 화면은 `기록1 MAP 2`를 표시해 SHA-256 `e0499863bc8f4c9bb5894d64b96640378c8d41134a88725f0e812cc844d9b253`였으며, 다시 `A`와 1,000프레임 자동 전환 뒤 2장 첫 화면 `6a52173b1ffc67abf6b192445056cba33b614ae19419e7a0d11b52d750f49d2f`에 도달했다. 중단 데이터가 없으므로 `이어하기` 변형은 이 실행으로 검증하지 않는다.

진행 메뉴는 6항목이며 첫 항목에서 열린다. `ターンおわる`는 여섯 번째이므로, 턴 종료는 `DOWN` 5회 뒤 커서가 마지막 항목에 도달한 화면을 확인하고 결정한다.

첫 항목 `いちらん`은 `A`로 부대 목록에 들어가고 `B`로 맵에 돌아온다. 다섯째 `スイッチ`는 설정 화면이 아니라 `アイテム / エリア / ユニット` 하위 메뉴를 연다. 여기서 `B`를 누르면 상위 메뉴가 아니라 맵으로 돌아가며, 확인한 직후 상태 `$24=0C`에서는 곧바로 보낸 `SELECT`가 등록되지 않았다. 이 동작을 설정 화면 경로로 부르지 않으며, 입력 수용 상태와 실제 설정 진입 소유자를 다시 확인하기 전에는 하위 항목을 탐색 입력으로 선택하지 않는다.

같은 누적 콜드 실행에서 맵의 `SELECT`는 원본 진행 메뉴 `c39871a67a4568ffd581e6c9bdb0171aecaf69b882643dc05305a871fb8606b3`을 열었다. 첫 항목 `A` 뒤 부대 목록은 한글 `이름`, 원본 `LV/HP`·숫자·일본어 유닛명·초상화를 함께 표시했고 화면 SHA-256 `f96db41a428bc0c78857615b0f283d139c03208010694232fb6fa7975838d976`이 7·19·43프레임 추가 표본에서 유지됐다. `B` 뒤에는 지도 화면으로 돌아갔다. 설정 화면은 누적 ROM에 정적으로 포함돼도 정상 진입 소유자가 미확정인 동안 탐색 입력으로 재검증하지 않는다.

아군명 단계 ROM `97bc9be510a0a69c54ea725324f23b809a618a0b`에서는 같은 `SELECT → 첫 항목 A`가 한글 `이름`과 `마르스/제이건/카인/아벨/도가/고든/시더`, 원본 `LV/HP`·숫자를 표시했다. 화면 SHA-256 `fa81697ccce00068bd2c8866f41ee2fba251e97b102aa9159adeafe966c4f11e`은 +7/+19/+43프레임에서 같았다. `B`로 맵에 복귀한 뒤 유닛 위 `A`는 한글 `마르스`와 원본 `S/HP`·숫자, 일본어 병종·아이템을 함께 표시했고 다음 `A`의 상세 화면은 전환 직후 요약창이 보이지 않다가 +7프레임에 다시 나타났다. 한 프레임만 보고 상단 요소 누락으로 판정하지 않는다. 이 실행은 과거 맵 상태를 도달 가속에 사용했으므로 콜드 회귀와는 구분한다.

병종 소개 단계 ROM `63d36eb2c182979873ea662eb27a9afcdbbbb88c`은 콜드 시작 뒤 입력을 한 번도 보내지 않았다. 프레임 1790·6352·7752·12452·12952에서 프로필 인덱스 `0/8/11/20/21`의 한글 제목·설명과 원본 `STR/SKI/WLV/AGI/DEF/MOV/H.P/EXP`·숫자를 확인했다. 페이지 경계 인덱스 11에서는 mapper 레지스터 2와 4가 모두 `BC`였고, 프레임 13352의 검은 자동 전환과 13852의 원본 영어 도입까지 자연 진행했다. 일곱 화면은 서로 다른 이미지이며 프레임 간격도 불규칙하다. 이 경로는 자동 장면이므로 검증 중 버튼 입력을 보내지 않는다.

현재 제어된 Mesen 실행에서는 2프레임 방향키·취소 탭이 메뉴와 상태 화면에서 입력 폴링에 잡히지 않았고, 10프레임 탭은 한 번의 동작으로 안정적으로 등록됐다. 별도 화면에서 확인하기 전까지 직접 입력은 `press_frames=10`을 기준으로 하며, 방향키를 길게 눌러 자동 반복에 맡기지 않는다. 각 입력 뒤 기대 화면이나 커서 위치가 확인되지 않으면 다음 입력을 보내지 않는다.

관리 실행은 첫 명령 전 동결 시작과 네이티브 CPU 정지를 지원한다. 세이브 상태 로드는 같은 ROM이라도 현재 정지가 안전한 CPU 경계일 때만 성공하며, 프레임 step이나 중단점으로 멈춘 상태에서는 `unsafe_halt`로 거부된다. 이때 뒤 입력을 계속 보내지 않는다. 실행을 재개한 뒤 네이티브 pause로 다시 멈추고, 로드의 `status=completed`와 기준 화면·CHR 그림자를 별도 호출에서 확인한 뒤 다음 입력을 보낸다. 과거 세이브 상태는 화면 도달 가속에만 쓰고, 판정할 실행 이벤트는 로드 이후 같은 관리 실행 세대에서 새로 수집한다.

1장 맵에서 커서 RAM `$008E/$008F=08/18`과 아군 27바이트 레코드의 좌표가 일치하는 유닛을 사용해 위 전이를 확인했다. 첫 `A` 뒤에는 이름·병종·레벨·HP·아이템 요약이 유지되고, 같은 자리의 두 번째 `A`가 상세 능력치를 연다. 상세에서 `B` 한 번은 맵 유휴가 아니라 이동 선택으로 돌아가므로, 맵 유휴까지는 `B`를 한 번 더 보내고 화면을 확인한다. 이동 선택에서 같은 자리를 확정하면 `もちもの / たいき` 명령 메뉴가 열린다. 다른 칸을 확정하면 즉시 메뉴로 가지 않고 자동 이동이 진행되므로 입력 없이 완료를 기다린다. 메뉴의 `B`는 행동을 끝내지 않고 유닛 요약으로 돌아가며, 이동한 두 표본에서는 커서와 유닛 레코드 좌표도 원래 `$08/$18`로 복구됐다.

명령 조립기는 공격·지팡이·변신·지형·대화·소지품·시설·대기를 이 순서로 판정해 `$05EB` 비트 0~7을 사용한다. 합성 중 임시 값인 `$05EB`을 안정 화면의 영구 명령 마스크로 해석하지 않는다. 메뉴가 열린 뒤에는 입력 대기이며 152프레임 동안 글자 페이지는 바뀌지 않았다. `もちもの`의 결과 6은 소지품 목록을 여는 비변경 전이까지 결속했지만, 나머지 명령의 `A`는 개별 handler를 결속하기 전에는 보내지 않는다. 대표 지형·시설 변형은 목적 칸으로 이동한 뒤 메뉴를 읽고 `B`로 빠지는 데까지만 관측하며, 이동 자체의 영향을 없애야 할 비교에서는 같은 관리 실행의 안전한 기준 상태를 다시 로드한다.

적 자동 처리 중에는 `$29=06`과 `$7FF3=06`이 남아 있어도 진행 메뉴가 아니었다. 자동 처리가 끝나 `$84=00`이 된 뒤 `SELECT`를 보내면 메뉴가 `$84=01`, 선택값 `01`로 새로 열렸다. 따라서 모든 턴에 `SELECT`와 `DOWN`을 기계적으로 반복하지 않고, 화면과 `$84/$7FF3`을 함께 읽어 현재 입력 대기 소유자를 판정한다.

불리 전투는 최초 `$C1F2` 실행에서 저장한 상태를 기준으로 1·7·19·43·82·127·191·263·383·565·711프레임을 불규칙 표본화했다. 예측, 적 공격, 아군 피격, 카인 반격, 성장, 경험치 결과까지 `battle_animation` 수명 안에서 확인했고 934프레임에는 지도로 복귀했으므로 그 표본은 전투 합집합에서 제외했다.

같은 무개입 기준선의 다음 아군 입력 대기에서 카인을 좌표 `08/17`로 이동시켜 가자크 `07/17`을 공격했다. 입력 효과는 `$84=00→09→0B→23→25→26→0C→0D→0F→10→11→12→13` 상태열과 최초 공용 writer `$C1F2` 1회로 결속했으며, 치트나 메모리 쓰기는 사용하지 않았다. 플레이어 선공 전투는 그 writer 진입 상태에서 1·7·19·43·82·127·191·263·383·565프레임을 표본화해 예측, 카인 공격, 속도 성장, 가자크 반격과 피해 결과를 확인했다. 711프레임에는 `$84=00`인 지도로 복귀했으므로 전투 합집합에서 제외했다.

1장 첫 인트로 메시지부터 맵까지는 화면별로 `A`를 15회 결정하면 도달한다. 이는 한 번의 연속 입력이나 자동 넘김 수가 아니라, 각 메시지 화면이 입력 대기임을 확인하고 10프레임 탭을 한 번씩 보낸 현재 기준선 경로다.

## 중단 저장과 재개

맵의 진행 메뉴는 첫 항목에서 시작하며 `ちゅうだん`은 네 번째다. 따라서 `SELECT`로 메뉴를 연 뒤 `DOWN` 3회로 네 번째 커서를 확인하고 `A`로 결정한다. 완료 화면은 추가 선택지가 아니라 다음 안내 메시지다.

```text
ゲームをおわらせるときは
リセットボタンをおしながら
でんげんをきってください
```

즉 게임은 중단 직후 바로 전원을 끄는 흐름이 아니라 리셋을 누른 채 전원을 끄도록 안내한다. 에뮬레이터 검증에서도 중단 메시지만 확인하고 프로세스를 강제 종료한 결과를 정상 저장 증거로 취급하지 않는다.

정상 중단 검증은 상태 주입 없이 위 조작을 수행한 뒤 에뮬레이터의 native power cycle을 사용한다. 이 동작은 같은 관리 실행 세대와 같은 ROM이 다시 연결될 때까지 기다리는 전원 재인가 경계다. 전원 재인가 성공 응답만으로 배터리 파일 기록을 주장하지 않고, 중단 직후 8 KiB SRAM과 생성된 `.sav`가 바이트 단위로 같은지 별도로 확인한다.

지원 원본과 mapper 165 프로브에서 이 경로를 각각 실행했다. 두 ROM의 중단 직전 SRAM, 중단 직후 SRAM, `つづきをする` 재개 뒤 SRAM이 단계별로 서로 같았고, 첫 전원 재인가 뒤에는 이어하기가 나타나 같은 맵으로 복귀했다. 재개 뒤 다시 전원을 재인가하면 이어하기가 사라져 중단 데이터의 일회성 소비도 같았다.

새 관리 프로세스 실행은 격리된 실행 묶음을 다시 만들기 때문에 이전 실행의 `Saves` 디렉터리를 이어받는 배터리 지속성 시험이 아니다. 프로세스 강제 종료나 새 관리 실행 결과를 위 native power cycle 검증과 혼동하지 않는다.

## 장 완료 뒤 숨은 사운드 테스트

1~24장을 완료한 뒤 첫 저장 질문에서 “예”로 저장하고, 이어지는 계속 질문에서 “아니오”를 고르면 데이터 손실을 막기 위해 전원을 끄라는 일본어 안내에 정착한다. 이 화면에서 다음 순서를 입력하면 사운드 테스트로 들어간다.

```text
UP, DOWN, LEFT, RIGHT, UP, A
```

지원 ROM의 뱅크 `0B:$9BA0`은 현재 입력을 `08 04 02 01 08 80`과 비교하고 일치한 단계 수를 `$775B`에 저장한다. 실행에서는 각 입력마다 `$775B=00→05`를 확인했고 마지막 `A` 뒤 `$05EE=0B→0C`를 거쳐 `SOUND TEST MODE` 화면을 열었다. 사운드 테스트의 영문 라벨과 숫자는 원래 영어이므로 번역하지 않는다.

현재 ROM의 `0B:$9C17`은 위·아래를 번호 `$775C` 변경, `A`를 `$06F0..$06F7`의 선택 이벤트 비트 기록, `B`를 `$06F0=01` 기록으로 분기한다. 실행에서는 위 `00→01`, 아래 `00→50`의 번호·표시 변화를 확인했다. `A`는 선택 번호 1에서 `$06F0=02`, `B`는 `$06F0=01`을 썼지만 음원 소비자가 같은 프레임에 지우므로 쓰기 경계로 검증한다.

`START`는 상태 `0D`의 뱅크 7 전투 애니메이션 테스트로, `SELECT`는 상태 `0E/0F`의 뱅크 4 엔딩 상태기로 이탈한다. 공개 자료도 `START`의 반복 전투 테스트와 `SELECT`의 현재 진행도 엔딩을 설명한다. 복원 가능한 기준 상태에서 `hold_until`로 `$05EE`가 `START:0C→0D`, `SELECT:0C→0E`로 바뀌는 것까지 확인하고 입력을 해제했으며, 그 뒤에는 입력하지 않았다. `START`는 유닛 정보·예측·공격·피해·필살·격파·EXP를 거쳐 다음 전투 쌍으로 자동 반복했다. `SELECT`도 추가 입력 없이 원본 영어 도입·캐스트, 일본어 장 기록, 원본 영어 스태프, 일본어 인물 후일담, 원본 서명·저작권 화면까지 갔다. 마지막 `$7731=1D`는 no-op 처리기 `$C73D`를 쓰고 `$7732=00`이라 엔딩 시간 상태 갱신이 꺼져 있다. 21,000·24,000·28,000·33,000프레임의 스크린샷·네임테이블·OAM·팔레트가 모두 같았으므로 서명은 점멸하지 않는다. 앞서 종단 진입 전 검은 전환 프레임을 종단 점멸로 묶었던 판단은 폐기한다.

### 확인된 마르스 패배 개입

1장 맵의 첫 아군 레코드는 CPU 주소 `$6A90`에서 시작하며 크기는 27바이트다. `$6A90=01`은 마르스 ID이고 `$6A93/$6A94=12/12`는 현재/최대 HP `18/18`이다. `$6A93`을 일회성으로 `01`에 썼을 때 부대 목록의 마르스 HP가 `1`로 바뀌어 실제 소비 주소임을 확인했다.

패배 표본은 깨끗한 1장 맵에서 `$6A93`만 일회성으로 `00`에 쓴 뒤 입력 없이 120프레임을 확인하고, `SELECT`와 `DOWN` 5회로 `ターンおわる`를 선택한다. 유휴 상태에서는 패배가 발동하지 않았고 턴 전환에서 게임 오버 메시지가 나타났다. 계속 적용되는 치트로 만들거나 다른 아군 레코드까지 바꾸지 않는다. mapper 165 실행에서는 게임 오버 CHR 쌍 `07/07 + 00/19`의 최초 쓰기에 멈춘 뒤 1·7·19·43·82·127·191·263·383·565·934·1,273프레임을 불규칙 표본화했다. 완성 문구는 383~1,273프레임에 동일하게 유지돼 입력 대기였고, 그 뒤 `A`는 `$29:0A→06`에서 해제돼 원본 부팅·타이틀 복귀 연출을 시작했다. 원본 영문·숫자는 번역하지 않는다.

이 개입은 턴 전환의 마르스 패배 판정, 게임 오버 표시와 타이틀 복귀를 비교하는 불리한 경계 증거다. 자연 전투의 피해 계산·사망 애니메이션·전투 종료 처리를 대신하지 않는다. 12개 표본 모두 대사 선택자 `$77F4:$77F1=B0:0A`를 유지한다. 따라서 페이지 예산은 활성 원본 코드 90개와 정확한 패배 레코드 인덱스 10의 초벌 한글 30자, 합계 120/210슬롯이다. 장 승리 대사의 수명 예산으로 재사용하지 않는다.

### 확인된 1장 완료 가속

첫 아군 레코드의 `$6A9D`는 이동력이다. 일회성으로 `0F`를 쓴 뒤 부대 목록이 `MOV 15`를 표시해 소비 주소를 확인했다. 이 값과 적 HP 1 묶음은 화면 도달을 줄이는 데만 사용하며, 좌표 직접 쓰기나 행동 완료 플래그 해제는 장 완료 증거로 사용하지 않는다. 마르스는 실제 이동 명령으로 진행하고 적 턴은 실제 `ターンおわる`로 넘긴다.

보스는 턴 사이에 이동하거나 회복할 수 있으므로 실제 공격 직전에 해당 슬롯의 HP 1을 다시 확인한다. 실제 전투로 보스를 제거하고 마르스를 성에 이동했을 때 `しろ`가 나타나야 한다. `しろ` 결정 뒤의 원본 영어 `NEXT STORY`는 1,200 유휴 프레임 동안 유지돼 입력 대기 화면임을 확인했다. 일본판 원본 영어이므로 번역 대상이 아니다.

이후 `セーブしますか?`의 기본 `はい`를 선택하고 다음 맵으로 진행한다. 저장 지속성은 같은 관리 실행에서 native power cycle을 수행한 뒤 타이틀의 `ロードする`, `きろく1: MAP 2`, 2장 복귀를 순서대로 확인한다. 2장 화면의 아래 화살표는 점멸하므로 단일 프레임 해시가 다르면 같은 비점멸 위상을 표본화해 비교한다. 진행 가속으로 적 AI와 이동 경로가 달라진 실행끼리는 전체 SRAM이나 내부 RAM의 동일성을 요구하지 않고, 진행 상태와 같은 위상의 PPU 상태를 비교한다.

### 확인된 후반 장 도달 개입

정규 파일 1은 1-based 장 번호를 `$6519`에 두고, `$6000..$6542`의 16비트 가산 체크섬을 little-endian `$6542/$6543`에 둔다. 장 번호만 `02→0C`로 바꾸면 파일 선택 화면은 원본 영어 `MAP 12`를 표시하지만 로더는 검은 전환 뒤 파일을 거부한다. 체크섬도 `062E→0638`로 함께 바꾼 격리 실행에서 12장 도입에 도달했고, 현재 장 `$7674=0C`, 대사 문맥 `$781D=0B`, CHR `$59..$5C=0F 0F 00 18`을 확인했다.

같은 계약으로 장 번호 `0B`, 체크섬 `0637`을 쓴 파일은 11장 도입에 도달했고 `$7674=0B`, `$781D=0A`, CHR `1A 1A 00 18`이었다. 캡처한 완료 페이지에는 2장·12장 표본과 달리 초상화가 없었다. 파일 선택 상태에서 2프레임 `A`는 800프레임 동안 소비되지 않았지만, `$7674` 변경을 종료 조건으로 둔 `hold_until`은 63프레임 뒤 `02→0B`에서 입력을 해제했다. 선택 화면마다 짧은 탭이 충분하다고 일반화하지 않고, 기대 상태 변경과 묶인 조건부 입력을 우선한다. 완료 표식은 11장과 12장 모두 불규칙 간격 표본에서 표시·비표시 위상을 확인했다.

이 개입은 후반 장의 장 제목·맵·초상화·대사 합성 화면에 빨리 도달하기 위한 진행 가속이다. 10장이나 11장 완료, 종료 대사, 저장 제안·완료 또는 정상 유닛 생존 상태의 증거가 아니다. 장 번호와 체크섬 외의 저장 필드는 바꾸지 않으며, 개입한 파일과 세이브 스테이트는 기준선이나 자연 진행 증거로 재사용하지 않는다.

### 11장 성 명령과 연속 전환 관문

지원 원본의 11장 지도는 행 8, 열 5·6에 성 타일 `4B` 두 개를 둔다. 인트로 직후에는 적 슬롯 0의 ID `83`이 행 8, 열 5를, 슬롯 6의 ID `BF`가 행 8, 열 6을 점유했다. 런타임 지도 버퍼의 두 칸이 유닛 점유 값 `1B`였던 것은 성이 없다는 뜻이 아니다. 적 레코드는 ID와 HP만으로 활성 여부를 판정하지 않는다. 레코드 오프셋 18의 행동 바이트가 `FF`면 사망·비활성이고, ID와 일부 값은 남을 수 있다.

마르스는 좌표 쓰기 없이 실제 이동 명령, `ターンおわる`, 전투를 거쳐 접근했다. 이동 중 `$008E/$008F`는 커서·선택 좌표이고, 명령 메뉴가 열린 뒤 확정된 행동 좌표는 `$0500/$0501`에서 읽는다. 적 턴 처리로 슬롯 6이 행 5, 열 6으로 이동해 행 8, 열 6의 성이 열렸고, 마르스가 그 칸에 도달했다.

진행 가속으로 마르스 MOV 15, 현재 HP 복원, 문서화된 적 현재 HP 1 묶음을 사용했다. 메모리의 일회성 쓰기는 에뮬레이터의 지속 치트와 다르며 게임 처리에서 적 HP가 다시 채워질 수 있다. 따라서 필요한 경우 묶음 전체를 다시 적용하고 전투 직전에 활성 상태와 HP를 재확인한다. 이 실행은 명중률을 바꾸지 않았고 빗나감도 실제로 발생했다. 좌표 `$0500/$0501`, 주 상태 `$84`, 승리 단계 `$053E`, 외부 화면 상태 `$24`를 직접 쓰지 않았다.

성 위 명령 메뉴는 위에서부터 `こうげき / しろ / もちもの / たいき`였고 `$84=0F`, `$24=0C`, 선택 원시값 `$7FF3=02`에서 `しろ`가 선택됐다. 안정 화면과 불규칙 간격 표본에서 네 라벨은 유지되고 커서만 점멸했다. `A`는 `$84:0F→10`을 일으킨 뒤 `$84=3C`, `$053E=02`의 승리 처리로 들어갔다.

11장 종료 대사는 네 완료 페이지였고 초상화는 표시·표시·비표시·표시 순서였다. 승리 단계 `02`는 페이지 사이에 바뀌지 않으므로 각 `A`는 `$053E`가 아니라 대사 완료 상태 `$77F7=0E`에 결속한다. 뒤의 화면 수명은 다음과 같다.

- 종료 대사: `$24/$84/$053E/$77F7=0C/3C/02/0E`, CHR `11 11 00 18`
- 원본 영어 `NEXT STORY`: `$24/$84=0D/03`, CHR `1B 1B 00 18`, 1,200프레임 무입력 유지
- 저장 제안: `$24/$84=0D/07`, CHR `1B 1B 00 18`; 기본 “예”의 `A`는 저장을 기록
- 저장 완료·계속 질문: `$24/$84/$77F7=0E/04/11`, CHR `1C 1C 00 18`
- 검은 자동 전환: `$24/$84=09/00`, CHR `1A 1A 18 18`, 입력 불필요
- 12장 제목·대사 합성: `$7674/$24/$84/$77F7=0C/0B/00/0E`, CHR `0F 0F 00 18`

이 표본은 선언한 가속을 사용한 도달 증거다. 기준 난이도, 무개입 전투 동등성, 저장 질문의 “아니오”, 패배·자원 부족을 증명하지 않는다. 패배·불리한 검증에서는 승리 가속을 끄거나 목적에 맞는 불리한 개입을 별도 실행으로 사용한다.

## 필수 실패 경로

최종 회귀는 승리 경로만 통과해서는 안 된다. 적어도 다음 경로를 기준선 또는 명시한 불리한 개입으로 확인한다.

- 마르스 패배 → 게임 오버 → 저장 지점에서 재개
- 일반 아군 패배 → 해당 전투 종료 → 다음 장에서 영구 이탈 유지
- 적 턴과 반격에서의 피해·사망·메시지 표시
- 자금 부족 상태의 구매 거부와 정상 메뉴 복귀
- 무기 내구도 소진과 아이템·장비 표시 갱신
- 중단 저장 → `つづきをする` 재개 → 중단 데이터 소멸
- 장 완료 저장 → 콜드 런치 → `ロードする` 재개

진행 가속 치트가 켜진 실행은 패배·자원 부족 경로의 통과 증거로 사용하지 않는다. 해당 경로는 치트를 끄고 다시 실행하거나, 목적에 맞는 불리한 개입을 별도 실행으로 적용한다.

## 전투 합성 로더 경로

세이브 스테이트는 같은 매퍼뿐 아니라 같은 ROM 생성 계보에 결속한다. 256 KiB PRG 시점의 상태를 512 KiB 확장 ROM에 불러와 화면이 진행되더라도 캐시·뱅크·코드 실행 증거로 사용하지 않는다. 전투 합성 로더는 같은 512 KiB 계보의 상태 또는 콜드 경로에서만 검증한다.

현재 같은 계보의 무전투 적 턴 두 번 완료 상태에서는 `SELECT`가 진행 메뉴를 열며 주 상태를 `00→01`로 바꾼다. 커서는 OAM 엔트리 0의 Y 좌표 `1F→2F→3F→4F→5F→6F`에 대응하므로, 아래 입력은 고정 프레임 탭이 아니라 이 값의 한 단계 변화에 결속한다. 이 경로에서는 2프레임 탭이 누락됐지만 4프레임 입력 뒤 4프레임 해제는 한 행씩 안정적으로 이동했다. 첫 유효 `DOWN`은 점멸 중이던 첫 행 커서를 다시 보이게 했고, 그 뒤 다섯 번 더 이동해 여섯째 `ターンおわる`를 확인했다. 여기서 `A`를 누르면 주 상태가 `01→20`으로 바뀌고 턴을 실제 종료한다. 이 입력은 단순 화면 이동이 아니므로 메뉴 구조와 효과를 확인하지 않은 다른 행에서 반복하지 않는다.

합성 진입과 반환 뒤에는 1·7·19·43·82·171·308·351·400·565·934프레임처럼 불규칙 간격으로 전투 창·글자·점멸·스프라이트를 확인한다. 손상 ROM과 직전 정상 ROM은 같은 전투 진입 상태를 진단 기준으로만 공유해 합성 전 매퍼 상태와 입력을 고정했다. 손상 ROM은 합성 CHR-RAM은 맞지만 페이지 0의 오른쪽 FE 선택에서 `$8000=4` 없이 `$8001=0`만 써 PPU가 다른 페이지를 읽었고, 수정 ROM은 `$8000=4 → $8001=0`을 복구해 +43프레임의 CHR-RAM과 PPU `$1000` 페이지가 같았다. 이 동일 상태 A/B는 원인 격리 증거이며 자연 진행 증거를 대신하지 않는다.

현재 수정 증거는 ROM `3399a2ab385e00ffa4a28ef70b653c16a69a9ed2`에 묶인다. 사운드 테스트의 공용 전투는 `$84=04`, `$05EE=0D`, `$7730=05`를 함께 활성 조건으로 쓰고, 반복 단계 `04`의 `07:$AC17`이 `$047D=1`을 쓴 뒤 `$7730=05`로 넘어가는 원본 경계에서 `$07DF`만 지운다. 수정 뒤 연속 두 `$FB30` 합성은 서로 다른 재배치 쌍을 만들었고 각각 +43프레임에 CHR-RAM과 PPU `$1000` 페이지가 일치했다. 이전 ROM의 여섯 반복·자동 엔딩 비개입 증거는 원인 격리의 비교 자료로 유지하되 수정 ROM 전체로 자동 승계하지 않는다.

정확 최대 수요는 자연 진행에서 우연히 기다리지 않고, 정상 턴 종료 입력으로 합성 창에 들어간 뒤 `$FB30` 직전에만 모델 증인 입력을 주입했다. 수정 ROM에서도 선택된 결과는 131개 고유 오버레이·152개 글리프 참조, 재배치 6쌍이며 독립 계산과 실제 CHR-RAM SHA-1이 모두 `e0facc315aa43d02f987009abfa6b91f93e6b18b`였다. +43프레임에는 PPU `$1000` 전체가 CHR-RAM과 같고 한국어 이름·병종·장비, 원본 `LV/HIT`·숫자·그래픽이 함께 읽혔다. 상태와 쌍은 +171프레임까지 유지됐고 +341프레임에 원래 종료 상태 `33`으로 나간 뒤 첫 바이트가 0이 됐다. 이 입력 주입은 최악 구조의 실행 가능성과 표시 용량을 증명하지만 자연 도달 증거는 아니다.

## 실행 증거 규칙

각 실행 기록에는 ROM SHA-1, 시작 상태, 입력 경로, 활성 치트의 주소·값, 켠 구간, 기대 결과와 실제 결과를 남긴다. 치트가 활성화된 세이브 스테이트는 오염된 상태로 표시하며 기준선 실행의 시작점으로 재사용하지 않는다. 치트를 끈 뒤에는 깨끗한 저장 데이터나 콜드 런치로 기준선을 다시 만든다.

가속 실행은 화면 도달과 렌더 경로 증거가 될 수 있지만 게임 진행 동등성의 단독 증거는 아니다. G5의 전역 최악 수명 관문과 G7의 전체 회귀는 기준선 성공 경로와 실패 경로를 각각 가져야 한다.
