# 렌더 경로 조사

기준일: 2026-08-07

이 문서는 G1에서 확인한 MMC4 CHR 공급 코드와 실제 화면별 작업 집합을 기록한다. 여기서 `확인`은 지원 일본판 SHA-1 `0179c550d424e0397496078789e7b116601d120c`에 귀속된다. 아직 관측하지 않은 상점·아이템·후반 장 전환·엔딩 경로까지 일반화하지 않는다.

## MMC4 CHR 공급 코드

고정 PRG 뱅크의 네 루틴은 입력값을 제로 페이지 그림자에 보존하고 `$52`를 OR한 뒤 MMC4 CHR 레지스터에 쓴다.

| CPU | 그림자 | MMC4 레지스터 | 래치 영역 | 원본 명령 바이트 |
| --- | --- | --- | --- | --- |
| `$C9AE` | `$59` | `$B000` | PPU `$0000`, FD | `85 59 05 52 8D 00 B0 60` |
| `$C9B6` | `$5A` | `$C000` | PPU `$0000`, FE | `85 5A 05 52 8D 00 C0 60` |
| `$C9BE` | `$5B` | `$D000` | PPU `$1000`, FD | `85 5B 05 52 8D 00 D0 60` |
| `$C9C6` | `$5C` | `$E000` | PPU `$1000`, FE | `85 5C 05 52 8D 00 E0 60` |

`analyze-font-supply` 보고서 스키마 3은 이 네 루틴의 바이트를 검사하고 직접 `JSR`·`JMP` 바이트 패턴 후보를 PRG 뱅크·PRG 오프셋·파일 오프셋·CPU 주소로 출력한다. 지원 원본의 `JSR` 후보는 차례로 12, 12, 11곳, 7곳이고 `$C9C6`을 가리키는 `JMP` 후보가 2곳 더 있다. 스키마 5는 `$A000`~`$F000` 직접 절대 쓰기 패턴도 각각 12, 31, 9, 9, 9, 5곳 기록한다. 스키마 6은 이 가운데 가까이 이어진 CHR 쓰기를 13개 후보 집단으로 묶어 실행 검증 우선순위를 제공한다. PRG 안의 코드와 데이터 경계를 아직 모두 확정하지 않았으므로 어느 목록이나 집단도 실행 호출자나 패치 지점으로 자동 승격하지 않는다.

글꼴 페이지의 코드 `FD`와 `FE`는 단순 공백이나 회수 슬롯이 아니라 PPU `$1000` 쪽 래치를 전환하는 보호 코드다. 다음 실측에서 일본어가 있는 화면은 `$5B=00`을 유지하면서 `$5C`에 화면별 그래픽 페이지를 짝지었다.

## 관리 실행의 매퍼 쓰기 실측

같은 Mesen 호스트의 첫 명령 전 경계에서 원본을 다시 시작하고 CPU `$A000`~`$FFFF` 쓰기를 감시했다. 부팅의 `$A000` 뱅크 쓰기는 이벤트 상한을 넘었으므로 양성 적중만 사용했다. 이후 `$A000`을 제외하고 처음부터 메뉴, 인트로 진입·대화, 맵 진입과 능력치까지 나눈 6개 관측 창은 모두 `dropped=0`이었다. 여섯 이벤트 파일을 그 순서로 결합한 SHA-256은 `bc0bc733e79b14e207a8988f9f068d851cc443726ce796125abab1f192b02c43`이다.

Mesen 쓰기 이벤트의 PC는 해당 3바이트 명령 다음 주소였다. 라이브 디스어셈블로 다음 원인 명령을 결속했다.

| 레지스터 | 이벤트 PC | 원인 명령 | 관측 범위 |
| --- | --- | --- | --- |
| `$A000` | `$C9AD`, `$C200`, `$C208` | `$C9AA`, `$C1FD`, `$C205`의 `STA $A000` | 부팅 양성 적중 |
| `$B000` | `$C9B5` | `$C9B2: STA $B000` | 무손실 6개 창 |
| `$C000` | `$C9BD` | `$C9BA: STA $C000` | 무손실 6개 창 |
| `$D000` | `$C9C5` | `$C9C2: STA $D000` | 무손실 6개 창 |
| `$E000` | `$C9CD` | `$C9CA: STA $E000` | 무손실 6개 창 |
| `$F000` | `$C9DD` | `$C9DA: STA $F000` | 부팅 양성 적중 |

대표 경로의 `$B000`~`$E000` 쓰기는 모두 중앙 공급 루틴을 통과했다. 이는 정적 직접 쓰기 후보 전체가 데이터라는 뜻이 아니다. 상점·아이템·후반 장 전환·엔딩에서 적중하지 않은 후보는 계속 미확정이며, 매퍼 변환에서 삭제하거나 고칠 수 없다.

## 1장 초반에서 확인한 공급 호출자

`$C9BE/$C9C6` 실행 중단점에서 내부 RAM `$0000`~`$01FF`를 원자적으로 보존했다. 스택 반환 주소로 `JSR` 원점을 복원하고, 제로 페이지 `$51`로 `$8000`~`$BFFF`에 매핑된 PRG 뱅크를 식별했다. 고정 뱅크의 `$C1E0`은 반환 주소가 아니라 실제 명령 `4C C6 C9`를 디스어셈블해 꼬리 `JMP`로 확인했다.

| 역할 | 대상 | 확인한 전달 지점 | 입력 페이지 | 관측 경로 |
| --- | --- | --- | --- | --- |
| 처음부터 화면 초기화 | `$C9BE`, `$C9C6` | 뱅크 `02:$A685`, `02:$A688`의 직접 `JSR` | `00`, `00` | 타이틀 → 처음부터 |
| 장면 그래픽 쌍 초기화 | `$C9BE`, `$C9C6` | 뱅크 `06:$A7B9`, `06:$A7BC`의 직접 `JSR` | `18`, `18` | 슬롯 선택 → 인트로, 인트로 → 대화 |
| 문자 페이지 00 공급 | `$C9BE` | 뱅크 `0B:$928A`의 직접 `JSR` | `00` | 처음부터, 대화, 능력치, 맵 메뉴, 부대 목록 |
| FD 쪽 그래픽 페이지 준비 | `$C9BE` | 뱅크 `0B:$9324`의 직접 `JSR` | `15`, `18`, `19` | 대화·능력치 진입과 이탈 |
| 장면 애니메이션 쌍 교체 | `$C9BE`, `$C9C6` | 고정 뱅크 `$C1DD`의 `JSR`, `$C1E0`의 꼬리 `JMP` | `15`, `18`, `19` | 인트로와 맵의 애니메이션 구간 |

이 표는 해당 1장 초반 실행에서 실제로 적중한 지점만 확정한다. 나머지 정적 후보는 아이템·상점·후반 장 전환·엔딩을 관측하기 전까지 미확정이다. 원시 중단점 이벤트는 `evidence/private/g1-caller-*.json`에 두며 Git에는 넣지 않는다.

## 자동 능력치 화면의 직접 CHR 쓰기

무입력 콜드 실행의 프레임 1928에서 원본과 중앙 CHR writer만 옮긴 MMC5 프로브를 같은 경계로 덤프했다. 네임테이블·팔레트·OAM·PRG RAM은 바이트 단위로 같았고, 내부 RAM은 2,048바이트 중 4바이트만 달랐다. 제로 페이지 그림자 `$59/$5A=14/14`, `$5B/$5C=00/14`도 같았지만 원본의 실제 MMC4 페이지는 `$0000` 쪽 `02/02`, `$1000` 쪽 `00/00`이었고, 프로브의 `$5123/$5127`은 `14/14`에 남았다.

원본 `$B000`~`$E000` 쓰기 추적과 라이브 디스어셈블로 다음 직접 명령을 확인했다. 긴 관측 창은 반복 쓰기로 이벤트 128개가 누락됐으므로 전수성 근거로 쓰지 않고, 아래 양성 적중과 최종 매퍼 상태만 사용한다.

| PRG 위치 | 원본 명령 | 관측값 | 역할 |
| --- | --- | --- | --- |
| `0D:$8036` | `STA $D000` | `00` | 자동 화면 진입의 PPU `$1000` FD 페이지 |
| `0D:$8039` | `STA $E000` | `00` | 자동 화면 진입의 PPU `$1000` FE 페이지 |
| `0D:$83AB` | `STA $B000` | `00 → 02` | 자동 화면 애니메이션의 PPU `$0000` FD 페이지 |
| `0D:$83AE` | `STA $C000` | `00 → 02` | 자동 화면 애니메이션의 PPU `$0000` FE 페이지 |

네 명령을 같은 3바이트 길이로 `$5127/$5123`에 옮긴 프로브는 프레임 1206 타이틀과 프레임 1928 자동 능력치 화면을 각각 원본과 픽셀 단위로 재현했다. 따라서 기존 프레임 1928 실패는 MMC4 래치 공존 증거가 아니라 직접 쓰기 누락 증거로 교정한다. 다른 화면과 아직 실행 분류하지 않은 후보에는 이 결론을 일반화하지 않는다.

## 전투 애니메이션의 직접 CHR 쓰기

1장 맵에서 적 턴 전투 애니메이션으로 진입해 정적 분석에서 남긴 고정 뱅크 직접 쓰기를 관측했다. `$C1F2/$C1F7`는 제로 페이지 `$5E/$5F`의 `02/06`을 오른쪽 FD/FE에 매 프레임 공급했다. 30프레임 짧은 창에서 두 지점이 각각 30회 적중했고 이벤트 누락은 0건이었다. 두 페이지의 타일 `FD` 상위 비트플레인은 모두 0이므로 mapper 165에서도 별도 변형 없이 호환된다.

후속 전투에서는 왼쪽 FE·FD 공통 선택기에서 호출 스택과 매핑된 `$810E` 코드를 함께 보존했다. 같은 프레임의 반환 주소 `8110/8115`, 패치된 `JSR $FA40/$FA60`, `$5E/$5F=02/06`이 일치해 bank 05 `$810E/$8113` 쌍을 왼쪽 `02/06`으로 결속했다. 이후 FE 선택 없이 `$E414`가 `$0484+X`의 FD를 `06 → 02`로 바꿔 왼쪽 `06/06`, `02/06`이 실제로 이어졌다. 이 두 페이지의 타일 `FD` 상위 비트플레인도 모두 0이므로 추가 변형이 필요 없다.

이로써 직접 CHR writer 31곳은 같은 A를 연속 기록하는 26곳의 정적 동등 쌍, 고정 뱅크 오른쪽 2곳, bank 05 왼쪽 2곳, `$E414` 단독 1곳으로 전부 분류됐다. 장 완료 저장·콜드 로드·2장 전환은 별도 실행 증거로 확인했지만, 이 분류 자체는 전체 진행 동등성의 증거가 아니다.

## 현재 설계 판정

- 관측한 문자 화면은 모두 PPU `$1000` FD 쪽 공급값 `$5B=00`을 사용한다. 반대 래치 `$5C`는 문자 화면에 따라 `00`, `14`, `18`, `19`로 바뀐다.
- 문자창이 없는 인트로와 맵에서는 페이지 00이 빠지고 `$C1DD/$C1E0` 경로가 `15`, `18`, `19` 그래픽 쌍을 교체한다. 표의 `15/15`는 그 순환 중 한 표본이다. 문자 페이지의 수명은 게임 전체가 아니라 화면 진입과 이탈에 결속돼 있다.
- 따라서 동적 한글 글꼴의 첫 접점 후보는 `$C9BE`를 통과하는 페이지 00 공급 경로다. G2에서 mapper 165의 CHR-RAM을 사용할 수 있게 됐으므로 이제 이 경로의 페이지 수명에 글리프 적재를 결속한다.
- 기존 영어·숫자와 일본어가 같은 페이지 00을 소비한다. 한글 캐시는 영어 슬롯을 덮는 구조가 아니라 보호 고정 슬롯과 화면별 한글 슬롯을 함께 구성해야 한다.
- 확인된 보호 42코드와 합성 레이아웃의 `0F`, `1F`, `FF`를 예약하면 현재 한글 활성 슬롯 상한은 211개다. 이는 화면별 활성 한글 슬롯 예산이 아니다. 코드 `00`~`FF`의 실제 소비 집합과 아직 관측하지 않은 렌더 경로를 모두 연결하면서 추가 예약 코드를 빼고 최종 예산을 확정한다.

## 화면 단위 글꼴 계약

동적 글꼴은 전역 페이지 번호가 아니라 화면 역할과 그 화면에서 동시에 살아 있어야 하는 요소를 기준으로 선택한다. 각 화면은 배경 FD 문자, 배경 FE 그래픽, 스프라이트, 기존 영문·숫자, 전환 상태를 따로 기록한다. 국소 소비자를 찾더라도 이 계약에서 빠진 요소가 있으면 페이지를 실행에 결속하지 않는다.

첫 계약 대상은 1장 맵 메뉴의 설정 화면이다. `SELECT`로 맵 메뉴를 열고 다섯 번째 항목 `スイッチ`를 선택하면 진입한다. 이 화면의 그림자는 `$52=00`, 왼쪽 `$59/$5A=1A/1A`, 오른쪽 `$5B/$5C=00/15`다.

| 화면 요소 | 실제 공급과 상태 | 현재 판정 |
| --- | --- | --- |
| 설정 라벨 3개 | 오른쪽 FD 페이지 `00`; 코드 `0F,30,31,32,33,3A,3B,3F,40,44,46,50,53,5F,8B` | 일본어 번역 대상. 정적 PoC의 한글 12글리프가 실제로 필요한 화면 작업 집합이다. |
| 문자 레이아웃 | 같은 FD 쪽의 `FE`, `FF` | 각각 래치 전환과 빈 칸이므로 한글로 덮지 않는다. |
| 창과 지도 배경 | 오른쪽 FE 페이지 `15`; 78개 고유 타일 코드 | 번역 대상이 아닌 그래픽. FD 글꼴 페이지 교체와 동시에 보존해야 한다. |
| 선택 커서 | PPU `$0000` 쪽 페이지 `1A`; OAM 첫 스프라이트 타일 `F2`, X=`18` | 배경 글꼴과 별도인 스프라이트. 행 이동 때 Y만 `1F → 2F → 3F`로 움직인다. |
| 선택 행 상태 | 내부 RAM `$0034`의 `20`, `30`, `40` | 차례로 사운드·애니메이션·대기시간. `Down`은 다음 행, `Up`은 이전 행으로 이동한다. |
| 기존 영문 | 이 화면에는 없음 | G3의 영문 동시 표시 증거는 `LV/HP`가 있는 부대 목록이나 영문 약어가 있는 능력치 화면에서 별도로 닫아야 한다. |

고급 메모리 덤프의 2 KiB 네임테이블 SHA-1은 `3b25421890ded5f92e9c350d2dbac4f15a66fd04`다. 두 번째 물리 페이지를 초기 FE, FD=`00`, FE=`15`로 투영하면 FD/FE 트리거는 `6/135`, 실제 타일 fetch 수는 `66/894`였다. 설정 첫째 행과 둘째 행 표본의 네임테이블은 바이트 단위로 같고, OAM 첫 바이트만 `1F → 2F`로 바뀌었다. 첫째 행에서 입력 없이 8프레임 간격과 30프레임 간격으로 총 152프레임을 표본화한 화면은 모두 SHA-256 `bf9e91ca3e4ace890dc66287be709beb9c8c7a45eceae8400be57f4ed6533e53`으로 같았다. 이는 그 관측 창 안에서 놓친 점멸 위상이 없다는 근거이며 다른 화면의 점멸 주기까지 일반화하지 않는다.

따라서 첫 `A → B → A` 후보는 설정 화면의 정확한 CHR 그림자 네 값과 `$0034=20/30`을 함께 검사하고, `Down`과 `Up`으로 페이지를 왕복시키는 구조다. 화면 밖에서는 원본 FD 페이지를 복구해야 한다. 다만 설정 화면 자체에는 기존 영문이 없으므로 이 왕복만으로 G3 전체를 통과했다고 판정하지 않는다.

행 이동 때 기존 CHR 공급 루틴이 다시 호출되는지도 별도로 추적했다. `$0034` 쓰기는 매 프레임 뱅크 `0B:$93BF`의 `STA $34`에서 적중했고, 히트 시점 `$51=0B`, 오른쪽 그림자 `00/15`가 결속됐다. 첫째 행에서 `Down`을 누른 41프레임 창에는 41회 쓰기가 있었으며 값이 `20 → 30`으로 바뀐 뒤에도 같은 지점이 매 프레임 새 상태를 기록했다.

반면 mapper 165 코드의 CHR 선택기 범위 `$FA80`~`$FB7F`가 원인인 `$8000/$8001` 쓰기를 감시한 `Up` 10프레임과 후속 30프레임에는 적중이 없었다. 행 이동은 OAM과 `$0034`를 바꿀 뿐 기존 CHR writer를 재호출하지 않는다. 그러므로 화면 쌍을 판정하는 중앙 FD 선택기만 수정해서는 A/B가 움직이지 않는다. 실행 훅은 설정 화면의 이 매 프레임 행 계산부에 결속하고, 원래 행 좌표 계산과 플래그·레지스터 결과를 보존한 뒤 오른쪽 FD 페이지를 선택해야 한다. 전역 NMI나 다른 화면의 입력 처리에는 결속하지 않는다.

화면 전용 훅을 넣은 콜드 실행에서 첫째·둘째·셋째 행의 `$0034`는 `20 → 30 → 40`, 오른쪽 FD mapper 값은 `88 → 8C → 88`로 움직였다. 세 화면 모두 `사운드`, `애니메이션`, `대기시간`과 지도·창·커서가 함께 유지됐다. 설정에서 이탈하면 오른쪽 FD/FE 그림자가 `15/15`, mapper 값이 자연 페이지 `5C`로 돌아갔다. 같은 이탈 상태를 훅 없는 패리티 ROM과 비교해 화면, 모드 `$24=0C`, 좌표와 CHR 그림자가 같음을 확인했으므로 이탈 직후 입력 비활성은 한글 훅 회귀가 아니다. 정상 재진입 경로는 다음 화면 전이 조사에서 별도로 닫는다.

## 남은 G1 조사

1. 아이템, 상점, 후반 장 전환과 엔딩의 `$59`~`$5C` 상태를 같은 형식으로 추가한다.
2. 남은 직접 `JSR`·`JMP` 후보를 해당 화면의 실행 적중과 디스어셈블로 판정한다.
3. 대사·이름·아이템·지형 등 후보 포인터 표를 일본판의 실제 디코더까지 추적한다.
4. 부대 목록과 능력치 화면도 같은 계약으로 분해해 기존 영문·숫자와 한글의 실제 동시 소비 집합을 계산한다.
