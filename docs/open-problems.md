# 열려 있는 문제

마지막 확인: 2026-08-22

이 문서는 현재 제품을 막는 문제만 적는다. 닫힌 원인과 과거 산출물은 `decisions.md`와 `playtesting.md`, 현재 기준선은 `status.md`가 맡는다.

최종 판정은 크래시 0건, 일본어 잔존 0건, 진행 불가 0건인 플레이 가능한 ROM이다. 정적 설치 성공이나 한 화면 성공은 이 판정을 대신하지 않는다.

## 1. 남은 실행 분모를 화면이 아니라 목적별 묶음으로 닫아야 한다

등록된 화면 역할 53개는 적어도 한 번 관측됐고 일본어 대상 44개 수명은 정적 예산을 통과했다. 그러나 exact-ROM 실행 장부는 모든 변형과 이탈을 닫지 않았다.

구조 통합의 exact 무회귀는 닫혔다. 기능 동결을 해제한 뒤 남은 우선 묶음은 다음과 같다.

1. 다른 장의 대표 시설: 무기점·도구점·비밀상점, 보관·찾기, 구매·취소·자금 부족과 복귀
2. 장 종료 변형: 잔류 맵, 초상화 유무, 완료 대사, 저장 분기와 다음 장 정착
3. 아직 정확 CHR 쌍이 결속되지 않은 속도·유닛 선택·보관소·전달·버리기·중단 안내 역할
4. 성공·패배·사망·영입·엔딩을 포함하는 전체 플레이 계보

같은 exact ROM과 목적별 기준 SaveRAM 파일을 재사용한다. 화면 하나마다 빌드하지 않는다. 공통 반례가 나온 경우에만 생산자 → 재료 → 상주 계획 → 런타임 → 소비 경계를 수정하고 새 후보를 만든다.

## 2. 새 대사 수명의 콜드 합성 대기가 길다

글리치 대신 빈 대사 슬롯을 유지하도록 했지만, 새 CHR-RAM 수명의 최악 합성은 약 231프레임이다. 같은 상주 그룹의 637개 연결 전이는 다시 합성하지 않으므로 모든 페이지 전환 문제는 아니다.

정확성을 해치지 않고 줄일 수 있는 후보는 원본 페이지 복원 루프와 프레임마다 수행하는 CHR 뱅크 복구다. vblank 예산 초과, 화면별 지연 예외, 마지막 완료 프레임만 확인하는 방식은 허용하지 않는다. 현재는 진행 불가 블로커가 아니라 품질·속도 블로커다.

## 3. whole-program 매퍼 쓰기 분모가 완전히 닫히지 않았다

알려진 양성 실행 그래프, reset/NMI/IRQ 벡터, 오디오 handler 표와 `$C34C` 인라인 포인터 dispatch는 결속돼 있다. 그러나 동적 bank 전이와 selector-domain dispatch의 열린 edge가 남아 있어 “원본 전체에서 다른 mapper writer가 없음”을 아직 선언할 수 없다.

정적 분석은 실제 후보나 열린 edge를 유한하게 줄일 때만 계속한다. 실행 순서나 동적 값 때문에 정적으로 결정할 수 없는 지점은 미해결로 보존하고 동적 계측과 결합한다.

## 4. 실기·배포 경계가 열려 있다

현재 산출물은 개발 ROM이다. 실기 또는 선언한 플래시 카트 범위, 최종 패치 포맷, 깨끗한 원본에 대한 적용 결과, 공개 파일 allowlist가 아직 하나의 release gate로 닫히지 않았다. 원본 ROM, 생성 ROM, 대규모 대사 작업공간, SaveRAM과 내부 QA 캡처는 공개 저장소나 배포물에 포함하지 않는다.

## 결함 처리 규칙

- 일본어처럼 보이는 화면을 만나도 번역 누락으로 단정하지 않는다. 저장 바이트, 코드북, 글리프 페이지와 실제 소비를 순서대로 비교한다.
- 한 화면의 좌표·문자·상태를 예외로 넣기 전에 같은 생산자 또는 수명을 쓰는 전체 가족을 찾는다.
- 관측 튜플을 허용 목록으로 늘리는 대신 원본 생산자 분모를 결속한다.
- 다른 ROM 해시의 성공을 현재 후보의 실행 완료로 승계하지 않는다.
