# 열려 있는 문제

마지막 확인: 2026-08-22

이 문서는 «지금 무엇이 막혀 있고, 무엇을 알아야 풀리는가»만 적는다. 무엇을 했는지는 `status.md`, 왜 그렇게 했는지는 `decisions.md`, 앞으로의 순서는 `roadmap.md`에 있다.

판정 기준은 하나다 — **크래시 0건, 일본어 잔존 0건, 진행 불가 0건인 플레이 가능한 ROM.** 아래 항목은 그 기준에서 아직 «아니오»인 것들이다.

## 현재 우선 블로커: 남은 목적별 화면군을 같은 exact ROM에서 묶어 검증해야 한다

현재 통합 ROM은 `C50BC2E15EB51CB482DB906DB3BFF1FFC24C5F67`이고 스키마 41 설치 보고서는 `33E50FCDD24E68447190734E00D410224BD54625`다. 선언한 14개 도메인의 정적 설치와 전체 1,097개 시험은 통과했지만, 최종 실행 모집단 전체는 아직 닫히지 않았다.

최근 사운드 테스트에서 일본어처럼 보인 적 이름은 번역 누락이 아니라 공용 합성기의 두 모듈이 참가자 역할을 다르게 판정한 결함이었다. 화면 적용기는 staging 위치로 아군/적군을 골랐지만 selected-color 수집기는 최상위 비트로 다시 추측했고, 원본 사운드 테스트는 적 ID `1..8`에 그 비트를 세우지 않는다. 두 경로를 위치 기반 역할로 통일하고 원본 난수·병종/장비 생산자 전체를 코드북 분모에 넣었다. 현재 exact ROM의 자연 실행에서 적 ID `1..8`과 `[03,02]` 조합은 모두 독립 재합성과 실제 CHR-RAM 4,096바이트가 일치했다. 이 역할 결함은 닫혔으며, 같은 적 이름을 더 반복하는 일은 현재 블로커가 아니다.

직전 반복 결함의 공통 원인은 같은 소비자가 쓰는 입력과 수명을 여러 모듈이 서로 다르게 정의한 것이었다. 현재 구현은 공용 전투 위상 `$047C=00..1F`를 수명 권위로 삼고, 투기장 생성기의 병종·장비 출력까지 입력 분모에 포함한다. `$047D=1` 직접 writer 네 곳을 모두 새 전투 시작으로 분류했던 후보는 같은 투기장의 다음 라운드 `05:$82BB`에서도 `$07FE`를 지워 오히려 글꼴을 깨뜨렸다. 현재 구현은 실제 합성 수명 시작인 `06:$9300`, `06:$9D52`, `07:$AC17` 세 곳만 공통 초기화 루틴으로 보내고 `05:$82BB`는 보존한다. 현재 exact ROM에서 콜드 투기장의 첫 수명과 다음 라운드, 일반 전투, 사운드 테스트의 연속 두 자동 전투를 묶어 확인했다. 세 시작점은 모두 `무효화 → 합성`을 보였고 투기장 다음 라운드는 캐시·CHR을 유지했다. 독립 재합성 결과와 실제 CHR-RAM도 일반 전투와 사운드 테스트 두 합성에서 4,096바이트 모두 같았다. 남은 전투 관문은 이미 닫은 시작점 하나를 반복하는 것이 아니라 이름·병종·장비·메시지 변형을 목적별 화면군으로 묶어 실제 소비까지 확인하는 것이다.

25개 장의 제목·첫 완료 본문 결합은 직전 exact ROM에서 25/25 전수 실행했다. 여덟 CHR 쌍과 초상화 유무를 포함한 전체 화면에서 일본어 잔존·가블·보더 손상을 찾지 못했고, 이번 변경은 전투 활성 writer의 수명 분류에 한정되므로 장 도입 첫 페이지 변형은 현재 블로커에서 제외한다. 이를 현재 ROM의 실행 표본으로 바꿔 부르지는 않는다. 남은 우선순위는 다른 장의 대표 시설과 장 종료 뒤 잔류 맵·초상화·대사 변형을 목적별 기준 저장 자료로 묶어 같은 exact ROM에서 실행하는 것이다. 이미 닫은 8장 투기장·부대 명단·유닛·소지품·보관소, 일반 아군 사망, 자연 전투 보상, 자동 엔딩·후일담은 변경 영향권에 새 반례가 없으면 처음부터 반복하지 않는다. 14명 자연 영입과 네 품목의 자연 수집 이력은 전체 플레이 경로 증거로 남지만 이미 닫은 표시 수명을 다시 막지 않는다.

새 결함이 나오면 화면 문구나 좌표를 바로 예외 처리하지 않는다. 실제 필드를 만든 생산자, 최종 코드북, 페이지 게시, 버퍼 수명, 매퍼 공급 중 가장 먼저 어긋난 공통 경계를 찾는다. 정적 분석은 유한 생산자 분모를 실제로 줄일 때만 확장하고, 실행 순서·난수·비동기 시점에 의존하는 지점은 묶음 동적 실행으로 넘긴다.

## 최근 닫힘: 25개 장 인트로 결합 수명의 첫 완료 페이지

**과거 증상.** 초기 전역 대사 탐침은 맵·창·초상화와 대사 본문 한글을 함께 표시했지만 같은 화면의 장 제목이 깨졌고, 첫 줄 앞에서 `{EA}`가 만드는 원본 표식 `9E AB`도 잘못된 두 글리프로 바뀌었다.

**닫힌 원인.** 첫 산출물은 표시 selector가 mapper165의 오른쪽 FD 레지스터 2와 FE 레지스터 4를 모두 같은 CHR RAM 페이지로 바꿨다. FD 글꼴과 FE 맵 배경은 같은 타일 코드 공간을 서로 다른 패턴으로 쓰므로 한 페이지로 합칠 수 없다. FD만 RAM으로 고르는 구조로 바꿨고 배경 손상은 닫혔다. 반복 E4 생산자가 `ready` 직후 같은 요청을 다시 냉합성하던 문제도 게시 원문 정체성 비교로 닫혔다.

**셋째 실행에서 닫힌 원인.** 탐침 `A4AE24B8DE40F2930FDC799C48A6D2C3E6E2894D`은 새 런타임 코드북을 만들면서 정규 대사 저장소는 이전 누적 후보의 국소 코드북 바이트로 남겼다. 300프레임 안정성은 수명만 증명했으며 표시 정확성은 증명하지 않았다. 현재 빌드는 저장소 11구간과 포인터 517개를 같은 코드북에서 설치하고 최종 이미지에서 다시 검증한다.

**현재 실행 결과.** 탐침 `018EDE4D6E6E500D025CBCC5279194BB142161ED`의 1장 프레임 2937은 `ready`를 쓰는 NMI 내부에서 멈춘 상태여서 새 CHR이 아직 프레임버퍼에 나타나지 않았다. 한 프레임 뒤 2938에서 대사 본문은 읽혔다. 그때 네임테이블 코드, 현재 그룹 23 코드북, 참조 CHR 타일의 16바이트 전체와 PPU `$1000..$1FFF`가 일치했다. 따라서 런타임 2bpp 전송이나 PPU 소비는 현재 막힘이 아니다.

**통과한 것.** `ready` 게시, 같은 원문의 현재 완성 페이지 재사용, FD RAM/FE 원본 분리, 현재 대사 저장소와 현재 코드북의 정적·실행 코드 일치, 1장 첫 본문의 가독성은 통과했다. v25 `26A8D6587D23EDBF06964FF175C4285F05DBE9BE`에서는 같은 정체성 재사용도 밀어낸 원본 `$E6B2`를 실행한다. 첫 레코드 전이에서 보조 버퍼 길이 `06`이 소비 전에 기록됐고, `$053E=02`를 유지한 채 다음 두 한글 대사 화면까지 진행했다.

**정적 해결.** 장 제목 글리프는 해당 장의 전체 인트로 전이 사슬 페이지에 넣고, 제목 저장소를 한 번만 인코딩해도 모든 해당 페이지에서 같은 글리프 코드가 유지되도록 고정 배정을 찾는다. 25개 장·관련 가시 페이지 129개·제목 글리프 88개가 결속됐고, 제목 저장소 25개를 동일한 Expected Write 이미지에 설치한다. 최대 합성 페이지 수요는 `210/210`이다. `{EA}` 공통 처리기가 화자명 앞에 스크립트 밖의 일본어 표식 `9E AB`를 합성하던 경로는 원천 처리기에 결속한 같은 길이의 투영으로 바꾸어 두 칸을 빈 타일로 유지한다.

**현재 실행 결과.** 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`의 1장 첫 완료 화면은 장 제목 `마르스의 여정`, 원본 `EA` 표식, 한글 본문, 맵·창·초상화를 함께 유지했다. 1장 결합 수명은 닫혔다.

**최종 통합 교정.** 첫 통합 ROM은 제목 저장소의 원본 고정 뱅크만 갱신하고 실행 중 CPU가 읽는 확장 고정 뱅크 복사본을 빠뜨렸다. 정확 통합 ROM `97da073050e437c9d2ec32c852c2623dd6c0b368`은 25개 제목을 두 복사본에 모두 설치한다. 콜드 1장 화면의 `마르스의 여정`과 한글 본문은 0·7·19·43·82프레임에 가블 없이 유지됐고, 완료 상태 `$77F7=0E`에서 `A` 한 번 뒤 800프레임으로 다음 대사 페이지까지 전진했다.

**다중 페이지 교정.** 위 표본 뒤 레코드 003에서는 같은 첫 페이지가 반복되는 진행 회귀가 남아 있었다. 원인은 완료 훅 바깥 `$85C7`이 공유하는 `$85E5 RTS`를 훅이 `NOP`으로 덮어 대기 프레임마다 `$85E6` source resolver로 추락한 것이었다. 정확 통합 ROM `5e8eaaf096dc5a18e6501be1007064f1831d7a62`은 선행 분기를 설치 사전조건으로 결속하고 공유 `RTS`를 보존한다. 콜드 실행에서 첫 페이지 30프레임 포인터 쓰기 0건, 서로 다른 둘째 페이지, 다음 레코드, 후속 페이지, 맵 이탈을 연속으로 통과했다.

**최악 경로 결속.** 정확 통합 ROM `5e8eaaf0...`에서 게임의 중단 직렬화로 만든 SaveRAM만 주입하고 현재 ROM을 reset한 뒤 `이어하기`, 실제 턴 종료와 성 명령을 거쳤다. `C0:18`의 완료 페이지 15개가 가시 색인 `0..14`로 전진했고 각 페이지의 0·7·19·43·82·171프레임 표본과 마지막 `NEXT STORY` 이탈을 결속했다. 최종 실행 증거는 15페이지와 그 뒤 이탈 표본이 없으면 이 최악 역할을 거부한다.

**최신 표본.** 검증된 SaveRAM을 첫 명령 전에 넣고 정확 통합 ROM `801a1950db75e169f5f93eb7f74fbcc71ccb9e5e`를 시작한 7장 화면에서 네임테이블의 화자명 앞 코드는 `FD FF FF`였고, `하마인장군`·장 제목·본문·초상화·창이 함께 유지됐다. 이 한 화면은 공통 처리기의 출력 변경을 확인하지만 나머지 장의 표시 회귀를 대신하지 않는다.

**현재 결과.** 정확 통합 ROM `97034214F12D5F6165C808097294566BE3616D00`에서 25개 장을 모두 source-bound SaveRAM 분기로 불러왔다. 각 완료점은 `$7674=01..19`, `$781D=00..18`, `$77F7=0E`를 만족했고 여덟 CHR 쌍을 포함했다. 25개 제목·첫 본문 접촉판 SHA-256은 `DF80F3AE212F420BD79C71C149D28199D0A695905A3EE801E372BB0A7494E893`다. 이 첫 페이지 변형은 닫혔으며, 각 장의 자연 선행 완료와 모든 후속 페이지는 별도 전체 플레이·최악 사슬 증거가 맡는다.

## 2. 콜드 합성의 표시 글리치는 닫혔지만 빈 창 대기가 길다

한 페이지를 새로 올리는 데 복원 128프레임 + 덮기 최대 103프레임 = **231프레임, 약 3.9초**다. 전용 CHR-ROM 냉간 표시 페이지가 한글 활성 슬롯 210개를 비우고 보호된 영어·숫자·제어·레이아웃 46코드를 원본 그대로 유지하므로, 준비 중 글리치 대신 빈 대사 슬롯을 보여 준다. 정확 탐침 `30C5406ED6724ADBBCA2B124D626129587C0D22D`의 복원·덮기 단계 다섯 표본과 완료 표본에서 확인했다.

내역은 이렇다. vblank 여유가 프레임당 1,259사이클이고, 복원은 32바이트 덩어리 하나(약 460사이클), 덮기는 타일 두 개(약 700사이클)가 한 프레임에 들어가는 한계다.

**줄일 여지.**

- 같은 정적 그룹의 레코드 전환은 resolver 뒤 그룹 비교로 닫았다. E6 상태 `10`은 상주권을 유지하며 1장 실행에서 이전의 즉시 재합성이 사라졌다.
- E7 재진입은 호출자 안전 목록 없이 닫았다. E7은 상주권을 보류하고, 누적 후보의 직접 선택 세 곳과 결속한 실제 전투 4 KiB 합성 진입만 먼저 상주권을 무효화한다. 프레임 3141의 인계와 3261의 이어진 한글 화면을 확인했다.
- 복원의 바이트당 비용이 12사이클이다. `LDA (zp),Y`가 6, `STA $2007`이 4, `INY`가 2. 원본 주소를 언롤해 `LDA abs,X`(5)로 바꾸면 바이트당 11이 되지만 코드가 길어진다.
- CHR 뱅크 복원이 프레임마다 최대 292사이클을 쓴다(`$FA80`·`$FAA0` callee 각 140 + 호출자 `JSR` 각 6). 이것을 프레임마다 하지 않아도 되는 조건이 있는지 아직 안 봤다.
- 전이 사슬을 같은 코드북 수명으로 묶어 현재 637개 상주 전이는 CHR 쓰기 없이 재사용한다. 콜드는 대사 수명이 새로 시작되거나 실제 CHR-RAM 소유권이 바뀔 때만 든다.

**필요한 것.** 새 대사 수명의 콜드 복원 비용을 줄인다. 현재 291개 전이 수명 안의 637개 레코드 전이는 같은 코드북으로 묶여 차이 전송 없이 재사용된다. 나머지 장과 외부 호출 복귀에서도 요청 뒤 첫 표시 프레임부터 완료 프레임까지 글리치 0건을 다시 검증한다.

**하지 않을 것.** 예산을 늘려 vblank를 넘기는 것, 또는 마지막 `ready` 프레임만 보고 중간 깨짐을 무시하는 것. 속도는 품질 지표이고 예산 초과와 가시 글리치는 모두 정확성 위반이다.

## 3. 전역 대사 소비자는 정적으로 닫혔고 최종 산출물 실행 결속을 시작했다

원본 상태 머신과 공유 CHR-RAM 경계의 제어 역할 10개와 동적 아이템·아군·마을 아이템·후일담 인물·후일담 지명 생산자 5개, 합계 **15 / 15**가 통합 Expected Write에 들어간다. 504레코드·2,548번역 줄의 저장과 517포인터도 같은 코드북으로 인코딩된다.

`$FA80/$FAA0` 관측 훅은 설치하지 않는다. 둘은 직접 CHR 기록기가 쓰는 stateless helper이고, 여기서 `$5B/$5C`를 갱신하면 mapper165가 의도적으로 나눈 중앙 상태와 일시적 직접 기록을 섞는다. 대사 소비자는 후보의 중앙 기록기 `$C9BE/$C9C6`가 소유하는 `$5B/$5C`를 읽기만 하며, 이 두 생산자와 두 helper의 바이트를 설치 선행 조건으로 묶었다. 이전 임시 그림자 `$07EB`는 기존 전투 런타임의 `$07E0..$07EF`와 충돌하므로 폐기했다.

**닫힌 상주 전이.** 연속 페이지와 `E4/E6` 전이 그래프를 291개 표시 수명으로 묶었다. 최대 수요는 `198/210`이고, 현재 637개 상주 전이는 모두 같은 코드북을 재사용하므로 레코드 경계에서 CHR을 다시 쓰지 않는다. 같은 정체성 재사용도 한글 합성만 생략하고 밀어낸 원본 resolver를 실행한다. 새 수명과 전투 합성으로 상주권이 실제 무효화된 뒤에만 콜드 복원한다.

**동적 remap은 더 이상 빠진 경로가 아니다.** 동적 글리프마다 모든 소비 페이지에서 충돌하지 않는 canonical 물리 코드를 고정했고, 다섯 생산자 훅이 91개 아이템·53개 아군·24개 지명의 전용 인코딩을 직접 쓴다. 대표 아이템·인물·지명은 v30에서 저장부터 화면까지 통과했다.

**현재 결속.** 과거 v30 실행 증거는 공유 atlas와 쓰기 집합이 다른 최종 통합 이미지에 승계하지 않았다. 정확 통합 ROM `5e8eaaf096dc5a18e6501be1007064f1831d7a62`의 새 private manifest는 산출물 해시·콜드 부팅·세이브스테이트 미사용·이미지 SHA-256뿐 아니라 서로 다른 대사 페이지 둘, 다음 레코드, 역할 이탈의 시간 순서를 검사한 뒤에만 `chapter_intro_title_dialogue_composite`를 `chapter_titles`와 `main_dialogue`에 결속한다.

**현재 실행 결속.** 통합 보고서 자체는 최종 manifest를 받지 않아 과거의 형식적 역할 수치를 승계하지 않는다. 별도 현재-ROM 장부에서는 패배·저장, 자연 인물명과 직접·라우팅 후일담의 인물·지명 소비, 자동 엔딩 종단, 자연 전투 보상 소지품 초과의 보관·취소·버리기 분기까지 실행했다. 현재 exact ROM에서는 여기에 투기장 합성·결과·퇴장, 내용이 있는 상태 `17`의 부대 명단 안정성, 25개 장의 제목·첫 완료 본문을 더했다. 남은 것은 다른 장 시설과 장 종료 변형을 같은 정확 산출물에서 묶는 일이다.

## 4. 14개 도메인의 정적 설치는 완료됐지만 최종 실행 모집단이 남았다

전체 설치가 요구하는 도메인은 주 대사 1개와 비대사 13개, 합계 14개다. 공유 atlas는 14개 도메인의 한글을 모두 포함한다. 주 대사 504레코드·517포인터와 비대사 13개 도메인의 338엔트리가 같은 이미지에 설치되며, 현재 쓰기 집합 기여와 소비자 정적 결속은 모두 **14 / 14**이고 미결 정적 소비자 도메인은 0개다.

이 수치는 게임 전체 실행 완료를 뜻하지 않는다. 통합 보고서는 최종 manifest를 받지 않았고, 별도 exact-ROM 장부는 실제로 관측한 역할만 닫는다. 현재 장부에는 저장·장 기록·후일담·엔딩·소지품 초과·투기장·부대 명단과 25개 장 도입 첫 페이지가 있지만, 다른 장의 시설·종료 변형은 남는다. 정적 설치나 과거 산출물의 표본을 게임 전체 실행 완료로 올리지 않는다.

전투의 `213 > 210`은 더 이상 이 절의 블로커가 아니다. 전역 논리색 213개를 유지하면서 보존 전투 리터럴에 없는 표시 코드 3개를 논리 원천으로 빌리고, 선택된 전투만 활성 물리 코드 210개에 투영한다. 보수적 결합 수요는 `173/210`, 정확 모델 최대는 `170/210`, 교차 가족 중복을 공제하지 않은 재배치 수요는 `7/8`이라 기존 런타임 저장소 안에 든다. 이 계획은 지도·증원 적뿐 아니라 투기장 생성기의 병종·장비 39조합도 포함한다.

과거 7장 완료 페이지 경계가 전체 작업공간 SHA에 묶인 문제는 닫혔다. 현재 계약은 대상 레코드의 원천 포인터, 626바이트의 글리프/제어 topology, 57개 줄 경계를 SHA-1 `5ee3b66823c66070447a180a63058a2e1277b75a`에 결속한다. 과거 출력은 topology를, 현재 열째 단계 출력 `80f63bc4cb6afa977ade127af60aafd4f17275b0`은 현재 글리프 래스터를 각각 정적으로 통과했다. 정확 통합 출력은 별도로 15개 완료 페이지·90개 점멸 표본과 마지막 `NEXT STORY` 이탈을 통과했다. 과거 정적 세 글꼴 묶음의 매퍼 값은 현재 전역 런타임의 실행 통과 조건으로 승계하지 않는다.

깨끗한 전체 빌드는 통합 ROM을 방출하며, 정확 산출물 manifest가 제공되면 검증된 화면 역할만 최종 실행 결속으로 센다. 현재 exact ROM은 `97034214F12D5F6165C808097294566BE3616D00`, 스키마 41 보고서는 `F5030972F88FC5EA46282753A67EB1857D61F429`다. 현재 다음 실행 모집단은 다른 장의 대표 시설·종료 변형이다. 앞선 exact ROM에서 닫은 역할은 변경 영향 분석에 사용하되 현재 보고서가 자동 승계하지 않는다.

## 6. 실기 지원이 선언만 되어 있다

배포 이미지는 NES 2.0으로 매퍼 165, CHR 256 KiB 정렬, CHR RAM 4 KiB와 배터리 작업 RAM 8 KiB를 정확히 선언한다. 소비자도 vblank 안에서만 `$2007`에 쓴다는 것을 실측으로 확인했다(`$C3A5` 인계 시점 scanline 257, 남은 431사이클).

**확인되지 않은 것.** 실기 플래시 카트가 매퍼 165를 지원하는가. 지원 목록을 아직 확인하지 않았다. 지원하지 않으면 배포 형태 자체를 다시 정해야 하므로, 코드가 더 쌓이기 전에 닫는 편이 싸다.

## 7. 새 외부 호출은 사이클 CFG를 함께 확장해야 한다

`worst_case_cycles`는 «비용을 모르는 `JSR`»를 거부한다. `$FA80`·`$FAA0`의 공용 131사이클 상수도 제거했다. 후보 고정 뱅크를 typed RP2A03으로 해석해 분기·직접 점프·중첩 호출·복귀의 최장 경로를 계산한 현재 callee 상한은 둘 다 140사이클이고, 호출자의 `JSR` 6사이클은 방출 명령 쪽에서 별도로 센다. 이전 예산은 helper마다 9사이클을 작게 셌지만 현재 프레임 예산은 수정된 값으로도 통과한다.

분기 조건의 실제 도달 가능성은 좁히지 않고 양쪽 중 큰 값을 택하므로 안전한 상한이다. 선언 코드 범위 밖 전이, 간접 점프, 루프·재귀, 아직 모델링하지 않은 명령 형식은 전부 설치를 거부한다. 따라서 남은 규칙은 새 외부 호출을 추가할 때 그 callee의 허용 범위와 CFG 상한을 같은 작업 단위에서 결속하는 것이다.

## 되풀이되는 실패 방식

같은 유형이 이 작업에서 네 번 나왔다. 새 코드를 쓸 때 확인할 목록으로 남긴다.

**자기 상수를 자기 테스트로 확인하기.** CHR selector가 `encode_chr_page_register(0)`과 같은지를 단언하고 통과했는데, 그 함수는 물리 페이지 0용이라 1을 돌려주고 CHR RAM은 0이었다. 테스트는 **하드웨어 계약**을 단언해야 한다.

**기존 훅이 성립하던 조건을 안 물려받기.** 전투 합성이 `$C191`에서 동작한다는 사실이 대사에도 맞는다는 뜻이 아니었다. 전투는 렌더링을 끄고 돌아 면제를 받고 있었다.

**끼어드는 자리가 나르던 것을 안 돌려주기.** CHR selector가 사슬의 누산기를 덮어 화면 전체를 깨뜨렸다. 사슬은 페이지 번호를 A로 나른다.

**«나중에 해도 되는 것»을 잘못 고르기.** 원본 페이지 복원을 «첫 페이지에는 필요 없다»며 미뤘는데, 맵 타일과 글꼴이 같은 4 KiB 페이지에 있어 첫 페이지의 전제였다.

넷 다 단위 시험은 전부 통과한 상태에서 **실행**이 잡았다.
