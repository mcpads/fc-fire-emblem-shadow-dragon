# 열려 있는 문제

마지막 확인: 2026-08-23

이 문서는 현재 제품을 막는 문제만 적는다. 현재 exact 산출물과 다음 행동은 `status.md`, 안정된 처리 규칙은 `refactoring.md`, 과거 실행은 `playtesting.md`가 맡는다.

최종 판정은 크래시 0건, 일본어 잔존 0건, 진행 불가 0건인 플레이 가능한 ROM이다. 정적 설치 성공이나 한 화면 성공은 이 판정을 대신하지 않는다.

## 1. 현재 exact ROM의 목적별 실행 분모가 열려 있다

통합 ROM `89315359070F1DA09BE7941B1B55330CC630D68D`은 정적 설치를 통과했고 콜드 타이틀, 지팡이 전투 합성, 결과 끝단과 맵 인계가 한 실행 기록으로 묶였다. 직전 ROM에서 통과한 저장·투기장·시설·엔딩 실행은 원인과 소비 경로 근거로만 남으며 현재 후보의 성공으로 승계하지 않는다.

공용 전투 수명 반례는 현재 ROM에서 닫혔다. 비전투 타이틀은 남아 있던 전투 캐시를 제거하고, 일반 전투는 `$047D`가 내려간 뒤에도 마지막 가시 위상 `1E`까지 캐시를 유지하며, 위상 `1F`의 맵 인계에서 제거한다. 이 결과는 지팡이 경로 한 변형과 콜드 타이틀만 덮으므로 전체 실행 분모는 같은 ROM과 파일로 보존한 SaveRAM을 사용해 다음 목적별 묶음으로 계속 닫는다.

1. 콜드 새 게임·불러오기·기록 삭제·1장과 후반 장 도입
2. 소지품·전달·폐기·회복·시설·장 저장의 성공·취소·실패·복귀
3. 일반 전투·투기장·사운드 테스트의 이름·병종·장비·지형·기술·대사·보상·사망
4. 장 종료·패배·영입·사망·후일담·엔딩 변형과 다음 장 정착

공통 반례가 나오면 같은 생산자 → 재료 → 상주 계획 → 런타임 → 소비 가족을 먼저 모아 한 수정으로 처리한다. 화면 하나의 예외나 다른 ROM의 상태를 허용 목록으로 추가하지 않는다.

## 2. 새 대사 수명의 콜드 합성 대기가 길다

글리치 대신 빈 대사 슬롯을 유지하지만 새 CHR-RAM 수명의 최악 합성은 약 231프레임이다. 같은 상주 그룹의 연결 전이는 다시 합성하지 않으므로 모든 페이지 전환의 비용은 아니다.

정확성을 해치지 않고 줄일 후보는 원본 페이지 복원 루프와 프레임마다 수행하는 CHR 뱅크 복구다. vblank 예산 초과, 화면별 지연 예외, 마지막 완료 프레임만 확인하는 방식은 허용하지 않는다. 현재는 진행 불가가 아니라 품질·속도 블로커다.

## 3. whole-program 매퍼 쓰기 분모가 완전히 닫히지 않았다

알려진 양성 실행 그래프, reset/NMI/IRQ 벡터, 오디오 처리자 표와 `$C34C` 인라인 포인터 dispatch는 결속됐다. 동적 bank 전이와 selector-domain dispatch의 열린 edge가 남아 있어 원본 전체의 다른 mapper writer 부재를 아직 선언할 수 없다.

정적 분석은 실제 후보나 열린 edge를 유한하게 줄일 때만 계속한다. 실행 순서나 동적 값 때문에 정적으로 결정할 수 없는 지점은 실행 계측으로 넘긴다.

## 4. 실기·배포 경계가 열려 있다

현재 산출물은 개발 ROM이다. 실기 또는 선언한 플래시 카트 범위, 최종 패치 포맷, 깨끗한 원본에 대한 적용 결과와 공개 파일 allowlist가 하나의 release gate로 닫히지 않았다. 원본 ROM, 생성 ROM, 대규모 대사 작업공간, SaveRAM과 내부 QA 캡처는 공개 저장소나 배포물에 포함하지 않는다.
